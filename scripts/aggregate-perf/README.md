# Измерение точного ARRAYAVERAGE

Инструмент измеряет существующую общую реализацию `ARRAYAVERAGE`, не заменяя её приближённым алгоритмом. Запуск из корня репозитория:

```powershell
dotnet run --project scripts/aggregate-perf/Axiom.AggregatePerf.csproj -c Release -- C:/Axiom
dotnet run --project scripts/aggregate-perf/Axiom.AggregatePerf.csproj -c Release -- C:/Axiom measurements-repeat.json
```

Отчёты сохраняются в `.artifacts/aggregate-perf-1125/`. Повторный запуск с другим простым именем файла сохраняет первый отчёт. Команды .NET выполняются последовательно.

Первое измерение вызывает общий обработчик через заранее созданный делегат. Поиск метода, создание и заполнение массива не входят в измеряемый интервал. Проверяются размеры 3, 63, 999, 99 999 и 999 999 элементов, обычные значения со средним 2, сокращение `1e308`, `-1e308`, `1e-308`, минимальные субнормальные значения и нули. Каждый вызов сверяет биты результата с независимым ожидаемым значением. Размеры 3 и 63 добавлены в Session 1126; для них нет сохранённого исходного измерения Session 1125.

Второе измерение запускает заранее скомпилированную программу `arrayaverage_exact_cancellation.axm` в BytecodeVm. Интервал включает создание и заполнение массива, восемь вычислений среднего и вывод проверки. Компиляция не входит в интервал. Проверяются успешный результат, ожидаемый вывод и фактический исполнитель.

Для каждой строки выполняются три прогрева и семь измерений; JSON содержит все наблюдения и медианы. Память измеряется через `GC.GetAllocatedBytesForCurrentThread`: это сумма выделений текущего потока, а не пиковая память процесса и не объём живых объектов. Измерение не доказывает быстродействие всех форм массивов или других типов элементов. JIT и сборка мусора могут влиять на время; маленькие размеры особенно чувствительны к прогреву. Результаты относятся к конкретной программе и одной VM. Исторические измерения находятся в архиве.
