# Независимые проверки языка Axiom

Инструмент сохраняет исходные наблюдения и проверяет заранее заданные ожидания. Он не исправляет реализацию языка. Исходная проверенная ревизия — `2603b3d1fd2edea79a5bbe2cd392762836a961e5`.

Запуск из корня репозитория, последовательно с другими командами MSBuild:

```powershell
dotnet run --project scripts/language-audit/Axiom.LanguageAudit.csproj -- C:\Axiom
pwsh -File scripts/language-audit/Export-Audit.ps1
```

Путь после `--` должен указывать на текущий корень репозитория. Результаты и проверочные файлы создаются только в `.artifacts/language-audit-20261007/`. Файловые проверки очищают только собственные подкаталоги `fs-cases`, предварительно проверяя абсолютную границу каталога. Не запускайте два экземпляра инструмента одновременно: они используют одни проверочные файлы.

Код завершения `1` означает расхождение с проверенным ожиданием или CLR-исключение. В исходной ревизии такие ошибки ожидаются: это инструмент воспроизведения, а не зелёный регрессионный набор. Сценарии без независимого ожидаемого результата сохраняются как наблюдения. Они не превращаются автоматически в дефекты.

- `Inventory.cs` читает реальный реестр, проверяет диспетчеры и повторяющиеся сигнатуры, сохраняет пути к коду, тестовым упоминаниям, примерам, справочнику и обеим схемам подсветки. Полиморфные политики сохраняются отдельно от объявленного типа.
- `AuditCases.cs` проверяет числовые границы, Unicode, регулярные выражения, агрегаты, кодировки и свойства с фиксированным зерном `7012026`.
- `FileCases.cs` проверяет файловые операции и жизненный цикл дескрипторов в изолированных каталогах.
- `CoreCases.cs` проверяет приоритеты, процедуры, BYREF, TYPE, циклы и FINALLY.
- `SampleAudit.cs` разбирает весь корпус `.axm` и запускает автономные семейства в BytecodeVm без графического/интерактивного контекста и внешних изменений. Фиксированные часы и генератор обеспечивают воспроизводимость. Успешный запуск без независимого ожидания не доказывает правильность результата. Диагностика в отрицательном примере проверяется отдельно.
- `Export-Audit.ps1` экспортирует подробные данные в `docs/audit/bytecode-only/` с текущей датой в именах. Матрица сценариев называется `LANGUAGE_AUDIT_FUNCTION_MATRIX_YYYYMMDD.csv`, а сверка реестра использует `LANGUAGE_FUNCTION_MATRIX_YYYYMMDD.csv`. Старые отчёты в `docs/audit/` сохраняются. До создания каталога экспорта инструмент проверяет чтение исходных результатов. Поддерживаются PowerShell 7 и Windows PowerShell 5.

Файловые байты записываются в наблюдения. Для строк дополнительно сохраняются UTF-16-коды: отображение одиночных суррогатов в JSON и терминале само по себе не доказывает их сохранность.

Ограничения: отмена проверяется движком между операциями и не прерывает произвольный зависший CLR-вызов. Исполняемые семейства примеров выбираются консервативно по пути и тексту; файл с комментарием о `INPUT` тоже может быть пропущен. При расширении корпуса нужен пересмотр отбора. Наличие имени в тесте, справочнике или примере не доказывает проверку конкретной перегрузки: в CSV такая полнота явно помечена `UNVERIFIED_PER_OVERLOAD`.


## Снимок текущего реестра без исполнения старых сценариев

Команда `dotnet run --project scripts/language-audit/Axiom.LanguageAudit.csproj -- C:/Axiom --inventory-only` читает загруженный реестр и сохраняет inventory.json/matrix.md в `.artifacts/language-inventory-current`. Она не исполняет программы старого аудита и не заменяет исторические CSV в docs/audit. Семантическое покрытие каждой формы остаётся UNVERIFIED_PER_FORM; ссылки на старые дефекты вынесены в HistoricalIssue и не считаются текущим статусом BROKEN. Упоминания имён — только указатели для чтения исходника, не доказательство исполнения.

Для сверки с CLI сохраните его актуальный `metadata` в `.artifacts/language-inventory-current/cli-metadata.json`, затем выполните `python scripts/language-audit/export-current-inventory.py`. Скрипт сравнивает все сигнатуры и политики, сохраняет отдельную таблицу 20261008 и сводку сверки; исторические снимки 20261007 не заменяет. Указатели на CSV по ID без Arity требуют отдельной проверки формы. Перед повторным экспортом другой даты нужно изменить дату целевого снимка, чтобы сохранить историю.


## Экспорт снимка с явной датой

Начиная с Session 1180 команда экспорта требует `python scripts/language-audit/export-current-inventory.py --snapshot-date 20261009`. Сначала обновите inventory-only и метаданные CLI указанными выше командами. Экспорт собирает CSV доказательств всех дат до указанной включительно, сравнивает ID и при наличии Arity число аргументов. Снимки других дат сохраняются; повторный запуск той же даты обновляет только её CSV/JSON. Ссылки остаются кандидатами для проверки, а не подтверждением всех типов и границ.

Экспорт также отклоняет строки доказательств с неизвестной парой ID/Arity или именем, не соответствующим этой форме. Для перегрузок с overwrite используются отдельные зарегистрированные ID: CopyFileOverwrite, MoveFileOverwrite и CopyDirOverwrite.
