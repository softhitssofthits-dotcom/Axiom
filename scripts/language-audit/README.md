# Независимые проверки языка Axiom

Инструмент сохраняет исходные наблюдения и проверяет заранее заданные ожидания. Он не исправляет реализацию языка. Исходная проверенная ревизия — `2603b3d1fd2edea79a5bbe2cd392762836a961e5`.

Запуск из корня репозитория, последовательно с другими командами MSBuild:

```powershell
dotnet run --project scripts/language-audit/Axiom.LanguageAudit.csproj -- C:\Axiom
pwsh -File scripts/language-audit/Export-Audit.ps1
```

Путь после `--` должен указывать на текущий корень репозитория. Результаты и проверочные файлы создаются только в `.artifacts/language-audit-20261007/`. Файловые проверки очищают только собственные подкаталоги `fs-cases`, предварительно проверяя абсолютную границу каталога. Не запускайте два экземпляра инструмента одновременно: они используют одни проверочные файлы.

Для нового прогона без перезаписи исторического результата можно передать `--output-dir` с относительным каталогом внутри `.artifacts`, например:

```powershell
dotnet run --project scripts/language-audit/Axiom.LanguageAudit.csproj -- C:\Axiom --output-dir .artifacts/language-audit-20261010
```

Путь назначения проверяется: записывать результаты этой командой разрешено только внутри `.artifacts`.

Код завершения `1` означает расхождение с проверенным ожиданием или CLR-исключение. В исходной ревизии такие ошибки ожидаются: это инструмент воспроизведения, а не зелёный регрессионный набор. Сценарии без независимого ожидаемого результата сохраняются как наблюдения. Они не превращаются автоматически в дефекты.

- `Inventory.cs` читает реальный реестр, проверяет диспетчеры и повторяющиеся сигнатуры, сохраняет пути к коду, тестовым упоминаниям, примерам, справочнику и техническим метаданным подсветки. Полиморфные политики сохраняются отдельно от объявленного типа.
- `AuditCases.cs` проверяет числовые границы, Unicode, регулярные выражения, агрегаты, кодировки и свойства с фиксированным зерном `7012026`.
- `FileCases.cs` проверяет файловые операции и жизненный цикл дескрипторов в изолированных каталогах.
- `CoreCases.cs` проверяет приоритеты, процедуры, BYREF, TYPE, циклы и FINALLY.
- `SampleAudit.cs` компилирует весь корпус `.axm`. Автономные примеры запускаются в BytecodeVm, а файловые примеры — в отдельных копиях каталога `samples` внутри выбранного `.artifacts`; переменные `TEMP` и `TMP` на время такого запуска также направляются в копию. Примеры с графикой и ручным вводом, с абсолютными путями и с требующей подготовки ссылок Windows-сценарной фикстурой не запускаются, а получают точную причину пропуска. Фиксированные часы и генератор обеспечивают воспроизводимость. Успешный запуск без независимого ожидаемого результата не доказывает правильность вывода. Отрицательные примеры компиляции и времени выполнения учитываются отдельно.
- `Export-Audit.ps1` экспортирует подробные данные в `docs/audit/bytecode-only/` с текущей датой в именах. Матрица сценариев называется `LANGUAGE_AUDIT_FUNCTION_MATRIX_YYYYMMDD.csv`, а сверка реестра использует `LANGUAGE_FUNCTION_MATRIX_YYYYMMDD.csv`. Старые отчёты сохраняются в `docs/archive/`. До создания каталога экспорта инструмент проверяет чтение исходных результатов. Поддерживаются PowerShell 7 и Windows PowerShell 5.

Файловые байты записываются в наблюдения. Для строк дополнительно сохраняются UTF-16-коды: отображение одиночных суррогатов в JSON и терминале само по себе не доказывает их сохранность.

Ограничения: отмена проверяется движком между операциями и не прерывает произвольный зависший CLR-вызов. Отбор для исполнения по-прежнему требует проверки при появлении новых внешних действий в примерах. Наличие имени в тесте, справочнике или примере не доказывает проверку конкретной перегрузки: в CSV такая полнота явно помечена `UNVERIFIED_PER_OVERLOAD`.


## Снимок текущего реестра

Выполните последовательно из корня репозитория:

```powershell
dotnet run --project scripts/language-audit/Axiom.LanguageAudit.csproj -- C:/Axiom --inventory-only --output-dir .artifacts/language-inventory-current
dotnet run --project src/Axiom.Cli -c Release -- metadata > .artifacts/language-inventory-current/cli-metadata.json
python scripts/language-audit/export-current-inventory.py --snapshot-date 20261011
```

Экспорт сравнивает сигнатуры и политики CLI с реестром. Параметры `--inventory-dir` и `--output-dir` позволяют выбрать другой входной каталог и отдельный каталог экспорта внутри репозитория. Дата должна существовать в календаре. Повторный запуск той же даты обновляет её снимок.

Исторические CSV доказательств читаются из архива; ссылки остаются кандидатами для проверки конкретной формы. Наличие имени в тесте или примере не доказывает семантику всех перегрузок. Экспорт текущей матрицы исключает сведения об устаревших редакторских схемах подсветки; поддержку Monaco проверяет отдельный набор `ide/tests` и `ide/e2e`.

Последний сохранённый полный аудит от 10 октября: 449 сценариев, компиляция 763 примеров, нарушений утверждённых ожиданий нет. Эта ревизия документации повторяет сверку реестра, а не полный аудит. Текущие экспорты — `docs/audit/bytecode-only/`.
