# Исследование: алгоритмы классической Elite — справочник проекта (Этап 0)

**Назначение:** алгоритмический справочник для собственной реализации на Axiom. Источники использованы как исторический и алгоритмический справочник; **копирование кода, текстов, имён, моделей и наборов данных запрещено** (см. раздел «Правовые границы»). Реализация проекта — «чистая комната»: по описанным принципам и формулам, собственным кодом.

**Дата:** 2026-10-30. Исследование выполнено по первоисточникам: elite.bbcelite.com (документация и разбор исходников BBC Micro / 6502SP) и txtelite.c (richcarl/txtelite — порт-образец генерации систем и рынка).

## A. Модель полёта оригинала

Источники: [Pitching and rolling](https://elite.bbcelite.com/deep_dives/pitching_and_rolling.html), [Ship data blocks](https://elite.bbcelite.com/deep_dives/ship_data_blocks.html), [Rotating the universe](https://elite.bbcelite.com/deep_dives/rotating_the_universe.html), [A sense of scale](https://elite.bbcelite.com/deep_dives/a_sense_of_scale.html).

- Каждый объект: позиция (3 знако-модульных 24-битных числа) + три единичных вектора ориентации: **nosev** (нос), **roofv** (крыша), **sidev** (крыло). Скорость `DELTA` 1–40, ускорение `DELTA2` одноразовое.
- Управление — только pitch и roll (yaw нет). Поворот на фиксированный угол 1/16 радиана за шаг счётчика.
- Матрица поворота заменена приближением малых углов, совпавшим с алгоритмом кругов Минского (HAKMEM 149): `y = y - a*x; x = x + a*y; y = y - b*z; z = z + b*y`. Дрейф гасится рутиной TIDY (периодическая ортонормализация).
- Ключевой приём: **не корабль вращается, а «вращается вселенная»** — при pitch/roll игрока поворачиваются координаты всех объектов.
- Инерция аркадная: скорость сохраняется при отпускании клавиш; летит по прямой вдоль носа.
- Физический масштаб в оригинале намеренно не определён («A sense of scale» фиксирует противоречия) — в нашем проекте единицы — собственная условность.

## B. Преобразование координат и проекция

Источники: [Extended screen coordinates](https://elite.bbcelite.com/deep_dives/extended_screen_coordinates.html), [Calculating vertex coordinates](https://elite.bbcelite.com/deep_dives/calculating_vertex_coordinates.html), [Map of the source code](https://elite.bbcelite.com/6502sp/articles/map_of_the_source_code.html).

- Координаты кораблей хранятся относительно игрока; для планеты/солнца/станции вычитание позиции выполняется явно (VCSU1).
- Вершины переводятся в систему наблюдателя умножением на **транспонированную** матрицу ориентации (обратная ортогональной = транспонированная).
- Проекция перспективная: `screen_x = центр + k·x/z`, `screen_y = центр − k·y/z` (рутина PROJ, целочисленные деления DVID3B2).
- Экранные координаты — знаковые 16-битные «расширенные»: виртуальная сетка экранов 256×256; объект корректно рисуется частично за краем экрана.

## C. Отсечение

Источники: [Line-clipping](https://elite.bbcelite.com/deep_dives/line-clipping.html), [Drawing ships](https://elite.bbcelite.com/deep_dives/drawing_ships.html).

- Ближняя плоскость — в LL9 в два слоя: (1) корабль рисуется только если его центр впереди (z>0); (2) вершина за ближней плоскостью помечается «clipped», её экранные координаты вычисляются **параметрическим делением ребра**: `t = z_видимой / (z_видимой − z_скрытой)` — тот же принцип, что реализован в нашем `math3d.ProjectEdge`.
- Границы экрана отсекаются отдельно (LL145→LL118) поверх расширенных координат: быстрый отсев «оба конца за одним ребром», дробный градиент, сдвиг конца вдоль линии до границы.

## D. Каркасные модели (blueprints)

Источники: [Ship blueprints](https://elite.bbcelite.com/deep_dives/ship_blueprints.html), [Drawing ships](https://elite.bbcelite.com/deep_dives/drawing_ships.html).

- Три секции: **VERTEX** (координаты + знаки + дистанция видимости + до 4 примыкающих граней), **EDGE** (дистанция видимости, номера двух граней, номера двух вершин), **FACE** (знаки и модули нормали, масштабированной на 2^k, + дистанция).
- Отбор задних рёбер: грань видима, если нормаль направлена к нам (скалярное произведение); ребро видно, если видима хотя бы одна из двух его граней. Видимые рёбра складываются в «line heap» и отрисовываются.
- Упрощение для нашего этапа 1 (осознанное): храним только вершины и рёбра без нормалей — каркас «просвечивает»; back-face culling — кандидат в этап полировки.

## E. Звёзды (stardust)

Источник: [Stardust in the front view](https://elite.bbcelite.com/deep_dives/stardust_in_the_front_view.html).

- В оригинале это не карта неба, а **облако частиц** вокруг игрока с координатами относительно центра экрана; размер точки зависит от дистанции (эффект «линий скорости» при разгоне).
- Движение за кадр: приближение деления на 256 (сдвиг); «к нам»: `q = 64*speed/z_hi`, смещения пропорциональны расстоянию от центра; плюс члены roll/pitch.
- Наш этап 1 использует небесную сферу звёзд (проще, без параллакса); облако с заворачиванием по 3D-боксу — кандидат в этап полировки для ощущения скорости.

## F. Генерация галактики (для этапа 2)

Источники: [Galaxy and system seeds](https://elite.bbcelite.com/deep_dives/galaxy_and_system_seeds.html), [Twisting the system seeds](https://elite.bbcelite.com/deep_dives/twisting_the_system_seeds.html), [Generating system data](https://elite.bbcelite.com/deep_dives/generating_system_data.html), [Generating system names](https://elite.bbcelite.com/deep_dives/generating_system_names.html).

- Вселенная: 8 галактик × 256 систем из **одного 6-байтового семени** (три 16-битных числа), без RND и без хранения данных. Следующая система — «twist» (Tribonacci): `tmp = s0+s1; s0 = s1; s1 = s2; s2 = tmp+s1`.
- Галактический прыжок: циклический сдвиг каждого байта семени влево на 1; через 8 прыжков семена циклятся.
- Параметры системы из битов семян (формулы оригинала; у нас — свой вариант «приправ»):
  - координаты на карте: `x = s1_hi`, `y = s0_hi >> 1`;
  - правительство: биты 3–5 `s1_lo` (0..7); экономика: биты 0–2 `s0_hi` (0..7), при правительстве ≤1 экономика |= 2;
  - техуровень: `(экономика XOR 7) + (s1_hi AND 3) + (правительство+1)/2`;
  - население: `(техуровень*4 + экономика + правительство + 1) ×0.1 млрд`; производительность: `((экономика XOR 7)+3) * (правительство+4) * население * 8` MCR; радиус: `((s2_hi AND 15)+11)*256 + s1_hi` км.
- Имена: 3–4 диграммы из таблицы из 31 пары по индексу `s2_hi AND 31`, после каждой пары — twist. **Таблицу слогов, стартовые семена и имена не копировать** — своя таблица и свои константы.

## G. Экономика (для этапа 3)

Источники: [txtelite.c](https://github.com/richcarl/txtelite/blob/master/txtelite.c) (genmarket/gamebuy/gamesell), [Market item prices and availability](https://elite.bbcelite.com/deep_dives/market_item_prices_and_availability.html).

- 17 товаров; каждый: `{baseprice, gradient, basequant, maskbyte, units, name}`; единицы: тонны/кг/г; вместимость трюма считают только тонновые товары. Цены — целые в четвертях крéдица (внутренняя единица 0.1 CR).
- Генерация рынка (`genmarket(fluct, p)`), где `product = economy * gradient`, `changing = fluct AND mask`:
  - количество: `q = basequant + changing − product; q AND 0xFF; если старший бит — 0; финально q AND 0x3F`;
  - цена: `q = baseprice + changing + product; q AND 0xFF; price = q*4`;
  - товар Alien Items всегда с нулевым количеством.
- Асимметрия знаков: в количестве экономический член **вычитается**, в цене **прибавляется** — бедные аграрные системы дёшево производят и дорого покупают.
- Покупка/продажа по одной цене, без спреда: `t = min(доступно, трюм, cash/цена)`.
- Топливо: 0.2 CR за световой год, бак 7.0 LY. Рынок перегенерируется при прыжке с новым байтом колебаний.

## H. Радар-сканер (для этапа 2)

Источник: [The 3D scanner](https://elite.bbcelite.com/deep_dives/the_3d_scanner.html).

- Эллипс на панели; объект показывается при |x|,|y|,|z| ≤ 63·256. Проекция без перспективы:
  - горизонталь: `X1 = центр + x_hi`;
  - база «стика»: `SC = центр_y − z_hi/4` (z — вперёд/назад);
  - высота «стика»: `A = −y_hi/2` — пунктирный вертикальный стик от базы.
- Цвет стика — по типу корабля; огрубление делениями на 2 и 4 — сознательное.

## I. Бой (для этапа 4)

Источники: [Program flow of the tactics routine](https://elite.bbcelite.com/deep_dives/program_flow_of_the_tactics_routine.html), [In the crosshairs](https://elite.bbcelite.com/deep_dives/in_the_crosshairs.html).

- Попадание — геометрическое, без разброса: центр цели в прицеле, если `x_lo² + y_lo² < targetable_area` из blueprint. Тот же тест обслуживает ракеты.
- ИИ (TACTICS): состояния по энергии (лазеры/ракеты/паника), прицеливание скалярным произведением носа на вектор к цели, маневрирование по нормированному вектору на цель (сближение/отворот), вероятностные пуски, 2.5% случайного крена.
- Наши повреждения: щиты (заряд от энергии) → корпус; четыре банка энергии; E.C.M. тратит энергию.

## J. HUD (для этапа 5)

Источник: [The dashboard indicators](https://elite.bbcelite.com/deep_dives/the_dashboard_indicators.html).

- 11 полосных индикаторов одной рутиной (щиты ×2, топливо, температуры ×2, высота, скорость, 4 банка энергии); масштабы полос огрублены (например, скорость 0–40 в полосе 0–32).
- Отдельно: сканер, компас, ракеты, прицелы, статус-экран.

## K. Игровой цикл и состояния

Источник: [Program flow of the main game loop](https://elite.bbcelite.com/deep_dives/program_flow_of_the_main_game_loop.html).

- Два уровня: главный цикл (редкие вероятностные спавны + панель + клавиши) и полётный цикл из 16 частей (альфа/бета из pitch/roll, клавиши, для каждого корабля: тактика+движение, дистанции/стыковка/столкновения, наша стрельба, отрисовка; затем щиты/энергия, станция, звёзды).
- Второстепенные задачи планируются счётчиком MCNT. Состояния: полёт/док; доковые экраны: рынок, оборудование, карты, данные системы, статус.
