# Maze Chase — многомодульная игра

Это отдельная версия [исходной игры](../maze_chase.axm), разделённая по обязанностям. Карта, рисунок, правила и управление сохранены. Все исходники `.axm` лежат рядом; точка входа — [main.axm](main.axm). Отдельного файла проекта не требуется.

Откройте `main.axm` в Axiom IDE и запустите его. Для проверки из корня репозитория:

```powershell
.artifacts/bin/Axiom.Cli/Release/net10.0/axiom.exe check samples/graphics/game/maze_chase_project/main.axm --json
```

Игра использует собственную папку `art/` и собственный `maze_chase_pellet_calibration.txt`. Переносите всю папку целиком, а не только main. Абсолютных путей и требований к дополнительному диску нет. Рабочая папка запуска в IDE — папка main.

## Файлы и границы

| Файл | Ответственность | Основные открытые операции |
|---|---|---|
| [main.axm](main.axm) | Запуск, фиксированный шаг времени, пауза и выход | Точка входа, экспортов нет |
| [maze_config.axm](maze_config.axm) | Размеры, направления и единый TYPE Walker | Константы, Walker, DirX/DirY, MaxInt, ClampInt |
| [maze_world.axm](maze_world.axm) | Карта, стартовые клетки, точки и туннели | InitMaze, CellAt, CanMove, TakePellet, функции чтения состояния |
| [maze_calibration.axm](maze_calibration.axm) | Поправки координат, проверка файла и панель настройки | InitPelletAlignment, LoadPelletAlignment, ToggleCalibration, PelletPixelX/Y, DrawCalibrationOverlay |
| [maze_motion.axm](maze_motion.axm) | Общий шаг персонажа по ссылке | StepWalker, EntityPixelX/Y |
| [maze_player.axm](maze_player.axm) | Герой, клавиши и анимация | ResetPlayer, StepPlayer, GetPlayer, ResetPlayerAnimation |
| [maze_ghost.axm](maze_ghost.axm) | Призрак и поиск пути к переданной цели | ResetGhost, StepGhost, GetGhost |
| [maze_game.axm](maze_game.axm) | Очки, жизни, столкновение и победа | InitGame, UpdateGameStep, GameScore/Lives/Status/Finished |
| [maze_render.axm](maze_render.axm) | Изображения, спрайты, поле и HUD | LoadResources, ClearGameFrame, DrawMazeWorld, DrawHud |

Карта, таблицы поправок, ресурсы и переменные персонажей закрыты через PRIVATE. GetPlayer/GetGhost возвращают копии Walker; изменение копии не перемещает персонажа. StepWalker получает настоящий Walker по BYREF. Функция выбора направления передаётся значением и вызывается на каждой границе клетки: maze_motion не импортирует maze_ghost, поэтому цикла зависимостей нет.

Все потребители общего Walker прямо импортируют maze_config. Импорт одного модуля не переэкспортирует его зависимости. Код разделён русскими комментариями `#region` и `#endregion`; перед процедурами объяснены их назначение и значимые условия.

## Управление и калибровка

- Стрелки задают направление героя; SPACE включает и выключает паузу; ESC завершает игру.
- K переключает калибровку. В этом режиме симуляция не движет персонажей.
- C выбирает строки или столбцы; W/S выбирают номер; стрелки изменяют поправку выбранного номера.
- Строчная r дописывает выбранную поправку, строчная t сохраняет полный снимок таблицы. При повторяющихся строках старый дописанный файл не считается корректным полным снимком: для загрузки используйте полную запись t.

Сохранение изменяет только файл данных этой папки, не `.axm`. При отсутствии файла используются встроенные поправки. При некорректном, неполном или повторном определении строк внешняя таблица не применяется частично; сообщение появляется в HUD. Чтобы сохранить исходную поставляемую таблицу при экспериментах, сначала скопируйте папку игры в другое место.

Соседний `maze_chase_apply_calibration.axm` относится к монолиту: он переписывает процедуру в `maze_chase.axm`. Для этого проекта он не нужен; здесь файл данных загружается автоматически.

## Помощник и левая панель

1. Откройте main и выберите его общей точкой входа помощника.
2. Откройте maze_motion, выберите StepWalker и запросите входящие связи: вызовы находятся в StepPlayer и StepGhost разных файлов.
3. В maze_player поставьте каретку на вызов StepWalker и нажмите F12: откроется объявление в maze_motion. Shift+F12 на Walker показывает употребления общего типа, включая другие модули.
4. Переключайте файлы: левая панель показывает объявления и русские разделы активного файла. Помощник анализирует достижимую по IMPORT программу; соседние посторонние файлы не включаются автоматически.

Граф отмечает вызов функционального параметра StepWalker как косвенный и сообщает о неполноте статического графа. Это не ошибка компиляции: цель произвольного функционального вызова заранее не определена. Передача ChooseGhostDirection отображается отдельной ссылкой на функцию.

Выбор точки входа помощника не меняет кнопку запуска: перед запуском активируйте main. Отладка поддерживает переход в зависимость и маркер на её исходнике; несохранённые правки участвуют в новом снимке программы, но не изменяют уже запущенную сессию.

## Проверки примера

Адресная команда .NET из корня:

```powershell
dotnet test tests/Axiom.Execution.Tests --filter "FullyQualifiedName~MazeChase|FullyQualifiedName~Module" --nologo
node ide/e2e/runner.js maze-project --out .artifacts/maze-chase-modules/e2e.json
```

Проверки сравнивают обе игры, включая расположение первого кадра, паузу, калибровку и движение. Отдельные ожидания проверяют PRIVATE, нетранзитивный импорт, общий Walker/BYREF, туннели и стены, повторный сбор точки, атомарное принятие таблицы и восстановление байт-кода с функциональным параметром. Поиск пути сравнивается с исходником на 120 шагах. Сценарии Electron проверяют настоящую игру, помощник, список процедур, F12, ссылки, несохранённые тексты и отладку закрытой зависимости.
