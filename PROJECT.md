# PROJECT.md

## Project name
Axiom IDE

## Project type
Desktop app + language runtime + IDE

## One-sentence summary
Собственная IDE и интерпретируемый BASIC-подобный язык на C# в духе QuickBASIC, но с более чистой и современной архитектурой.

## Problem
Существующие BASIC-подобные проекты либо слишком старые, либо завязаны на чужую историческую совместимость, либо неудобны как база для собственной IDE и дальнейшего развития языка. Нужна своя управляемая кодовая база, в которой язык, интерпретатор и IDE развиваются вместе.

## Goal
Готовый продукт должен позволять пользователю писать программы на собственном BASIC-подобном языке, запускать их из своей IDE, видеть подсветку синтаксиса, сообщения об ошибках и постепенно расширять язык новыми возможностями.

## Target users
- основной пользователь: автор проекта;
- далее: разработчики и энтузиасты, которым интересен современный BASIC-подобный язык с собственной IDE;
- дополнительная аудитория: пользователи, которым близка эстетика QuickBASIC, но нужен современный стек и собственная расширяемая реализация.

## Объём продукта
- полноценный интерпретируемый BASIC-подобный язык;
- лексер, парсер, синтаксическое дерево и семантическая проверка;
- интерпретатор для запуска программ;
- настольная IDE на C#;
- редактор кода с подсветкой синтаксиса и навигацией;
- панель вывода;
- панель ошибок и диагностик;
- загрузка и сохранение исходных файлов;
- запуск программы из IDE;
- постепенное расширение языка, среды и справочника до состояния готового повседневного продукта.

## Отдельно проектируемые направления продукта
- совместимость с QuickBASIC 4.5 там, где она полезна продукту;
- компиляция в exe или native code;
- графические команды языка;
- расширенная файловая подсистема языка;
- отладчик с точками останова;
- автодополнение, навигация по коду и рефакторинг;
- система проектов из множества модулей;
- классы, объекты, указатели;
- другие платформы, если они будут отдельно спроектированы.

## Functional requirements
- пользователь может открыть, создать, редактировать и сохранить файл программы;
- система разбирает исходный код на токены;
- система строит синтаксическое дерево;
- система проверяет семантику программы;
- система показывает понятные ошибки с координатами;
- пользователь может запускать программу из IDE;
- система показывает вывод `PRINT`;
- система поддерживает `DIM`, `CONST`, присваивания, арифметику, сравнения и логические операции;
- система поддерживает `IF / ELSE / END IF`;
- система поддерживает `FOR / NEXT`;
- система поддерживает `WHILE / END WHILE`;
- система поддерживает `SUB`, `FUNCTION`, `RETURN`;
- система поддерживает одномерные массивы;
- система поддерживает `PRINT`, `INPUT` и базовые встроенные функции.

## Non-functional requirements
- простая и поддерживаемая архитектура;
- минимально необходимое количество зависимостей;
- понятное разделение слоёв: lexer/parser/semantics/runtime/IDE;
- маленькие и проверяемые изменения;
- обязательная актуализация документации при изменении поведения;
- проект должен запускаться локально на Windows в первую очередь;
- код должен быть пригоден для дальнейшего расширения языка.

## Preferred stack
- language/runtime: C# / .NET
- IDE: C# desktop app
- UI: WPF (предпочтительно) или WinForms, если это явно подтверждено в документации
- storage: локальные текстовые `.axm` файлы
- tests: .NET test project
- stack note: стартуем с интерпретатора, не с компилятора

## Data / integrations
- внешние API не требуются для локального ядра продукта;
- хранение исходников в локальных файлах;
- опционально: локальная конфигурация IDE в JSON на более позднем этапе.

## Repository expectations
- `src/` для исходного кода;
- `tests/` для тестов;
- `docs/` для документации проекта;
- отдельные подпроекты для core, lexing, parsing, semantics, runtime и IDE.

## UX / UI expectations
- desktop-first интерфейс;
- тёмная тема желательна, но не обязательна для самого первого шага;
- простой читаемый редактор;
- отдельные панели для вывода и ошибок;
- минимум визуального мусора;
- сначала функциональность, потом украшательство.

## Constraints
- не ограничивать продукт старой рамкой первой версии;
- не уходить в полную совместимость с QuickBASIC без отдельного проектного решения;
- не делать компилятор в exe до стабилизации языка и явного архитектурного решения;
- не добавлять legacy-фичи без явного решения в документации;
- не раздувать IDE раньше времени;
- не генерировать лишний boilerplate без необходимости.

## Risks / unknowns
- окончательный выбор UI-стека IDE (WPF или WinForms) ещё может потребовать фиксации;
- выбор редакторного компонента для подсветки может повлиять на архитектуру IDE;
- набор встроенных функций языка может уточняться;
- формат диагностики может потребовать отдельной стабилизации;
- спецификация может корректироваться по мере роста языка, интерпретатора и IDE.

## First implementation goal
- создать начальную структуру solution на C#;
- завести проекты для core, lexing, parsing, syntax, semantics, runtime и IDE;
- зафиксировать скелет доменных типов и базовые документы;
- не начинать большие фичи IDE до появления работающего ядра языка.
