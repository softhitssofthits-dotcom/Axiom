# Готовый набор проверок новой Electron IDE

## Источник для продолжения работы

Набор хранится в этом репозитории GitHub: https://github.com/softhitssofthits-dotcom/Axiom/tree/master/ide/e2e . На 11 октября 2026 года каталог содержит **77 сценариев в 27 файлах**. Проверки сохранности документов, пустых новых документов, прокрутки вкладок и темы QuickBASIC добавлены в существующие files.spec.js и documents.spec.js; тесты и каталог передаются вместе с исправлениями обычным коммитом и push. Продолжать работу нужно с этих файлов, без повторного создания уже существующих тестов.

- `specs/*.spec.js` — исполняемые сценарии новой IDE.
- `runner.js` — последовательный запуск всех сценариев либо выбранного файла/идентификатора.
- `helpers.js`, `isolation.cjs` — общая автоматизация и изолированные профили.
- `SCENARIOS.json` — полный опубликованный каталог: идентификатор, файл, название каждого сценария.
- `package.json`, `package-lock.json` — команды и закреплённые зависимости Playwright.
- `evidence/` — сохранённые результаты отдельных этапов. `results.json` содержит последний выбранный прогон и сам по себе не доказывает прохождение всего набора.

## Что входит

Запуск Electron, редактор Monaco, файлы и сохранение, меню, панели, оформление, русская/английская локализация, подсветка, форматирование, навигация, диагностика, выполнение, INPUT, отладка, CANVAS, SCREEN, клавиатура/мышь, повтор запусков, закрытие и отказы процессов.

Runner загружает только `ide/e2e/specs/*.spec.js`. Он не вызывает `dotnet test`, старую WPF-оболочку, `Axiom.Ide.SmokeHarness` или набор `tests/Axiom.Ide.Tests`. Эти старые наборы не входят в данный каталог и команду запуска.

DesktopHost и CLI — необходимые служебные компоненты новой оболочки. DesktopHost использует общие службы .NET и создаёт нативное окно SCREEN; это не запуск старой IDE. CANVAS отображается в Electron. Проверки языка и служебных компонентов здесь выполняются через действия новой IDE.

## Подготовка на другом компьютере

Требуется Windows с доступным интерактивным рабочим столом, Node.js/npm и .NET SDK 10. Получите актуальный master обычным способом Git. Выполните из корня своей копии репозитория последовательно:

```powershell
npm ci --prefix ide
npm ci --prefix ide/e2e
dotnet build src/Axiom.Cli -c Release
dotnet build src/Axiom.DesktopHost -c Debug
```

Установка зависимостей IDE выполняет prepare и копирует Monaco. Сценарии используют Electron из зависимостей IDE; отдельный браузер Playwright для этого набора устанавливать не требуется. Бинарные сборки и node_modules не публикуются: на новом компьютере необходима установка зависимостей и локальная сборка приложения, но исходные тесты уже готовы и не требуют повторного написания.

Не выполняйте несколько .NET-сборок одновременно с общим obj. Графические и процессные сценарии выполняйте последовательно на интерактивном рабочем столе; обычный сервер без пользовательского сеанса не считается эквивалентной приёмкой SCREEN.

## Просмотр и запуск

Просмотр всех готовых сценариев без запуска Electron и проверки бинарных сборок:

```powershell
node ide/e2e/runner.js --list
```

Полный набор новой IDE:

```powershell
npm --prefix ide/e2e test
```

Отдельная область или конкретный сценарий:

```powershell
node ide/e2e/runner.js input-prompts.spec.js
node ide/e2e/runner.js graphics-renderer-crash
```

Код выхода 0 означает успешное завершение выбранного прогона; ненулевой код означает провал. Результат записывается в `ide/e2e/evidence/results.json`; при провале создаётся снимок в evidence/shots. Исходники проверочных программ создаются в .artifacts, настройки тестовой IDE изолированы от пользовательского профиля. Не запускайте несколько экземпляров этого runner параллельно: общий файл результата будет перезаписан.

## Как следующий агент должен продолжать

1. Прочитать AGENTS.md, обязательные документы проекта и последние разделы WORKLOG5.md/PLANS4.md.
2. Открыть этот документ и SCENARIOS.json; найти уже существующий сценарий по области задачи.
3. Использовать или дополнить существующую проверку. Не пересоздавать набор и общую автоматизацию.
4. Запустить подходящий файл; полный набор использовать для общей приёмки по поручению пользователя.
5. При добавлении сценария обновить каталог:

```powershell
node ide/e2e/runner.js --list > ide/e2e/SCENARIOS.json
```

6. Записать выполненные проверки, ограничения и точку продолжения, затем сделать коммит и push завершённого этапа.
