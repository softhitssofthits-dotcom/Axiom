# План: подсветка выражений внутри `{}` интерполированных строк `$"..."` без поломки комментариев

## Причина проблемы

В AvalonEdit движок подсветки проверяет **начала Span раньше Rule** и дополнительно ограничивает совпадения Rule будущими началами Span: Rule, чьё совпадение «накрывает» позицию будущего начала Span, отбрасывается. Поэтому попытка 85e8f38 (Span для `$"..."` при комментариях-Rule) сломала `' PRINT $"..."`: Rule-комментарий начинался на позиции 0, но тянулся до конца строки «через» начало Span `\$"` на позиции 8 и проигрывал. Официальные режимы AvalonEdit (C#, VB) решают это тем, что **комментарии и строки — тоже Span**, размещённые первыми в RuleSet.

## Решение (только xshd, обе темы, движок не трогаем)

Перестроить оба xshd по канонической схеме AvalonEdit:

```xml
<RuleSet ignoreCase="true">
    <!-- 1. Комментарии — Span (multiline=false, без End → до конца строки), размещены ПЕРВЫМИ -->
    <Span color="Comment" multiline="false"><Begin>'</Begin></Span>
    <Span color="Comment" multiline="false"><Begin>\bREM\b</Begin></Span>

    <!-- 2. Интерполированная строка — многострочный Span (лексер разрешает переводы строк) -->
    <Span color="String" multiline="true">
        <Begin color="Interpolation">\$&quot;</Begin>   <!-- `$"` остаётся фиолетовым, как сейчас -->
        <End>(?&lt;!\\)&quot;</End>                      <!-- `\"` не закрывает строку (лексер: `\`-экранирование) -->
        <RuleSet ignoreCase="true">
            <!-- Дырка {выражение}: `{{` и `\{` не открывают дырку (лексер считает их литералами);
                 multiline=false — незакрытая `{` не раскрашивает хвост файла -->
            <Span color="InterpolationText" multiline="false">
                <Begin color="Interpolation">(?&lt;![\\{])\{(?!\{)</Begin>
                <End color="Interpolation">\}</End>
                <RuleSet ignoreCase="true">
                    <!-- вложенный обычный строковый литерал: {LEN("слово")} — `}` внутри него не закрывает дырку -->
                    <Span color="String" multiline="false"><Begin>&quot;</Begin><End>&quot;</End></Span>
                    <Import ruleSet="Code"/>
                </RuleSet>
            </Span>
        </RuleSet>
    </Span>

    <!-- 3. Обычная строка — Span (вместо Rule: защита `'` внутри "it's" от комментария-Span; `""`-удвоение красится корректно) -->
    <Span color="String" multiline="false"><Begin>&quot;</Begin><End>&quot;</End></Span>

    <Import ruleSet="Code"/>
</RuleSet>

<!-- 4. Слова и числа — в именованный RuleSet, чтобы не дублировать ~340 слов в дырке -->
<RuleSet name="Code" ignoreCase="true">
    <Rule color="Number">\b\d+(\.\d+)?\b|&amp;H[0-9A-F]+\b</Rule>
    <Rule color="Operator">&lt;&lt;|&gt;&gt;|&lt;&gt;|&lt;=|&gt;=|:=|[-+*/\\^=&lt;&gt;&amp;]</Rule>
    <Keywords color="Keyword">…переносятся дословно…</Keywords>
    <Keywords color="TypeName">…</Keywords>
    <Keywords color="BuiltIn">…</Keywords>
</RuleSet>
```

- Новый цвет `InterpolationText` (содержимое дырки = «обычная подсветка», идентификаторы без окраски): светлый `#000000`, тёмный `#D4D4D4` (как Operator). Скобки `{`/`}` и `$"` — существующий `Interpolation`.
- Regex Number/Operator и все `<Word>` переносятся **дословно** — тесты `Assert.Contains` по сырому XML должны проходить без правок.
- Подтверждено по исходникам V2Loader AvalonEdit: `<Begin color>/<End color>`, `<Import ruleSet>`, именованные RuleSet поддержаны; `multiline` по умолчанию `false`.
- Почему это не ломает комментарии: на позиции `'`/`REM` первым матчится Span-комментарий и съедает строку целиком до EOL, включая любой `$"..."`; внутри самой строки действует RuleSet строки, где комментария нет; внутри дырки — RuleSet дырки, тоже без комментария (`{x ' y}` — валидное выражение, `'` там не комментарий).

## Новые тесты (реальный движок через DocumentHighlighter)

Использовать публичный `ICSharpCode.AvalonEdit.Highlighting.DocumentHighlighter(new TextDocument(код), definition)` → `HighlightLine(1).Sections` и ассертить `(Offset, Length, Color.Name)`. Ключевые кейсы (светлая тема + дубль/параметризация для тёмной):

- `Highlighting_CommentRuleWinsOverInterpolatedString` — `' PRINT $"Привет, {name}!"` → вся строка `Comment`;
- `Highlighting_RemCommentRuleWinsOverInterpolatedString` — `REM PRINT $"{a}"` → вся строка `Comment`;
- `Highlighting_InterpolatedStringTextColoredAsString` — `PRINT $"Текст"` → `$"` = Interpolation, текст = String;
- `Highlighting_InterpolationHoleHighlightsExpression` — `PRINT $"Сумма: {a + 1}"` → `{`,`}` = Interpolation, `a` = InterpolationText, `+` = Operator, `1` = Number;
- `Highlighting_InterpolationHoleHighlightsBuiltInAndNestedString` — `PRINT $"Длина: {LEN("слово")}"` → LEN = BuiltIn, `"слово"` = String;
- `Highlighting_DoubleBraceStaysStringText` — `$"a{{b"` → `{{` не открывает дырку, всё String;
- `Highlighting_EscapedQuoteDoesNotEndInterpolatedString` — `PRINT $"a\"b" ' комм` → строка заканчивается на `b"`, хвост — Comment;
- `Highlighting_ApostropheInsidePlainStringStaysString` — `PRINT "it's"` → вся строка String (регрессия для комментария-Span);
- `Highlighting_PlainStringFollowedByComment` — `PRINT "x" ' комм` → String, затем Comment;
- `Highlighting_MultilineInterpolatedStringContinues` — строка с переводом строки;
- структурный тест: `MainRuleSet.Spans` начинается с двух Span-комментариев, есть вложенный Span дырки, `GetNamedColor("Interpolation")` и `("InterpolationText")` не null (расширить существующие тесты именованных цветов).

Если `DocumentHighlighter` окажется непригоден в xUnit-контексте — запасной вариант: ассерты по структуре `definition.MainRuleSet` (порядок Spans, вложенность, Rules).

## Известные принимаемые ограничения (косметика, согласована с лексером)

- `...\\"` (экранированный бэкслеш + закрывающая кавычка): упрощённый lookbehind `(?<!\\)"` продолжит подсветку строки чуть дальше лексера; при желании усиливается до `(?<!\\(?:\\\\)*)"`.
- `x$"..."` (`$` сразу после идентификатора) красится как интерполяция — так же, как и сегодняшним Rule.
- Вложенные `$"` внутри дырки не подсвечиваются рекурсивно (лексер их фактически тоже не поддерживает).
