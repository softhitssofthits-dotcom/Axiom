# Версии языка, компилятора и IDE

## Источник номеров

`versions.json` в корне задаёт три независимых номера `MAJOR.MINOR.PATCH`: `language`, `compiler`, `ide`. Нумерация начата заново с 0.1.0 на опубликованном состоянии c5b21d8. Версия 0 означает начальную разработку; 1.0.0 объявляется автором отдельно. Исторические номера не перенумеровываются.

Подход перенят из решения D65 проекта X# (`C:\X__sharp`): повышение после завершённого изменения, согласованные номера в коде и документах, обязательная автоматическая проверка. В Axiom номера IDE и компилятора независимы, чтобы исправление интерфейса не меняло номер языка.

Основа формата — [семантическое версионирование](https://semver.org/lang/ru/). Во время разработки до 1.0 действует проектное уточнение: небольшие добавления и завершённые правки получают PATCH; новая подсистема или несовместимое изменение получают MINOR. Несовместимость явно описывается в истории версий. После 1.0 совместимые новые возможности повышают MINOR, несовместимые — MAJOR.

## Когда повышать

| Изменение | Какие номера повышать |
|---|---|
| Синтаксис, семантика, операторы, функции, языковые диагностики, исполнение | Язык и компилятор |
| CLI, сборка/поставка компилятора без изменения языка | Компилятор |
| Редактор, темы, консоль, окна, сохранение, DesktopHost и обмен с IDE | IDE |
| Изменение языка вместе с поддержкой в редакторе | Язык, компилятор и IDE |
| Правка справочника без изменения реализации языка или компилятора | Повышение не требуется |
| Изменение запускаемых примеров языка | Язык и компилятор |
| Прочие действующие документы и инструменты | Затронутый компонент; для общих правил проекта — IDE |
| Только запись результатов проверок, журнал сессии или исторический архив | Повышение не требуется |

Одна завершённая задача получает одно повышение затронутых компонентов. Внутренние попытки исправления и повторные сборки не повышают версию. Несколько законченных независимых задач получают отдельные записи и повышения, даже если коммит общий. Рефакторинг в языковом ядре также повышает язык и компилятор: автоматическая проверка намеренно использует консервативное сопоставление путей. Версия формата байт-кода — отдельный технический договор; её нельзя менять автоматически вместе с версией продукта.

## Команды агента

Перед работой прочитать этот документ, `versions.json` и последнюю запись [CHANGELOG.md](CHANGELOG.md). После реализации и перед завершением задачи:

```powershell
# Исправление интерфейса: 0.1.0 -> 0.1.1.
node scripts/versioning.mjs bump ide patch "Описание исправления"

# Изменение языка повышает одновременно язык и компилятор.
node scripts/versioning.mjs bump language patch "Описание изменения языка"

# Новая подсистема во всех компонентах.
node scripts/versioning.mjs bump all minor "Название подсистемы"

node scripts/versioning.mjs check
node scripts/versioning.mjs check --base HEAD
```

Команда `bump` обновляет `versions.json`, созданные из него `Versions.props` и `src/Axiom.Core/AxiomVersionInfo.cs`, версии `ide/package.json` и обе записи `ide/package-lock.json`, затем добавляет запись в конец CHANGELOG с московской датой и временем. Уточнить запись: что изменилось, какие формы/диагностики добавлены, есть ли несовместимость. В WORKLOG указать итоговые номера и границы выполненных проверок. Нельзя закрывать задачу с изменением поведения без повышения версии.

`sync` восстанавливает производные файлы из `versions.json`, но сам номер не повышает и не заменяет запись в CHANGELOG. Производные файлы вручную не редактировать. После повышения пересобрать изменённые .NET-компоненты; повторная сборка не является новой версией.

## Защита от пропуска

`check` сверяет формат номеров, созданные файлы .NET, npm и последнюю запись CHANGELOG. `check --base <ревизия>` дополнительно сопоставляет изменённые пути с затронутыми компонентами и запрещает уменьшение или отсутствие повышения.

Обработчик `.githooks/pre-commit` выполняет `check --staged`: проверяет именно подготовленный к коммиту набор, а не более новые правки рабочей папки. На новом компьютере подключить его:

```powershell
node scripts/versioning.mjs install-hooks
```

Подключение выполняет также `npm --prefix ide run prepare`. Существующие пользовательские обработчики Git не перезаписываются: при другой настройке `core.hooksPath` команда сообщает, что проверку нужно подключить к ним. Проверка перед запуском IDE контролирует согласованность номеров. GitHub Actions проверяет согласованность и повышение относительно исходной ревизии при push и pull request.

Проверка путей не может определить смысл изменения и выбрать степень PATCH/MINOR за автора. Она также не доказывает правильность программы. Агент обязан выбрать степень повышения, описать изменение и выполнить разрешённые проверки реализации. Обход Git-обработчика не отменяет правила проекта.

## Что видит пользователь

«Справка → О программе» показывает три строки: версия IDE, язык Axiom, компилятор/CLI. Номера языка и компилятора берутся из метаданных реально запускаемого `axiom.exe`, номер IDE — из её пакета. Если CLI недоступен или устаревшая сборка не сообщает номера, выводится «не найден», а не выдуманная версия. Git-ревизия остаётся служебным полем метаданных для проверки свежести сборки и не выводится в окне «О программе».

## Уточнение по решению автора — 2026-10-13

Исправление текста, синтаксических схем, примеров в тексте и оформления справочника само по себе не меняет версии языка, компилятора или IDE. Версии повышаются при изменении соответствующей реализации; справочник обновляется вслед за ней в той же задаче. Изменение правил версионирования и их автоматической проверки также не требует повышения продуктовых версий. Уже опубликованные номера не понижаются.

При проверке редакционной задачи вместе со справочником учитываются его генераторы и сопровождающие записи в плане, журнале, отчётах и реестрах покрытия. Эти записи сами по себе не превращают правку справочника в изменение продукта. Исключение применяется только к набору правок справочника и перечисленных сопутствующих файлов; изменение реализации языка или IDE по-прежнему требует повышения, а посторонние инструменты под это исключение не подпадают. Проверка `--staged` учитывает только подготовленный к коммиту набор.
