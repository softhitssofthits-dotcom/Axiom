# Отложенные и будущие задачи

Этот файл нужен для тем, которые важно не потерять между сессиями, но которые не должны смешиваться с активным ближайшим шагом в `docs/PLANS3.md`.

Правило ведения:
- новые записи добавляются только в конец файла;
- каждая запись должна явно говорить, что именно отложено, почему это не делается сейчас и что будет критерием возврата к теме;
- если тема становится активной работой текущего шага, она должна дополнительно появиться в `docs/PLANS3.md`, но старая запись из этого файла не удаляется.

## Отложено - 2026-05-14 - прокрутка и перенос текста в SCREEN 0

Контекст:
- после реализации прозрачного текстового фона `COLOR ..., TRANSPARENT` был отдельно пересмотрен вопрос автопереноса и прокрутки экранного текста;
- для графических режимов `SCREEN 1..10` текущий договор с жёстким клиппингом признан правильным: он лучше подходит для HUD, подписей, строк состояния и текста поверх графики;
- для текстового режима `SCREEN 0` вертикальная прокрутка в будущем выглядит полезной, но сейчас её не нужно смешивать с графическим развитием.

Решение:
- не вводить сейчас ни автопрокрутку, ни word wrap как общий договор для всех `SCREEN`;
- для `SCREEN 1..10` сохранить текущее поведение: без автопереноса, без автопрокрутки, текст за правой и нижней границей не отображается;
- для `SCREEN 0` позже рассмотреть отдельный договор только вертикальной прокрутки;
- `word wrap` не планировать как ближайший шаг: он хуже сочетается с `LOCATE`, перезаписью ячеек и BASIC-моделью экранного текста.

Ожидаемый будущий договор для `SCREEN 0`:
- при выводе новой строки за нижнюю границу экран прокручивается вверх на одну текстовую строку;
- верхняя строка удаляется, остальные строки смещаются вверх, нижняя строка очищается;
- `LOCATE` и явная адресная перезапись продолжают работать по ячейкам без скрытого word wrap;
- `INPUT` использует тот же экранный текстовый договор, что и обычный `PRINT`.

Когда возвращаться к теме:
- после следующего самостоятельного графического среза;
- или раньше, если появится явный пользовательский запрос именно на консольное поведение `SCREEN 0`.

Пользователь выбрал именно договор прокрутки `SCREEN 0` как следующий отдельный шаг.

Состояние:

- активный следующий шаг перенесён в `docs/PLANS3.md`;
- старая запись остаётся здесь как историческое объяснение, почему прокрутка не смешивалась с предыдущим графическим срезом.
