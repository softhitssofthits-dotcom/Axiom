# План внедрения общего слоя ввода для IDE, runtime и будущих функций

## Кратко

Вводим внутренний слой снимка ввода: IDE и окно `SCREEN` записывают события клавиатуры/мыши в общую потокобезопасную структуру, а runtime читает её без постоянных обращений к WPF `Dispatcher`.

Публичная семантика языка не меняется. Новые функции и операторы клавиатуры/мыши в будущем обязаны использовать этот слой, а не обращаться напрямую к IDE/WPF.

## Ключевые изменения

- Добавить внутренний runtime-input слой:
  - очередь клавиш;
  - состояние удержанных клавиш;
  - очередь событий мыши;
  - последние координаты мыши;
  - состояние кнопок мыши;
  - быстрые флаги `SCREEN`.

- Перевести `ProgramConsoleService` на правило «UI пишет, runtime читает»:
  - обработчики WPF/Win32 обновляют общий снимок;
  - `ReadKey`, `IsKeyDown`, `ReadMouseEvent`, `GetMouseX/Y`, `IsMouseButtonDown`, `IsScreenActive` читают готовое состояние без `Dispatcher.Invoke`;
  - потокобезопасность обеспечить через `lock` или атомарные поля.

- Зафиксировать архитектурное правило:
  - все текущие и будущие функции/операторы клавиатуры и мыши работают только через общий runtime-input слой;
  - прямой доступ новых runtime-функций к WPF, `ProgramConsoleService` внутренностям или native-окну запрещён;
  - IDE остаётся поставщиком событий, но не исполняющей логикой ввода.

- Сохранить текущие быстрые пути:
  - если нет `ON KEY`, не читать клавиатурную очередь на границах операторов;
  - если нет `ON MOUSE`, не читать мышиную очередь на границах операторов;
  - обычные вычислительные программы не платят за ввод.

- Уточнить потребности программы:
  - `BytecodeVm` и интерпретатор используют существующие признаки наличия обработчиков;
  - при необходимости добавить внутренние флаги `UsesKeyboardInput`, `UsesMouseInput`, `UsesScreen`, но без изменения языка.

## Проверки

- Runtime:
  - `INKEY`, `KEYDOWN`, `KEYPRESS`, `ON KEY` сохраняют прежнее поведение;
  - `MOUSEX`, `MOUSEY`, `MOUSEBUTTON`, `MOUSEPRESS`, `ON MOUSE` сохраняют прежнее поведение;
  - программы без обработчиков не вызывают host-опрос ввода на границах операторов.

- IDE:
  - чтение клавиш, мыши и состояния `SCREEN` с runtime-потока не требует `Dispatcher.Invoke`;
  - ввод из `Output` и окна `SCREEN` попадает в общий слой;
  - закрытие окна `SCREEN` по-прежнему отменяет запуск.

- Производительность:
  - повторить `samples/smoke/repair_plans_mojibake.axm` в `Bytecode` и `Interpreter`;
  - вручную проверить интерактивный `SCREEN` sample с клавиатурой и мышью;
  - при добавлении отдельного производительного сценария обновить `docs/BYTECODE_PERF_MATRIX.md`.
