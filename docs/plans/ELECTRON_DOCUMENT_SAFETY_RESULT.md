# Сохранность документов Electron — Session 1355

## Исправленный случай

При подтверждённой перезагрузке внешнего файла ответ чтения мог прийти после новой правки редактора. Прежний обработчик заменял текст и снимал признак несохранённых изменений. Сценарий files-external-reload-preserves-new-edit до исправления провалил оба утверждения: PRINT 99 заменился на PRINT 2, документ стал считаться сохранённым.

Теперь handleExternalChange сохраняет ссылку на запись документа, documentId, revision и путь. Ответ применяется только к тому же открытому снимку. Правка, закрытие/повторное открытие или переименование отклоняют ответ. Запрос остаётся активным до окончания чтения; finally освобождает его и при отказе. Форматирование и договор языка не менялись.

## Повторение и продолжение

Подготовка описана в ide/e2e/README.md. Из корня выполнить последовательно:

```powershell
node ide/e2e/runner.js files.spec.js
node ide/e2e/runner.js save.spec.js
node ide/e2e/runner.js documents.spec.js
node --test ide/tests/document-save.test.cjs ide/tests/documents.test.cjs ide/tests/document-services.test.cjs
```

Следующий участок сохранности: конфликт внешнего изменения непосредственно перед сохранением, отсутствующий файл без локальных правок и повторные внешние записи во время чтения. Этот этап не доказывает защиту от всех гонок файловой системы и не реализует автоматическое восстановление несохранённых моделей после аварии. Бесконечное зависание, аппаратные DPI/мониторы и физическая мышь SCREEN остаются открытыми; проектное дерево отложено.
