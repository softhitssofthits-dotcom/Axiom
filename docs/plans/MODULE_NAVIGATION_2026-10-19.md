# Межфайловые связи подпрограмм — план реализации

Продолжение Session 1566. Пользователь поручил продолжить согласованный этап навигации.

## Договор и границы

Граф строится из связанного дерева всех достижимых IMPORT с тем же приоритетом открытого текста, что у проверки и запуска. Идентичность подпрограммы включает документ и позицию, связи содержат документ места вызова. Для каждого модуля отдельно показывается основной код. Переход открывает нужный файл; перед применением координат сравнивает его текст с исходным снимком. Изменение открытой зависимости делает панель устаревшей. Косвенные вызовы остаются явно неполными.

Первый законченный шаг — граф и переходы к объявлениям/местам использования подпрограмм через существующую панель. Универсальные переходы по переменным и типам и переименование требуют отдельного индекса символов и следуют после этого шага.

## Проверяемые шаги

1. Добавить адресные тесты EditorCallGraph: импорт, два закрытых одинаковых имени, основной код зависимостей, неполный импорт. Подключить исходник проекции к тестовому проекту, не добавляя зависимость от исполняемого Host.
2. Расширить EditorCallGraph параметрами документа и зависимостей; связывать через Binder.BindModules, разделить основные узлы, сохранить пути и тексты снимка. DocumentCommands передаёт SourceProject.LoadDependencies.
3. ProgramAssistant выбирает текущую подпрограмму по документу, открывает закрытые файлы и проверяет исходный текст перед переходом; показывает файл рядом с координатами и проверяет актуальность всего снимка.
4. Добавить настоящий сценарий Electron для открытой несохранённой зависимости, одноимённых закрытых функций, перехода в закрытый файл и возврата.
5. Выполнить адресные .NET и Electron проверки, обновить документацию и журнал, повысить только IDE, проверить версии. Без коммита и push до отдельного поручения.
