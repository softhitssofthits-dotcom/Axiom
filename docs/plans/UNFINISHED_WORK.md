# Что осталось сделать в Axiom

Актуализация 21 октября 2026 года. Текущая пятёрка работ по стабильности приведена в последнем разделе и в [отдельном плане](STABILITY_PRIORITIES_2026-10-21.md). Рабочая IDE — Electron; ядро — компилятор и BytecodeVm. Исходный список собран до архивирования прежних планов, договоров и аудитов. Очередь ниже учитывает завершённые этапы до переноса SCREEN на DirectX; датированные разделы в конце сохраняют историю уточнений. Неподтверждённые условия не означают отсутствие реализации.

Статусы: **открытый этап** — действующая очередь; **неполная приёмка** — код/отдельные проверки есть, полного доказательства нет; **предложение** — отсутствующая или отдельно проектируемая возможность, без обязательства реализовать её сейчас; **требует перепроверки** — старый технический кандидат без свежего воспроизведения. Отсутствие проверки не означает отсутствие реализации.

## 3. Действительно отсутствующие предложения языка

Сверка: SyntaxKind, ParsePrimaryExpression, ParseParameter, разбор FOR/ON, типы Symbols и свежие 335 форм реестра. Подробный первоначальный замысел сохранён в проверке предложенных форм и классификации API. Сигнатуры предложений не считаются утверждённой частью Axiom.

| Предложение | Что отсутствует / как решается сейчас |
|---|---|
| Литералы массивов | Нет разбора `{...}` как литерала массива; DIM с границами и отдельные присваивания работают. |
| FOR EACH | Нет отдельной формы обхода; работает FOR/LBOUND/UBOUND. |
| Многострочные литералы | Нет строки с тройными кавычками; конкатенация и CHRW(10) дают многострочный текст. |
| Словари | Нет встроенного DICTIONARY/MAP и литерала ключ/значение; TILEMAP является графическим типом. |
| Необязательные параметры | ParseParameter разбирает имя/тип/передачу без значения по умолчанию; явные аргументы и функции-обёртки работают. |
| Лямбды | Нет анонимной формы `=>`; ARRAYMAP и другие функции принимают поддержанные именованные функции. |
| Сопоставление с образцом | SELECT CASE есть; предложенные дополнительные шаблоны не являются реализованным расширением. |
| MODULE/IMPORT, пространства имён и несколько файлов | Договор многофайловой модели требует проектирования; действующая программа — отдельный документ. Источник: проект модулей. |
| ON TIMER | Есть TIMER() и ON KEY/ON MOUSE; отдельного события таймера нет. |
| DATA/READ/RESTORE | Нет подсистемы встроенных таблиц и указателя чтения; READLINE(FILE) относится к другому источнику. Замысел. |
| Универсальный двоичный FILE | Режимы RuntimeTextFile — Input/Output/Append; текстовые кодировки и COPYFILE не заменяют позиционный доступ к произвольным байтам. |
| Относительный путь между полными путями | FULLPATH/COMBINEPATH и разбор компонентов не вычисляют относительный маршрут; договор разных дисков/корней не выбран. |
| Самостоятельный exe/native code | Отдельное направление продукта; наличие CLI/байт-кода не является готовой пользовательской поставкой программы. |
| Классы/объекты/указатели как отдельное направление | TYPE с методами/конструкторами уже есть. Более широкое объектное направление не считать выполненным по наличию SELF/New; сначала конкретный договор. |

Точный строковый разбор DECIMAL, полный равномерный случайный LONG и HYPOT остаются кандидатами для отдельного воспроизведения/сценария. VAL/ISNUMERIC/CDEC не объявляются универсальным точным парсером DECIMAL. Для устойчивого расстояния уже есть [scaled_distance.axm](../../samples/functions/sqr/scaled_distance.axm); новый API не обязателен для проверенного случая.

## Нативный INPUT: исправленное состояние запроса — 15 октября 2026 года

Ограничение, найденное при переносе SCREEN, исправлено в IDE 0.6.1. Нативный Enter и отмена публикуют input.completed; Electron очищает совпадающий запрос. INPUT в SCREEN 0/1 не переводит фокус в терминал. Повтор после ошибки преобразования организуется программой через TRY/CATCH, без изменения языка. Новый оконный сценарий проверил 28 утверждений, включая русский текст и Stop во время ожидания. Эта работа больше не является открытым дефектом; причины и итог — ревизия.

## Ревизия очереди стабильности — 15 октября 2026 года

Размеры каталога и ссылки на ранние результаты выше являются историческими: текущий SCENARIOS.json содержит 456 сценариев, полного прогона этого каталога не заявлено. SCREEN на DirectX опубликован в 719d35a; повторно планировать перенос и исправления PAINT/CIRCLE/LINE не требуется. Восстановление после бесконечного зависания уже реализовано; исправлено устаревшее описание протокола.

Первым кандидатом стабилизации выбрано согласование завершения нативного INPUT с Electron. Рассогласование подтверждено кодом DesktopHost и адресным воспроизведением настоящего ExecutionController: сохраняется старый запрос и приглашение, повторная отправка допускает ложный отказ интерфейса. Исправление пока не выполнено. Причина, границы проверки и критерии приёмки — ревизия стабильности. Предложения новых возможностей языка и полная переаттестация матрицы в эту задачу не входят.

## Запоздалые ответы команд исполнения — 15 октября 2026 года

В IDE 0.6.2 исправлена подтверждённая гонка: ответ INPUT/Stop/отладки предыдущей сессии мог сбросить новый запуск, поздний отказ INPUT — следующий запрос той же программы. Реализация сверяет принадлежность ответа; отчёт и точные границы приёмки: ../reports/electron/EXECUTION_SESSION_STABILITY.md. Это исправление существующего исполнения, не новая языковая возможность. Итог проверок — в конце WORKLOG5.

## Устойчивость подготовки — 16 октября 2026 года

В IDE 0.6.3 исправлены незавершённое ожидание старта после аварии DesktopHost и применение запоздалого ответа старта к следующей программе. Проверены отказ компиляции после успеха, отмена сохранения и повторный запуск. Кэш в проверенном случае уже работал правильно. Подробности и оставшиеся границы IDE15/23/28/29: отчёт. Следующая адресная проверка — ресурсная база одинакового исходника в разных каталогах и CHANGEDIR. Полная матрица этим этапом не закрыта.

## Каталоги исполнения: подтверждённый объём — 16 октября 2026 года
