## F6-1. P1 — просроченное представление аварийно прерывает отладочный запуск

Места: `src/Axiom.Runtime/Values/RuntimeArrayValue.Copy.cs:62`, `src/Axiom.Runtime/Values/RuntimeSnapshotFactory.cs:58`.

```basic
DIM stale[] AS INTEGER
DIM values[] AS INTEGER = [1, 2, 3]
stale[] = values[1 TO 2]
DIM removed AS INTEGER = ARRAYPOP(values[])
DIM marker AS INTEGER = 0
TRY
    PRINT stale[1]
CATCH problem
    PRINT problem.Code
END TRY
```

Обычный запуск выводит `MB3014` из CATCH. При запуске того же скомпилированного модуля с точкой останова на строке 6 VM выбрасывает необработанное `ExpiredArrayViewException` при создании истории, ещё до требуемой остановки. Обратный шаг для воспроизведения не нужен. Стек: `TryCreateReversibleStateSnapshot` → `TryCreateLocalSnapshots` → `RuntimeSnapshotFactory.CreateValueSnapshot` → `FillStorageSnapshotInto:71` → `EnsureAllocated`.

После ARRAYPOP без перевыделения корень и устаревший срез имеют один физический буфер, но разные поколения срока жизни. Новый снимок объединяет их по `_elements`, а копирование физической области не учитывает инвалидированное состояние. Если первым посещается устаревшее представление, создаётся инвалидированное хранилище и обход его элементов выбрасывает исключение. Порядок объявлений в примере обеспечивает этот случай.

Требуется корректно сохранять поколения хранилища и состояние недействительности представлений. Нельзя вызывать операции действительного массива на инвалидированном снимке. Порядок обхода переменных не должен влиять на возможность отладки.

Воспроизведение: `.artifacts/foreach-stage6-review/stale-view-first.axm`, точка 6. Вариант с объявлением корня первым также сохранён в `stale-view.axm`; в нём обратный шаг на проверенных точках недоступен. Теоретическое восстановление просроченного вида как действительного в этом варианте запуском не подтверждено и отдельным дефектом не заявляется.

## F6-2. P1 — обратный шаг подменяет захват старой итерации новой ячейкой

Место: `src/Axiom.Runtime/Execution/BytecodeVm.Debug.cs:292`, `RestoreCapturedSlots`.

```basic
DIM values[] AS INTEGER = [1, 2]
DIM reader AS FUNCTION() AS INTEGER
FOR EACH BYREF item IN values[]
    reader = Capture(item, reader)
NEXT item
PRINT reader()
FUNCTION Capture(BYREF value AS INTEGER, previous AS FUNCTION() AS INTEGER) AS FUNCTION() AS INTEGER
    IF value = 2 THEN
        PRINT previous()
    END IF
    FUNCTION ReadValue() AS INTEGER
        DIM marker AS INTEGER = 0
        RETURN value
    END FUNCTION
    RETURN ReadValue
END FUNCTION
```

Обычный запуск и остановка с последующим продолжением дают `1`, `2`. Установить точку на строке 13 (`RETURN value`), при первой остановке выполнить один обратный шаг и продолжить до конца: фактически выводится `2`, `2`. Обратный шаг возвращается к строке 12 внутри старого замыкания, когда второй вызов Capture ещё находится в стеке.

У параметров двух вызовов Capture одинаковый `VariableSymbol`, но разные ячейки: первая указывает на элемент 1, вторая — на элемент 2. Восстановление предпочитает видимый слот по символу фактическому снимку захваченной ячейки. Поэтому старое замыкание получает адрес второй итерации.

Требуется сохранять и восстанавливать идентичность конкретного захваченного слота; совпадение символа объявления не доказывает совпадение экземпляра ячейки.

Воспроизведение: `.artifacts/foreach-stage6-review/captured-old-cell.axm`, точка 13.

## F6-3. P1 — функция внутри массива после обратного шага читает старый граф состояния

Места: `src/Axiom.Runtime/Values/RuntimeSnapshotFactory.cs:75–81`, `src/Axiom.Runtime/Execution/BytecodeVm.Debug.cs:366`.

```basic
DIM values[] AS INTEGER = [1]
DIM readers[1 TO 1] AS FUNCTION() AS INTEGER
FOR EACH BYREF item IN values[]
    readers[1] = Capture(item)
NEXT item
values[1] = 9
PRINT readers[1]()
FUNCTION Capture(BYREF value AS INTEGER) AS FUNCTION() AS INTEGER
    FUNCTION ReadValue() AS INTEGER
        RETURN value
    END FUNCTION
    RETURN ReadValue
END FUNCTION
```

Обычный запуск и остановка с продолжением дают `9`. Точка останова на строке 6; один обратный шаг, затем продолжение: фактически `1` вместо `9`.

Для самостоятельного значения функции добавлен специальный путь копирования захватов. Но элементы массива копируются через общий `RuntimeSnapshotFactory.CreateValueSnapshot`; функциональный элемент попадает в `CopyForStorage`, сохраняя исходную функцию и её адрес элемента. После восстановления `values[]` относится к восстановленному массиву, а `readers[1]` всё ещё читает прежний объект.

Требуется единый обход графа снимка для функций и захваченных слотов независимо от того, где находится функция: непосредственно в переменной или внутри составного значения. Простого исправления только самостоятельных функциональных переменных недостаточно.

Воспроизведение: `.artifacts/foreach-stage6-review/functions-in-array.axm`, точка 6.

## F6-4. P2 — завершённый обход продолжает отображаться как текущая итерация

Места: `src/Axiom.Bytecode/Lowering/BoundProgramLowerer.ForEach.cs:93`, `src/Axiom.Runtime/Execution/BytecodeCallFrame.cs:297`, `src/Axiom.Runtime/Execution/BytecodeVm.Debug.cs:16`.

Подтверждены два случая:

1. Исключение или ошибка изменения формы переводит исполнение в CATCH вне цикла и обходит `ClearForEachItem`. В `cleared-after-catch.axm` точка на строке 9 после END TRY возвращает `CurrentForEachItem = item / INTEGER / ‹недоступно›`, хотя FOR EACH уже завершён. Нормальный вывод программы — `MB3014`, затем `done`.
2. Замыкание первой итерации вызывается после NEXT. Прежняя захваченная ячейка сохранила `IsForEachItem=true`, поскольку очистка сбросила только последнюю локальную ячейку цикла. В `captured-after-loop.axm` точка на строке 9 внутри ReadValue возвращает `CurrentForEachItem = value / INTEGER / 1`, хотя обход уже окончен.

Второй случай целиком:

```basic
DIM values[] AS INTEGER = [1, 2]
DIM first AS FUNCTION() AS INTEGER
FOR EACH BYREF item IN values[]
    IF item = 1 THEN first = Capture(item)
NEXT item
PRINT first()
FUNCTION Capture(BYREF value AS INTEGER) AS FUNCTION() AS INTEGER
    FUNCTION ReadValue() AS INTEGER
        RETURN value
    END FUNCTION
    RETURN ReadValue
END FUNCTION
```

Требуется отделять активность обхода от срока жизни ячейки, удерживаемой замыканием, и очищать состояние при переходах за пределы цикла. В проверке непосредственно прочитано свойство VM `CurrentForEachItem`; новая оболочка передаёт его в IDE. Физический сценарий Electron для этих ошибок повторно не запускался.
