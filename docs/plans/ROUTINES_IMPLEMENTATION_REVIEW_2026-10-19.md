## Незавершённые архитектура и договор

1. **Отладка по документу.** Вопреки неточности переданного резюме, `SourceInstructionMap` и `BytecodeVmExecutionSnapshot` уже несут Document через TextLocation в памяти. Но `BytecodeSourceBreakpoint`, подавление повторной остановки и условия StepInto/Over сравнивают строки без документа. Требуются ключ документа и позиции, отображение нужного файла, проверки одинаковых строк в разных документах, продолжения и восстановленного байт-кода.
2. **Владелец символа.** ModuleSymbol пока является таблицей экспортов в `Binder.Modules.cs`; у FunctionSymbol нет ContainingModule, у результата CompiledProgram нет набора исходных документов. Исполнение по объектной идентичности уже разделяет проверенные закрытые имена, но для навигации, переименования, отладки и кэширования происхождение символа и полный состав программы надо сохранять явно.
3. **Конфликты импортов.** Открытый импортированный TYPE может быть молча перекрыт локальным TYPE с тем же именем; функции и переменные обрабатываются иначе. Нужны единые установленные правила по категориям имён и соответствующие отрицательные тесты. Текст «уточните модуль» в MB2054 пока предлагает отсутствующий способ: квалифицированный модульный доступ не реализован.
4. **Неиспользуемые документы.** Импорты проверяются во всех переданных файлах, а связывание тел выполняется только для достижимых от точки входа. Поэтому неизвестный импорт в неиспользуемом файле останавливает запуск, а неизвестное имя в его PRINT — нет. Нужно явно выбрать область обязательной проверки; это пока не специфицированная политика, а не доказанное нарушение согласованного договора.
5. **Открытые сигнатуры с закрытым TYPE.** `ReadBox(MakeBox())` успешно переносит закрытый тип через открытые функции. Это допустимый вариант абстракции, но закрытый тип также может требовать ограничения доступа к полям. Один выбор «закрыто по умолчанию» ответа не даёт; закрепить ожидаемую модель и тесты, не объявляя действующее поведение ошибкой без решения.
6. **Циклы.** Сейчас запрещён любой цикл IMPORT, включая граф, необходимый для взаимных прямых вызовов двух модулей. Предыдущая матрица содержала межмодульную рекурсию; её надо согласовать с политикой циклов. Для разрешения циклических ссылок потребуются отдельные проходы объявления и связывания, независимо от допустимости циклической инициализации.
7. **Границы проекта.** Папка исходников, явная точка входа, загрузка с диска, неназванные/несохранённые документы, диагностика некорректных имён и одинаковых коротких имён в разных папках пока не образуют завершённого пользовательского пути. Не добавлять неоговорённый формат проекта ради внутренних параметров API.
8. **Инициализация и ресурсы.** Порядок зависимостей реализован, но нужны постоянные проверки общего ромбовидного импорта с однократной инициализацией, ошибки инициализации, повторного запуска, BYREF между модулями и неизменности базы относительных файловых путей.

## Сопровождение и пользовательский путь

- Передача нескольких документов отсутствует в DesktopHost/CLI и службах IDE. Один параметр AdditionalDocuments в API ещё не позволяет автору запускать проект из редактора.
- В изменениях нет поддержки IMPORT/PUBLIC/PRIVATE в Monaco, семантических категориях, форматировании и связанных Node/Electron-проверках. Требуется также работа с несколькими документами для диагностики, дополнения, hover, навигации и устаревших результатов проверки.
- Новые формы модулей не описаны в справочнике, спецификации и текущем журнале. Текущие планы всё ещё утверждают, что реализация не начиналась; запись ниже уточняет фактическое состояние без переписывания истории.
- `node scripts/check-manual.mjs` сейчас завершается с ошибкой: устарел снимок языка. До выпуска нужны обновление реестра, описания и навигация новых форм, пересборка индексов и успешная проверка.
- MB2056 объявлен, но не используется: наличие диапазона MB2049–MB2056 не означает, что каждый код уже реализован и проверен.
- Версии 0.1.41/0.1.41/0.6.28 согласованы технически; последняя запись относится к снимку BYVAL, а не завершённым модулям. Новая подсистема и будущая интеграция IDE требуют сопровождения по VERSIONING при завершении реализации. Аудит сам по себе повышения не требует.
