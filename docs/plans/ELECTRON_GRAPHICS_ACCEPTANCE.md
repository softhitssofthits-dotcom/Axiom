## Выход из IDE и отказ служебного процесса

Сценарии находятся в `ide/e2e/specs/graphics-shutdown.spec.js`; результаты — в `ide/e2e/evidence/graphics-shutdown-results.json`. Два сценария, 11 утверждений, все прошли.

- Выход через команду оболочки при CANVAS/INPUT, SCREEN/SLEEP и цикле CANVAS завершает Electron и его собственный DesktopHost. Повторный запуск IDE не начинает исполнение прежней программы.
- Отказ собственного DesktopHost при ожидании ввода отображается пользователю; запрос освобождается. Новый Run создаёт другой DesktopHost, отклоняет ответ старой сессии и принимает новый ввод 2718 без диагностики.
- PID берётся из основного процесса Electron, а не из процесса запуска Playwright. Принадлежность DesktopHost определяется по его имени и ParentProcessId. Проверка существования процесса не завершает его; в сценарии отказа завершается только подтверждённый собственный дочерний процесс.

Повторены семь существующих сценариев backend.spec.js: 22 утверждения прошли. Всего в этом участке выполнены 12 сценариев и 56 утверждений. Полный набор теперь содержит 65 сценариев; весь набор из 65 в этой работе не запускался.

## Особенность автоматизации фокуса

Playwright включает `Emulation.setFocusEmulationEnabled` и поддерживает видимость фокуса страницы даже при переключении нативного окна. Первые попытки проверить потерю фокуса с этой настройкой не переключили document.hasFocus(); TRUE у удержанной кнопки не являлось доказательством ошибки среды.

Для настоящей проверки blur эмуляция фокуса отключена отдельной CDP-сессией у CANVAS. Перед чтением состояния тест дожидается document.hasFocus() = false. Получен результат `Сброс=FALSEFALSEFALSE`. Постоянная задержка вместо наблюдения фокуса не используется.

Первоначальная проверочная программа ошибочно использовала STR для BOOLEAN и была отклонена с MB2003. Тест исправлен: логическое значение выводится оператором PRINT. Мгновенный click также заменён раздельным нажатием и отпусканием, чтобы чтение текущего MOUSEBUTTON происходило во время удержания. Это исправления проверок, а не изменение договора языка.

## Физический ввод нативного SCREEN

Системный инструмент управлял окном Axiom SCREEN процесса Axiom.DesktopHost, созданным запуском из Electron:

1. Пробел завершил SLEEP; программа завершилась, поверхность закрылась.
2. Клавиши 2, 7, 1, 8 и Enter передали INPUT точное число 2718. Проверочная программа выдала бы ошибку деления на ноль при другом значении; выполнение завершилось без диагностики.
3. Alt+F4 при ожидании SLEEP остановил выполнение; статус стал «Остановлено», окон Axiom SCREEN больше не было, диагностика отсутствовала.

Команда инструмента type_text не передала число в нативный INPUT: Enter завершил пустой ввод с MB3003. Это отдельно от подтверждённого физического цифрового набора; автоматический текстовый ввод и все варианты Unicode нативного окна ещё не приняты.

Получение изображения SCREEN снова завершилось `FrameArrived timed out`. Физические мышиные координаты и системный DPI нативного SCREEN в этой работе не подтверждены.
