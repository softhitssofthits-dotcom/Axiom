# Переход массивов на квадратные скобки — результаты 23 октября 2026 года

## Что изменено

По поручению автора продолжена непрерывная работа по [плану перехода](ARRAY_SQUARE_BRACKETS_MIGRATION_2026-10-22.md). Публичный компилятор и Electron IDE используют один квадратный договор массивов. Исходный снимок рабочего дерева — `ed3741bd` с уже существовавшими незакоммиченными этапами массивов, подсказок IDE и редактурой справочника. Эти изменения не откатывались и не выдаются за чистую исходную ревизию.

Версии: **язык 0.3.0, компилятор/CLI 0.4.0, IDE 0.9.0**. Номера повышены штатным `bump all minor`, поскольку переход несовместим с прежней записью. Версия формата байт-кода не менялась.

### Действующая запись

```basic
DIM fruit AS STRING = "яблоко"
DIM fruits[] AS STRING = SPLIT("яблоко,банан", ",")
DIM basket[] = fruits[]
basket[2] = "груша"
PRINT fruit
PRINT fruits[2]
```

Результат: «яблоко», «груша». `fruits[]` обозначает весь массив, `fruits[2]` — элемент; присваивание сохраняет общую память. Независимую копию создаёт `ARRAYCLONE(fruits[])`.

- Скобки после имени обязательны у массива в выражениях, включая поля TYPE и аргументы встроенных функций.
- В объявлении `[]` означает ранг 1, `[,]` — 2; в выражении `grid[]` обозначает весь массив любого ранга, а `grid[,]` не является массивным значением.
- Параметр: `values[] AS STRING`; результат/безымянный тип: `STRING[]`, `INTEGER[,]`.
- `MakeFruits()` остаётся вызовом функции с массивным результатом, `MakeFruits()[2]` выбирает его элемент.
- `REDIM fruits[1 TO 3]`, `ERASE fruits[]`; именованный DIM/CONST со скобками после типа запрещён.
- Массивный CONST записывается `CONST fruits[] AS STRING = ...`. Прежняя защита имени и общая память сохранены, новый неизменяемый контейнер не вводился.
- Голые массивные имена, прежнее круглое индексирование, неподходящие именованные формы дают MB2003 до исполнения.
- Сохранены прежние ограничения BYREF: целый массив-переменная допустим, поля/элементы/представления не получили нового договора ссылочного аргумента.

Типы элементов, нижние границы, пустое/невыделенное состояние, фиксированные строки, TYPE, представления, ARRAYCLONE, инвалидирование хранилища, снимки и отладочный откат не перестраивались. Литералы, FOR EACH, новые коллекции и оптимизация числового хранения не добавлены.

## Реализация по слоям

1. Lexer распознаёт `OpenBracketToken`/`CloseBracketToken`. `ArrayAccessExpressionSyntax` отделён от `CallExpressionSyntax`; декларации и типы используют нейтральные свойства токенов границ.
2. `Parser.Arrays.cs` разбирает whole/индексы/диапазоны, ранги, параметры и REDIM. Круглые вызовы, группировка и графические координаты сохранены. Новый публичный Parser помечает ProgramSyntax.UsesSquareArraySyntax, Binder применяет политику отдельно к каждому модулю.
3. Binder разрешает непосредственную квадратную цель без запрета голого имени, но не отключает строгую проверку вложенных выражений. Целый массив сохраняет прежний bound-узел; индексы/представления — прежние BoundArrayAccessExpression.
4. ArrayTypeSymbol и метаданные показывают `[]`. BytecodeModuleSerializer формирует собственное прежнее представление типов с круглыми суффиксами; сериализация и восстановление проверены отдельно.
5. Formatters Classic/Modern сохраняют квадратные пары, диапазоны, отрицательные индексы, вложенные вызовы, интерполяцию и `:=`. Monaco поддерживает автозакрытие/удаление пар, четыре темы и категорию array. Подсказка функции не учитывает запятые внутри индекса как аргументы вызова.
6. Обновлены справочник, навигация/поиск, подсветка и свежий снимок реестра. Необязательность в формальных схемах обозначена `⟦…⟧`, квадратные скобки языка буквальны.

## Предварительное преобразование старых программ

`ArraySyntaxMigrationService` использует внутренний прежний Parser и Binder с редакторскими символами, а не совпадение имени или глобальную замену круглых скобок. Правки строятся по исходным диапазонам UTF-16, проверяются на пересечение; преобразованный текст повторно разбирается и связывается. Неизвестные имена и ошибки запрещают весь результат. Проверяется идемпотентность, область видимости, зависимости IMPORT, строки/комментарии, Unicode-текст и окончания строк.

CLI:

```powershell
axiom migrate-arrays old-program.axm --json
axiom migrate-arrays --stdin
```

Команда только показывает результат, не выполняет программу и не записывает файлы. `--write`, неизвестные и повторные параметры отклоняются. У файлового входа зависимости загружаются для разрешения имён; результат относится только к выбранному исходнику. Пользовательские проекты не переписываются автоматически. [Руководство](../manual/arrays-migration.html), [команды разработки](../DEVELOPMENT.md).

Проверки независимого чтения выявили и помогли закрыть два пробела: поглощение `[]` выражением длины фиксированной строки и отсутствие диагностики присваивания результату вызова `Make() = values`. Отдельно согласована единая запись массивного CONST, чтобы суффикс после типа не оставался обходом строгой формы. Мигратор теперь отвергает такую неверную цель, не выдавая частичных правок.

## Перенос корпуса и сохранность ожиданий

Перед массовым переводом сохранены точные исходные байты 1378 файлов и прежний CLI: `.artifacts/square-brackets-baseline/`. Сначала получены предварительные правки. Применение разрешалось только при совпадении SHA-256 исходного файла. Дополнительные ошибочные/составные тестовые программы переводились адресно с сохранением проверяемой ошибки, а не автоматическим исправлением по догадке.

Относительно этого снимка изменены 198 прежних .axm-файлов, 107 тестовых C#-файлов, один контрольный C#-файл scripts и десять файлов IDE-проверок; последующие новые проверки и документы учитываются отдельно. Цифры относятся к переносу, а не ко всему накопленному `git diff`.

Полный старый корпус: 891 программа. После перехода сохранены 828 успешных компиляций и те же 63 отрицательных результата с совпадающими наборами кодов. Девять контрольных запусков дали тот же вывод, включая две программы engine-compare. Алгоритмы/размеры измерительных программ не менялись, ускорение не заявляется. Генератор исходника калибровки Maze Chase отдельно переведён на квадратные обращения; формат внешнего calibration .txt намеренно сохранён.

Новые ручные программы:

- `samples/operators/dim/square_array_values.axm`: строка, целый массив, элемент, функция, общий массив и копия; вывод «яблоко», «груша», «груша», «апельсин», «банан».
- `samples/smoke/square_array_views.axm`: таблица/представление, TYPE-поле и BYREF; вывод «3 4», «4», «груша», «яблоко».
- `samples/operators/const/array_value.axm`: массивная константа и независимая копия; вывод «банан», «2», «банан», «груша».

Все три исполнены свежим CLI. Для ручной приёмки открыть файл в Electron IDE и выполнить F5; вывода достаточно для сравнения с указанными строками, графических пауз эти консольные примеры не требуют.
