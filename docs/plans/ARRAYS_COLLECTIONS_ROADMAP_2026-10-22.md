# План развития массивов и коллекций Axiom

Дата: 22 октября 2026 года. Статус: составление и обсуждение плана; реализация ещё не выполняется.

**Цель:** сначала устранить подтверждённые недочёты массивов, затем улучшить запись и обработку данных, после этого вводить новые структуры с самостоятельной пользой.

**Технический подход:** сохранить действующие типы и правила хранения, переиспользовать функциональные параметры, отдельно проверять новые синтаксические формы. Каждый этап должен давать законченный результат с проверками и запускаемыми примерами. Крупные изменения внутреннего хранения выполнять последними, через измеряемый опыт.

**Стек:** C#/.NET 10, BytecodeVm, Electron/Monaco, действующие группы проверок из `docs/TESTING.md`.

Основание — [независимый аудит](ARRAYS_EVOLUTION_INDEPENDENT_AUDIT_2026-10-22.md) и последующие решения автора. Этот документ задаёт последовательность по теме массивов; действующая очередь других задач IDE не переопределяется. Начало реализации требует отдельного поручения автора. Старый [подробный план FOR EACH](FOR_EACH_IMPLEMENTATION_2026-10-22.md) используется внутри этапа 6, а не как команда немедленно начать работу.

## Принятые решения

1. Поддержать массивные инициализаторы **с явным и с выведенным типом**. Последнее решение автора отменяет промежуточный выбор только явного типа. Прежний вывод типа скалярных переменных сохраняется.
2. `FOR EACH` внедряется **одним завершённым этапом с обоими режимами — `BYVAL` и `BYREF`**. Внутренние действия выполняются последовательно, но этап не объявляется завершённым после одного режима.
3. При обсуждении каждого нового договора показывать короткие программы Axiom с фруктами, оценками, инвентарём и ожидаемым результатом. Предлагаемый синтаксис явно отличать от уже работающего.
4. Предпочтение явного типа в учебных по смыслу пояснениях и примерах можно использовать для читаемости; обязательный запрет неявной формы не вводится. В справочнике сохраняется его формальный жанр.

## Общая последовательность

| Этап | Результат | Почему расположен здесь |
|---|---|---|
| 1 | Быстрые вставка и удаление в конце массива | Самое локальное изменение существующего выполнения |
| 2 | Работающие массивные инициализаторы | Устранение подтверждённого разрыва между связыванием и понижением |
| 3 | Эффективное удаление повторов записей `TYPE` | Завершение адресных улучшений существующих массивов |
| 4 | Сортировка массива записей по выбранному полю | Переиспользование имеющихся функциональных параметров |
| 5 | Простое создание массивов из набора значений | Новая краткая форма с проверяемым договором типов и границ |
| 6 | `FOR EACH` с `BYVAL` и `BYREF` | Новый синтаксис, области видимости, адреса элементов и отладочные снимки |
| 7 | Типизированный словарь | Первая новая самостоятельная коллекция |
| 8 | Типизированное множество | Использует уже проверенные правила хеширования словаря |
| 9 | Кортежи и распаковка | Новые составные типы, вывод типов и правила доступа |
| 10 | Экономное внутреннее хранение числовых массивов | Наиболее широкое изменение представления данных и VM |

Сначала идут локальные исправления, затем новые формы и типы, последней — перестройка хранения. Это порядок по сложности и зависимостям, а не обещание, что каждый следующий этап обязательно потребует больше строк кода: множество после готового словаря может оказаться проще самого словаря.

Будущие рабочие формы после этого этапа:

```basic
DIM fruits = SPLIT("яблоко,банан,апельсин", ",")
PRINT fruits[2]
```

```basic

PRINT fruits[2]
```

Обе программы выводят `банан`. Во второй тип читается непосредственно из объявления, в первой определяется по результату `SPLIT`. Проверки: `scripts/test.ps1 bytecode -Filter Array`, `scripts/test.ps1 execution -Filter Array`; при изменении связывания — адресная группа `semantics`. Готовность: обе формы выполняются свежей сборкой, неподдержанные сочетания получают согласованные диагностики, `check` и `run` не расходятся. - [~] Проверить отдельные ячейки итераций, захват через вызванные функции, фиксированные строки, `TYPE`, `EXIT`, `CONTINUE`, исключения, сохранение байт-кода и обратный шаг. — Для `BYVAL` проверены `TYPE`, `EXIT`, `CONTINUE` и сохранение байт-кода. Отдельные ячейки, захват через замыкания, фиксированные строки при записи и обратный шаг относятся к `BYREF`.
- [~] Доставить оба режима в форматтер, подсветку, навигацию и отладчик. Этап закрывается только после приёмки обоих режимов. — Сделано для `BYVAL`: контекстная подсветка `EACH`/`IN`, справочник, сценарии проверки. Отладка `BYREF` и обратный шаг остаются.

Предлагаемые новые формы. Исходный массив оценок содержит 3 и 4:

```basic
FOR EACH grade IN grades[]
    grade = grade + 1
NEXT grade
```

Массив сохраняет оценки 3 и 4: меняется переменная цикла.

```basic
FOR EACH BYREF grade IN grades[]
    grade = grade + 1
NEXT grade
```

Массив получает оценки 4 и 5: меняются его ячейки. Для записей и вложенных динамических массивов действуют правила обычного копирования Axiom, а не обещание глубокой независимости.

Файлы и подробная приёмка перечислены в старом предметном плане: синтаксис/парсер, связывание и понижение циклов, адреса слотов VM, `RuntimeSnapshotFactory.cs`, `BytecodeVm.Debug.cs`, `ide/src/renderer/lang-features.js`, `semantic-colors.js`, темы, форматтер и `BlockLineClassifier`. Примеры — `samples/control-flow/for/each_byval.axm`, `each_byref.axm`, `each_multidimensional.axm`, `each_resize_invalidates.axm`.

Группы по затронутому подэтапу: `syntax`, `parser`, `semantics`, `bytecode`, `runtime`, `execution`, `ide-backend`, `ide-unit-renderer`, выбранные Electron-проверки редактора и отладки. ## 24 октября 2026 года - этап 4 выполнен

## 25 октября 2026 года - этап 6, часть первая: CONTINUE и FOR EACH BYVAL

По плану этапа 6 сначала адресно воспроизведена указанная проблема `CONTINUE` в смешанных циклах. Она подтвердилась в обоих направлениях: `CONTINUE FOR` внутри `WHILE`, вложенного в `FOR`, переходил к условию внутреннего `WHILE`, а `CONTINUE WHILE` внутри `FOR` — к счётчику `FOR`. Причина — единый стек продолжений для всех трёх форм. Стеки разделены по видам циклов, каждая форма выбирает ближайший цикл своего вида; выполнение `FINALLY` до перехода сохранено. Добавлены четыре проверки смешанного вложения, включая `TRY`/`FINALLY`, и пример `samples/control-flow/for/continue_loop_kinds.axm`.

Реализован режим `BYVAL` обхода массива: `FOR EACH item IN values[]` с необязательными `BYVAL` и `AS <тип>`. `EACH` и `IN` — контекстные слова заголовка; вне его остаются именами, числовой `FOR` не изменился. Источник вычисляется один раз, обход учитывает фактические границы и многомерный порядок, пустой массив даёт ноль проходов, невыделенный сообщает MB3005 собственным сообщением. Переменная цикла получает копию элемента. Новые диагностики MB2062 и MB2063. ## 25 октября 2026 года - EACH и IN зарезервированы по требованию строгости

Автор указал, что контекстные `EACH` и `IN` противоречат строгости языка: `DIM each AS INTEGER = 100` разбиралось как обычное объявление. Слова переведены в зарезервированные: лексер относит их к ключевым токенам, `AxiomLanguageKeywords` включает их в реестр `axiom metadata`, а `MatchIdentifier` отклоняет использование как имени с MB1002 и отдельным сообщением. Разбор заголовка `FOR EACH` переведён на ключевые токены, вспомогательное сравнение текста удалено.

Имена вида `in2`, `eachItem`, `inside` остаются допустимыми: зарезервированы ровно слова целиком. В IDE контекстные состояния токенизатора удалены, слова входят в общий список ключевых слов. Пример `each_byval.axm` очищен от строки `Dim each As Integer = 100`, которая демонстрировала теперь недопустимую программу.

Это несовместимое изменение языка. Версии: язык 0.7.0, компилятор/CLI 0.8.0, IDE 0.12.0. Этап 6 по-прежнему не закрыт: следующий шаг — режим `BYREF`.
