# Проекты Axiom

Проект объединяет исходники, ресурсы и одну точку входа. Его описание хранится в файле `.axproj` рядом с программой и переносится вместе с папкой. Открытые вкладки не определяют состав проекта.

## Открытие и создание

В IDE выберите «Файл → Открыть проект…» и укажите `.axproj`. Поддерживается также открытие такого файла обычной командой «Открыть…». Команда «Открыть папку…» автоматически использует единственный `.axproj` в корне папки. Если их несколько, откройте нужный файл явно. Повреждённый файл не подменяется режимом папки.

Выберите «Файл → Создать проект…». В окне создания введите имя, нажмите «Выбрать папку…», укажите папку проекта и нажмите «Создать». Если уже написан непустой черновик, IDE предложит сохранить его в этой папке; файл из другой папки можно сохранить туда командой «Сохранить как». Отмена сохраняет черновик и не открывает проект. Создаётся `<имя-проекта>.axproj`. Если описание уже существует, IDE предлагает открыть его, без создания второго описания.

Можно начать и с пустой папки: IDE создаст `main.axm`, назначит его файлом запуска и откроет для набора. В существующей папке используется корневой `main.axm` либо единственный исходник; при нескольких исходниках без `main.axm` файл запуска выбирается в свойствах.

Крестик в заголовке проекта действительно закрывает сеанс, с запросом о несохранённых изменениях. Закрытый проект не восстанавливается при следующем запуске IDE. Крестик всей боковой панели только скрывает панель. История папок диалога хранится отдельно от открытого проекта.

Готовый проект суммы двух чисел: `samples/smoke/input_sum_project/input_sum.axproj`. Главный файл читает два числа через `INPUT`, модуль `arithmetic.axm` возвращает сумму через `RETURN`; для ввода 8 и 13 результат равен 21.

Обычная папка без `.axproj` пока открывается в прежнем режиме совместимости. Превращение папки в самостоятельный проект выполняется явной командой создания. Отдельные `.axm` по-прежнему можно открывать, проверять и запускать без описания проекта.

## Состав и дерево

Пример описания:

```json
{
  "formatVersion": 1,
  "name": "Maze Chase",
  "entry": "main.axm",
  "sources": ["*.axm"],
  "assets": ["art/**", "maze_chase_pellet_calibration.txt"],
  "exclude": []
}
```

Корень проекта — папка `.axproj`. Все пути относительные, с разделителем `/`. Абсолютные пути, сегменты `..` и `.`, обратная косая черта, ссылки и точки повторной обработки Windows не поддерживаются. Разрешены буквальные пути, `*` внутри одного сегмента и `**` как отдельный сегмент для вложенных каталогов. Например, `*.axm` включает только исходники корня, а `**/*.axm` — исходники корня и подпапок.

`formatVersion` обязателен и равен `1`. `name` — непустое имя; без него используется имя файла описания. `entry` — относительный путь файла запуска. Пустая или отсутствующая точка входа допускает открытие дерева и исправление свойств, но запрещает запуск и проверку проекта. Удалённый или исключённый файл не заменяется случайным другим исходником.

`sources` задаёт маски исходников `.axm`; по умолчанию используется `["**/*.axm"]`. `assets` задаёт ресурсы и данные, по умолчанию список пуст. `exclude` исключает файлы из обеих групп; по умолчанию список пуст. Пересечение исходников и ресурсов показывается как исходник. Файл описания не считается ресурсом и представлен отдельной строкой свойств. Служебные каталоги `.git`, `.artifacts`, `node_modules`, `bin`, `obj`, скрытые и системные элементы исключены. Символьные ссылки и точки повторной обработки не обходятся.

Дерево показывает папки, исходники и перечисленные ресурсы. При открытии проекта открывается файл запуска; остальные исходники открываются по нажатию. Для ресурса доступны его свойства, автоматическое редактирование двоичных файлов не выполняется. Внешний открытый документ остаётся вкладкой и не появляется в дереве проекта. В контекстном меню свободного места есть «Обновить проект» для перечитывания внешних изменений состава.

## Свойства и запуск

Нажмите на строку `.axproj` в дереве либо выберите «Файл → Свойства проекта…». В окне меняются имя, файл запуска и списки масок. В каждом многострочном поле одна строка означает одну маску. Свойство файла запуска также меняется командой «Назначить файлом запуска» в контекстном меню исходника.

Сохранение проверяет исходное содержимое описания. Если другой процесс изменил его, IDE отказывает в перезаписи: закройте окно свойств, обновите проект и повторите нужную правку. Запись выполняется через временный файл рядом с описанием и атомарную замену; при отказе проверки или записи прежнее описание сохраняется.

Обычный запуск и начало отладки в режиме `.axproj` используют `entry`, даже если активна внешняя вкладка. Отдельная команда «Запуск → Запустить текущий файл отдельно» запускает активный `.axm` без описания проекта. В режиме старой папки внешний документ сохраняет прежний самостоятельный запуск.

Попадание исходника в `sources` не выполняет его инструкции. Зависимости программы по-прежнему подключаются через `IMPORT`; импорт исключённого исходника запрещён ещё до чтения его содержимого. Импорты из подпапок, зависимости между проектами и циклические импорты этим форматом не добавлены. Действуют прежние правила соседних модулей.

Команда проверки проекта проверяет граф запуска и остальные включённые исходники, которые не входят в уже проверенные графы. Ошибка в неимпортированном исходнике тоже видна. Повторные диагностики устраняются по исходнику, коду, диапазону и сообщению. Открытые исходники берутся из текущих моделей редактора; остальные — с диска. Запуск использует сохранённый текст точки входа и существующий механизм снимков открытых зависимостей.

Относительные пути файловых и графических ресурсов при запуске `.axproj` считаются от корня проекта, даже если `entry` расположена в подпапке. Самостоятельный запуск `.axm` сохраняет прежний договор. Исключение ресурса из дерева не является изоляцией файловой системы программы: программа сохраняет обычные файловые возможности языка.

## CLI

Из корня репозитория после сборки CLI:

```powershell
.artifacts/bin/Axiom.Cli/Release/net10.0/axiom.exe check samples/graphics/game/maze_chase_project/maze_chase.axproj
.artifacts/bin/Axiom.Cli/Release/net10.0/axiom.exe check --json samples/graphics/game/maze_chase_project/maze_chase.axproj
```

Команда `axiom run path/to/program.axproj` запускает точку входа. Графические программы, включая Maze Chase, запускаются в IDE: CLI сохраняет существующее ограничение консольного хоста. `check` не исполняет исходники и проверяет весь состав проекта. Коды возврата: `0` — успех, `1` — ошибки компиляции или выполнения, `2` — неверные аргументы либо ошибка чтения/описания проекта. При `check --json` ошибки описания передаются машинно с кодом `AXPROJECT`, отдельно от языковых кодов `MB`.

## Перенос и личные настройки

Копируйте `.axproj`, исходники и ресурсы с сохранением относительных путей. Выбор запуска не зависит от `projectEntries` на другом компьютере. Описание не хранит вкладки, положение курсоров, тему и размеры панелей — эти параметры остаются в локальном профиле IDE. Последний открытый самостоятельный проект восстанавливается по пути `.axproj`.

Переименование открытого файла запуска через согласованное сохранение в IDE обновляет `entry`. Если файл перемещён внешним процессом, обновите проект и назначьте новый путь в свойствах. Удаление файла запуска оставляет проект открытым для исправления и запрещает запуск до выбора существующего исходника.


### Последняя папка диалога

Диалог «Открыть проект…» запоминает папку выбранного .axproj в локальном профиле IDE и использует её при следующем открытии, включая перезапуск. Отмена выбора не стирает сохранённую папку. Если она больше не существует, используется доступная папка текущего или последнего проекта, затем системный выбор каталога.


## Добавление следующих исходников

Сохраните новый `.axm` в папке открытого проекта: дерево перечитывается сразу после сохранения, дополнительное добавление для стандартной маски `**/*.axm` не требуется. Команда «Файл → Новый файл в проекте…» создаёт пустой исходник под новым именем. Кнопка с плюсом и команда «Файл → Добавить существующий файл…» открывают выбор уже существующего файла: файл внутри проекта перечитывается без записи, внешний исходник копируется в корень проекта без замены существующего файла. При совпадении имени выберите другое имя или расположение заранее; оригинал не удаляется.

Поля `sources` и `exclude` в свойствах продолжают ограничивать состав. Если выбранный файл ими исключён, IDE сообщает об этом. Файлы, добавленные сторонней программой, можно обнаружить через «Обновить проект» в контекстном меню дерева.

## Переименование исходников и числовые имена

В контекстном меню файла дерева доступно «Переименовать…». Введите полное новое имя вместе с `.axm`. Переименование сохраняет содержимое на диске и несохранённый текст открытой вкладки, обновляет дерево и путь точки входа в описании проекта. Во время выполнения команда недоступна. Файл с совпадающим именем не заменяется. Строки `IMPORT` автоматически не переписываются: после смены имени модуля измените соответствующие импорты вручную.

Создание, добавление существующего исходника, сохранение нового документа внутри открытого проекта и переименование отвергают имена вида `222.axm`, состоящие только из цифр. Сообщение объясняет, что для IMPORT требуется имя модуля, например `arithmetic.axm` или `sum2.axm`. Существующие числовые файлы доступны для редактирования и переименования. Эта проверка интерфейса не меняет грамматику языка; остальные ограничения идентификаторов IMPORT сохраняются.
