# Руководство разработчика Axiom

Этот документ описывает сборку, запуск из исходников, проверки и сопровождение версий. Общее описание проекта — в [README](../README.md), пользовательский справочник языка — в [справочнике](manual/index.html).

## Что это за продукт

Axiom — BASIC-подобный язык с компиляцией в байт-код и настольная IDE на Electron. Ядро языка и служебный процесс написаны на C#/.NET 10; редактор использует Monaco, консоль — xterm.js.

## Подготовка и запуск

Текущий рабочий способ запуска из исходников требует Windows, .NET SDK 10 и Node.js/npm. Из корня репозитория выполнить последовательно:

```powershell
npm ci --prefix ide
npm ci --prefix ide/e2e
dotnet build src/Axiom.Cli -c Release
dotnet build src/Axiom.DesktopHost -c Debug
.\run-ide.bat
```

`run-ide.bat` проверяет наличие и свежесть DesktopHost, затем запускает Electron. Сборки .NET используют `.artifacts/bin` и `.artifacts/obj`; команды с общей промежуточной папкой выполняются последовательно. Поставка для компьютера без SDK/Node пока не принята.

## Работа с программой

Открыть файл `.axm` в IDE, проверить исходник, затем запустить его. Поддержаны отдельные документы, четыре глобальные темы (светлая, тёмная, QuickBASIC и Borland Pascal), диагностика во время набора, форматирование Classic/Modern, дополнение, вывод, `INPUT`, графика и трассировка. `CANVAS` открывается нативным окном DirectX служебного процесса: игровые кадры рисуются и показываются на GPU, при недоступности подходящего устройства используется WARP. Графические режимы `SCREEN 1..10` также используют DirectX: страницы, палитра, примитивы и общий текстовый слой обрабатываются на GPU без полного CPU-снимка при обычной публикации. Для `POINT`, `GET`/`PUT` и совместимой `PAINT` доступны явные читающие пути; сложные дуги передаются подготовленным набором точек. `SCREEN 0` сохраняет текстовый режим. Язык исполняет `BytecodeVm`.

Сохранение проверяет исходную версию файла и пишет под исключительным дескриптором. Внешние изменения требуют решения пользователя. После аварии восстанавливаются завершённые правки, безымянные и отсутствующие документы, выбранная вкладка; программа автоматически не запускается. Восстановление не включает историю отмены и точки останова. Подробности сохранности документов — в локальных отчётах `reports/electron/` (в репозиторий не публикуются).

## Проверки

Проверки разделены на логические группы; полный каталог и правила выбора — [TESTING.md](TESTING.md). Единая точка запуска:

```powershell
.\scripts\test.ps1 list
.\scripts\test.ps1 lexer
.\scripts\test.ps1 ide-unit-renderer
.\scripts\test.ps1 e2e-editor
.\scripts\test.ps1 all
```

На 17 октября 2026 года: 10 проектов .NET, 41 файл Node-тестов (270 тестов), 63 файла Electron-сценариев (471 сценарий) и 799 приёмочных программ `.axm`. Просмотр каталога без запуска приложения: `node ide/e2e/runner.js --list`, список групп — `node ide/e2e/runner.js --groups`. Подготовка, изоляция и ограничения: [инструкция набора](../ide/e2e/README.md).

Проверка документации и действующего реестра:

```powershell
dotnet run --project scripts/language-audit/Axiom.LanguageAudit.csproj -- C:/Axiom --inventory-only --output-dir .artifacts/language-inventory-current
node scripts/check-manual.mjs --inventory .artifacts/language-inventory-current/inventory.json
powershell -NoProfile -File scripts/ai-context.ps1 -StdoutOnly
```

Проверки языка и служебных компонентов запускаются по группам (`lexer`, `parser`, `semantics`, `bytecode`, `execution`, `runtime`, `cli`, `ide-backend`, `ide-dotnet`) или целиком через `dotnet test Axiom.sln` последовательно. Проверка CLI без исполнения: `dotnet run --project src/Axiom.Cli -- check samples/smoke/bytecode-only/compiler_execution.axm --json`.

## Версии

Номера языка, компилятора и IDE независимы и задаются в [versions.json](../versions.json). Текущие номера и изменения — в [истории версий](CHANGELOG.md), порядок повышения — в [VERSIONING.md](VERSIONING.md). Начальная основа новой нумерации — 0.1.0; дальнейшие правки повышают затронутые компоненты.

```powershell
node scripts/versioning.mjs install-hooks
node scripts/versioning.mjs check
node scripts/versioning.mjs bump ide patch "Описание исправления IDE"
```

Обработчик Git проверяет версии перед коммитом, GitHub Actions — при публикации. `npm --prefix ide run prepare` подключает локальный обработчик автоматически. В «Справка → О программе» отображаются IDE, язык Axiom и компилятор/CLI без Git-ревизии.

## Переносимая папка приложения

На компьютере разработчика выполнить `node scripts/package-ide.mjs`. Результат: `.artifacts/distribution/Axiom IDE/Axiom IDE.exe`. Переносить всю папку; пользователь запускает exe без установки SDK, Git и Node.js. В составе находятся справочник и примеры. Адресная автоматическая проверка копии по пути с кириллицей/пробелами и недоступными инструментами разработки: `node ide/e2e/portable-smoke.cjs`. Выпуск предназначен для Windows x64; установщик и другие платформы этой командой не создаются.

## Параметры редактора

Параметры открываются командой «Настройки» справа на строке меню или сочетанием Ctrl+,. Диалог содержит восемь вкладок, поиск по всем настройкам, русские и английские пояснения при наведении и фокусе, а также предпросмотр шрифта и темы. Закреплённые строки отключаются на вкладке «Прокрутка и обзор». «Применить» сохраняет изменения без закрытия окна; «ОК» сохраняет и закрывает; «Отмена» отбрасывает изменения после последнего применения. Выбранные параметры сохраняются между запусками. Подробности: [договор диалога](plans/EDITOR_SETTINGS_DIALOG.md).

Недоступные возможности текущего Axiom остаются в параметрах видимыми, но отключёнными и бледными; причина объясняется на русском и английском. Поэлементные сценарии действия всех 261 пункта, результаты и границы проверки — в локальном отчёте `reports/electron/EDITOR_SETTINGS_LIVE_AUDIT.md` (в репозиторий не публикуется).

## Навигация по подпрограммам

Левая панель «Структура программы» показывает объявления активного документа. Поиск отбирает имена без учёта регистра; фильтр разделяет процедуры, функции и типы. Список можно упорядочить по исходнику или имени. Звёздочка закрепляет объявление наверху отдельно для каждого файла. Наведение показывает сигнатуру, строки и комментарий объявления. Текущая подпрограмма отмечается при движении курсора; кнопка «Следовать за курсором» включает прокрутку к ней.

В поиске стрелка вниз переводит фокус в список, Enter открывает результат, Escape очищает запрос. В списке работают стрелки, Home/End и Enter; Escape возвращает фокус в поиск. Закрепления, фильтр, порядок и следование сохраняются в профиле; запрос и прокрутка сохраняются между открытыми вкладками в текущем сеансе.

## Тематические разделы программы

Для группировки соседних подпрограмм добавьте отдельные строки комментариев:

```basic
' #region Игровая логика
SUB UpdateGameStep()
    PRINT "Шаг игры"
END SUB
' #endregion
```

Кнопка «Группы» переключает разделы и плоский список. Треугольник у названия сворачивает раздел; рядом с кнопкой доступны команды разворачивания и сворачивания всех групп. Состояние сохраняется отдельно для файла. Разделы могут быть вложенными; объявления без раздела остаются видимыми снаружи. Закреплённые подпрограммы выносятся наверх без дублирования.

Поиск учитывает имена подпрограмм и названия разделов, временно раскрывает найденные группы и после очистки возвращает прежнюю свёрнутость. Если включено следование за курсором, переход в тело подпрограммы раскрывает её группу. Метки также позволяют сворачивать участки кода в редакторе. В дополнениях доступна заготовка #region с обеими границами.

Метки пишутся с апострофом, на отдельных строках, регистр не важен. Они являются комментариями и не влияют на исполнение. Для панели располагайте их между целыми подпрограммами; метки внутри тела подпрограммы используются только для сворачивания кода в редакторе. Пропущенная закрывающая метка продолжает группу до конца файла и вызывает пояснение в панели. Реальный пример разметки — samples/graphics/game/maze_chase.axm.

Команды навигатора под полями фильтра и порядка представлены компактными значками: дерево — режим групп, прицел — следование за курсором, расходящиеся стрелки — раскрытие всех групп, сходящиеся — сворачивание. Подсказка при наведении сообщает назначение, включённые команды отмечены цветом значка.

Команды раскрытия и сворачивания объединены в одну кнопку. При наличии свёрнутой группы она показывает значок раскрытия и подсказку «Развернуть все группы»; когда все отображаемые группы открыты — значок сворачивания и «Свернуть все группы». Три значка команд выровнены по правому краю панели.

## Помощник по подпрограммам

Откройте контекстное меню подпрограммы в левой панели или редакторе. Команды «Кто вызывает» и «Что вызывает» показывают дерево связей в нижней вкладке «Помощник». Значок связей справа над списком открывает исходящие связи подпрограммы под курсором; вне подпрограмм показывает основной код. В дереве доступны переходы к объявлениям и отдельным местам использования. Повторение узла в цепочке отмечается явно; ветвь можно изучать по уровням.

Данные поступают из связанного дерева компилятора для текущего буфера файла. Учитываются локальные функции, методы, перегрузки и встроенные функции. Прямой вызов, регистрация обработчика и ссылка на функцию обозначаются отдельно. Для вызова через переменную помощник показывает место и сообщает, что адресат зависит от значения. Статические связи описывают устройство программы; фактические значения и выполненные ветви изучаются средствами трассировки.

«Быстрый просмотр» открывает выбранное объявление в редакторе только для чтения внутри вкладки помощника. Переходы записываются в историю: кнопки «Назад»/«Вперёд», а в основном редакторе Alt+←/Alt+→ возвращают положение, выделение и прокрутку. История сохраняется в текущем сеансе и ограничена ста переходами. Правки перед сохранённой позицией отслеживаются; закрытые документы из истории исключаются.

Значки рядом с объявлениями и группами сообщают число ошибок и предупреждений. Щелчок открывает первую проблему с приоритетом ошибки; фильтр «С проблемами» оставляет соответствующие объявления. После изменения исходника старые отметки скрываются до новой проверки. Изменение документа также делает открытый граф или просмотр устаревшим; кнопка обновления получает новый снимок.

Для создания раздела выделите соседние объявления и выберите «Объединить в раздел…» в контекстном меню либо палитре команд. При пустом выделении используется выбранная подпрограмма. Диалог показывает количество объявлений и диапазон строк; название вводится перед применением. Обе границы вставляются одной отменяемой операцией. Команда «Переименовать раздел…» находится в контекстном меню заголовка группы. Пересекающиеся границы и изменение текста во время диалога отклоняются; редактирование недоступно в документе только для чтения. Для групп панели используются объявления верхнего уровня.

## Приёмка существующего исполнения

Общие службы DesktopHost можно проверять отдельно от редактора: `dotnet test tests/Axiom.Ide.Backend.Tests/Axiom.Ide.Backend.Tests.csproj`. Проект включён в решение и подтверждает очистку кэша после отказов компиляции (границы проверки BackendFailure — в локальном отчёте `reports/electron/BACKEND_FAILURE_ACCEPTANCE.md`).

16 октября 2026 года закрыты едиными этапами отказы и запоздалые ответы команд существующего исполнения: подготовка и запуск (IDE 0.6.3–0.6.4), диапазоны диагностик LF/CRLF и UTF-16 (0.6.5), Stop/Restart (0.6.6), отказы команд отладки (0.6.9), принадлежность владельца исполнения при `Сохранить как` на паузе (0.6.14). Каждый этап подтверждён адресной выборкой Node/Electron, а не полным прогоном каталога; точные результаты и границы — в отчётах `docs/reports/electron/` и в [текущем состоянии](agent/CURRENT_STATE.md).


## Публикация справочника на GitHub Pages

Справочник `docs/manual/` — это статический сайт. Публикацию выполняет workflow `.github/workflows/pages.yml`. Страницы справочника ссылаются на примеры как `../../samples/*` (путь для локального просмотра из репозитория). На сайте страницы лежат в корне `/Axiom/`, поэтому такой путь уводит выше корня и ведёт к 404; сборка переписывает эти ссылки на страницы GitHub вида `https://github.com/softhitssofthits-dotcom/Axiom/blob/HEAD/samples/...`, где `.axm` открывается как исходный код. Дополнительно сборка добавляет `.nojekyll` и `robots.txt` с запретом индексации. Запуск только ручной (`workflow_dispatch`), автопубликация не настроена.

Pages включён (источник — GitHub Actions), сайт опубликован: <https://softhitssofthits-dotcom.github.io/Axiom/>. Его адрес также указан в поле Homepage репозитория.

Обновить сайт после правок справочника:

1. пройти проверки справочника (`node scripts/check-manual.mjs`);
2. закоммитить и запушить изменения в `master`;
3. запустить workflow «Публикация справочника» (кнопка Run workflow в разделе Actions).

Проверка сборки локально: скопировать содержимое `docs/manual` в отдельную папку, рядом положить `samples/`, добавить `.nojekyll` и `robots.txt`, затем открыть `index.html`.
