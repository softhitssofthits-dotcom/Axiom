# Руководство разработчика Axiom

Этот документ описывает сборку, запуск из исходников, проверки и сопровождение версий. Общее описание проекта — в [README](../README.md), пользовательский справочник языка — в [справочнике](manual/index.html).

## Что это за продукт

Axiom — BASIC-подобный язык с компиляцией в байт-код и настольная IDE на Electron. Ядро языка и служебный процесс написаны на C#/.NET 10; редактор использует Monaco, консоль — xterm.js.

## Подготовка и запуск

Текущий рабочий способ запуска из исходников требует Windows, .NET SDK 10 и Node.js/npm. Из корня репозитория выполнить последовательно:

```powershell
npm ci --prefix ide
npm ci --prefix ide/e2e
dotnet build src/Axiom.Cli -c Release
dotnet build src/Axiom.DesktopHost -c Debug
.\run-ide.bat
```

`run-ide.bat` проверяет наличие и свежесть DesktopHost, затем запускает Electron. Сборки .NET используют `.artifacts/bin` и `.artifacts/obj`; команды с общей промежуточной папкой выполняются последовательно. Поставка для компьютера без SDK/Node пока не принята.

## Работа с программой

Открыть файл `.axm` в IDE, проверить исходник, затем запустить его. Поддержаны отдельные документы, четыре глобальные темы (светлая, тёмная, QuickBASIC и Borland Pascal), диагностика во время набора, форматирование Classic/Modern, дополнение, вывод, `INPUT`, графика и трассировка. `CANVAS` открывается нативным окном DirectX служебного процесса: игровые кадры рисуются и показываются на GPU, при недоступности подходящего устройства используется WARP. Графические режимы `SCREEN 1..10` также используют DirectX: страницы, палитра, примитивы и общий текстовый слой обрабатываются на GPU без полного CPU-снимка при обычной публикации. Для `POINT`, `GET`/`PUT` и совместимой `PAINT` доступны явные читающие пути; сложные дуги передаются подготовленным набором точек. `SCREEN 0` сохраняет текстовый режим. Язык исполняет `BytecodeVm`.

Сохранение проверяет исходную версию файла и пишет под исключительным дескриптором. Внешние изменения требуют решения пользователя. После аварии восстанавливаются завершённые правки, безымянные и отсутствующие документы, выбранная вкладка; программа автоматически не запускается. Восстановление не включает историю отмены и точки останова. Подробности сохранности документов — в локальных отчётах `reports/electron/` (в репозиторий не публикуются).

Текущие номера и изменения — в [истории версий](CHANGELOG.md), порядок повышения — в [VERSIONING.md](VERSIONING.md). ```powershell
node scripts/versioning.mjs install-hooks
node scripts/versioning.mjs check
node scripts/versioning.mjs bump ide patch "Описание исправления IDE"

## Параметры редактора

Параметры открываются командой «Настройки» справа на строке меню или сочетанием Ctrl+,. Диалог содержит восемь вкладок, поиск по всем настройкам, русские и английские пояснения при наведении и фокусе, а также предпросмотр шрифта и темы. Недоступные возможности текущего Axiom остаются в параметрах видимыми, но отключёнными и бледными; причина объясняется на русском и английском. Поэлементные сценарии действия всех 261 пункта, результаты и границы проверки — в локальном отчёте `reports/electron/EDITOR_SETTINGS_LIVE_AUDIT.md` (в репозиторий не публикуется).

## Навигация по подпрограммам

Левая панель «Структура программы» показывает объявления активного документа. Поиск отбирает имена без учёта регистра; фильтр разделяет процедуры, функции и типы. Список можно упорядочить по исходнику или имени. Звёздочка закрепляет объявление наверху отдельно для каждого файла. Наведение показывает сигнатуру, строки и комментарий объявления. Текущая подпрограмма отмечается при движении курсора; кнопка «Следовать за курсором» включает прокрутку к ней.

В поиске стрелка вниз переводит фокус в список, Enter открывает результат, Escape очищает запрос. В списке работают стрелки, Home/End и Enter; Escape возвращает фокус в поиск. Закрепления, фильтр, порядок и следование сохраняются в профиле; запрос и прокрутка сохраняются между открытыми вкладками в текущем сеансе.

## Тематические разделы программы

Для группировки соседних подпрограмм добавьте отдельные строки комментариев:

```basic
' #region Игровая логика
SUB UpdateGameStep()
    PRINT "Шаг игры"
END SUB
' #endregion
```

Кнопка «Группы» переключает разделы и плоский список. Треугольник у названия сворачивает раздел; рядом с кнопкой доступны команды разворачивания и сворачивания всех групп. Состояние сохраняется отдельно для файла. Разделы могут быть вложенными; объявления без раздела остаются видимыми снаружи. Закреплённые подпрограммы выносятся наверх без дублирования.

Поиск учитывает имена подпрограмм и названия разделов, временно раскрывает найденные группы и после очистки возвращает прежнюю свёрнутость. Если включено следование за курсором, переход в тело подпрограммы раскрывает её группу. Метки также позволяют сворачивать участки кода в редакторе. В дополнениях доступна заготовка #region с обеими границами.

Метки пишутся с апострофом, на отдельных строках, регистр не важен. Они являются комментариями и не влияют на исполнение. Для панели располагайте их между целыми подпрограммами; метки внутри тела подпрограммы используются только для сворачивания кода в редакторе. Пропущенная закрывающая метка продолжает группу до конца файла и вызывает пояснение в панели. Реальный пример разметки — samples/graphics/game/maze_chase.axm.

Команды навигатора под полями фильтра и порядка представлены компактными значками: дерево — режим групп, прицел — следование за курсором, расходящиеся стрелки — раскрытие всех групп, сходящиеся — сворачивание. Подсказка при наведении сообщает назначение, включённые команды отмечены цветом значка.

Команды раскрытия и сворачивания объединены в одну кнопку. При наличии свёрнутой группы она показывает значок раскрытия и подсказку «Развернуть все группы»; когда все отображаемые группы открыты — значок сворачивания и «Свернуть все группы». Три значка команд выровнены по правому краю панели.

## Помощник по подпрограммам

Откройте контекстное меню подпрограммы в левой панели или редакторе. Команды «Кто вызывает» и «Что вызывает» показывают дерево связей в нижней вкладке «Помощник». Значок связей справа над списком открывает исходящие связи подпрограммы под курсором; вне подпрограмм показывает основной код. В дереве доступны переходы к объявлениям и отдельным местам использования. Повторение узла в цепочке отмечается явно; ветвь можно изучать по уровням.

Данные поступают из связанного дерева компилятора для выбранного файла и достижимых через IMPORT модулей. Открытые зависимости берутся из снимка редактора, закрытые — с диска. Учитываются локальные функции, методы, перегрузки и встроенные функции. Одноимённые закрытые подпрограммы разных модулей имеют независимые узлы; подписи показывают имя файла. В исходящем дереве основного кода отдельные ветви дают доступ к основному коду зависимостей. Прямой вызов, регистрация обработчика и ссылка на функцию обозначаются отдельно. Для вызова через переменную помощник показывает место и сообщает, что адресат зависит от значения. Статические связи описывают устройство программы; фактические значения и выполненные ветви изучаются средствами трассировки.

Переход к объявлению или месту использования открывает соответствующий файл и сверяет его текст с исходным снимком перед применением координат. Изменение открытой зависимости делает панель устаревшей. Поздний переход не меняет курсор и историю после выбора другой вкладки или нового представления панели. Перемещение каретки исходного документа во время открытия отменяет переход; проверка выполняется до создания вкладки.

Значок дома в помощнике выбирает активный именованный `.axm` как общую точку входа навигации. После этого граф и поиск из модулей той же папки включают достижимые `IMPORT` выбранного файла, в том числе вызывающий код точки входа. Повторный выбор снимает точку входа; закрытие выбранного документа также снимает выбор. Переименование сохраняет выбор по идентичности документа. Настройка действует в текущем сеансе, использует несохранённый текст и не меняет файл запуска. Для документа вне состава выбранной программы показывается причина отказа. Документы другой папки анализируются независимо.

Команды редактора «Перейти к объявлению» (F12) и «Найти использования» (Shift+F12) используют индекс связанных символов: `SUB`, `FUNCTION`, переменные, параметры, константы, `TYPE` и поля. Поиск включает объявление; одно найденное определение открывается сразу, остальные результаты доступны в помощнике. Перегрузки и одинаковые имена разных областей различаются по символу. Индекс учитывает именованные поля литерала записи, создание записи и константы фиксированных размеров. На правой границе имени F12 также работает. Ошибочный текст даёт частичный результат, отвергнутые объявления не становятся определениями. Встроенным именам не назначаются выдуманные исходные объявления. Автоматический поиск всех файлов папки и межфайловое переименование остаются отдельной работой.

«Быстрый просмотр» открывает выбранное объявление в редакторе только для чтения внутри вкладки помощника. Переходы записываются в историю: кнопки «Назад»/«Вперёд», а в основном редакторе Alt+←/Alt+→ возвращают положение, выделение и прокрутку. История сохраняется в текущем сеансе и ограничена ста переходами. Правки перед сохранённой позицией отслеживаются; закрытые документы из истории исключаются.

Значки рядом с объявлениями и группами сообщают число ошибок и предупреждений. Щелчок открывает первую проблему с приоритетом ошибки; фильтр «С проблемами» оставляет соответствующие объявления. После изменения исходника старые отметки скрываются до новой проверки. Изменение документа также делает открытый граф или просмотр устаревшим; кнопка обновления получает новый снимок.

Для создания раздела выделите соседние объявления и выберите «Объединить в раздел…» в контекстном меню либо палитре команд. При пустом выделении используется выбранная подпрограмма. Диалог показывает количество объявлений и диапазон строк; название вводится перед применением. Обе границы вставляются одной отменяемой операцией. Команда «Переименовать раздел…» находится в контекстном меню заголовка группы. Пересекающиеся границы и изменение текста во время диалога отклоняются; редактирование недоступно в документе только для чтения. Для групп панели используются объявления верхнего уровня.

## Публикация справочника на GitHub Pages

Справочник `docs/manual/` — это статический сайт. Публикацию выполняет workflow `.github/workflows/pages.yml`. Страницы справочника ссылаются на примеры как `../../samples/*` (путь для локального просмотра из репозитория). На сайте страницы лежат в корне `/Axiom/`, поэтому такой путь уводит выше корня и ведёт к 404; сборка переписывает эти ссылки на страницы GitHub вида `https://github.com/softhitssofthits-dotcom/Axiom/blob/HEAD/samples/...`, где `.axm` открывается как исходный код. Дополнительно сборка добавляет `.nojekyll` и `robots.txt` с запретом индексации. Запуск только ручной (`workflow_dispatch`), автопубликация не настроена.

Pages включён (источник — GitHub Actions), сайт опубликован: <https://softhitssofthits-dotcom.github.io/Axiom/>. Его адрес также указан в поле Homepage репозитория.

Обновить сайт после правок справочника:

1. пройти проверки справочника (`node scripts/check-manual.mjs`);
2. закоммитить и запушить изменения в `master`;
3. запустить workflow «Публикация справочника» (кнопка Run workflow в разделе Actions).

Проверка сборки локально: скопировать содержимое `docs/manual` в отдельную папку, рядом положить `samples/`, добавить `.nojekyll` и `robots.txt`, затем открыть `index.html`.

## Запуск сохранённых модулей

`dotnet run --project src/Axiom.Cli -- run samples/operators/import/main.axm` запускает точку входа и явно импортированные зависимости из её папки. Команда `check` загружает такой же состав, но не исполняет его. В Electron запускается активный сохранённый файл; открытые именованные зависимости берутся из снимка редактора, включая несохранённые изменения, а закрытые — с диска. Сохранение зависимостей для такого запуска не требуется. Посторонние `.axm` в папке автоматически не включаются в программу.

Для встраивания без диска передавайте SourceName и AdditionalDocuments в CompilationRequest/ExecutionRequest. Compile и Run используют одинаковый состав. SourceProject.LoadDependencies предоставляет общий загрузчик для CLI и служб IDE. Отсутствующая зависимость остаётся семантической ошибкой MB2049. Смена текста зависимости инвалидирует кэш ProgramRunService даже при неизменной точке входа.

Третий параметр `SourceProject.LoadDependencies` принимает заменяющие тексты открытых документов. В IPC необязательное поле `projectDocuments` содержит путь, текст, идентификатор и редакцию; принимаются только разные именованные `.axm` из папки точки входа. DocumentStore фиксирует снимок синхронно, DocumentServices проверяет актуальность всех его документов перед применением ответа. Форматирование одного файла не зависит от соседних модулей. Общий пакет ограничен существующим пределом IPC в 16 МБ.

ProgramRunService сохраняет фактический состав в CurrentSourceDocuments. DesktopHost передаёт использованный текст файла ошибки или остановки один раз на сессию; редактор сравнивает его с текущей моделью, даже если файл был закрыт при старте. Правка во время INPUT или отладки не меняет уже скомпилированный запуск. Чтобы выполнить изменённую зависимость, программу запускают заново.

Постоянные проверки модульного конвейера: ModuleSyntaxTests, ModuleVisibilityTests, ModuleExecutionTests, ModuleRegressionTests и SourceProjectTests. Проверки оболочки: `node ide/e2e/runner.js modules.spec.js --out .artifacts/modules-e2e.json`. Пользовательский договор изложен в `docs/manual/modules.html`, `import.html`, `visibility.html`.

## Размещение временных данных на разных компьютерах — 20 октября 2026 года

Общий договор остаётся переносимым: сборки и проверки обращаются к `.artifacts` внутри своей копии репозитория. Наличие второго диска не требуется. На ноутбуке с единственным диском C это обычная локальная папка; номера дисков другого компьютера не переносятся через Git.

На основном компьютере наиболее объёмный поток данных — изолированные профили Electron в `C:\Axiom\.artifacts\ide-shell\e2e`. Их физическое хранилище перенесено в `F:\Axiom-artifacts\ide-shell\e2e`, а по исходному пути создана локальная ссылка каталога Windows (`Junction`). Скрипты продолжают использовать `.artifacts/ide-shell/e2e/<pid>`; новые прогоны пишут на F. Ссылка и содержимое временных каталогов не публикуются в Git. Этот локальный выбор не меняет `Directory.Build.props` и не задаёт диск F как обязательный для проекта.

Перед переносом закрывают IDE и останавливают её проверки, проверяют абсолютные исходный и конечный пути и свободное место. Для восстановления такой конфигурации на другом компьютере сначала выбирают существующий локальный диск; если второго диска нет, ссылку не создают. Содержимое каталога должно быть перенесено полностью до запуска проверок через ссылку. При отсутствии диска назначения сначала восстанавливают доступность хранилища, а не запускают проверку с повреждённой ссылкой. Проверка локальной настройки: `Get-Item -LiteralPath C:\Axiom\.artifacts\ide-shell\e2e | Format-List FullName,LinkType,Target`.

Текущие `.artifacts/bin` и `.artifacts/obj` оставлены на C: они небольшие и используются рабочими сборками. Отчёты последних полных и адресных прогонов сохраняются отдельно от профилей, в том числе `full-test-20261020-080753` и `test-repair-20261020`. Старые профили — воспроизводимые данные проверки, но отчёты и материалы незакрытых ошибок следует сохранять до завершения работы. Перенос на другой диск уменьшает нагрузку на C, однако не вводит автоматический срок хранения: его по-прежнему нужно контролировать отдельно.

## Открытие проекта и выбранный запуск — 20 октября 2026 года

В IDE 0.7.0 «Файл → Открыть проект» открывает все .axm папки во вкладках, удаляя только пустую стартовую. В поле «Файл запуска» автоматически выбирается корневой main.axm либо единственный исходник; неоднозначный состав требует выбора. Выбор сохраняется в локальном профиле для папки. Запуск и начало отладки из документа проекта используют выбранный исходник, независимо от активной вкладки. Внешний файл остаётся самостоятельным. Закрытая вкладка запуска открывается по требованию, удалённая точка не заменяется молча другим файлом.

Это уточняет прежний договор папки как простого списка. Значок точки входа помощника по-прежнему управляет анализом; при открытии проекта он первоначально получает выбранный запускной документ. При перезапуске IDE восстанавливаются оставленные открытыми вкладки и сохранённый выбор, без навязывания закрытых пользователем вкладок. Рекурсивный список папки не расширяет правила IMPORT: файлы одной программы по-прежнему должны лежать рядом с её точкой входа.

### 2026-10-20 — проверка проекта и карточки проблем

В открытом проекте выбранный файл запуска определяет не только выполнение, но и граф IMPORT для фонового анализа и команды проверки. Несохранённые исходники учитываются без записи на диск. Файл вне этого графа проверяется самостоятельно. Это уточняет прежний договор проверки активного документа из записи об открытии папки. Окно подробностей диагностики не закрывается обновлением результатов, пока его ошибка ещё существует; при исправлении текста или исчезновении диагностики карточка закрывается автоматически. Адресные сценарии: project-advice-cross-module-reads, project-advice-maze-config, diagnostic-peek-survives-live-analysis, interpolation-print-typo-location.

## Локальная проверка сложности и дублирования

В пользовательском каталоге навыков `C:\AI\skills\local-code-quality` установлен общий навык `$local-code-quality`: Lizard 1.24.1 измеряет сложность функций, jscpd 5.4.2 ищет повторяющиеся фрагменты. Зависимости находятся отдельно в `C:\AI\tools\local-code-quality`; исходники инструментов открыты под MIT. Обычный анализ не требует сети, аккаунта или токена. Пути относятся к этому компьютеру и не являются обязательным условием сборки Axiom. Ранее предложенный CodeScene отключён в пользовательской конфигурации Codex.

Из корня проекта можно проверить выбранные файлы:

```powershell
$quality = 'C:/AI/skills/local-code-quality/scripts'
$out = '.artifacts/code-quality/current'
New-Item -ItemType Directory -Path $out -Force | Out-Null
& "$quality/lizard.ps1" src/Axiom.Core/CanonicalTemporalText.cs ide/src/renderer/ui-controls.js -i -1 --xml -o "$out/lizard.xml"
& "$quality/jscpd.ps1" src/Axiom.Core/CanonicalTemporalText.cs ide/src/renderer/ui-controls.js --format 'csharp,javascript' --fail-on-empty --reporters json --output $out --no-colors --no-tips
```

После каждого вызова проверяется `$LASTEXITCODE`; ненулевой код контроля порога отличают от ошибки запуска по диагностике и отчёту. Полные примеры, исключения производных файлов и порядок сравнения до/после находятся в `C:\AI\skills\local-code-quality\SKILL.md`. При выборе каталогов исходников нужны явные исключения: Lizard не ищет родительский `.gitignore`, а `--ignore` у jscpd фильтрует файлы без прекращения обхода папок. Отчёты и исходные сравнения хранятся только в `.artifacts/` активного проекта. Для сопоставления сохраняются одинаковые область, параметры и версии анализаторов.

Эти средства сокращают ручной поиск сложных функций и копирования. Разбор приблизительный: метрика может неверно представить конструкцию языка, а повторение может быть обоснованным. Собственная оценка jscpd не эквивалентна CodeScene Code Health; файлы `.axm` не анализируются. Найденные места требуют чтения кода и адресных проверок поведения. `docs/agent/` помогает извлекать проектный контекст, но не вычисляет метрики исходников; инструменты дополняют его, не вводя второй источник проектных решений. Действующие документы остаются источником истины. Нового обязательного порога для коммитов эта установка не вводит.

## Предварительный перевод массивов на квадратную запись

Начиная с языка 0.3.0 обычный компилятор требует квадратные обращения к массивам. Старый исходник можно проверить преобразователем без исполнения и записи файла:

```powershell
dotnet .artifacts/bin/Axiom.Cli/Release/net10.0/axiom.dll migrate-arrays samples/old-program.axm --json
Get-Content -Raw -Encoding UTF8 .artifacts/old-program.axm | dotnet .artifacts/bin/Axiom.Cli/Release/net10.0/axiom.dll migrate-arrays --stdin
```

Команда `migrate-arrays` без `--json` выводит подготовленный исходник в stdout, с `--json` — исходный/новый текст, правки в координатах UTF-16 и причины отказа. Файловый вход загружает зависимости IMPORT для разрешения имён; результат относится только к выбранному файлу. Ошибка любого переданного модуля запрещает применение. Преобразователь не выполняет программу, не записывает файлы, не предлагает второй режим исполнения языка. `--write`, неизвестные и повторные параметры отклоняются. Перед ручным сохранением нужно проверить предварительный результат; не направлять stdout в тот же входной файл. Пользовательские проекты автоматически не переписываются.

[Правила новой записи](manual/arrays-migration.html) и [план перехода](plans/ARRAY_SQUARE_BRACKETS_MIGRATION_2026-10-22.md) сохраняют границы изменения.
