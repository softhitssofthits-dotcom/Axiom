# План: структурированный журнал действий IDE

## Кратко

Добавить отдельный событийный журнал IDE поверх существующего текстового трассировщика. Он будет фиксировать действия пользователя, состояние отладки, вывод, команды, меню, документы, статус-бар и ошибки в структурированном виде, но запись не должна блокировать интерфейс.

Существующий `FileIdeTraceService` оставить как низкоуровневый технический лог. Новый журнал сделать отдельным слоем: `IIdeEventLogService` + файловая реализация с асинхронной записью.

## Хранение и доступ

- Основной формат: `JSON Lines`, один объект события на строку.
- Папка по умолчанию: `%LOCALAPPDATA%\Axiom\Logs\Events`.
- Имя файла сессии: `ide-events-YYYYMMDD-HHMMSS.jsonl`.
- Если `%LOCALAPPDATA%` недоступен, использовать `AppContext.BaseDirectory\Logs\Events`.
- В IDE добавить:
  - меню `Вид -> Журнал действий IDE`;
  - окно/панель журнала с таблицей: время, уровень, категория, событие, документ, строка, колонка, статус IDE, подробности;
  - кнопки `Открыть текущий файл`, `Открыть папку журналов`, `Очистить старые журналы`;
  - фильтры по уровню, категории, документу и тексту.

## Формат события

Каждая запись содержит стабильные поля:

- `schemaVersion`
- `sessionId`
- `sequence`
- `timestampUtc`
- `timestampLocal`
- `level`
- `category`
- `eventName`
- `source`
- `threadId`
- `documentPath`
- `documentName`
- `line`
- `column`
- `commandName`
- `menuName`
- `debugLine`
- `opcode`
- `callDepth`
- `canStepBack`
- `outputLength`
- `textLength`
- `textPreview`
- `statusBar`
- `properties`

`statusBar` должен быть структурированным снимком видимых полей статус-бара: текст состояния, строка, колонка, путь файла, время подготовки, время выполнения, общее время, состояние кэша, движок выполнения и другие текущие поля, если они показаны пользователю.

По умолчанию не писать полный исходный текст программы и большие вставки. Для набора, вставки и копирования фиксировать длину, короткий предпросмотр и при необходимости хеш.

## Производительность

- Все события складывать в ограниченную очередь, запись выполнять одним фоновым писателем.
- Поток интерфейса только создаёт короткий объект события и сразу продолжает работу.
- При переполнении очереди не подвешивать IDE: низкоприоритетные шумные события сжимать или отбрасывать с отдельной записью `events.dropped`.
- Частые события объединять:
  - перемещение курсора и изменение статус-бара сжимать за интервал примерно 250 мс;
  - повторные стрелки и выделение объединять;
  - набор текста писать пачками по паузе или по смене команды;
  - вывод терминала фиксировать по изменению буфера и при остановке отладчика.
- Принудительный сброс на диск делать при закрытии IDE и при необработанном исключении.

## Очистка

- Настройки по умолчанию:
  - хранить 14 дней;
  - общий лимит папки журналов: 200 МБ;
  - лимит одного файла: 20 МБ;
  - всегда сохранять последние 5 сессий.
- Очистку запускать при старте IDE и при переключении на новый файл журнала.
- Удалять самые старые файлы первыми.
- В IDE добавить ручные действия:
  - `Очистить старые журналы`;
  - `Очистить все журналы...` с подтверждением;
  - `Открыть папку журналов`.

## События первого среза

- Жизненный цикл IDE: запуск, закрытие, необработанные ошибки.
- Меню и команды: открыто главное меню, выбрана команда, команда недоступна.
- Документы: создать, открыть, сохранить, сохранить как, закрыть, переключить вкладку.
- Редактор: изменение текста, вставка, копирование, вырезание, отмена, повтор, перемещение курсора, изменение выделения.
- Статус-бар: отдельное событие `status-bar.changed` при изменении видимых полей и снимок `statusBar` внутри значимых событий.
- Отладка: запуск, продолжение, шаг вперёд, шаг назад, шаг внутрь, шаг наружу, остановка, текущее состояние остановки.
- Вывод: изменение текста вывода, запрос ввода, отправка ввода, откат вывода при шаге назад.
- Диагностика: ошибки чтения/записи журналов, переполнение очереди, пропущенные события.

## Этапы реализации

1. Добавить модель события, параметры журнала и сервис `IIdeEventLogService`.
2. Реализовать файловый асинхронный писатель, ротацию файлов и очистку старых журналов.
3. Подключить сервис в composition root IDE рядом с текущим `IIdeTraceService`.
4. Добавить окно/панель журнала и команды открытия файла, папки и очистки.
5. Инструментировать первый набор событий: запуск IDE, меню, команды, документы, статус-бар, отладка, вывод.
6. Отдельно добавить сжатое логирование шумных событий редактора: курсор, выделение, набор текста, частые обновления статус-бара.
7. Обновить `docs/SPECIFICATION3.md`, `docs/ARCHITECTURE.md`, `docs/PLANS3.md` и `docs/WORKLOG4.md`.

## Проверки

- Модульные тесты: запись корректного JSONL, монотонный `sequence`, экранирование многострочных данных.
- Тесты очистки: возраст, общий размер, размер файла, сохранение последних 5 сессий.
- Тесты производительности: переполненная очередь не блокирует вызывающий поток.
- Тесты сжатия: частые перемещения курсора, набор текста и изменения статус-бара объединяются.
- IDE-тесты: меню журнала существует, команды открытия/очистки вызывают нужные сервисы.
- Проверка сценария отладки: шаг вперёд/назад внутри `PrintBanner` пишет события остановки, изменения вывода, состояние статус-бара и доступность шага назад.

## Принятые допущения

- В первой версии не использовать системный Windows Event Log: журнал будет похож на него по структуре, но храниться в файлах проекта Axiom.
- Журнал включён по умолчанию.
- Полный текст программы и большие вставки не пишутся по умолчанию.
- Текущий технический `.log` не ломаем и не переносим в этом срезе.
