# Каталог проверок Axiom

Документ описывает, какие проверки есть в репозитории, на какие логические группы они разделены и какую группу запускать при конкретном изменении. Он нужен, чтобы не запускать весь набор ради одной правки: например, проверки лексера не относятся к поведению IDE.

Правило: сначала определяется затронутый слой, затем запускается **наименьшая подходящая группа**. Полный набор (`all`) — только по прямому поручению автора или перед крупной публикацией.

## Слои проверок

| Слой | Где лежит | Что проверяет | Объём на 17 октября 2026 года |
|---|---|---|---|
| Язык и VM (.NET) | `tests/` | Лексер, синтаксис, парсер, семантика, байткод, исполнение, runtime, CLI, бэкенд IDE | 10 проектов; 2 773 `Fact`, 355 `Theory`, 1 373 `InlineData` |
| Модули IDE (Node) | `ide/tests/` | Службы главного процесса, renderer-модули, доставка команд | 41 файл, 270 тестов |
| Оболочка IDE (Electron) | `ide/e2e/specs/` | Редактор, настройки, документы, запуск, отладка, графика, меню, локализация | 63 файла, 471 сценарий |
| Приёмочные программы | `samples/` | Операторы, функции, границы значений, графика, smoke | 799 файлов `.axm` |

Число сценариев Electron — это число зарегистрированных проверок, а не число успешных. Результаты прогонов лежат в `ide/e2e/evidence/`, временные — в `.artifacts/` (в Git не публикуются).

## Единая точка запуска

```powershell
.\scripts\test.ps1 list                 # список групп
.\scripts\test.ps1 lexer                # один проект .NET
.\scripts\test.ps1 ide-unit-renderer    # группа Node-тестов
.\scripts\test.ps1 e2e-language         # группа Electron-сценариев
.\scripts\test.ps1 ide                  # IDE: .NET + Node + Electron
.\scripts\test.ps1 all                  # весь набор (долго)
```

Для Electron можно дополнительно передать `-Filter <подстрока>`, `-From <id>` и `-Out <файл>`:

```powershell
.\scripts\test.ps1 e2e-settings -Filter suggest.insertMode
.\scripts\test.ps1 e2e-all -From editor-settings-live-lightbulb.enabled -Out .artifacts/e2e-continue.json
```

Напрямую runner также понимает группы и служебные команды:

```powershell
node ide/e2e/runner.js --groups
node ide/e2e/runner.js --group e2e-editor
node ide/e2e/runner.js --list
```

## Группы .NET

Запускаются последовательно: несколько `dotnet test` одновременно с общим `obj` запрещены.

| Группа | Проект | Когда запускать |
|---|---|---|
| `lexer` | `Axiom.Lexing.Tests` | Изменения токенизации, литералов, комментариев |
| `syntax` | `Axiom.Syntax.Tests` | Синтаксические узлы и их устройство |
| `parser` | `Axiom.Parsing.Tests` | Разбор выражений и инструкций |
| `semantics` | `Axiom.Semantics.Tests` | Связывание имён, типы, диагностика |
| `bytecode` | `Axiom.Bytecode.Tests` | Компиляция в байт-код |
| `execution` | `Axiom.Execution.Tests` | Подготовка и исполнение программ |
| `runtime` | `Axiom.Runtime.Tests` | Встроенные функции, значения, границы |
| `cli` | `Axiom.Cli.Tests` | Команды `axiom` и их вывод |
| `ide-backend` | `Axiom.Ide.Backend.Tests` | Общие службы DesktopHost |
| `ide-dotnet` | `Axiom.Ide.Tests` | Модель IDE на C# |
| `language` | Все языковые проекты | Сквозная правка языка без IDE |
| `dotnet-all` | `Axiom.sln` | Полная проверка .NET |

## Как выбрать группу

| Изменение | Минимальная группа |
|---|---|
| Токенизация, литералы | `lexer` |
| Разбор выражений/инструкций | `parser`, при необходимости `syntax` |
| Имена, типы, диагностика языка | `semantics` |
| Байт-код, VM, встроенные функции | `bytecode`, `execution` или `runtime` |
| Команды CLI | `cli` |
| Службы DesktopHost | `ide-backend` |
| Модуль главного процесса IDE | `ide-unit-main` |
| Модуль renderer | `ide-unit-renderer` |
| Доставка команд, устаревшие ответы | `ide-unit-delivery` |
| Поведение редактора | `e2e-editor` |
| Диалог настроек | `e2e-settings` |
| Документы и сохранение | `e2e-documents` |
| Запуск, консоль, ввод | `e2e-execution` |
| Отладка | `e2e-debug` |
| Графика | `e2e-graphics` |
| Меню, темы, локализация, справка | `e2e-shell` |
| Языковые формы в редакторе | `e2e-language` |

Если правка затрагивает несколько слоёв, запускаются соответствующие группы по очереди; `ide` объединяет `.NET`-часть IDE, Node-модули и Electron.

## Особенности и границы

- Electron-сценарии требуют интерактивного рабочего стола; их нельзя считать аппаратной приёмкой DPI, мониторов и физической мыши.
- `ide/tests/desktop-host.test.cjs` содержит нативный CANVAS-сценарий, которому нужен Hardware/WARP; на части окружений он падает по аппаратной причине.
- Полный прогон Electron пишет `ide/e2e/evidence/results.json` только в конце; для длинных прогонов используйте `-Out` и `--from`, чтобы не потерять результат.
- `samples/*.axm` — запускаемые приёмочные программы, а не автоматические тесты. Их проверяют через `axiom check`, ручной запуск в IDE или существующие сценарии.
- `.artifacts/` и локальные снимки `FAIL_*` не публикуются в Git.
