Раздел

Обработка пользовательских ошибок

Раздел обработки ошибок описывает средства Axiom для создания и перехвата ошибок времени выполнения: блок TRY ... CATCH ... FINALLY ... END TRY, оператор ERROR и встроенный тип ERROR.

Как работает обработка

Оператор ERROR создаёт пользовательскую ошибку времени выполнения или повторно поднимает уже пойманное значение ошибки. Если выполнение находится внутри подходящего блока TRY, управление переходит к CATCH. Если обработчика нет, программа завершается диагностикой времени выполнения с указанным кодом и сообщением.

Здесь важно различать два похожих имени. ERROR как оператор создаёт или повторно поднимает ошибку. ERROR как встроенный тип — это значение, которое получает переменная в строке CATCH err.

В QuickBASIC обработка ошибок строилась вокруг ON ERROR GOTO и перехода к метке. В Axiom используется блочный TRY ... CATCH ... FINALLY, а оператор ERROR служит для создания или повторного проброса значения ошибки.

Основные формы

ERROR код
ERROR код, сообщение
ERROR ошибка

код и сообщение являются выражениями типа STRING. Код может быть проектным кодом вроде "APP001". Если сообщение не указано, Axiom формирует сообщение по умолчанию. ошибка должна иметь тип ERROR и обычно берётся из CATCH err.

Перехват

TRY
    ERROR "APP001", "Manual failure"
CATCH err
    PRINT err.Code
    PRINT err.Message
END TRY

PRINT "after"

После выполнения ERROR строки внутри TRY ниже этого оператора не выполняются. В CATCH переменная err доступна только для чтения и содержит сведения о перехваченной ошибке.

Передача ошибки дальше

TRY
    TRY
        ERROR "APP003", "Original failure"
    CATCH err
        PRINT "local cleanup"
        ERROR err
    END TRY
CATCH outerErr
    PRINT outerErr.Code
    PRINT outerErr.Message
    PRINT outerErr.Line
END TRY

ERROR err повторно поднимает уже пойманное значение ERROR. Внешний обработчик видит исходные Code, Message, Line и Column, поэтому такая форма подходит для локальной очистки, журналирования или преобразования управления без скрытия места первоначальной ошибки.

Значение ERROR

В этом разделе ERROR означает встроенный тип значения ошибки, а не строку оператора ERROR код.

ПолеТипСмысл
CodeSTRINGПолный код ошибки. Для системных ошибок времени выполнения это код вроде MB3001, для пользовательских ошибок - строка, переданная в ERROR.
MessageSTRINGТекст сообщения об ошибке.
LineINTEGERСтрока исходного текста, где возникла ошибка, или 0, если место неизвестно.
ColumnINTEGERКолонка исходного текста, где возникла ошибка, или 0, если место неизвестно.

Ограничения

  • CATCH пока не фильтрует ошибки по коду или типу.
  • В одном блоке TRY поддерживается не более одного CATCH.
  • RESUME, ON ERROR GOTO и продолжение с точки ошибки не поддерживаются.
  • TRY/CATCH/FINALLY, ERROR код, ERROR код, сообщение и ERROR err выполняются BytecodeVm после компиляции.

Ручная проверка

  • ERROR: пользовательский код и перехват через CATCH
  • ERROR: повторный проброс пойманной ошибки
  • TRY: перехват системной ошибки времени выполнения и FINALLY
