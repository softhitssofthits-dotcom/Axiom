Оператор OPEN

OPEN — оператор языка Axiom, который открывает файл для чтения, записи или дописывания. Оператор связывает файл с заранее объявленной переменной типа FILE, через которую далее работают все файловые операции.

Как OPEN связывает файл с переменной

Оператор OPEN открывает текстовый файл и связывает его с переменной типа FILE. В Axiom файл открывается не по историческому номеру, а сразу в именованную переменную.

Где работает оператор OPEN

Оператор OPEN работает в любом контексте программы и не зависит от графического режима SCREEN. Файловые операции доступны в текстовом, графическом и консольном режимах одинаково.

Синтаксис

Чтение с автоматическим выбором кодировки

OPEN path FOR INPUT AS fileVariable

Запись в UTF-8 без BOM

OPEN path FOR OUTPUT AS fileVariable

Дописывание в UTF-8 без BOM

OPEN path FOR APPEND AS fileVariable

Чтение с выбранной кодировкой

OPEN path FOR INPUT AS fileVariable USING encoding

Запись с выбранной кодировкой

OPEN path FOR OUTPUT AS fileVariable USING encoding

Дописывание с выбранной кодировкой

OPEN path FOR APPEND AS fileVariable USING encoding

USING encoding — расширение Axiom, а не историческая форма кодировки QuickBASIC.

Части записи

path задаёт путь к файлу. fileVariable обозначает переменную типа FILE, с которой будет связан открытый файл.

Режим INPUT открывает существующий файл для чтения, OUTPUT создаёт новый файл или полностью перезаписывает существующий, а APPEND открывает файл для дописывания в конец.

В режиме INPUT Axiom проверяет весь текст файла как UTF-8, включая первые байты и короткие файлы. Если текст не является корректным UTF-8, используется Windows-1251. Начальный BOM UTF-8 пропускается и не входит в позиции FILEPOS. При чтении функцией READTEXT один символ Unicode, в том числе emoji, читается целиком; байтовые позиции файла при этом сохраняются.

Явная кодировка и границы текста

Аргументы path и encoding должны быть строками. Допустимые имена кодировок: UTF-8, WINDOWS-1251, UTF-16LE, UTF-16BE; регистр и внешние пробелы не учитываются. Слово encoding остаётся обычным именем переменной.

Относительный путь считается от рабочей папки текущего запуска. INPUT требует существующий файл; OUTPUT создаёт или перезаписывает его; APPEND создаёт отсутствующий файл или дописывает существующий. Родительские каталоги автоматически не создаются.

При явной кодировке INPUT и APPEND строго проверяют весь существующий текст. Совпадающий Unicode BOM пропускается, противоречащий BOM отвергается, отсутствие BOM допускается. Windows-1251 не распознаёт Unicode BOM и трактует любые байты как выбранную однобайтовую кодировку. Новый UTF-16-файл получает соответствующую подпись; UTF-8 и Windows-1251 записываются без BOM. APPEND сохраняет существующую подпись или её отсутствие и не добавляет вторую.

При явной кодировке FILEPOS и FILELENGTH измеряются в байтах текста без распознанного BOM. READTEXT считает символы Unicode, включая целые эмодзи. READLINE распознаёт CR, LF и CRLF по символам; байт 0A внутри символа UTF-16 не разделяет строку. После SEEKFILE нечётная позиция UTF-16 или середина суррогатной пары отвергается при чтении с сохранением позиции. Нулевое количество READTEXT не читает текст.

WRITE и WRITELINE проверяют возможность кодирования до изменения буфера и позиции. При непредставимом символе или непарном суррогате возникает перехватываемая ошибка MB3007. LINENUMBER на нечётной позиции UTF-16 также даёт MB3007 без изменения позиции. Байтовое редактирование через SEEKFILE может повредить текст. Запись при ошибках диска не является транзакцией. Общий договор описан на странице текстовых файловых функций.

Состояние FILE-переменной

  • Переменная после AS должна иметь тип FILE.
  • Если в переменной уже есть открытый файл, повторный OPEN даёт ошибку времени выполнения.
  • После открытия файл используется вместе с EOF, READLINE, WRITE, WRITELINE и другими файловыми функциями.

Диагностика

Нестрочные аргументы и переменная неверного типа после AS отклоняются при проверке программы. MB3007 возникает при неизвестной кодировке, конфликтующем BOM, повреждённом Unicode в INPUT/APPEND, недоступном пути, отсутствии файла INPUT и повторном открытии занятой переменной. Отказ из-за неизвестной кодировки не стирает файл OUTPUT. При отказе проверки INPUT/APPEND файл не изменяется, а системный поток освобождается.

Пример явной кодировки

DIM folder AS STRING = MAKETEMPDIR("open_encoding_")
DIM path AS STRING = COMBINEPATH(folder, "notes.txt")
DIM f AS FILE
' Создаём текст UTF-16LE с подписью.
OPEN path FOR OUTPUT AS f USING "UTF-16LE"
PRINT WRITELINE(f, "Привет 😀")
CLOSE f
' Читаем в той же кодировке; подпись не входит в позицию.
OPEN path FOR INPUT AS f USING "UTF-16LE"
PRINT FILEPOS(f)
PRINT READLINE(f)
CLOSE f

Программа выводит TRUE, начальную позицию 0 и строку «Привет 😀». Запускаемый пример: чтение UTF-16LE.
