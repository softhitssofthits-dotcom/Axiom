Данные и объявления

Тип TYPE

TYPE ... END TYPE создаёт пользовательский тип записи. Если говорить совсем просто, это способ хранить несколько связанных значений под одним именем и, при желании, дать этой записи свои действия через методы.

Если совсем просто

Представьте карточку человека: имя, возраст и город. Хранить это в трёх отдельных переменных неудобно. TYPE позволяет собрать их в одну запись.

TYPE Person
    Name AS STRING
    Age AS INTEGER
    City AS STRING
END TYPE

DIM user AS Person
user.Name = "Ada"
user.Age = 36
user.City = "London"

PRINT user.Name
PRINT user.City

После этого user — одна переменная, но внутри неё лежат сразу несколько полей.

Что находится внутри TYPE

  • Поле — это отдельное значение внутри записи. Например, Name или Age.
  • Метод — это процедура или функция, которая живёт внутри записи и работает именно с ней.
  • Конструктор — это специальный SUB New(...), который помогает собрать запись при создании.
  • Инвариант — это специальная проверка FUNCTION IsValid() AS BOOLEAN, которая отвечает на вопрос: "запись после конструктора в допустимом состоянии или нет?"

Объявление

TYPE typeName
    fieldDeclaration
    [anotherFieldDeclaration]
    [methodDeclaration]
END TYPE

Внутри TYPE можно объявлять поля, методы, конструкторы и специальную проверку IsValid().

  • Name AS STRING — обычное поле.
  • Age AS INTEGER = 18 — поле со значением по умолчанию.
  • Имя после TYPE становится новым типом данных, который можно использовать в DIM, параметрах и результатах функций.
  • TYPE ... END TYPE объявляется на верхнем уровне программы.

Как создать запись

Запись создаётся через форму TypeName(...). У неё есть несколько режимов.

1. Именованная форма

DIM user AS Person
user = Person(Name := "Ada", Age := 36)

Здесь вы явно говорите, какое поле чем заполнить. Эта форма особенно удобна, когда у записи много полей.

2. Пустая форма

DIM user AS Person
user = Person()

Если у типа нет пользовательского конструктора, поля получают значения по умолчанию. Если есть SUB New(), пустой вызов идёт уже в него.

3. Позиционная форма

DIM user AS Person
user = Person("Ada", 36)

Здесь значения сопоставляются по порядку. Без конструктора это позиционный литерал записи. Если внутри TYPE объявлен SUB New(...), такая форма становится вызовом конструктора.

  • Смешивать именованные и позиционные аргументы в одном TypeName(...) нельзя.
  • Именованная форма с := не вызывает SUB New(...).
  • Именованная форма с := не запускает IsValid().

Что такое метод

Метод — это обычная процедура или функция, но не снаружи программы, а внутри записи. Он нужен, когда запись должна уметь что-то делать со своими полями.

TYPE Counter
    Value AS INTEGER

    SUB Add(stepValue AS INTEGER)
        SELF.Value = SELF.Value + stepValue
    END SUB

    FUNCTION Current() AS INTEGER
        RETURN SELF.Value
    END FUNCTION
END TYPE

DIM counter AS Counter
counter.Add(2)
counter.Add(3)

PRINT counter.Current()
PRINT counter.Value

Здесь Add и Current — методы. Они вызываются через точку.

  • counter.Add(2) — вызов метода у переменной.
  • counter.Current() — вызов функции-метода, которая возвращает значение.
  • Внутри метода текущая запись доступна через SELF.

Что такое SELF

SELF — это имя для текущей записи внутри её метода или конструктора. Проще говоря, это способ обратиться к самому объекту данных, с которым сейчас работает код.

TYPE Person
    Name AS STRING

    SUB Rename(newName AS STRING)
        SELF.Name = newName
    END SUB
END TYPE
  • SELF не нужно объявлять вручную.
  • Если метод вызван у обычной переменной, изменения через SELF сохраняются в этой переменной.
  • Если метод вызван у временного значения, например Person("Ada").Rename("Grace"), изменение живёт только во время этого вызова.

Когда у одного имени может быть несколько методов

Иногда удобно дать одному действию одно имя, но разрешить несколько вариантов аргументов. Это называется перегрузкой методов.

TYPE Counter
    Value AS INTEGER
    Label AS STRING

    SUB Set(value AS INTEGER)
        SELF.Value = value
    END SUB

    SUB Set(label AS STRING)
        SELF.Label = label
    END SUB

    SUB Set(value AS INTEGER, label AS STRING)
        SELF.Value = value
        SELF.Label = label
    END SUB
END TYPE

DIM counter AS Counter
counter.Set(2)
counter.Set("Alpha")
counter.Set(7, "Beta")

Axiom сам выбирает нужный вариант по имени метода, числу аргументов и их типам.

  • Если подходит один вариант, будет вызван он.
  • Если одинаково хорошо подходят несколько вариантов, программа получает семантическую ошибку MB2033.
  • Тип результата в выборе перегрузки не участвует.

Что такое конструктор

Конструктор — это специальный SUB New(...) внутри TYPE. Он нужен, когда простого заполнения полей недостаточно и при создании записи надо выполнить дополнительную логику.

TYPE Person
    Name AS STRING = "Unknown"
    Age AS INTEGER = 18

    SUB New()
        SELF.Name = "Zero"
    END SUB

    SUB New(name AS STRING)
        SELF.Name = name
        SELF.Age = SELF.Age + 1
    END SUB

    SUB New(name AS STRING, age AS INTEGER)
        SELF.Name = name
        SELF.Age = age
    END SUB
END TYPE

PRINT Person().Name
PRINT Person("Ada").Age
PRINT Person("Grace", 20).Age

Здесь у одного типа есть три способа создания записи.

  • Person() вызывает SUB New().
  • Person("Ada") вызывает одноаргументный конструктор.
  • Person("Grace", 20) вызывает двухаргументный конструктор.
  • Перед входом в SUB New(...) запись уже существует, а поля уже имеют значения по умолчанию.
  • Именованная форма Person(Name := "Ada") конструктор не вызывает.

Что такое инвариант

Инвариант — это простая автоматическая проверка после конструктора. Она отвечает на вопрос: "запись собрана правильно?"

TYPE Person
    Name AS STRING = ""
    Age AS INTEGER = 0

    SUB New(name AS STRING, age AS INTEGER)
        SELF.Name = name
        SELF.Age = age
    END SUB

    FUNCTION IsValid() AS BOOLEAN
        RETURN SELF.Name <> "" AND SELF.Age >= 0
    END FUNCTION
END TYPE

PRINT Person("Ada", 20).Name
PRINT Person("Ada", 20).Age
  • IsValid() вызывается только после успешного SUB New(...).
  • Если IsValid() возвращает TRUE, запись считается корректной.
  • Если IsValid() возвращает FALSE, конструкторный путь завершается runtime-ошибкой MB3005.
  • IsValid() не является обычным методом по точке.
  • Именованный литерал TypeName(Field := ...) эту проверку не запускает.

Как запись копируется и сравнивается

TYPE в текущем договоре остаётся value-oriented типом. Это значит, что запись ведёт себя скорее как значение, а не как отдельный ссылочный объект.

TYPE Person
    Name AS STRING
    Age AS INTEGER
END TYPE

DIM first AS Person
DIM second AS Person

first = Person(Name := "Ada", Age := 36)
second = first

first.Name = "Grace"

PRINT first.Name
PRINT second.Name

После такого присваивания second хранит свою копию записи.

  • second = first копирует всю запись.
  • = и <> сравнивают записи по значениям полей.
  • Структурное сравнение сейчас не поддерживается для записей с массивными полями.

Массивы внутри TYPE

Поле записи может быть массивом. Это удобно, когда у одной сущности есть собственный набор элементов, например таблица оценок, сетка клеток или список кодов.

TYPE Board
    Scores(,) AS INTEGER
END TYPE

DIM board AS Board
REDIM board.Scores(1 TO 2, 1 TO 3)

board.Scores(1, 2) = 10
board.Scores(2, 3) = 20

PRINT board.Scores(1, 2)
PRINT board.Scores(2, 3)
  • Поддерживаются динамические и фиксированные массивные поля.
  • Для массивного поля работают те же правила индексирования и срезов, что и для обычного массива.
  • Пользовательские типы не могут образовывать прямой или косвенный цикл вложенности.

Что важно помнить

  • Именованная форма TypeName(Field := ...) — это литерал записи, а не вызов конструктора.
  • Неименованная форма TypeName(...) при наличии SUB New(...) становится конструкторным вызовом.
  • SELF работает внутри методов и конструкторов, но не объявляется вручную.
  • IsValid() — это специальная проверка после конструктора, а не обычный метод.
  • Если значение поля по умолчанию не указано, поле получает обычное значение своего типа: 0, пустую строку или FALSE.

Ручная проверка

  • TYPE: поля, вложенный TYPE и копирование записи
  • TYPE: методы и SELF
  • TYPE: методы у поля записи и элемента массива
  • TYPE: методы у временного литерала и результата функции
  • TYPE: перегрузка методов
  • TYPE: пользовательский конструктор
  • TYPE: инвариант после конструктора
  • TYPE: именованные литералы
  • TYPE: позиционная форма TypeName(...)
  • TYPE: массивные поля
  • TYPE: многомерные массивные поля
  • TYPE: структурное сравнение записей

Диагностика

  • MB2002 — имя типа, поля или сигнатура метода внутри одного TYPE объявлены повторно.
  • MB2021 — тип после AS не найден.
  • MB2022 — внутри TYPE использована неподдерживаемая форма члена.
  • MB2023 — указанного поля нет в записи.
  • MB2024 — доступ через точку применён к значению, у которого нет пользовательского типа.
  • MB2025 — REDIM или ERASE применены к фиксированному массивному полю.
  • MB2027 — значение поля по умолчанию недопустимо.
  • MB2031 — в одном TypeName(...) смешаны именованные и позиционные аргументы.
  • MB2032 — позиционная форма TypeName(...) получила неверное число аргументов.
  • MB2033 — вызов конструктора или перегруженного метода оказался неоднозначным.
  • MB3005 — инвариант IsValid() вернул FALSE после конструктора.
