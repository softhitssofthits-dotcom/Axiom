Оператор

Оператор TYPE

TYPE ... END TYPE — оператор языка Axiom, который объявляет пользовательскую запись: новый тип данных, в котором несколько полей хранятся как одно значение. Запись удобно представлять как карточку с подписанными графами.

Что делает TYPE

Обычная переменная хранит одно значение. Запись хранит несколько связанных значений сразу. Например, человеку нужны имя и возраст, точке на экране нужны координаты, товару нужны название и цена.

TYPE Person
    Name AS STRING
    Age AS INTEGER
END TYPE

Эта запись ещё не создаёт конкретного человека. Она описывает форму будущей карточки: в каждой карточке Person будут поля Name и Age.

Самый простой пример

TYPE Person
    Name AS STRING
    Age AS INTEGER
END TYPE

DIM user AS Person

user.Name = "Ada"
user.Age = 36

PRINT user.Name
PRINT user.Age

Здесь есть три шага. Сначала TYPE Person описывает форму записи. Потом DIM user AS Person создаёт переменную такого типа. Потом через точку заполняются и читаются поля этой переменной.

Синтаксис объявления

TYPE имяТипа
    имяПоля AS типПоля
    другоеПоле AS другойТип = значениеПоУмолчанию
END TYPE
  • имяТипа становится новым типом данных. Его можно использовать в DIM, параметрах процедур и типах результата функций.
  • имяПоля — имя отдельного значения внутри записи.
  • типПоля может быть скалярным типом, строкой, другой записью или массивным типом.
  • TYPE ... END TYPE объявляется на верхнем уровне программы.

Поле и точка

Поле — это подписанная часть записи. Точка показывает, какое поле нужно взять из какой записи.

user.Name = "Ada"
PRINT user.Name

Читается так: у записи user возьми поле Name. Если поле само является записью, точки можно продолжать.

TYPE Address
    City AS STRING
END TYPE

TYPE Person
    Name AS STRING
    Home AS Address
END TYPE

DIM user AS Person
user.Home.City = "London"
PRINT user.Home.City

Как создать запись

Переменную записи можно заполнить по полям вручную или создать запись выражением TypeName(...). В этой записи TypeName — не ключевое слово, а имя вашего типа, например Person(...) или Counter(...).

Пустая запись

DIM user AS Person
user = Person()

Без конструктора такая форма создаёт запись со значениями по умолчанию: числа получают 0, строки — пустой текст, BOOLEAN — FALSE. Если у типа есть SUB New() без параметров, будет вызван он.

Именованная форма

DIM user AS Person
user = Person(Name := "Ada", Age := 36)

Эта форма заполняет поля по именам. Она самая понятная, когда полей много. Важно: именованная форма с := не вызывает SUB New(...) и не запускает IsValid().

Позиционная форма

DIM user AS Person
user = Person("Ada", 36)

Значения идут по порядку. Если конструкторов нет, это позиционный литерал записи. Если внутри TYPE есть хотя бы один SUB New(...), неименованная форма становится вызовом конструктора.

  • В одном TypeName(...) нельзя смешивать позиционные аргументы и именованные аргументы Field := value.
  • Для позиционной формы число аргументов должно подходить к полям или к одному из конструкторов.
  • Для именованной формы можно указывать поля в удобном порядке.

TYPE и массивы: три случая

Записи и массивы часто встречаются рядом. Главное — понимать, где карточка, а где набор карточек или набор значений.

Массив записей

DIM people(1 TO 3) AS Person

people(1).Name = "Ada"
people(2).Name = "Grace"

people — массив, а каждый его элемент — запись Person.

Массивное поле внутри записи

TYPE Student
    Name AS STRING
    Marks() AS INTEGER
END TYPE

DIM pupil AS Student
REDIM pupil.Marks(1 TO 3)

pupil.Marks(1) = 5

pupil — одна запись, а pupil.Marks — массив внутри этой записи. Поддерживаются динамические и фиксированные массивные поля, включая многомерные.

Запись как поле другой записи

TYPE Address
    City AS STRING
END TYPE

TYPE Person
    Name AS STRING
    Home AS Address
END TYPE

Так запись можно разбивать на понятные части. Пользовательские типы не могут образовывать прямой или косвенный цикл вложенности.

Методы и SELF простыми словами

Метод — это процедура или функция внутри TYPE. Он нужен, когда действие естественно принадлежит самой записи. SELF внутри метода означает текущую запись.

TYPE Counter
    Value AS INTEGER

    SUB Add(stepValue AS INTEGER)
        SELF.Value = SELF.Value + stepValue
    END SUB

    FUNCTION Current() AS INTEGER
        RETURN SELF.Value
    END FUNCTION
END TYPE

DIM counter AS Counter
counter.Add(2)
counter.Add(3)

PRINT counter.Current()
  • counter.Add(2) вызывает метод у записи counter.
  • SELF.Value внутри метода означает поле Value у той записи, для которой метод вызвали.
  • SELF не нужно объявлять вручную.
  • Методы можно перегружать по числу и типам параметров. Если выбор неоднозначен, Axiom сообщает MB2033.

Конструктор SUB New

SUB New(...) — специальная процедура внутри TYPE. Она запускается при создании записи неименованной формой TypeName(...), если подходит по числу и типам аргументов.

TYPE Person
    Name AS STRING = "Unknown"
    Age AS INTEGER = 0

    SUB New(name AS STRING, age AS INTEGER)
        SELF.Name = name
        SELF.Age = age
    END SUB
END TYPE

DIM user AS Person
user = Person("Ada", 36)

PRINT user.Name
PRINT user.Age
  • Перед входом в SUB New(...) запись уже создана, а поля уже имеют значения по умолчанию.
  • Внутри конструктора поля обычно заполняют через SELF.
  • У одного TYPE может быть несколько SUB New(...) с разными параметрами.
  • Person(Name := "Ada", Age := 36) остаётся именованным литералом записи и конструктор не вызывает.

Проверка IsValid

FUNCTION IsValid() AS BOOLEAN — специальная проверка после конструктора. Она отвечает на простой вопрос: получилась ли допустимая запись?

TYPE Person
    Name AS STRING = ""
    Age AS INTEGER = 0

    SUB New(name AS STRING, age AS INTEGER)
        SELF.Name = name
        SELF.Age = age
    END SUB

    FUNCTION IsValid() AS BOOLEAN
        RETURN SELF.Name <> "" AND SELF.Age >= 0
    END FUNCTION
END TYPE

DIM user AS Person
user = Person("Ada", 36)
  • IsValid() запускается только после успешного SUB New(...).
  • Если функция вернула TRUE, запись создана.
  • Если функция вернула FALSE, создание завершается runtime-ошибкой MB3005.
  • IsValid() не вызывается для именованной формы TypeName(Field := value).

Копирование и сравнение

Запись TYPE ведёт себя как значение. Когда вы присваиваете одну запись другой, Axiom копирует запись целиком.

TYPE Person
    Name AS STRING
    Age AS INTEGER
END TYPE

DIM first AS Person
DIM second AS Person

first = Person(Name := "Ada", Age := 36)
second = first

first.Name = "Grace"

PRINT first.Name
PRINT second.Name

После присваивания second хранит свою копию. Изменение first.Name не меняет second.Name.

  • = и <> сравнивают две записи одного пользовательского типа по полям.
  • Структурное сравнение не поддерживается для записей с массивными полями.
  • Если поле само является записью, копируется и эта вложенная запись.

Что важно помнить

  • TYPE описывает форму записи, а DIM name AS TypeName создаёт переменную этой формы.
  • Поле читается и записывается через точку: record.Field.
  • Массив записей записывается как items(index).Field.
  • Массивное поле записывается как record.Items(index).
  • Именованная форма TypeName(Field := value) не вызывает SUB New(...).
  • Неименованная форма TypeName(...) при наличии конструктора выбирает SUB New(...).
  • SELF доступен только внутри методов и конструкторов записи.

Ручная проверка

  • TYPE: поля, вложенный TYPE и копирование записи
  • TYPE: именованные литералы
  • TYPE: позиционная форма TypeName(...)
  • TYPE: методы и SELF
  • TYPE: методы у поля записи и элемента массива
  • TYPE: методы у временного значения
  • TYPE: перегрузка методов
  • TYPE: пользовательский конструктор
  • TYPE: проверка IsValid после конструктора
  • TYPE: массивные поля
  • TYPE: многомерные массивные поля
  • TYPE: структурное сравнение записей

Диагностика

  • MB2002 — имя типа, поля или сигнатура метода внутри одного TYPE объявлены повторно.
  • MB2021 — тип после AS не найден.
  • MB2022 — внутри TYPE использована неподдерживаемая форма члена.
  • MB2023 — указанного поля нет в записи.
  • MB2024 — доступ через точку применён к значению без пользовательского типа.
  • MB2025 — REDIM или ERASE применены к фиксированному массивному полю.
  • MB2027 — значение поля по умолчанию недопустимо.
  • MB2031 — в одном TypeName(...) смешаны именованные и позиционные аргументы.
  • MB2032 — позиционная форма TypeName(...) получила неверное число аргументов.
  • MB2033 — вызов конструктора или перегруженного метода оказался неоднозначным.
  • MB3005 — IsValid() вернул FALSE после конструктора или массивное поле использовано до выделения.
