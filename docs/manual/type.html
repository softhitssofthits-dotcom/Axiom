Оператор TYPE

TYPE ... END TYPE объявляет пользовательский тип записи: набор именованных полей, к которым программа обращается через точку.

Сводка

TYPE задаёт новый тип данных, который затем можно использовать в DIM, параметрах SUB/FUNCTION и типах результата FUNCTION.

Синтаксис

TYPE <имя типа>
    <имя поля> AS <тип поля>
    [<имя поля> AS <тип поля>]
END TYPE
DIM <имя переменной> AS <имя типа>
<имя переменной>.<имя поля> = <выражение>
PRINT <имя переменной>.<имя поля>
DIM <имя массива>(<нижняя граница> TO <верхняя граница>) AS <имя типа>
<имя массива>(<индекс>).<имя поля> = <выражение>
PRINT <имя массива>(<индекс>).<имя поля>

Части синтаксиса

  • <имя типа> — имя пользовательского типа. Оно объявляется после TYPE и затем используется после AS.
  • <имя поля> — имя поля внутри записи. В одном TYPE имена полей не должны повторяться.
  • <тип поля> — скалярный встроенный тип Axiom или уже объявленный пользовательский тип.
  • <имя переменной>.<имя поля> — доступ к полю записи через точку.
  • <имя массива>(<индекс>).<имя поля> — доступ к полю записи, которая хранится в элементе одномерного массива.

Замечания

  • TYPE ... END TYPE объявляется на верхнем уровне программы, а не внутри SUB, FUNCTION, IF, циклов или другого TYPE.
  • Поле получает значение по умолчанию своего типа: 0 для чисел, пустую строку для STRING и FALSE для BOOLEAN.
  • Поле может иметь другой пользовательский тип, поэтому допустимы цепочки вида person.Home.City.
  • Обычное присваивание записи целиком создаёт независимую копию значения. После second = first изменение first.Name не меняет second.Name.
  • Пользовательский тип можно использовать как тип элемента одномерного массива: DIM people(1 TO 10) AS Person.
  • Присваивание записи в элемент массива целиком тоже сохраняет копию значения. После people(1) = first изменение first.Name не меняет people(1).Name.
  • В текущей реализации внутри TYPE поддерживаются скалярные поля, вложенные пользовательские типы, динамические массивные поля вида fieldName() AS TYPE, фиксированные массивные поля вида fieldName(lower TO upper) AS TYPE и групповые объявления с общим AS.
  • Групповое объявление позволяет задать несколько полей одной строкой, например Name, Alias AS STRING или Scores(), Flags(1 TO 2) AS INTEGER. Скобки диапазона или динамической формы относятся к каждому имени отдельно.
  • Фиксированное массивное поле получает выделенный диапазон сразу при создании записи, хранит значения по умолчанию для элементов и копируется вместе с записью как часть её значения.
  • Строковое поле можно объявить в форме FieldName AS STRING * N. Такое поле по-прежнему остаётся строковым, но пустое значение создаётся как строка из пробелов длины N, короткие присваивания дополняются пробелами справа, а длинные — обрезаются.
  • Для динамического массивного поля работают REDIM, REDIM PRESERVE и ERASE. Для фиксированного массивного поля эти операторы не допускаются: его диапазон задаётся прямо в объявлении TYPE.
  • Границы фиксированного массивного поля в TYPE должны быть целочисленными константами. Можно использовать литералы, простые целочисленные константные выражения и имена верхнеуровневых CONST. Порядок объявления CONST и TYPE в файле для этой формы не важен. Специальная пустая форма 1 TO 0 допустима и создаёт уже выделенный, но пустой массив.
  • Пользовательские типы не могут образовывать прямой или косвенный цикл вложенности.

Массивы записей

Если нужно хранить несколько записей одного вида, объявите одномерный массив пользовательского типа. После выбора элемента через индекс можно читать и менять его поля через точку.

TYPE Person
    Name AS STRING
    Age AS INTEGER
END TYPE

DIM people(1 TO 2) AS Person

people(1).Name = "Ada"
people(1).Age = 36

PRINT people(1).Name

Для такого массива работают обычные границы и информационные функции массива, например LBOUND, UBOUND, ARRAYLENGTH и ARRAYISALLOCATED. Массив остаётся ссылочным значением, но каждая запись внутри элемента хранится по правилам значения.

Ручная проверка

Для ручной проверки откройте в IDE пример samples/operators/type/field_access.axm и запустите его. Пример проверяет значения по умолчанию, присваивание полям, вложенный пользовательский тип и копирование записи.

Для проверки массива записей откройте пример samples/operators/type/array_elements.axm и запустите его. Пример проверяет поля элементов массива и копирование записи при присваивании в элемент.

Для проверки динамических массивных полей откройте пример samples/operators/type/array_fields.axm и запустите его. Пример проверяет REDIM, REDIM PRESERVE, ERASE и индексирование для массивного поля записи.

Для проверки фиксированных массивных полей откройте пример samples/operators/type/fixed_array_fields.axm и запустите его. Пример проверяет автоматическое создание диапазона, копирование записи вместе с полем и доступ к полю у элемента массива записей.

Для проверки границ через CONST откройте пример samples/operators/type/const_fixed_array_fields.axm и запустите его. Пример показывает, что фиксированное поле может брать диапазон из ранее объявленных констант.

Для проверки независимости от порядка объявления откройте пример samples/operators/type/const_fixed_array_fields_forward.axm и запустите его. В нём TYPE идёт раньше, чем используемые им константы.

Для проверки фиксированных строковых полей откройте пример samples/operators/type/fixed_string_fields.axm и запустите его. Пример показывает пробельное значение по умолчанию, дополнение короткой строки и обрезку длинной строки в поле записи.

Для проверки групповых объявлений откройте пример samples/operators/type/grouped_fields.axm и запустите его. Пример показывает общую форму Name, Alias AS STRING, смешанные массивные деклараторы и то, что динамическое поле-массив сохраняет ссылочную семантику даже после копирования записи.

Примеры

TYPE Person
    Name AS STRING
    Age AS INTEGER
END TYPE

DIM USER AS Person
USER.Name = "Ada"
USER.Age = 36

PRINT USER.Name
PRINT USER.Age
TYPE Address
    City AS STRING
END TYPE

TYPE Person
    Home AS Address
END TYPE

DIM USER AS Person
USER.Home.City = "London"
PRINT USER.Home.City
TYPE Person
    Name AS STRING
END TYPE

DIM people(1 TO 2) AS Person
people(1).Name = "Ada"
PRINT people(1).Name
TYPE Person
    Scores(1 TO 3) AS INTEGER
END TYPE

DIM first AS Person
DIM second AS Person

first.Scores(1) = 10
second = first
PRINT second.Scores(1)
CONST MinScore AS INTEGER = 1
CONST MaxScore AS LONG = MinScore + 2

TYPE Person
    Scores(MinScore TO MaxScore) AS INTEGER
END TYPE

DIM user AS Person
PRINT ARRAYLENGTH(user.Scores)
TYPE Employee
    Name AS STRING * 5
    Role AS STRING * 8
END TYPE

DIM user AS Employee
user.Name = "Ada"
user.Role = "Architect"

PRINT "[" + user.Name + "]"
PRINT "[" + user.Role + "]"
TYPE Person
    Name, Alias AS STRING
    Scores(), Flags(1 TO 2) AS INTEGER
END TYPE

DIM user AS Person
REDIM user.Scores(1 TO 2)
user.Alias = "Ada"
user.Flags(2) = 7
PRINT user.Flags(2)

Диагностика

  • MB2002 — имя пользовательского типа или поле в одном TYPE объявлено повторно.
  • MB2021 — тип после AS не найден.
  • MB2022 — поле TYPE имеет неподдерживаемую форму или пользовательские типы образуют цикл вложенности.
  • MB2023 — указанное поле отсутствует в пользовательском типе.
  • MB2024 — доступ через точку применён к значению, которое не имеет пользовательского типа.
  • MB2025 — REDIM или ERASE применены к фиксированному массивному полю записи.
  • MB2026 — длина фиксированной строки в объявлении STRING * N не сводится к целочисленной константе диапазона 1..65535.
