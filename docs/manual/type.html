Данные и объявления

Тип TYPE

TYPE ... END TYPE объявляет пользовательский тип записи: набор именованных полей, к которым программа обращается через точку. Запись можно хранить в переменной, передавать в процедуры и функции, помещать в массив и создавать через именованный литерал.

Сводка

TYPE нужен, когда несколько связанных значений должны жить под одним именем. Вместо набора отдельных переменных вы объявляете запись один раз и затем используете её как самостоятельный тип данных.

Синтаксис

TYPE typeName
    fieldDeclaration
    [anotherFieldDeclaration]
END TYPE
DIM variableName AS typeName
variableName.fieldName = expression
PRINT variableName.fieldName
DIM arrayName(lowerBound TO upperBound) AS typeName
arrayName(index).fieldName = expression
PRINT arrayName(index).fieldName
DIM user AS Person
user = Person(Name := "Ada", Age := 36)
DIM emptyUser AS Person
emptyUser = Person()

Части синтаксиса

  • typeName — имя пользовательского типа. Оно объявляется после TYPE, а затем используется после AS.
  • fieldDeclaration — объявление поля внутри записи. Базовая форма: fieldName AS fieldType.
  • variableName.fieldName — доступ к полю записи через точку.
  • TypeName(Field := value) — именованный литерал записи. Каждое имя слева от := должно совпадать с полем объявленного TYPE.

Замечания

  • TYPE ... END TYPE объявляется на верхнем уровне программы, а не внутри SUB, FUNCTION, IF, циклов или другого TYPE.
  • Тело TYPE состоит только из объявлений полей. Обычные операторы программы внутри него не используются.
  • Поле получает значение по умолчанию своего типа: 0 для чисел, пустую строку для STRING и FALSE для BOOLEAN.
  • Поле может иметь другой пользовательский тип, поэтому допустимы цепочки вида person.Home.City.
  • Присваивание записи целиком копирует значение. После second = first изменение first.Name не меняет second.Name.
  • Пользовательский тип можно использовать как тип элемента массива: DIM people(1 TO 10) AS Person.
  • Внутри TYPE поддерживаются скалярные поля, вложенные пользовательские типы, динамические массивные поля любого ранга, фиксированные массивные поля любого ранга, фиксированные строковые поля и групповые объявления с общим AS.
  • Частичное индексирование и диапазоны у массивного поля записи работают по тем же правилам, что и у обычного массива. Выражения вида lineView = board.Cells(2) и window = board.Cells(2 TO 3, 3 TO 4) возвращают представление на то же хранилище, а не скрытую копию.
  • Именованный литерал записи в форме Person(Name := "Ada", Age := 36) использует := только внутри TypeName(...). В этом шаге := не становится общим синтаксисом именованных аргументов для обычных вызовов SUB, FUNCTION и встроенных функций.
  • Пустая форма Person() создаёт запись, где все поля остаются в значениях по умолчанию.
  • Если поле имеет другой пользовательский тип, допустим вложенный литерал такого же вида, например Person(Home := Address(City := "Paris")).
  • Пользовательские типы не могут образовывать прямой или косвенный цикл вложенности.

Массивы записей и массивные поля

Если нужно хранить несколько записей одного вида, объявите массив пользовательского типа. Если же массив относится только к одной записи, объявите массивное поле прямо внутри TYPE. Оба случая подчиняются одному и тому же общему массивному договору Axiom.

TYPE Board
    Cells(,) AS INTEGER
END TYPE

DIM board AS Board
DIM lineView() AS INTEGER

REDIM board.Cells(1 TO 3, 1 TO 4)
board.Cells(2, 3) = 23
lineView = board.Cells(2)
lineView(4) = 24

PRINT board.Cells(2, 4)

Ручная проверка

  • TYPE: поля, вложенный TYPE и копирование записи
  • TYPE: именованные литералы через :=
  • TYPE: массив записей и поля элементов
  • TYPE: динамические массивные поля
  • TYPE: подмассивы и диапазонные представления через поле
  • TYPE: многомерные динамические массивные поля
  • TYPE: фиксированные массивные поля
  • TYPE: многомерные фиксированные массивные поля
  • TYPE: границы поля через CONST
  • TYPE: границы через CONST при объявлении ниже
  • TYPE: фиксированные строковые поля
  • TYPE: групповые объявления полей

Примеры

TYPE Person
    Name AS STRING
    Age AS INTEGER
END TYPE

DIM user AS Person
user.Name = "Ada"
user.Age = 36

PRINT user.Name
PRINT user.Age
TYPE Address
    City AS STRING
END TYPE

TYPE Person
    Name AS STRING
    Age AS INTEGER
    Home AS Address
END TYPE

DIM user AS Person
DIM blank AS Person

user = Person(Name := "Ada", Age := 36, Home := Address(City := "Paris"))
blank = Person()

PRINT user.Name
PRINT user.Age
PRINT user.Home.City
PRINT LEN(blank.Name)
PRINT blank.Age
PRINT blank.Home.City = ""
TYPE Board
    Scores(,) AS INTEGER
END TYPE

DIM board AS Board
REDIM board.Scores(1 TO 2, 1 TO 3)
board.Scores(1, 2) = 10
board.Scores(2, 3) = 20

PRINT board.Scores(1, 2)
PRINT board.Scores(2, 3)

Диагностика

  • MB2002 — имя пользовательского типа или поле в одном TYPE объявлено повторно.
  • MB2021 — тип после AS не найден.
  • MB2022 — поле TYPE имеет неподдерживаемую форму или пользовательские типы образуют цикл вложенности.
  • MB2023 — указанное поле отсутствует в пользовательском типе.
  • MB2024 — доступ через точку применён к значению, которое не имеет пользовательского типа.
  • MB2025 — REDIM или ERASE применены к фиксированному массивному полю записи.
  • Использование := вне литерала TYPE(...) приводит к семантической ошибке: именованные аргументы для обычных вызовов в этом шаге не поддерживаются.
