Структура программы

Программа Axiom состоит из инструкций, объявлений, процедур и функций. Исходный текст хранится в файле .axm. Инструкции верхнего уровня выполняются последовательно; операторы управления изменяют порядок выполнения.

Основные элементы

Переменные объявляются оператором DIM, константы — оператором CONST. Тип указывается через AS или выводится из инициализатора в поддерживаемых формах объявления. Оператор PRINT записывает значения в поток вывода. Процедуры и функции объявляются операторами SUB и FUNCTION.

Как читать записи синтаксиса

На страницах справочника формы записи конструкций показаны в едином формате. Обозначения имеют следующий смысл:

  • текст в <угловых скобках> — метапеременная; её имя обозначает роль подставляемой части, например <счётчик> или <список вывода>;
  • части в [квадратных скобках] необязательны: конструкция работает и без них;
  • ключевые слова языка пишутся как есть: IF, THEN, END IF;
  • если у конструкции несколько форм записи, каждая форма показывается отдельным блоком, а не смешивается в одну строку.

Например, запись FOR <счётчик> = <начало> TO <конец> [STEP <шаг>] читается так: после FOR пишется имя счётчика, затем начальное значение, ключевое слово TO и конечная граница, а часть STEP <шаг> в квадратных скобках необязательна — без неё цикл использует шаг 1.

Как устроен файл программы

Исходные тексты обычно хранятся в файлах с расширением .axm. Компилятор обрабатывает такой файл как последовательность инструкций, объявлений и блоков, поэтому код удобнее всего писать так, чтобы его можно было читать сверху вниз без догадок о скрытом порядке выполнения.

Что полезно помнить с самого начала:
  • одна строка обычно содержит одну инструкцию;
  • пустые строки допустимы и помогают отделять смысловые блоки;
  • вложенные конструкции должны быть явно закрыты: END IF, END SELECT, END WHILE, LOOP, NEXT.

Пример программы

Самая простая проверка среды — вывести строку в панель Output. Такой пример полезен не только как тест запуска, но и как первый ориентир по синтаксису: программа может состоять даже из одной рабочей инструкции.

PRINT "Привет, Axiom!"

Оператор PRINT вычисляет выражение после своего имени и отправляет результат в поток вывода. Если в качестве аргумента дана строка в кавычках, на экран попадает именно этот текст.

PRINT "Заголовок"
PRINT 42
PRINT 1 + 2 * 3
PRINT

Этот пример показывает, что PRINT выводит строки, числа, результаты выражений и пустую строку.

Комментарии

Комментарий можно записать двумя способами: через апостроф ' и через ключевое слово REM. Оба варианта оставляют пояснение для читателя и не влияют на выполнение программы, поэтому комментарии удобно использовать как краткие ориентиры рядом с неочевидными местами.

' Современная краткая запись комментария
REM Комментарий после ключевого слова

PRINT "Комментарий в вывод не попадает"

Комментарий уместен там, где нужно кратко пояснить назначение блока. Он должен дополнять код, а не пересказывать его построчно.

Как запускать примеры

В Axiom действует один путь запуска: компилятор проверяет исходный текст и создаёт байт-код, затем виртуальная машина BytecodeVm выполняет его. Выбирать исполнитель не требуется. Ошибка компиляции препятствует запуску; ошибки во время выполнения показываются с кодом и местом в исходнике.

Для проверки откройте compiler_execution.axm. Пример показывает вычисление суммы, пустую строку, два вызова процедуры в цикле и обработку ошибки функции POW с выполнением FINALLY. Это компиляция в байт-код; создание самостоятельного .exe в этот сценарий не входит.

Для первых ручных проверок лучше брать очень маленькие программы. Так проще понять, где именно возникла ошибка: в синтаксисе, в типах данных или уже в самой логике.

  1. Откройте Axiom.Ide.
  2. Создайте новый документ или откройте существующий файл .axm.
  3. Вставьте пример программы.
  4. Запустите его через кнопку Run.
  5. Посмотрите результат в панели Output.

Если программа не запускается

Чаще всего причина связана с синтаксисом или с неверным типом данных. В этом случае нужно посмотреть, на какой строке и в каком месте возникла ошибка компиляции или выполнения.

Основные правила

Правила выполнения

  • программа Axiom читается сверху вниз;
  • PRINT является самым простым способом увидеть результат;
  • DIM обычно становится первой точкой входа в работу с переменными и типами;
  • комментарии задаются через ' или REM;
  • первые примеры должны быть короткими и легко проверяемыми.
