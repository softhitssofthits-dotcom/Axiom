Диапазоны и ограничения типов

Диапазоны и ограничения типов — быстрая таблица: какой тип какие значения хранит, где Axiom выбирает тип литерала автоматически и какие ограничения чаще всего приводят к диагностике.

Числовые диапазоны

ТипМинимумМаксимумКратко
INTEGER -2147483648 2147483647 32-битное знаковое целое число.
LONG -9223372036854775808 9223372036854775807 64-битное знаковое целое число.
DOUBLE около -1.7976931348623157E+308 около 1.7976931348623157E+308 64-битное число с плавающей точкой; результат должен оставаться конечным.
DECIMAL -79228162514264337593543950335 79228162514264337593543950335 Точное десятичное число с 28-29 значащими цифрами.

DOUBLE может хранить очень большие и очень малые величины, но не каждую десятичную дробь точно. Для денег и табличных десятичных расчётов обычно выбирают DECIMAL, если его диапазона достаточно.

Нечисловые скалярные значения

ТипЧто хранитОграничение
BOOLEAN TRUE или FALSE Число не подставляется вместо логического значения автоматически.
STRING Текст переменной длины Длина ограничена доступной памятью и возможностями среды выполнения.
STRING * N Строку фиксированной длины При записи короткая строка дополняется пробелами справа, длинная обрезается до N символов.
FILE Открытый файл Значение создаётся файловыми операциями и должно быть закрыто через CLOSE.

Как выбирается тип литерала

ЗаписьТипПравило
123INTEGERЕсли целое десятичное значение помещается в диапазон INTEGER.
2147483648LONGЕсли значение уже не помещается в INTEGER, но помещается в LONG.
1.25DOUBLEЛитерал с десятичной точкой получает тип DOUBLE.
&HFFINTEGER или LONGШестнадцатеричный литерал выбирает целочисленный тип по диапазону значения.
TRUE, FALSEBOOLEANЛогические литералы не являются числами.

Отрицательное число записывается как унарный минус перед литералом. Например, в записи -10 знак минус является операцией, а 10 остаётся числовым литералом.

Ограничения массивов и индексов

  • Границы массива задаются включительно: в DIM a(1 TO 5) AS INTEGER допустимы индексы 1, 2, 3, 4 и 5.
  • В текущей реализации нижняя граница массива не может быть равна -2147483648, потому что это значение используется внутренними поисковыми функциями массива как признак отсутствия совпадения.
  • Обращение к элементу за пределами выделенного диапазона приводит к ошибке времени выполнения.
  • Динамический массив, объявленный без диапазона, получает реальные границы только после REDIM.

Преобразования и переполнение

Axiom допускает только безопасные автоматические расширения: INTEGER может перейти в LONG, DOUBLE или DECIMAL, а LONG может перейти в DOUBLE или DECIMAL. Обратные переходы нужно делать через поддержанные функции или явную логику программы.

Если арифметика целого типа выходит за его диапазон, выполнение сообщает переполнение. Если результат DOUBLE становится бесконечностью или нечислом, это тоже считается ошибкой выполнения.

Отличия, важные при чтении старых BASIC-материалов

В QuickBASIC INTEGER был 16-битным типом, а LONG — 32-битным. В Axiom INTEGER является 32-битным типом, а LONG — 64-битным, поэтому старые таблицы диапазонов нельзя переносить напрямую.

В QuickBASIC существовал отдельный тип SINGLE. В текущем договоре Axiom отдельного SINGLE нет: для вещественных вычислений используется DOUBLE, а для точных десятичных расчётов — DECIMAL.

Диагностика

  • MB0004 — числовой литерал выходит за допустимый диапазон.
  • MB2018 — константное значение не помещается в явно указанный тип.
  • MB3002 — индекс массива выходит за доступные границы.
  • MB3007 — недопустимый массивный диапазон или запрещённая операция с массивом.
  • MB3008 — арифметическое переполнение или неконечный результат DOUBLE.
