Оператор TRY ... CATCH ... FINALLY

Перехват ошибки времени выполнения и обязательная очистка.

Управление выполнением

Оператор TRY ... CATCH ... FINALLY

TRY выделяет участок программы, где может возникнуть ошибка времени выполнения. CATCH получает управление, если ошибка произошла и её нужно обработать без остановки программы. FINALLY используют для действий, которые должны выполниться при выходе из блока: после обычного выполнения, после обработанной ошибки или перед передачей необработанной ошибки наружу.

Сводка

В Axiom эта форма заменяет старую идею ON ERROR GOTO без перехода по метке. Обработчик расположен рядом с опасным участком кода, а переменная CATCH содержит структурированное значение ошибки.

Текущий срез поддерживается интерпретатором. Байткодная машина пока не выполняет TRY, поэтому в режиме принудительного байткода такие программы остаются временным ограничением.

Синтаксис

TRY
    [tryStatements]
CATCH errorVariable
    [catchStatements]
FINALLY
    [finallyStatements]
END TRY

Должна быть указана хотя бы одна часть: CATCH или FINALLY. Если обработка ошибки не нужна, можно оставить только FINALLY. Если отдельная очистка не нужна, можно оставить только CATCH.

Части записи

tryStatements — инструкции, при выполнении которых может возникнуть ошибка времени выполнения.

errorVariable — локальная переменная только для чтения. Она доступна только внутри блока CATCH и имеет встроенный тип ERROR.

catchStatements — инструкции обработки. Если ошибка обработана, выполнение продолжается после END TRY, если только обработчик сам не завершился новой ошибкой или ранним выходом.

finallyStatements — инструкции завершения. Они выполняются при обычном выходе, после CATCH и перед выходом с необработанной ошибкой.

Значение ERROR

Переменная CATCH содержит сведения о перехваченной ошибке:

ПолеТипНазначение
CodeINTEGERЧисловая часть диагностического кода, например 3001 для MB3001.
MessageSTRINGТекст сообщения времени выполнения.
LineINTEGERСтрока исходного кода, где возникла ошибка.
ColumnINTEGERКолонка исходного кода, где возникла ошибка.

Пример

TRY
    PRINT "before"
    PRINT 10 \ 0
CATCH err
    PRINT "caught"
    PRINT err.Code
    PRINT err.Line
FINALLY
    PRINT "cleanup"
END TRY

PRINT "after"

Деление на ноль не завершает программу: управление переходит в CATCH, затем выполняется FINALLY, после чего программа продолжает работу после END TRY.

Правила и ограничения

  • CATCH в текущем срезе не фильтрует ошибки по типу: он перехватывает любую ошибку времени выполнения из соответствующего TRY.
  • Поддерживается не более одного CATCH в одном блоке TRY.
  • Пользовательского оператора выброса ошибки пока нет.
  • RESUME, ON ERROR GOTO и продолжение с точки ошибки не поддерживаются.
  • Тело TRY, CATCH и FINALLY образуют отдельные блочные области видимости.

Ручная проверка

  • TRY: перехват ошибки времени выполнения и FINALLY
