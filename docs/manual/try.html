13 · Обработка ошибок

Оператор TRY

TRY — оператор языка Axiom, который защищает участок программы для обработки ошибок времени выполнения. Блок CATCH получает возникшую ошибку, а блок FINALLY выполняет завершающие инструкции.

Назначение и контекст

TRY позволяет обработать ожидаемый отказ, например недоступный файл или недопустимый аргумент, и продолжить программу после END TRY. Он доступен на верхнем уровне и внутри подпрограмм. Ошибки лексического, синтаксического и семантического анализа обнаруживаются до запуска и этим оператором не перехватываются.

Форма с обработчиком

TRY
    <защищённые инструкции>
CATCH <имя ошибки>
    <инструкции обработки>
END TRY

Форма с завершающим блоком

TRY
    <защищённые инструкции>
FINALLY
    <завершающие инструкции>
END TRY

Форма с обоими блоками

TRY
    <защищённые инструкции>
CATCH <имя ошибки>
    <инструкции обработки>
FINALLY
    <завершающие инструкции>
END TRY

Части записи и объявление переменной CATCH

Защищённые инструкции выполняют основную операцию. Имя ошибки объявляет доступную только для чтения переменную встроенного типа ERROR внутри CATCH. Инструкции обработки выполняются при ошибке из защищённого участка. Завершающие инструкции выполняются после обычного завершения, обработки ошибки или передачи неперехваченной ошибки дальше.

В записи CATCH err слово CATCH вводит обработчик, а имя err объявляет его переменную. Объявление уже присутствует в этой строке: писать предварительно DIM err или CONST err не нужно. Тип ERROR задаётся конструкцией CATCH, поэтому после имени не указывается AS ERROR. Имя выбирает программист по обычным правилам: например, CATCH failure объявляет переменную failure.

Переменная обработчика доступна только для чтения. Это означает, что программа получает сведения о возникшей ошибке и может их прочитать, но не может присвоить новое значение самой переменной или её полям. Переменная CATCH не является константой, объявленной оператором CONST: сведения об ошибке поступают во время выполнения при переходе в обработчик. Подсказка IDE обозначает её как «переменная ошибки, только для чтения» и показывает тип ERROR.

Область видимости переменной начинается в блоке соответствующего CATCH и заканчивается перед FINALLY или END TRY. Переменная доступна во вложенных блоках обработчика, но недоступна в защищённых инструкциях TRY, в соседнем блоке FINALLY и после END TRY. Имя переменной обработчика нельзя повторно объявить в той же области или использовать для перекрытия доступного внешнего имени.

Тип ERROR и сведения об ошибке

ERROR — встроенный тип значения ошибки. Четыре поля этого типа заранее определены языком; программист не объявляет их через DIM или TYPE. При перехвате ошибки переменная обработчика получает значение с кодом, сообщением и местом отказа.

Поля читаются через точку. В выражении err.Code имя переменной — err, точка обозначает обращение к полю, а Code — имя поля. Вся запись является выражением чтения поля, а не одним именем с точкой. Для переменной failure те же поля записываются как failure.Code, failure.Message, failure.Line и failure.Column.

ПолеТипНазначение
CodeSTRINGКод системной или пользовательской ошибки.
MessageSTRINGАнглийский текст системной ошибки либо исходный текст пользовательского сообщения ERROR.
LineINTEGERНомер строки исходника начиная с 1; 0, если место неизвестно.
ColumnINTEGERНомер столбца исходника начиная с 1; 0, если место неизвестно.

Язык поля Message

Системное сообщение в поле Message формируется на английском языке независимо от выбранного языка интерфейса IDE и культуры выполнения программы. Например, ошибка POW(-2, 0.5) возвращает Function POW: argument 'value' cannot be used with the specified exponent.. Слово value в кавычках обозначает имя аргумента функции POW, в данном случае её основание -2.

Поле Message и сообщение на панели «Проблемы» имеют разные назначения. Диагностика IDE может отображаться на языке интерфейса. Программа получает английский текст системного отказа. Для отказов без специального английского описания используется общее английское описание по коду ошибки с названием операции и доступными именами или путями из контекста; подробный исходный текст используется в диагностике неперехваченной ошибки. Перехваченная ошибка снимается с панели «Проблемы». Имена и пути являются данными программы и могут содержать символы других алфавитов.

Сообщение, явно переданное оператору ERROR, сохраняется без перевода, включая русские символы и пустую строку. Это правило действует и при пользовательском коде, совпадающем с системным, например ERROR "MB3007", "Моя ошибка". Если сообщение не задано, оператор создаёт английский текст User error <код>.. Повторная передача ERROR err сохраняет поле Message исходной ошибки.

Запускаемый пример: язык системного и пользовательского сообщения. Для выбора обработки используйте поле Code, а не поиск слов в тексте Message.

Порядок работы и ограничения

При ошибке оставшиеся инструкции защищённого участка пропускаются. Если CATCH завершился обычно, исполнение продолжается после FINALLY и END TRY. Ошибка внутри CATCH не перехватывается тем же CATCH: сначала выполняется FINALLY, затем ищется внешний обработчик. Ошибка из FINALLY также передаётся внешнему обработчику.

RETURN из защищённого тела или CATCH выполняет все активные FINALLY, начиная с ближайшего и заканчивая внешним; каждый из них выполняется ровно один раз. Обработчик без FINALLY не мешает выполнению внешнего FINALLY. Если RETURN находится внутри самого FINALLY, этот FINALLY повторно не запускается. Блоки можно вкладывать. Каждый блок имеет собственную область видимости. Нужен хотя бы один CATCH или FINALLY; допускается только один CATCH, без фильтра по коду или типу. Продолжение с места отказа не предусмотрено.

Диагностика

MB1001 возникает, если отсутствует требуемый CATCH или FINALLY, имя после CATCH либо END TRY. MB2010 возникает при попытке присвоить значение переменной ошибки или её полям. MB2001 возникает при обращении к переменной обработчика вне её области видимости. MB2002 означает повторное объявление имени в той же области, MB2016 — перекрытие доступного внешнего имени. MB2023 возникает при обращении к отсутствующему полю ERROR, например err.Text вместо err.Message. Коды перехваченных ошибок задаются самой операцией; например, деление на ноль даёт MB3001.

Пример

TRY
    PRINT 10 \ 0
CATCH err
    PRINT err.Code
FINALLY
    PRINT "finally"
END TRY
PRINT "after"

Ожидаемый вывод:

MB3001
finally
after

Пример чтения всех полей

TRY
    PRINT POW(-2, 0.5)
CATCH err
    PRINT err.Code
    PRINT err.Message
    PRINT err.Line
    PRINT err.Column
FINALLY
    PRINT "Завершено"
END TRY

Вызов POW(-2, 0.5) вызывает ошибку MB3007. Строка CATCH err объявляет переменную err; следующие четыре инструкции читают её поля. Первая выводит MB3007, вторая — сообщение операции, третья и четвёртая — строку и столбец места ошибки. Затем блок FINALLY выводит «Завершено». Дополнительное объявление err в этой программе отсутствует, потому что её уже объявил CATCH.

Если нужно изменять собственный текст сообщения, объявите отдельную строковую переменную внутри обработчика и скопируйте в неё err.Message. Запись err.Message = "другой текст" запрещена.
