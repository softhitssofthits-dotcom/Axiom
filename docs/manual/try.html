Оператор TRY ... CATCH ... FINALLY

TRY — оператор языка Axiom, который выделяет участок программы, где может возникнуть ошибка времени выполнения. CATCH получает управление, если ошибка произошла и её нужно обработать без остановки программы. FINALLY используют для действий, которые должны выполниться при выходе из блока.

Как TRY заменяет переход к обработчику

В Axiom эта форма заменяет старую идею ON ERROR GOTO без перехода по метке. Обработчик расположен рядом с опасным участком кода, а значение ошибки попадает в переменную, указанную после CATCH, например err в записи CATCH err.

Поддержанные формы TRY/CATCH/FINALLY выполняются и интерпретатором, и BytecodeVm. Неподдержанными остаются старые формы продолжения с точки ошибки и фильтры обработчиков.

Синтаксис

TRY
    [tryStatements]
CATCH errorVariable
    [catchStatements]
FINALLY
    [finallyStatements]
END TRY

Должна быть указана хотя бы одна часть: CATCH или FINALLY. Если обработка ошибки не нужна, можно оставить только FINALLY. Если отдельная очистка не нужна, можно оставить только CATCH.

Части записи

TRY, CATCH, FINALLY и END TRY — ключевые слова одного блочного оператора. Имена tryStatements, catchStatements, finallyStatements и errorVariable в синтаксисе — не слова языка, а обозначения мест, куда в реальном коде вставляются инструкции и имя переменной.

tryStatements — инструкции, при выполнении которых может возникнуть ошибка времени выполнения.

errorVariable — локальная переменная только для чтения. Она доступна только внутри блока CATCH и имеет встроенный тип ERROR.

catchStatements — инструкции обработки. Если ошибка обработана, выполнение продолжается после END TRY, если только обработчик сам не завершился новой ошибкой или ранним выходом.

finallyStatements — инструкции завершения. Они выполняются при обычном выходе, после CATCH и перед выходом с необработанной ошибкой.

Значение ERROR

Встроенный тип ERROR описывает значение ошибки. Это не сам оператор ERROR, а тип данных у переменной после CATCH:

ПолеТипНазначение
CodeSTRINGПолный диагностический код, например MB3001.
MessageSTRINGТекст сообщения времени выполнения.
LineINTEGERСтрока исходного кода, где возникла ошибка.
ColumnINTEGERКолонка исходного кода, где возникла ошибка.

Пример перехвата ошибки

TRY
    PRINT "before"
    PRINT 10 \ 0
CATCH err
    PRINT "caught"
    PRINT err.Code
    PRINT err.Line
FINALLY
    PRINT "cleanup"
END TRY

PRINT "after"

Деление на ноль не завершает программу: управление переходит в CATCH, затем выполняется FINALLY, после чего программа продолжает работу после END TRY.

Правила и ограничения

  • CATCH в текущем срезе не фильтрует ошибки по типу: он перехватывает любую ошибку времени выполнения из соответствующего TRY.
  • Поддерживается не более одного CATCH в одном блоке TRY.
  • Пользовательскую runtime-ошибку можно создать оператором ERROR; пойманную ошибку можно передать дальше формой ERROR err.
  • RESUME, ON ERROR GOTO и продолжение с точки ошибки не поддерживаются.
  • Тело TRY, CATCH и FINALLY образуют отдельные блочные области видимости.

Ручная проверка

  • TRY: перехват ошибки времени выполнения и FINALLY
  • ERROR: пользовательский код и перехват через CATCH
  • ERROR: повторный проброс пойманной ошибки
