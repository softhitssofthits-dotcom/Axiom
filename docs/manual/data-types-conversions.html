Преобразования типов

Преобразование получает значение одного типа и представляет его в другом типе. Одни переходы выполняются автоматически при присваивании или передаче аргумента, другие требуют вызова функции. Допустимость перехода и сохранение точности являются разными свойствами.

Тип объявления и преобразование значения

При выводе типа компилятор выбирает тип новой переменной по начальному выражению. Например, DIM count = 3 объявляет INTEGER. При преобразовании тип исходного значения уже известен: запись этого числа в переменную LONG представляет его как LONG. Формы объявления находятся в статье DIM; типы литералов и их пределы приведены в таблице диапазонов.

Автоматические числовые переходы

Для уже типизированных числовых значений разрешены следующие переходы:

Исходный типЦелевые типы
INTEGERLONG, DOUBLE, DECIMAL
LONGDOUBLE, DECIMAL
DECIMALDOUBLE

Переход в DOUBLE может округлить исходное значение. Обратный переход, например из переменной LONG в INTEGER или из DOUBLE в DECIMAL, автоматически не выполняется. Для него нужна предусмотренная функция преобразования.

DIM count AS INTEGER = 3
DIM wide AS LONG = count
DIM exact AS DECIMAL = wide
DIM approximate AS DOUBLE = exact
PRINT count, wide, exact, approximate

Результат:

3 3 3 3

Обычная арифметика также приводит совместимые операнды к общему типу. Если участвует DOUBLE, DECIMAL преобразуется в DOUBLE. Функции MIN, MAX и CLAMP имеют более строгий договор: сочетание DECIMAL и DOUBLE в их аргументах отклоняется. Тип результата деления и общая последовательность числового продвижения описаны в статье операций.

Литерал в ожидаемом числовом типе

Непосредственный числовой литерал в объявлении, присваивании или аргументе проверяется с учётом ожидаемого типа. Так же обрабатывается минус непосредственно перед литералом. Литерал с десятичной точкой, помещённый в DECIMAL, читается как десятичное число без промежуточного значения DOUBLE:

DIM amount AS DECIMAL = 10.50
DIM extra AS DECIMAL = 0.20
PRINT amount + extra

Результат:

10.70

Ожидаемый тип не распространяется внутрь произвольного выражения. Скобки вокруг литерала также не сохраняют этот особый способ чтения: DIM amount AS DECIMAL = (10.50) получает выражение DOUBLE и отклоняется с MB2003. Тот же результат даёт DIM amount AS DECIMAL = 10.50 + 0.20, поскольку сложение сначала связывается как DOUBLE.

У сохранённой переменной тип уже известен. Преобразовать такую переменную DOUBLE в DECIMAL автоматически нельзя; применяется обычный договор переходов.

Функции преобразования

CINT, CLNG, CDBL и CDEC выполняют явные числовые преобразования. VAL разбирает числовой текст, STR получает текстовое представление числа. Типы аргументов, усечение, пределы и поведение при неверном тексте определяются договором каждой функции. Полные формы находятся в главе преобразования чисел и текста.

DIM raw AS DOUBLE = -3.75
PRINT CINT(raw)
PRINT CLNG(raw)
PRINT VAL("12.5")
PRINT STR(12)

Результат:

-3
-3
12.5
12

В этом примере CINT и CLNG отбрасывают дробную часть к нулю. Это правило не заменяет проверку диапазона результата.

Логические, строковые и составные значения

BOOLEAN не преобразуется в число автоматически или функциями CINT, CLNG, CDBL и CDEC. Встроенной CBOOL нет. Число проверяется сравнением; для выбора числового результата по BOOLEAN используется IF. Примеры: преобразования логических значений.

Строка и число не складываются через +. Для получения строки служит явное преобразование; операция & отдельно определяет, какие значения она переводит в текст.

Временные типы имеют собственные переходы и правила разбора канонических строк. В частности, неявное отбрасывание части DATETIME при записи в DATE или TIME запрещено. Полный договор, включая отдельный тип момента UTCDATETIME, находится в главе даты и времени.

FILE, массивы, пользовательские записи и функциональные значения не участвуют в общих скалярных преобразованиях. Их совместимость и способы передачи описываются на страницах соответствующих типов.

Диагностика

  • MB2003: несовместимые типы, в том числе недопустимый автоматический переход, сложение строки с числом либо смешение DECIMAL и DOUBLE в MIN, MAX или CLAMP.
  • MB2018: непосредственный числовой литерал нельзя прочитать в ожидаемом типе из-за записи или диапазона. Например, DIM n AS INTEGER = 1.0 отклоняется этим кодом, хотя величина 1 помещается в INTEGER: дробная запись не является целочисленной.
  • MB3008: числовое переполнение или неконечный результат во время выполнения.

Функции разбора и преобразования могут выдавать дополнительные диагностики по собственным правилам; они перечислены на страницах функций.
