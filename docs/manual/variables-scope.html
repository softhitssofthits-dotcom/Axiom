Раздел

Имена, регистр и область видимости переменных

Раздел имён и областей видимости определяет правила сопоставления имён, доступность переменных и констант, а также время существования значений в глобальной области, процедурах и блоках программы.

Основные правила

  • Регистр букв не важен: score, Score и SCORE — это одно и то же имя.
  • Имя нужно объявить заранее через DIM (переменная) или CONST (константа). Простое присваивание само имя не создаёт.
  • Переменная видна не везде, а только в своей области видимости: глобальной, процедурной или блока.
  • Повторно объявлять имя внутри вложенной области нельзя — это ошибка перекрытия имён MB2016.
  • Переменная блока (IF, FOR, WHILE, SELECT CASE и других) исчезает сразу после конца блока.
  • Локальные переменные процедуры создаются заново при каждом её вызове и не видны снаружи.

Каким может быть имя переменной

Имя переменной — это слово, по которому программа находит значение. В Axiom действуют простые правила:

  1. Имя начинается с латинской буквы A–Z, a–z или знака подчёркивания _.
  2. Дальше можно использовать латинские буквы, цифры 0–9 и знак подчёркивания.
  3. Пробелы и знаки пунктуации (тире, точки, запятые) в имени запрещены.
  4. Имя не должно совпадать с зарезервированным словом языка (IF, PRINT, DIM и другими).
  5. Русские буквы и буквы других алфавитов в именах запрещены: недопустимый символ вызывает MB0001.

Имена пишутся латинскими буквами, а сообщения в кавычках и комментарии могут быть русскими:

DIM counter AS INTEGER = 3 ' Объявляем счётчик.
PRINT COUNTER
PRINT "Русский текст разрешён в строках."

Вывод:

3
Русский текст разрешён в строках.

Регистр букв: большие или маленькие?

Axiom не различает заглавные и строчные буквы в именах переменных. Имена name, Name и NAME обозначают одну и ту же переменную. Поэтому вы можете писать имя в любом регистре — программа поймёт вас правильно.

DIM score AS INTEGER
score = 10
PRINT Score

Вывод:

10

То же правило работает при любом сочетании регистров, даже в середине слова:

DIM Total = 5
total = total + 1
PRINT ToTaL

Вывод:

6

Регистр не важен и для русских имён, и для встроенных констант PI, ROW, COLUMN.

Что нельзя делать: объявить одно имя дважды в одной области, меняя только регистр. Для Axiom это одно и то же имя, поэтому второе объявление — ошибка MB2002.

DIM value AS INTEGER = 1
DIM VALUE AS INTEGER = 2
PRINT value

Вывод: программа не запускается: компилятор выдаёт диагностику (сообщение об ошибке) MB2002: Имя 'VALUE' уже объявлено в этой области видимости.

Совет новичку: хотя регистр не влияет на работу, старайтесь писать одно имя всегда одинаково (например, всегда score или всегда Score). Так код легче читать. Редактор Axiom может сам приводить написание имён к единому виду по мере ввода.

Что такое область видимости

Область видимости — это «территория» программы, на которой имя можно использовать. Представьте коробки: переменная лежит внутри коробки, и пока вы находитесь внутри этой коробки, вы её видите. Вышли из коробки — переменная исчезла из виду (а может и вовсе перестала существовать).

В Axiom есть четыре вида «коробок»:

Глобальные переменные

Глобальная переменная объявляется на верхнем уровне программы — вне всех процедур и типов. Она живёт с начала и до конца программы и видна отовсюду: из SUB, FUNCTION и методов TYPE её можно и читать, и изменять.

DIM counter AS INTEGER = 100

SUB Show()
    PRINT counter
END SUB

SUB Bump()
    counter = counter + 1
END SUB

Show()
Bump()
PRINT counter

Вывод:

100
101

Show просто читает глобальную переменную, а Bump записывает в неё новое значение — это та же самая переменная, а не копия.

Порядок объявления не важен. Axiom сначала находит все глобальные переменные и только потом разбирает тела процедур, поэтому процедура видит глобальную переменную, даже если DIM стоит ниже неё в файле:

SUB Show()
    PRINT laterGlobal
END SUB

DIM laterGlobal AS INTEGER = 42
Show()

Вывод:

42

То же самое касается методов TYPE — они тоже видят глобальные переменные независимо от порядка.

Следствие правила «не перекрывай имена». Раз порядок больше не влияет на видимость, локальная переменная или параметр не могут носить то же имя, что и глобальная переменная, — в каком бы порядке они ни стояли. Такая программа не запустится с диагностикой MB2016:

SUB Show(age AS INTEGER)   ' параметр age
    PRINT age
END SUB

DIM age AS INTEGER = 30    ' глобальная age
Show(age)

Измените имя параметра — например, на inputAge, — и программа заработает.

Значения по умолчанию. Если переменной не задать начальное значение, Axiom даст ей «пустое» значение по типу: числа — 0, строка — "" (пустая строка), логическое значение — FALSE.

Локальные переменные процедур

Переменные, объявленные внутри SUB или FUNCTION, называются локальными. Параметры процедуры — тоже локальные имена. Локальные переменные:

  • не видны снаружи процедуры — после END SUB к ним обратиться нельзя;
  • создаются заново при каждом вызове процедуры;
  • исчезают, когда процедура заканчивает работу.
SUB Test()
    DIM n AS INTEGER = 0
    n = n + 1
    PRINT n
END SUB

Test()
Test()

Вывод:

1
1

Хотя Test вызвана дважды, счётчик n каждый раз начинается с нуля: при каждом вызове создаётся новая переменная.

Попытка обратиться к локальной переменной (или параметру) снаружи — ошибка MB2001:

FUNCTION DoubleValue(value AS INTEGER) AS INTEGER
    RETURN value + value
END FUNCTION

PRINT DoubleValue(21)
PRINT value

Вывод: PRINT DoubleValue(21) напечатает 42, но PRINT value уже за пределами функции — диагностика MB2001: Имя 'value' не объявлено.

Константа, объявленная внутри процедуры, тоже локальна — это просто неизменяемая локальная переменная:

SUB Show()
    CONST LOCAL_LIMIT AS INTEGER = 3
    PRINT LOCAL_LIMIT
END SUB

Show()

Вывод:

3

Параметры: по значению или по ссылке. По умолчанию параметр — копия значения (изменения внутри процедуры не влияют на исходную переменную). С ключевым словом BYREF процедура получает саму переменную и может её изменить:

SUB Modify(BYREF value AS INTEGER)
    value = value + 1
END SUB

DIM n AS INTEGER = 10
Modify(n)
PRINT n

Вывод:

11

Вложенные процедуры и замыкания

Внутри SUB и FUNCTION можно объявлять свои собственные SUB и FUNCTION. Вложенная процедура видит и локальные переменные внешней процедуры, и глобальные:

SUB Outer()
    DIM localOuter AS INTEGER = 10

    SUB Inner()
        PRINT localOuter
    END SUB

    Inner()
END SUB

Outer()

Вывод:

10

Если вложенная функция возвращается наружу как значение, она «забирает» с собой свои переменные. Такая функция называется замыканием, и её переменные продолжают жить между вызовами:

DIM counter AS FUNCTION () AS INTEGER
counter = MakeCounter()
PRINT counter()
PRINT counter()
PRINT counter()

FUNCTION MakeCounter() AS FUNCTION () AS INTEGER
    DIM current AS INTEGER = 0

    FUNCTION NextValue() AS INTEGER
        current = current + 1
        RETURN current
    END FUNCTION

    RETURN NextValue
END FUNCTION

Вывод:

1
2
3

Обратите внимание: current — локальная переменная MakeCounter, но она не исчезла после выхода из неё, потому что возвращённая функция продолжает на неё ссылаться.

Переменные в типах TYPE

Тип TYPE описывает запись — набор полей. Поля похожи на переменные, встроенные в запись. Обращаются к ним через переменную записи и точку:

TYPE Point
    x AS INTEGER
    y AS INTEGER
END TYPE

DIM p AS Point
p.x = 1
p.y = 2
PRINT p.x + p.y

Вывод:

3

Имена полей, как и обычные переменные, регистронезависимы: p.X и p.x — одно и то же поле.

Методы и SELF. Внутри метода типа (SUB или FUNCTION, объявленной в TYPE) свои поля доступны только через специальное имя SELF. «Голое» имя поля без SELF компилятор (программа, которая проверяет и запускает код) не поймёт — это ошибка MB2044, и её текст сразу подсказывает решение:

TYPE Counter
    Value AS INTEGER

    SUB Increment(stepValue AS INTEGER)
        SELF.Value = SELF.Value + stepValue
    END SUB
END TYPE

DIM counter AS Counter
counter.Increment(5)
PRINT counter.Value

Вывод:

5

Если написать SELF.Value с опечаткой — например, SELF.Valu, — придёт ошибка MB2023, а к ней подсказка с ближайшим похожим полем: «Возможно, вы имели в виду поле 'Value'».

Глобальные переменные из методов видны независимо от порядка объявления, как и из обычных процедур.

Записи копируются, массивы — нет. При присваивании одной переменной типа другой запись копируется целиком: изменения копии не затрагивают оригинал. А вот у массивов присваивание общее хранилище — обе переменные ссылаются на один и тот же массив:

TYPE Box
    v AS INTEGER
END TYPE

DIM b1 AS Box
b1.v = 1

DIM b2 AS Box
b2 = b1
b2.v = 99

PRINT b1.v
PRINT b2.v

Вывод:

1
99

Переменные в блоках

Блоки IF ... END IF, SELECT CASE ... END SELECT, циклы FOR ... NEXT, WHILE ... END WHILE, DO ... LOOP и TRY ... END TRY создают собственную область видимости. Переменная, объявленная внутри блока, видна только внутри этого блока:

IF TRUE THEN
    DIM inner AS INTEGER = 3
    PRINT inner
END IF

PRINT inner

Вывод: первый PRINT напечатает 3, а второй — ошибка MB2001: Имя 'inner' не объявлено. После END IF переменная исчезла.

Разные ветви — разные области. Можно использовать одно и то же имя в разных ветвях IF ... ELSE или в разных ветках CASE, потому что эти ветви не видят друг друга:

IF FALSE THEN
    DIM branchText AS STRING = "one"
ELSE
    DIM branchText AS STRING = "two"
    PRINT branchText
END IF

Вывод:

two

То же самое в SELECT CASE:

SELECT CASE 2
    CASE 1
        DIM caseText AS STRING = "one"
    CASE 2
        DIM caseText AS STRING = "two"
        PRINT caseText
END SELECT

Вывод:

two

Счётчик FOR. Счётчик FOR всегда создаётся самим циклом и живёт только внутри него: после NEXT он исчезает.

FOR i = 1 TO 2
    PRINT i
NEXT

PRINT i

Вывод: цикл напечатает 1 и 2, а PRINT i после цикла — ошибка MB2001.

Имя счётчика не может быть занято во внешней области: DIM i и затем FOR i — ошибка MB2016 (счётчик FOR всегда локальный). Если итоговое значение нужно после цикла, скопируйте его в свою переменную внутри тела:

DIM lastValue AS INTEGER = 0

FOR i = 1 TO 3
    lastValue = i
NEXT

PRINT lastValue

Вывод:

3

Переменная CATCH. Переменная ошибки в CATCH info видна только внутри блока CATCH. После END TRY к ней обращаться нельзя.

Перекрытие имён запрещено

Перекрытие имён (по-английски shadowing) — это когда внутренняя область объявляет имя, которое уже занято во внешней. В Axiom это не разрешено: вместо «тихого» перекрытия вы получаете понятную ошибку MB2016. Так программа не может незаметно подменить одну переменную другой.

DIM counter AS INTEGER = 100

SUB Show()
    DIM counter AS INTEGER = 5
    PRINT counter
END SUB

Вывод: диагностика MB2016: Имя 'counter' уже объявлено во внешней области видимости. В этом месте нельзя объявить его повторно.

То же самое происходит, если параметр процедуры повторяет имя глобальной переменной, или если вложенная процедура повторяет имя внешней процедуры, или блок повторяет имя переменной родительского блока. Решение простое: придумайте другое имя. В процедуре, которая хочет работать с глобальной counter, просто читайте и пишите её напрямую — отдельное объявление не нужно.

Время жизни — это промежуток, в течение которого переменная существует и хранит своё значение. Сводка:
