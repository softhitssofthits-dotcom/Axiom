Побитовые операции и сдвиги

Раздел побитовых операций описывает NOT, AND, OR, XOR, EQV, IMP и сдвиги << и >> над INTEGER и LONG. Синтаксические формы ниже относятся к разным операциям.

Разряды и знак целого числа

INTEGER содержит 32 двоичных разряда, LONG — 64. Разряд 0 находится справа и соответствует единице; разряд 1 соответствует двум, разряд 2 — четырём. Старший разряд 31 или 63 используется для знака. Отрицательные числа представлены дополнительным кодом; все установленные разряды дают -1.

Побитовая операция обрабатывает разряды целого числа и возвращает целое число. Это отличается от логической операции над BOOLEAN. Полные правила TRUE/FALSE находятся в статье логического типа. Запись чисел &H и &B описана в статье систем счисления.

Формы операций

Каждая форма ниже является отдельной операцией. NOT принимает одно целое выражение, остальные — два. Допустимы INTEGER и LONG; BOOLEAN, DOUBLE, DECIMAL и STRING не заменяют целочисленные операнды.

NOT <целое выражение>
<левое целое> AND <правое целое>
<левое целое> OR <правое целое>
<левое целое> XOR <правое целое>
<левое целое> EQV <правое целое>
<левое целое> IMP <правое целое>

NOT сохраняет тип операнда. Для двух INTEGER бинарная операция возвращает INTEGER. При участии LONG оба операнда приводятся к LONG и результат имеет тип LONG. Отрицательный INTEGER при расширении сохраняет значение и дополняется знаковыми разрядами.

Действие каждого разряда

NOT меняет 0 на 1 и 1 на 0 во всех разрядах выбранного типа. AND устанавливает разряд при двух единицах, OR — при хотя бы одной. XOR устанавливает разряд при различии входных разрядов. EQV устанавливает его при совпадении. IMP очищает разряд только при единице слева и нуле справа.

Битовые 0/1 в таблице являются разрядами, а не логическими литералами TRUE/FALSE. NOT 0 возвращает целое -1; NOT -1 возвращает 0.

Маски

Маска задаёт интересующие разряды. AND оставляет выбранные разряды, OR устанавливает их, XOR переключает, а AND с инверсией маски очищает. Ниже каждый результат показан двоичным текстом:

DIM value AS INTEGER = &B1010
DIM mask AS INTEGER = &B1100
PRINT $"{value AND mask:B4}"
PRINT $"{value OR mask:B4}"
PRINT $"{value XOR mask:B4}"
PRINT $"{value AND NOT mask:B4}"

Результат:

1000
1110
0110
0010

AND, OR, XOR, EQV и IMP вычисляют оба операнда слева направо. Условные ANDALSO/ORELSE принимают только BOOLEAN и не имеют побитового режима.

Ширина маски и результат NOT

Разрядность задаётся типом, а не количеством написанных шестнадцатеричных или двоичных цифр. Литерал &HFFFFFFFF — положительный LONG 4294967295. Его инверсия NOT &HFFFFFFFF также выполняется на 64 разрядах и возвращает -4294967296. Для 32-разрядного значения со всеми единицами используйте INTEGER -1 или NOT 0.

Для расчёта на 64 разрядах задайте LONG до операции. Добавление LONG к готовому результату не повторяет уже выполненную операцию на другой ширине. Например, CLNG(1) << 32 даёт 4294967296, а DIM wide AS LONG = 1 << 32 получает 1: сначала вычисляется сдвиг INTEGER, затем его результат расширяется.

Сдвиги

<целое значение> << <целое количество разрядов>
<целое значение> >> <целое количество разрядов>

Левый операнд имеет тип INTEGER или LONG и определяет тип результата. Правый операнд также должен быть INTEGER или LONG. Сдвиг влево отбрасывает разряды, вышедшие за ширину типа, и дополняет справа нулями. Сдвиг вправо сохраняет знак: освободившиеся старшие разряды отрицательного числа заполняются единицами, положительного — нулями.

После получения количества типа INTEGER допускается диапазон 0–63. Значения вне него вызывают MB3005. Для INTEGER фактическое количество определяется младшими пятью битами: 32 действует как 0, 33 как 1, 63 как 31. Для LONG используется количество 0–63 без такого повторения в допустимом диапазоне.

Если количество задано LONG, текущая реализация сначала сохраняет только его младшие 32 бита, затем проверяет полученный INTEGER. Поэтому LONG 4294967296 превращается в количество 0, а 4294967297 — в 1; отрицательное LONG -4294967296 тоже превращается в 0. Это особенность действующего договора; проверка не гарантирует допустимость исходной 64-разрядной величины. Для обычных сдвигов задавайте количество в пределах 0–63 без зависимости от такого преобразования.

Сдвиг не является проверяемым арифметическим умножением. Например, INTEGER 2147483647 + 1 вызывает MB3008, а 2147483647 << 1 возвращает -2 с отбрасыванием выходящих разрядов.

Беззнаковых целочисленных типов и отдельного сдвига >>> в языке нет. Для логического сдвига 32-разрядной маски можно сначала расширить значение в LONG и оставить только младшие 32 разряда маской &HFFFFFFFF; затем обычный >> работает с неотрицательным LONG.

Приоритет

NOT имеет больший приоритет, чем умножение, сложение, сдвиги и сравнения, но меньший, чем возведение в степень ^. Сдвиги имеют меньший приоритет, чем сложение, но больший, чем сравнения. Затем следуют AND, XOR, OR, EQV и IMP. Для масок используйте скобки, чтобы явно отделять нужные части, например (value AND mask) <> 0. Полная таблица: приоритет операций.

Диагностика

  • MB2003 — побитовая операция или сдвиг применены к неподходящему типу, например BOOLEAN смешан с INTEGER или количество сдвига имеет тип DOUBLE.
  • MB3005 — количество сдвига после преобразования в INTEGER находится вне 0–63.
  • MB2018 — литерал не помещается в ожидаемый целочисленный тип.
  • MB3008 — переполнение соседней арифметической операции; само отбрасывание разрядов при сдвиге этим кодом не диагностируется.
