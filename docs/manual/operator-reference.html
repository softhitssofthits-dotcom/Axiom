Операторы и инструкции

DIM

DIM — оператор языка Axiom, который вводит в программу одну или несколько переменных и связывает каждое имя с типом данных. Через оператор DIM объявляют скалярные переменные, массивы с заданными границами, динамические массивы без выделенного диапазона и строки фиксированной длины.

Полная статья: DIM

Синтаксис

DIM <имя> AS <тип>
DIM <имя> AS <тип> = <выражение>
DIM <имя> = <выражение>
DIM <имя1> AS <тип>, <имя2> AS <тип>
DIM <имя>(<нижняя граница> TO <верхняя граница>) AS <тип>
DIM <имя>(<нижняя1> TO <верхняя1>, <нижняя2> TO <верхняя2>) AS <тип>
DIM <имя>() AS <тип>
DIM <имя>(,) AS <тип>
DIM <имя> AS STRING * <длина>

Параметры и части синтаксиса

  • <имя> — имя объявляемой переменной или массива.
  • AS <тип> — явное указание типа: скалярного, пользовательского TYPE, массивного или фиксированной строки.
  • = <выражение> — начальное значение. В форме без AS это выражение также задаёт выводимый тип переменной.
  • (<нижняя граница> TO <верхняя граница>) — включительный диапазон индексов массива.
  • () — объявление одномерного динамического массива без выделенного диапазона.
  • (,), (,,) и более длинные формы с запятыми — объявление динамического массива указанного ранга.
  • STRING * <длина> — строка фиксированной длины; длина задаётся целочисленной константой.

Диагностика

  • MB2001 — имя используется до объявления или вне доступной области видимости.
  • MB2003 — значение инициализатора или присваивания несовместимо с типом переменной.
  • MB3005 — обращение к невыделенному массиву.
  • MB3007 — недопустимый массивный диапазон или запрещённая нижняя граница.

CONST

CONST — оператор языка Axiom, который вводит в программу именованную константу. Константа получает значение в момент объявления и дальше используется вместо повторяющегося числового, строкового или логического значения, которое не должно меняться во время работы программы.

Полная статья: CONST

Синтаксис

CONST <имя> AS <тип> = <выражение>
CONST <имя1> AS <тип> = <выражение1>, <имя2> AS <тип> = <выражение2>

Параметры и части синтаксиса

  • <имя> — имя объявляемой константы.
  • AS <тип> — тип константы: например INTEGER, LONG, DOUBLE, DECIMAL, STRING или BOOLEAN.
  • = <выражение> — значение константы. Оно обязательно задаётся прямо в объявлении.

Диагностика

  • MB2010 — попытка присвоить значение константе.
  • MB2002 — повторное объявление имени, включая попытку переобъявить PI, ROW или COLUMN.
  • MB2003 — значение объявления несовместимо с указанным типом.
  • MB2018 — литерал или константное значение не помещается в целевой тип.
  • MB2026 — фиксированная строка STRING * N использована в месте, где она не поддержана, например в CONST.

TYPE

TYPE ... END TYPE — оператор языка Axiom, который объявляет пользовательскую запись: новый тип данных, в котором несколько полей хранятся как одно значение. Каждое поле имеет имя и тип.

Полная статья: TYPE

TYPE и массивы: три случая

Записи и массивы часто встречаются рядом. Главное — понимать, где карточка, а где набор карточек или набор значений.

Массив записей

DIM people(1 TO 3) AS Person

people(1).Name = "Ada"
people(2).Name = "Grace"

people — массив, а каждый его элемент — запись Person.

Массивное поле внутри записи

TYPE Student
    Name AS STRING
    Marks() AS INTEGER
END TYPE

DIM pupil AS Student
REDIM pupil.Marks(1 TO 3)

pupil.Marks(1) = 5

pupil — одна запись, а pupil.Marks — массив внутри этой записи. Поддерживаются динамические и фиксированные массивные поля, включая многомерные.

Запись как поле другой записи

TYPE Address
    City AS STRING
END TYPE

TYPE Person
    Name AS STRING
    Home AS Address
END TYPE

Так запись можно разбивать на понятные части. Пользовательские типы не могут образовывать прямой или косвенный цикл вложенности.

Синтаксис объявления

TYPE имяТипа
    имяПоля AS типПоля
    другоеПоле AS другойТип = значениеПоУмолчанию
END TYPE
  • имяТипа становится новым типом данных. Его можно использовать в DIM, параметрах процедур и типах результата функций.
  • имяПоля — имя отдельного значения внутри записи.
  • типПоля может быть скалярным типом, строкой, другой записью или массивным типом.
  • TYPE ... END TYPE объявляется на верхнем уровне программы.

Диагностика

  • MB2002 — имя типа, поля или сигнатура метода внутри одного TYPE объявлены повторно.
  • MB2021 — тип после AS не найден.
  • MB2022 — внутри TYPE использована неподдерживаемая форма члена.
  • MB2023 — указанного поля нет в записи.
  • MB2024 — доступ через точку применён к значению без пользовательского типа.
  • MB2025 — REDIM или ERASE применены к фиксированному массивному полю.
  • MB2027 — значение поля по умолчанию недопустимо.
  • MB2031 — в одном TypeName(...) смешаны именованные и позиционные аргументы.
  • MB2032 — позиционная форма TypeName(...) получила неверное число аргументов.
  • MB2033 — вызов конструктора или перегруженного метода оказался неоднозначным.
  • MB3005 — IsValid() вернул FALSE после конструктора или массивное поле использовано до выделения.

SUB

Процедура SUB нужна для именованного действия: вывести сообщение, изменить переданную переменную, выполнить несколько связанных инструкций или выделить повторяющийся фрагмент программы. В отличие от функции, SUB не возвращает значение и не используется внутри выражения.

Полная статья: SUB

Где работает процедура SUB

Объявление SUB допустимо в любом контексте программы: на верхнем уровне, внутри другой процедуры или функции. Процедура не зависит от графического режима SCREEN и может работать в текстовом, графическом и консольном режимах одинаково.

Пример вызова SUB

' Ожидаемый вывод: ==Axiom==
SUB ShowBanner(text AS STRING)
    PRINT "=="; text; "=="
END SUB

ShowBanner("Axiom")

Синтаксис

SUB <имя>([<список параметров>])
    <инструкции>
END SUB
<имя>([<список аргументов>])
[BYVAL | BYREF] <имя параметра> AS <тип параметра>
RETURN

Параметры и части синтаксиса

<имя> - имя объявляемой процедуры или имя процедуры при вызове.

<список параметров> - объявления параметров через запятую. У каждого параметра указывается тип через AS; модификатор BYVAL можно не писать, потому что он действует по умолчанию.

BYVAL и BYREF - модификаторы параметра. Они не выполняются как отдельная инструкция и не вызываются по имени; они только задают способ передачи аргумента в процедуру.

<список аргументов> - значения, передаваемые процедуре при вызове в том же порядке, в котором объявлены параметры.

<инструкции> - тело процедуры.

Диагностика

Ошибка возникает, если SUB используется как выражение, если процедура вызывается с неверным числом или типами аргументов, если аргумент для BYREF не является простой переменной или если внутри SUB записан RETURN со значением.

  • MB2004 — процедура вызвана с неверным числом аргументов.
  • MB2006 — внутри SUB записан RETURN со значением.
  • MB2019 — процедура SUB используется как значение в выражении.
  • MB2028 — аргумент, передаваемый параметру BYREF, не является простой переменной подходящего типа.

FUNCTION

FUNCTION — оператор языка Axiom, который объявляет именованную функцию. Она принимает параметры, выполняет инструкции и возвращает одно значение заданного типа. Поэтому функцию можно использовать в выражении: напечатать результат, присвоить его переменной, передать дальше или проверить в условии.

Полная статья: FUNCTION

Где работает функция FUNCTION

Объявление FUNCTION допустимо в любом контексте программы: на верхнем уровне, внутри процедуры SUB или другой функции. Функция не зависит от графического режима SCREEN и может работать в текстовом, графическом и консольном режимах одинаково.

Пример вызова FUNCTION

' Ожидаемый вывод: 25
FUNCTION Square(value AS INTEGER) AS INTEGER
    RETURN value * value
END FUNCTION

PRINT Square(5)

Синтаксис

FUNCTION <имя>([<список параметров>]) AS <тип результата>
    <инструкции>
    RETURN <выражение>
END FUNCTION
<имя>([<список аргументов>])
DIM <переменная> AS FUNCTION([<типы параметров>]) AS <тип результата>
<переменная> = <имя функции>
[BYVAL | BYREF] <имя параметра> AS <тип параметра>

Параметры и части синтаксиса

<имя> - имя объявляемой функции или имя функции при вызове.

<список параметров> - объявления параметров через запятую. Каждый параметр имеет тип; BYVAL действует по умолчанию.

BYVAL и BYREF - модификаторы параметра. Они не являются операторами и не возвращают значение; они только задают, получит функция копию значения или связь с исходной переменной.

<тип результата> - тип значения, которое функция должна вернуть.

<выражение> - значение, возвращаемое оператором RETURN. Его тип должен быть совместим с типом результата функции.

<типы параметров> в функциональном типе перечисляют только типы, без имён параметров.

Диагностика

Ошибка возникает, если функция объявлена без типа результата, если RETURN внутри FUNCTION не возвращает значение, если возвращаемое выражение несовместимо с типом результата, если функция завершается без RETURN со значением или если функция с параметром BYREF используется как функциональное значение.

  • MB2003 — возвращаемое выражение несовместимо с объявленным типом результата.
  • MB2007 — внутри FUNCTION записан RETURN без выражения.
  • MB2029 — функция с параметром BYREF используется как функциональное значение.
  • MB3006 — выполнилась ветвь FUNCTION, которая завершается без RETURN со значением; ошибка времени выполнения.

PRINT

PRINT — оператор языка Axiom, который записывает в поток вывода программы текст, числа и результаты выражений. Оператор используют для сообщений пользователю, промежуточных результатов и простых таблиц, а форма PRINT USING применяет к значениям форматную строку.

Полная статья: PRINT

PRINT USING

PRINT USING сначала вычисляет строку формата, затем подставляет значения из списка вывода в поля формата слева направо.

Для строк поддержаны поля:

  • ! — первый символ строки;
  • & — вся строка;
  • \ \ — поле фиксированной ширины; число пробелов между обратными косыми чертами задаёт ширину вместе с самими границами поля.

Для чисел поддержаны маски на основе символов #, 0, ., +, -, ,, $, * и ^.

Пример обычного PRINT

В этом примере точка с запятой соединяет фрагменты без дополнительного пробела, запятая ставит один пробел, а пустой PRINT выводит пустую строку.

PRINT "Имя: "; "Анна"
PRINT "Курс:", 2
PRINT
PRINT "Готово"

Результат:

Имя: Анна
Курс: 2

Готово

Пример PRINT USING

В этом примере строковое поле ограничивает имя шириной поля, а числовая маска задаёт два знака после десятичной точки.

PRINT USING "Имя: \    \|"; "Боб"
PRINT USING "Итог: ###.##"; 12.5
PRINT USING "Флаг: !"; "XYZ"

Результат:

Имя: Боб   |
Итог:  12.50
Флаг: X

Синтаксис

PRINT
PRINT <список вывода>
PRINT <список вывода> ;
PRINT <список вывода> ,
PRINT USING <формат> ; <список вывода>
PRINT USING <формат> ; <список вывода> ;
PRINT USING <формат> ; <список вывода> ,

Параметры и части синтаксиса

  • <список вывода> — одно или несколько выражений, которые нужно вывести. Элементы списка разделяются точкой с запятой ; или запятой ,.
  • ; между элементами выводит соседние значения подряд, без добавленного пробела.
  • , между элементами выводит один пробел.
  • Завершающий ; или , подавляет автоматический перевод строки после оператора.
  • <формат> в PRINT USING — строковое выражение с полями форматирования.

Диагностика

  • MB2003 — выражение формата в PRINT USING не имеет тип STRING.
  • MB3007 — ошибка форматирования PRINT USING: неподходящий тип значения для поля, нехватка значения для числового поля или недопустимая форматная строка.

INPUT

INPUT — оператор языка Axiom, который останавливает выполнение программы, ждёт строку от пользователя и присваивает введённые значения указанным переменным. Оператор используют в простых интерактивных программах, когда данные должны поступить во время выполнения, а не быть записаны в тексте программы заранее.

Полная статья: INPUT

Как INPUT получает строку ввода

Оператор INPUT читает одну логическую строку ввода. Если в списке указана одна переменная, вся введённая строка преобразуется к типу этой переменной. Если переменных несколько, строка разбирается как список значений, разделённых запятыми.

Перед ожиданием ввода можно вывести строку приглашения. Если программа не выбирала экранный режим через SCREEN, ввод идёт через нижнюю область Output в IDE. Если активен SCREEN 0 или графический SCREEN, приглашение и ввод отображаются в окне SCREEN.

Как INPUT разбирает введённую строку

Когда выполнение доходит до INPUT, программа ждёт подтверждения строки ввода. После этого Axiom разбирает введённый текст и только затем записывает значения в переменные.

Для одной строковой переменной ввод не разбивается по запятым: вся строка становится значением переменной. Для нескольких переменных запятые разделяют поля ввода, а пробелы вокруг каждого поля отбрасываются.

Числовые значения разбираются в инвариантной записи с точкой как десятичным разделителем. Логическое значение должно быть записано как TRUE или FALSE без учёта регистра. Если преобразование невозможно, выполнение сообщает ошибку времени выполнения.

Если выполнение остановлено командой IDE во время ожидания оператора INPUT, программа завершается с результатом отмены. Отмена не подтверждает пустую строку, не записывает значения в переменные и не вызывает ошибку MB3003. Операторы после отменённого ввода не выполняются.

Синтаксис

INPUT <переменная>
INPUT <переменная1>, <переменная2>[, <переменнаяN>]
INPUT <приглашение> ; <переменная>
INPUT <приглашение> , <переменная>

Параметры и части синтаксиса

  • <приглашение> — строковая константа, которая выводится перед ожиданием ввода.
  • ; или , после приглашения отделяет текст приглашения от списка переменных. В текущем Axiom обе формы принимаются как синтаксические варианты одного договора.
  • <переменная> — изменяемая переменная, в которую записывается введённое значение.
  • <переменная1>, <переменная2> — список переменных. Количество введённых значений должно совпадать с количеством переменных.

Диагностика

  • MB3003 — число введённых значений не совпадает с числом переменных или введённый текст нельзя преобразовать к требуемому типу.

milliseconds задаёт длительность паузы в миллисекундах. Выражение приводится к типу LONG и должно давать неотрицательное значение, которое помещается в поддерживаемый диапазон ожидания среды выполнения.

RANDOMIZE

RANDOMIZE — оператор языка Axiom, который заново сеет генератор случайных чисел, используемый функцией RND. После RANDOMIZE с одним и тем же зерном последовательность RND повторяется от запуска к запуску.

Полная статья: RANDOMIZE

Для чего нужен оператор RANDOMIZE

Оператор RANDOMIZE нужен там, где случайность должна быть воспроизводимой: повторяемые тесты, одинаковые расклады уровней игры, отладка сценариев. Без явного посева источник случайности управляется средой запуска, и последовательность RND от программы не контролируется.

Синтаксис

RANDOMIZE
RANDOMIZE seed

Аргумент seed задаёт зерно генератора — число типа INTEGER или LONG. Форма без аргумента оставляет посев на усмотрение среды запуска.

Правила работы

  • после RANDOMIZE seed последовательность RND() одинакова при каждом прогоне программы с тем же зерном;
  • оператор влияет только на будущие вызовы RND и не возвращает значения;
  • зерно типа LONG должно умещаться в диапазон INTEGER, иначе оператор сообщает диагностику MB3008.

OPEN

OPEN — оператор языка Axiom, который открывает файл для чтения, записи или дописывания. Оператор связывает файл с заранее объявленной переменной типа FILE, через которую далее работают все файловые операции.

Полная статья: OPEN

Как OPEN связывает файл с переменной

Оператор OPEN открывает текстовый файл и связывает его с переменной типа FILE. Переменная типа FILE хранит открытый файл и передаётся файловым функциям.

Где работает оператор OPEN

Оператор OPEN работает в любом контексте программы и не зависит от графического режима SCREEN. Файловые операции доступны в текстовом, графическом и консольном режимах одинаково.

Синтаксис

Чтение с автоматическим выбором кодировки

OPEN path FOR INPUT AS fileVariable

Запись в UTF-8 без BOM

OPEN path FOR OUTPUT AS fileVariable

Дописывание в UTF-8 без BOM

OPEN path FOR APPEND AS fileVariable

Чтение с выбранной кодировкой

OPEN path FOR INPUT AS fileVariable USING encoding

Запись с выбранной кодировкой

OPEN path FOR OUTPUT AS fileVariable USING encoding

Дописывание с выбранной кодировкой

OPEN path FOR APPEND AS fileVariable USING encoding

USING encoding задаёт кодировку открываемого файла.

Параметры и части синтаксиса

path задаёт путь к файлу. fileVariable обозначает переменную типа FILE, с которой будет связан открытый файл.

Режим INPUT открывает существующий файл для чтения, OUTPUT создаёт новый файл или полностью перезаписывает существующий, а APPEND открывает файл для дописывания в конец.

В режиме INPUT Axiom проверяет весь текст файла как UTF-8, включая первые байты и короткие файлы. Если текст не является корректным UTF-8, используется Windows-1251. Начальный BOM UTF-8 пропускается и не входит в позиции FILEPOS. При чтении функцией READTEXT один символ Unicode, в том числе emoji, читается целиком; байтовые позиции файла при этом сохраняются.

Диагностика

Нестрочные аргументы и переменная неверного типа после AS отклоняются при проверке программы. MB3007 возникает при неизвестной кодировке, конфликтующем BOM, повреждённом Unicode в INPUT/APPEND, недоступном пути, отсутствии файла INPUT и повторном открытии занятой переменной. Отказ из-за неизвестной кодировки не стирает файл OUTPUT. При отказе проверки INPUT/APPEND файл не изменяется, а системный поток освобождается.

Полная статья: CLOSE

Синтаксис

CLOSE fileVariable

Параметры и части синтаксиса

fileVariable обозначает переменную типа FILE, которая уже содержит открытый файл.

Диагностика

Закрытый файл даёт диагностику MB3007. Ошибка записи при завершении буфера также даёт MB3007; её можно обработать через TRY/CATCH. Файл после такого отказа закрыт, но сохранение всего текста не гарантируется: часть данных могла быть записана до ошибки.

IF

IF — оператор языка Axiom, который выполняет один блок инструкций или другой блок инструкций в зависимости от значения логического выражения. С помощью оператора IF программа переходит от простого последовательного выполнения к условному ветвлению.

Полная статья: IF

Когда использовать IF

Оператор IF используется, когда дальнейшие действия программы зависят от условия. Условие вычисляется как значение типа BOOLEAN: если оно истинно, выполняется ветвь THEN; если ложно, Axiom проверяет следующие ветви ELSEIF или переходит к ветви ELSE.

Когда проверяется одно условие или небольшая цепочка связанных условий, IF обычно читается проще всего. Если же нужно выбрать один вариант из набора значений одного выражения, часто удобнее использовать SELECT CASE.

Синтаксис

IF <логическое выражение> THEN
    [<операторы>]
[ELSEIF <логическое выражение> THEN
    [<операторы>]]
[ELSE
    [<операторы>]]
END IF

Параметры и части синтаксиса

  • <логическое выражение> — выражение типа BOOLEAN, которое определяет, выполняется ли соответствующая ветвь.
  • THEN отделяет условие от блока операторов, выполняемого при истинном значении условия.
  • ELSEIF задаёт дополнительное условие. Таких ветвей может быть несколько.
  • ELSE задаёт блок операторов для случая, когда ни одно предыдущее условие не оказалось истинным.
  • END IF завершает блочную конструкцию.

Диагностика

  • MB2008 — условие после IF или ELSEIF не имеет тип BOOLEAN.
  • MB2001 — имя, объявленное внутри ветви, используется после выхода из области видимости.
  • MB1005 — в конструкции IF допускается только один блок ELSE.

SELECT CASE

SELECT CASE — оператор языка Axiom, который выполняет один из нескольких блоков операторов в зависимости от значения одного проверяемого выражения. Оператор удобен, когда программа должна выбрать ветвь по точному значению, диапазону или сравнению.

Полная статья: SELECT CASE

Когда использовать SELECT CASE

Оператор SELECT CASE применяют там, где одна и та же величина сравнивается с несколькими вариантами. Выражение выбора вычисляется один раз, а затем Axiom просматривает ветви CASE сверху вниз.

Если ветвление строится не вокруг одного значения, а вокруг разных логических условий, обычно лучше использовать IF ... ELSEIF ... ELSE. Если же все варианты относятся к одному выражению, SELECT CASE делает программу короче и нагляднее.

Синтаксис

SELECT CASE <выражение выбора>
    CASE <список селекторов>
        [<операторы>]
    [CASE <список селекторов>
        [<операторы>]]
    [CASE ELSE
        [<операторы>]]
END SELECT

Параметры и части синтаксиса

  • <выражение выбора> — числовое, строковое или логическое выражение, значение которого сравнивается с селекторами в ветвях CASE.
  • <список селекторов> — один селектор или несколько селекторов через запятую.
  • <операторы> — инструкции, которые выполняются, если соответствующая ветвь выбрана.
  • CASE ELSE — необязательная ветвь для случая, когда ни один обычный CASE не подошёл.
  • END SELECT завершает блочную конструкцию.

Диагностика

  • MB2015 — диапазон CASE ... TO используется с типом, для которого диапазоны не поддержаны.
  • MB2003 — селектор или сравнение несовместимы с типом выражения выбора.
  • MB2001 — имя, объявленное внутри ветви, используется после выхода из области видимости.
  • MB1006 — в конструкции SELECT CASE допускается только один блок CASE ELSE.

FOR

FOR ... NEXT — оператор языка Axiom, который повторяет блок операторов, пока управляющая переменная проходит заданный числовой диапазон. Такой цикл применяют, когда ход повторения удобно выразить начальным значением, конечным значением и шагом изменения счётчика.

Полная статья: FOR

Когда использовать FOR

Оператор FOR используется для циклов с заранее заданным счётом. Перед первым проходом Axiom присваивает счётчику начальное значение, затем перед каждым проходом проверяет, не вышел ли счётчик за конечную границу.

Если повторение зависит от общего логического условия, а не от счётчика, обычно удобнее использовать WHILE или DO ... LOOP. Если же нужно пройти от одного числового значения к другому, FOR делает намерение программы явным.

Синтаксис

FOR <счётчик> = <начало> TO <конец> [STEP <шаг>]
    [<операторы>]
    [EXIT FOR]
    [CONTINUE FOR]
    [<операторы>]
NEXT

Параметры и части синтаксиса

  • <счётчик> — управляющая переменная цикла. Она получает начальное значение перед первым проходом и автоматически изменяется после каждой итерации.
  • <начало> — числовое выражение, задающее первое значение счётчика.
  • <конец> — числовое выражение, задающее конечную границу цикла.
  • STEP <шаг> — необязательная часть, задающая изменение счётчика после прохода. Если STEP не указан, используется шаг 1.
  • <операторы> — инструкции, которые выполняются при каждом проходе цикла.
  • EXIT FOR — необязательный досрочный выход из ближайшего окружающего цикла FOR ... NEXT.
  • CONTINUE FOR — необязательный пропуск оставшейся части текущей итерации с переходом к инкременту счётчика.
  • NEXT завершает тело цикла и возвращает управление к проверке следующего значения счётчика.

Диагностика

  • MB2009 — выражение счётчика или занявшее имя переменной имеет тип, который нельзя использовать в FOR.
  • MB2016 — имя счётчика уже занято во внешней области (DIM, CONST, параметр, внешний цикл): счётчик FOR всегда локальный.
  • MB3004 — шаг цикла равен нулю.
  • MB2013 — EXIT FOR используется вне цикла FOR ... NEXT.
  • MB2037 — CONTINUE FOR используется вне цикла FOR ... NEXT.
  • MB2001 — счётчик, созданный самой строкой FOR, используется после выхода из его области видимости.

WHILE

WHILE — оператор языка Axiom, который повторяет блок инструкций до тех пор, пока заданное условие остаётся истинным. Условие проверяется перед каждым проходом, поэтому тело цикла может не выполниться ни одного раза.

Полная статья: WHILE

Переход после END WHILE

  • Условие проверяется до входа в тело и затем перед каждым следующим проходом.
  • Когда условие становится FALSE, управление переходит к первой инструкции после END WHILE.
  • Для прямого выхода из середины предусловного цикла используйте DO ... LOOP и EXIT DO: отдельной формы EXIT WHILE в Axiom сейчас нет.
  • CONTINUE WHILE пропускает оставшуюся часть тела и переходит к проверке условия в заголовке цикла.

Блок цикла закрывается оператором END WHILE. Для цикла с прямым выходом используется DO ... LOOP с оператором EXIT DO.

Синтаксис

WHILE <условие>
    <инструкции>
    [CONTINUE WHILE]
    [<инструкции>]
END WHILE

Параметры и части синтаксиса

<условие> - логическое выражение типа BOOLEAN. Пока оно равно TRUE, цикл выполняет очередной проход.

<инструкции> - тело цикла. В нём обычно меняют значение, от которого зависит условие, иначе цикл может не завершиться.

CONTINUE WHILE — пропуск оставшейся части текущей итерации с переходом к проверке условия. Подробнее — на странице оператора CONTINUE.

Диагностика

Ошибка возникает, если условие WHILE не имеет тип BOOLEAN, если блок не закрыт END WHILE или если в тексте используется неподдержанная форма выхода вроде EXIT WHILE.

  • MB2038 — CONTINUE WHILE используется вне цикла WHILE ... END WHILE.

RETURN

RETURN — оператор языка Axiom, который завершает выполнение текущей процедуры или функции. В функции оператор RETURN отдаёт вызывающему коду вычисленное значение, а в процедуре служит досрочным выходом без результата.

Полная статья: RETURN

Когда использовать RETURN

Оператор RETURN нужен для завершения текущей процедуры или функции. В FUNCTION оператор RETURN обязателен на исполняемом пути, который должен вернуть результат. В SUB оператор RETURN не обязателен: процедура может спокойно дойти до END SUB, а RETURN нужен только для раннего завершения.

Где работает оператор RETURN

Оператор RETURN допустим только внутри SUB или FUNCTION. Оператор RETURN выполняется BytecodeVm после компиляции.

Синтаксис

RETURN <выражение>
RETURN

Оператор RETURN поддерживает две формы: с выражением для функций и без выражения для процедур.

Параметры и части синтаксиса

ЧастьОписание
<выражение>Значение, которое возвращает текущая функция. Эта форма допустима только внутри FUNCTION.

Форма RETURN без выражения допустима только внутри SUB.

Правила работы

  • После выполнения RETURN оставшиеся инструкции текущей процедуры или функции не выполняются.
  • RETURN <выражение> должен вернуть значение, совместимое с типом результата текущей функции.
  • RETURN без значения в SUB удобен для проверки особого случая в начале процедуры.

Оператор RETURN завершает вызов процедуры или функции. В процедуре SUB значение не указывается; в функции FUNCTION указывается возвращаемое выражение.

Диагностика

  • Оператор RETURN записан вне SUB или FUNCTION.
  • SUB возвращает значение через RETURN.
  • FUNCTION использует RETURN без значения.
  • Тип возвращаемого выражения не подходит к типу результата функции.
  • Функция завершилась без возвращённого значения.

TRY

TRY — оператор языка Axiom, который выделяет участок программы, где может возникнуть ошибка времени выполнения. CATCH получает управление, если ошибка произошла и её нужно обработать без остановки программы. FINALLY используют для действий, которые должны выполниться при выходе из блока.

Полная статья: TRY

Как TRY заменяет переход к обработчику

В Axiom эта форма заменяет старую идею ON ERROR GOTO без перехода по метке. Обработчик расположен рядом с опасным участком кода, а значение ошибки попадает в переменную, указанную после CATCH, например err в записи CATCH err.

Поддержанные формы TRY/CATCH/FINALLY компилируются в байт-код и выполняются BytecodeVm. Неподдержанными остаются старые формы продолжения с точки ошибки и фильтры обработчиков.

Синтаксис

TRY
    [tryStatements]
CATCH errorVariable
    [catchStatements]
FINALLY
    [finallyStatements]
END TRY

Должна быть указана хотя бы одна часть: CATCH или FINALLY. Если обработка ошибки не нужна, можно оставить только FINALLY. Если отдельная очистка не нужна, можно оставить только CATCH.

Параметры и части синтаксиса

TRY, CATCH, FINALLY и END TRY — ключевые слова одного блочного оператора. Имена tryStatements, catchStatements, finallyStatements и errorVariable в синтаксисе — не слова языка, а обозначения мест, куда в реальном коде вставляются инструкции и имя переменной.

tryStatements — инструкции, при выполнении которых может возникнуть ошибка времени выполнения.

errorVariable — локальная переменная только для чтения. Она доступна только внутри блока CATCH и имеет встроенный тип ERROR.

catchStatements — инструкции обработки. Если ошибка обработана, выполнение продолжается после END TRY, если только обработчик сам не завершился новой ошибкой или ранним выходом.

finallyStatements — инструкции завершения. Они выполняются при обычном выходе, после CATCH и перед выходом с необработанной ошибкой.

ERROR

ERROR — оператор языка Axiom, который принудительно создаёт ошибку времени выполнения или повторно поднимает уже пойманное значение ERROR. Оператор используют, когда программа сама обнаружила недопустимое состояние либо обработчик должен передать ошибку внешнему CATCH без потери исходных сведений.

Полная статья: ERROR

Синтаксис

ERROR код
ERROR код, сообщение
ERROR ошибка

ERROR в начале строки — оператор. В форме ERROR ошибка слово ошибка обозначает выражение встроенного типа ERROR, например переменную из CATCH err.

код должен иметь тип STRING. сообщение тоже имеет тип STRING и является необязательным. ошибка должна иметь встроенный тип ERROR.

Параметры и части синтаксиса

код - строковый идентификатор ошибки. Для пользовательских ошибок удобно применять короткие проектные коды, например "APP001" или "FILEMODE".

сообщение - текст, который попадёт в err.Message и в диагностику времени выполнения, если ошибка не будет обработана. Если сообщение не указано, Axiom использует сообщение по умолчанию: Пользовательская ошибка <код>.

ошибка - существующее значение встроенного типа ERROR. Форма ERROR err повторно поднимает его с теми же Code, Message, Line и Column.

REDIM

REDIM — оператор языка Axiom, который выделяет хранилище массива с указанными границами. Форма REDIM PRESERVE сохраняет элементы из области пересечения прежних и новых границ.

Полная статья: REDIM

Синтаксис

REDIM <массив>(<нижняя граница> TO <верхняя граница>)
REDIM PRESERVE <массив>(<нижняя граница> TO <верхняя граница>)

Для многомерного массива пары границ всех измерений записываются через запятую.

Параметры

  • <массив> — изменяемое значение массива.
  • Нижняя и верхняя границы — целочисленные выражения с допустимыми индексами. Обе границы входят в диапазон.

Обычный REDIM создаёт новое хранилище и задаёт элементам значения по умолчанию. Форма с PRESERVE копирует элементы с теми же индексами в области пересечения всех измерений; остальные элементы получают значения по умолчанию. Если пересечение пусто, старые значения не сохраняются.

Ранг и тип элементов не меняются. Поле фиксированного массива внутри записи TYPE перераспределять нельзя. Границы, пустые измерения и ограничения индексов описаны в разделе многомерных массивов.

Диагностика

  • MB2011 — цель не является массивом.
  • MB2010 — цель объявлена неизменяемой.
  • MB2004 — число измерений не соответствует рангу массива.
  • MB2025 — цель является фиксированным полем массива в записи TYPE.

SCREEN

SCREEN — оператор языка Axiom, который выбирает экранный режим программы. Оператор SCREEN может открыть текстовое окно SCREEN 0 или графический экран SCREEN 1..10. После оператора SCREEN текстовый вывод и графика идут уже не в обычный поток вывода, а в отдельное окно программы.

Полная статья: SCREEN

Когда использовать SCREEN

Оператор SCREEN нужен тогда, когда программе требуется собственное экранное окно с текстовой сеткой, палитровыми цветами, пиксельной графикой, экранными страницами и операторами рисования Axiom.

Если программа не вызвала оператор SCREEN, операторы PRINT и INPUT работают в области текстового вывода среды исполнения. Если программа вызвала оператор SCREEN, текст и графика переносятся в отдельное экранное окно.

Где работает оператор SCREEN

Оператор SCREEN относится к экранному режиму Axiom. Этот оператор включает текстовый или графический режим SCREEN и управляет им.

Оператор SCREEN и оператор CANVAS относятся к разным графическим договорам. Если программа вызвала оператор CANVAS, последующий оператор SCREEN закрывает современный холст и возвращает программу к правилам экранного режима.

Что делает оператор SCREEN

Форма SCREEN 0 открывает текстовое окно с видимой сеткой 80 x 25. В этом режиме графические операторы рисования недоступны, но текстовый вывод, INPUT и работа курсора идут через отдельное экранное окно.

Формы SCREEN 1..10 открывают графический экран. После этого становятся доступны графические операторы PSET, PRESET, LINE, CIRCLE, PAINT, DRAW, а также экранные операторы VIEW, WINDOW, PCOPY, GET, PUT, COLOR, LOCATE и связанные функции.

Если указаны activePage и visiblePage, оператор SCREEN одновременно выбирает страницу для рисования и страницу для показа. Это позволяет собирать кадр на скрытой странице, а затем показывать его через PCOPY.

visiblePageНеобязательный номер видимой графической страницы от 0 до 3. Именно эта страница показывается в окне программы.

Пустое место после первой запятой оставлено под зарезервированный параметр colorSwitch. Этот параметр не поддерживается, поэтому для выбора страниц используется форма с пустым полем: SCREEN 1, , 1, 0.

Правила работы

В режиме SCREEN 0 действует текстовый договор. Новая строка из последней видимой строки прокручивает окно вверх на одну строку. В Axiom.Ide предыдущие строки не исчезают сразу: их можно просмотреть через вертикальную полосу прокрутки.

В режимах SCREEN 1..10 действует графический договор. Текст выводится поверх графического экрана по ячейкам 8 x 12 пикселей. Количество доступных строк и столбцов зависит от выбранного режима.

Режим SCREEN 10 выбирает максимально возможную клиентскую область с соотношением сторон 16:9, которая помещается в рабочую область текущего монитора. Поэтому функции SCREENWIDTH() и SCREENHEIGHT() в этом режиме возвращают фактические размеры окна, а не заранее фиксированное значение.

Диагностика

  • MB3007: режим SCREEN, активная страница или видимая страница имеют недопустимое значение.
  • MB3005: хост не смог создать экранное окно или выбранный экранный режим недоступен.

VIEW

VIEW — оператор языка Axiom, который задаёт прямоугольную область графического экрана, внутри которой работает рисование. Родственная форма VIEW PRINT задаёт не область пикселей, а диапазон строк для экранного текста на графическом экране.

Полная статья: VIEW

Когда использовать VIEW

Оператор VIEW нужен тогда, когда программе требуется ограничить физическую область экрана для рисования.

Оператор VIEW PRINT нужен тогда, когда программе требуется ограничить диапазон строк экранного текста на графическом экране.

Где работает оператор VIEW

Оператор VIEW и оператор VIEW PRINT работают только после выбора графического режима SCREEN 1..10.

Синтаксис оператора VIEW

VIEW
VIEW SCREEN (left, top)-(right, bottom)
VIEW SCREEN (left, top)-(right, bottom), fillColor
VIEW SCREEN (left, top)-(right, bottom), fillColor, borderColor
VIEW (left, top)-(right, bottom)
VIEW (left, top)-(right, bottom), fillColor
VIEW (left, top)-(right, bottom), fillColor, borderColor

Синтаксис оператора VIEW PRINT

VIEW PRINT
VIEW PRINT topRow TO bottomRow

Что делает оператор VIEW

Форма VIEW без аргументов сбрасывает viewport и возвращает рисование ко всему экрану.

Форма VIEW SCREEN (...) ограничивает область рисования, но сохраняет координаты как абсолютные экранные координаты.

Форма VIEW (...) ограничивает область рисования и переводит координаты в систему viewport.

Если программа указала цвет заливки, оператор VIEW заполняет внутреннюю область viewport этим цветом. Если программа указала цвет рамки, оператор VIEW рисует рамку viewport.

Что делает оператор VIEW PRINT

Форма VIEW PRINT без аргументов сбрасывает текстовое окно и возвращает экранный текст ко всей доступной текстовой сетке графического режима.

Форма VIEW PRINT topRow TO bottomRow ограничивает строки, в которых прокручиваются последующие PRINT, PRINT USING и подтверждённый INPUT на графическом экране.

Правила работы

Оператор VIEW ограничивает физическую область вывода графических операторов. Оператор WINDOW поверх этого viewport может дополнительно задать логическую систему координат.

Оператор VIEW PRINT не управляет пикселями. Этот оператор управляет только текстовыми строками.

  • форма VIEW без аргументов и форма VIEW PRINT без аргументов сбрасывают соответствующее ограничение и возвращают вывод ко всему экрану;
  • координаты viewport задаются в пикселях; строки VIEW PRINT задаются в строках текстовой сетки текущего графического режима;
  • недопустимые границы viewport или номера строк завершают выполнение диагностикой MB3007;
  • оператор VIEW действует только в графическом режиме: без активного SCREEN 1..10 выполнение завершается диагностикой MB3010;
  • заливка и рамка viewport становятся видимыми сразу после выполнения оператора VIEW, если указаны соответствующие цвета.

Диагностика

  • MB3010: оператор VIEW или оператор VIEW PRINT вызваны без активного графического режима SCREEN 1..10.
  • MB3007: координаты viewport или номера строк имеют недопустимое значение.

WINDOW

WINDOW — оператор языка Axiom, который задаёт логическую систему координат внутри текущего viewport. После оператора WINDOW программа может рисовать не по физическим пикселям экрана, а по собственной числовой шкале.

Полная статья: WINDOW

Когда использовать WINDOW

Оператор WINDOW нужен тогда, когда программе требуется рисовать графики, оси, фигуры или схемы не в пиксельных координатах, а в собственной логической системе координат.

Где работает оператор WINDOW

Оператор WINDOW работает только после выбора графического режима SCREEN 1..10.

Оператор WINDOW не открывает графический режим сам по себе. Перед оператором WINDOW программа должна вызвать оператор SCREEN.

Что делает оператор WINDOW

Форма WINDOW без аргументов сбрасывает логическое окно и возвращает координаты к текущей системе viewport.

Форма WINDOW SCREEN (...) включает логическую систему координат с экранным направлением оси Y.

Форма WINDOW (...) включает логическую систему координат с математическим направлением оси Y, то есть увеличение Y вверх.

Синтаксис

WINDOW
WINDOW SCREEN (left, top)-(right, bottom)
WINDOW (left, top)-(right, bottom)

Параметры и части синтаксиса

ЧастьОписание
left, top, right, bottomДве противоположные вершины логического прямоугольника.
SCREENСлово SCREEN сохраняет экранное направление оси Y, то есть увеличение Y вниз.

Правила работы

Оператор VIEW выбирает физическую область экрана, а оператор WINDOW задаёт логическую шкалу внутри этой области. Обычно программа сначала настраивает оператор VIEW, а затем при необходимости включает оператор WINDOW.

После оператора WINDOW логические координаты используют операторы PSET, PRESET, LINE, CIRCLE, PAINT, DRAW и форма POINT(x, y).

Для явного перевода между логическими координатами WINDOW и физическими координатами viewport программа использует функцию PMAP.

Диагностика

  • MB3010: оператор WINDOW вызван без активного графического режима SCREEN 1..10.
  • MB3007: границы логического окна имеют недопустимое значение или вырождают логический прямоугольник.

Раздел экранного текста описывает операторы CLS, COLOR и LOCATE в режимах SCREEN. Оператор CLS очищает экран, оператор COLOR задаёт цвета последующего текста, а оператор LOCATE переносит текстовый курсор в заданную строку и столбец.

Полная статья: CLS

Оператор CLS

CLS — оператор языка Axiom, который очищает экранный вывод.

CLS

Если программа работает в режиме SCREEN, оператор CLS очищает текущее экранное окно и возвращает текстовый курсор в позицию 1, 1.

Если программа не вызвала оператор SCREEN, оператор CLS очищает обычный вывод в области текстового вывода среды исполнения.

Если программа работает в графическом режиме SCREEN, оператор CLS очищает и экранный текст, и нарисованные пиксели.

SCREEN 3
PRINT "Старая надпись"
CLS
PRINT "Экран очищен"

Правила работы

В режиме SCREEN 0 подтверждённый вывод из последней видимой строки прокручивает окно вверх на одну строку.

В графических режимах SCREEN 1..10 текст рисуется по ячейкам поверх графического экрана. Если программа выводит текст ниже доступной сетки и не использует отдельное текстовое окно VIEW PRINT, текст ниже нижней границы не становится видимым.

Оператор COLOR меняет только последующий текст. Этот оператор не перекрашивает символы, которые уже были выведены раньше.

Диагностика

  • MB3010: оператор COLOR вызван без активного графического режима SCREEN 1..10.
  • MB3007: оператор LOCATE получил строку или столбец вне допустимого диапазона текущей экранной сетки.

COLOR

Раздел экранного текста описывает операторы CLS, COLOR и LOCATE в режимах SCREEN. Оператор CLS очищает экран, оператор COLOR задаёт цвета последующего текста, а оператор LOCATE переносит текстовый курсор в заданную строку и столбец.

Полная статья: COLOR

Оператор COLOR

COLOR — оператор языка Axiom, который задаёт оформление последующего текста на графическом экране SCREEN.

COLOR foreground
COLOR foreground, background
COLOR foreground, TRANSPARENT

foreground — номер цвета символов.

background — номер непрозрачного цвета фона под символами.

TRANSPARENT — специальное слово, которое включает прозрачный фон под последующим текстом.

Оператор COLOR foreground меняет только цвет символов и сохраняет текущий режим фона. Оператор COLOR foreground, background меняет цвет символов и цвет непрозрачного фона. Оператор COLOR foreground, TRANSPARENT меняет цвет символов и включает прозрачный фон.

Оператор COLOR в этом договоре работает только после выбора графического режима SCREEN 1..10. В режиме SCREEN 0 этот экранный цветовой договор не действует.

SCREEN 3
COLOR 14, 1
PRINT "Жёлтый текст на синем фоне"
COLOR 15, TRANSPARENT
PRINT "Белый текст поверх графики"

Правила работы

В режиме SCREEN 0 подтверждённый вывод из последней видимой строки прокручивает окно вверх на одну строку.

В графических режимах SCREEN 1..10 текст рисуется по ячейкам поверх графического экрана. Если программа выводит текст ниже доступной сетки и не использует отдельное текстовое окно VIEW PRINT, текст ниже нижней границы не становится видимым.

Оператор COLOR меняет только последующий текст. Этот оператор не перекрашивает символы, которые уже были выведены раньше.

Диагностика

  • MB3010: оператор COLOR вызван без активного графического режима SCREEN 1..10.
  • MB3007: оператор LOCATE получил строку или столбец вне допустимого диапазона текущей экранной сетки.

LOCATE

Раздел экранного текста описывает операторы CLS, COLOR и LOCATE в режимах SCREEN. Оператор CLS очищает экран, оператор COLOR задаёт цвета последующего текста, а оператор LOCATE переносит текстовый курсор в заданную строку и столбец.

Полная статья: LOCATE

Оператор LOCATE

LOCATE — оператор языка Axiom, который переносит текстовый курсор в указанную строку и в указанный столбец экранной сетки.

LOCATE row, column

row — номер строки экранной сетки, начиная с 1.

column — номер столбца экранной сетки, начиная с 1.

После оператора LOCATE следующий текстовый вывод начинается в указанной ячейке.

Оператор LOCATE работает по текстовой сетке, а не по пикселям. Поэтому значения row и column должны укладываться в количество строк и столбцов текущего режима SCREEN.

SCREEN 1
LOCATE 3, 5
PRINT "Текст начинается с третьей строки и пятого столбца"

PALETTE

PALETTE — оператор языка Axiom, который меняет соответствие между индексом палитры и видимым цветом на графическом экране SCREEN. Оператор PALETTE нужен для палитровой графики режима SCREEN, где пиксели хранят цветовые индексы, а палитра определяет, каким цветом эти индексы показываются пользователю.

Полная статья: PALETTE

Когда использовать PALETTE

Оператор PALETTE нужен тогда, когда программа хочет изменить вид уже нарисованных индексных пикселей без их перерисовки.

Оператор PALETTE позволяет временно сменить цветовую схему экрана, выделить важный объект, показать эффект тревоги или вернуть стандартную палитру после временной настройки цветов.

Где работает оператор PALETTE

Оператор PALETTE работает только в графических режимах SCREEN 1 ... SCREEN 10.

Оператор PALETTE не относится к современному полноцветному слою CANVAS. В слое CANVAS программа задаёт цвет напрямую через функцию RGB, а не через палитровое переназначение индексов.

Что делает оператор PALETTE

Оператор PALETTE без аргументов сбрасывает палитру текущего графического экрана к стандартному отображению цветов Axiom.

Оператор PALETTE index, color переназначает один индекс палитры на другой видимый цвет.

Оператор PALETTE USING array переназначает несколько индексов палитры по значениям одномерного числового массива.

Пример PALETTE USING

SCREEN 1
DIM colors(0 TO 2) AS INTEGER
colors(0) = 16
colors(1) = 196
colors(2) = 46

LINE (20, 40)-(180, 40), 1
PRINT POINT(20, 40)

PALETTE USING colors
PRINT POINT(20, 40)

В этом примере оператор PALETTE USING берёт новые цвета для индексов 0, 1 и 2 из массива colors. При этом линия по-прежнему хранит индекс 1.

Синтаксис

PALETTE
PALETTE index, color
PALETTE USING array

На этой странице показаны три разные формы одного оператора PALETTE. Это не одна общая запись, где нужно указывать все части сразу.

Параметры и части синтаксиса

ЧастьОписание
indexИндекс палитры, который оператор PALETTE должен переназначить. Значение приводится к целому и нормализуется по правилу ABS(value) MOD 256.
colorНовый видимый цвет для указанного индекса. Значение приводится к целому и нормализуется по тому же правилу ABS(value) MOD 256.
arrayОдномерный числовой массив. Видимые элементы массива задают цвета для индексов палитры, начиная с индекса 0.

Правила работы

Оператор PALETTE работает только в графических режимах SCREEN 1 ... SCREEN 10. Если графический режим не активен, оператор PALETTE сообщает ошибку времени выполнения MB3010.

Оператор PALETTE не перерисовывает пиксели и не меняет сохранённые индексы пикселей. Если программа нарисовала линию цветом 1, а затем выполнила PALETTE 1, 196, линия начнёт отображаться как цвет 196, но функция POINT(x, y) по-прежнему вернёт индекс 1.

Оператор PALETTE USING читает видимые элементы массива по порядку. Первый видимый элемент массива задаёт цвет для индекса 0, второй элемент задаёт цвет для индекса 1, и так далее. Нижняя граница массива не становится номером индекса палитры.

Элементы массива в операторе PALETTE USING приводятся к целому значению, а затем нормализуются по тому же правилу ABS(value) MOD 256, что и обычные аргументы index и color.

Если массив для оператора PALETTE USING содержит больше 256 видимых элементов, оператор PALETTE использует только первые 256 элементов. Если элементов меньше, остальные индексы палитры сохраняют прежние значения.

Оператор PALETTE не меняет текущую графическую позицию, область VIEW, систему координат WINDOW, область VIEW PRINT, текстовый курсор и состояние мышиного ввода.

Диагностика

  • MB3010: графический режим SCREEN не активен.
  • MB3005: массив для PALETTE USING объявлен, но ещё не выделен.
  • MB2003: форма PALETTE USING получила не одномерный числовой массив.

PCOPY

PCOPY — оператор языка Axiom, который копирует одну графическую страницу SCREEN в другую. Оператор PCOPY нужен для показа заранее подготовленного кадра, когда программа рисует на скрытой странице, а затем переносит готовый результат на видимую страницу.

Полная статья: PCOPY

Когда использовать PCOPY

Оператор PCOPY нужен для работы с экранными страницами палитрового графического режима SCREEN.

Обычный сценарий такой: оператор SCREEN делает страницу 1 активной для рисования и страницу 0 видимой для показа, программа собирает следующий кадр на странице 1, а оператор PCOPY 1, 0 переносит готовый кадр на страницу 0.

Где работает оператор PCOPY

Оператор PCOPY работает только в графических режимах SCREEN 1 ... SCREEN 10.

Оператор PCOPY не работает в SCREEN 0 и не относится к современному графическому слою CANVAS.

Что делает оператор PCOPY

Оператор PCOPY копирует кадровый буфер исходной страницы в страницу назначения.

Оператор PCOPY копирует индексный слой, полноцветный слой и палитру исходной страницы. Поэтому кадр с PSET, LINE, DRAWIMAGE, DRAWSPRITE и PALETTE переносится как единое изображение.

Синтаксис

PCOPY sourcePage, destinationPage

На этой странице показана одна форма оператора PCOPY. Оператор PCOPY всегда требует номер исходной страницы и номер страницы назначения.

Параметры и части синтаксиса

ЧастьОписание
sourcePageНомер исходной страницы от 0 до 3. Оператор PCOPY читает кадр именно из этой страницы.
destinationPageНомер страницы назначения от 0 до 3. Оператор PCOPY записывает копию кадра именно в эту страницу.

Правила работы

Оператор PCOPY работает только после выбора графического режима SCREEN 1 ... SCREEN 10. Если графический режим не активен, оператор PCOPY сообщает ошибку времени выполнения MB3010.

Номера sourcePage и destinationPage должны находиться в диапазоне 0..3. Если программа передаёт номер страницы вне этого диапазона, оператор PCOPY сообщает ошибку времени выполнения MB3007.

Оператор PCOPY не меняет активную страницу, видимую страницу, текущую графическую позицию, область VIEW, систему координат WINDOW, область VIEW PRINT, текстовый курсор и очереди ввода.

Текстовый слой графического режима SCREEN, выведенный через PRINT и LOCATE, относится к той же экранной странице. Поэтому оператор PCOPY переносит и такой текст вместе с остальным содержимым страницы.

Диагностика

  • MB3010: графический режим SCREEN не активен.
  • MB3007: номер исходной страницы или страницы назначения находится вне диапазона 0..3.

PSET

Раздел графических примитивов описывает операторы PSET, PRESET, LINE, CIRCLE, PAINT, DRAW и встроенную функцию POINT. Основные формы работают в палитровых режимах SCREEN 1..10. Формы POINT(x, y), PSET, PRESET и PAINT также поддерживаются на холсте CANVAS; правила каждого контекста приведены отдельно.

Полная статья: PSET

Оператор PSET

PSET — оператор языка Axiom, который закрашивает одну точку графического экрана.

PSET (x, y)
PSET (x, y), color
PSET STEP (x, y)
PSET STEP (x, y), color

Оператор PSET принимает координаты точки и необязательный номер цвета.

Если цвет не указан, оператор PSET использует текущий цвет рисования.

При активном SCREEN оператор PSET работает по правилам экранного режима, включая влияние VIEW и WINDOW.

При активном CANVAS оператор PSET принимает мировые координаты. Эти координаты проходят через CAMERA и затем попадают внутрь активного VIEWPORT.

При активном CANVAS оператор PSET записывает индексный цвет 0..255, а не полноцветное значение RGB(...). Если цвет выходит за диапазон, применяется обычное графическое правило приведения индекса.

Слово STEP означает, что координаты задаются как смещение от текущей графической позиции, а не как абсолютная точка экрана. В режиме CANVAS это смещение считается от текущей мировой графической позиции.

CANVAS 24, 18
CLS RGB(0, 0, 0)
VIEWPORT (10, 6)-(14, 10)
CAMERA 100, 50
PSET (100, 50), 12

PRINT POINT(10, 6)
PRINT POINT(9, 6)

В этом примере мировой пиксель 100, 50 становится видимым в физической точке 10, 6 внутри viewport. Соседняя точка 9, 6 остаётся фоном.

Правила работы

Операторы рисования работают в пределах текущего графического экрана. Если часть фигуры выходит за границы экрана, результат обычно обрезается по границе доступной области, а не превращается в ошибку.

Оператор VIEW может ограничивать физическую область вывода. Оператор WINDOW может переводить координаты в логическую систему. Поэтому при чтении любой графической формы важно понимать, действуют ли в программе VIEW, WINDOW или STEP.

Для современного CANVAS из этой страницы работают форма POINT(x, y) и операторы PSET, PRESET, PAINT. Форма POINT(x, y) читает физическую точку холста и не использует правила VIEW, WINDOW, CAMERA и VIEWPORT для преобразования аргументов.

Операторы PSET, PRESET и PAINT в современном слое, наоборот, работают с мировыми координатами и потому подчиняются CAMERA и VIEWPORT.

После выполнения графических операторов текущая графическая позиция может меняться. Это особенно важно для слова STEP, для оператора DRAW и для формы POINT(selector).

Диагностика

  • MB3010: операторы PSET, PRESET и PAINT вызваны без активного графического режима SCREEN и без активного CANVAS.
  • MB3010: операторы LINE, CIRCLE, DRAW и форма POINT(selector) вызваны без активного графического режима SCREEN 1..10.
  • MB3010: форма POINT(x, y) вызвана без активного графического режима SCREEN или CANVAS.
  • MB3007: оператор получил недопустимые координаты, радиус, селектор или другой числовой аргумент вне поддерживаемого договора.

GET

GET и PUT — операторы языка Axiom, которые копируют прямоугольный блок пикселей между активной графической поверхностью и двумерным числовым массивом. Оператор GET читает блок в массив, а оператор PUT возвращает содержимое массива обратно на экран или на холст.

Полная статья: GET

Что такое GET и PUT

GET — оператор языка Axiom, который считывает прямоугольный блок пикселей из активной графической поверхности в двумерный числовой массив.

PUT — оператор языка Axiom, который рисует такой буфер обратно на активной графической поверхности.

Когда использовать GET и PUT

Операторы GET и PUT нужны для старого блочного обмена: сохранить кусок изображения, временно убрать его, вернуть позже, перенести в другое место или наложить разными побитовыми действиями.

В новых полноцветных сценах чаще удобнее использовать IMAGE и SPRITE, но для небольших индексных блоков, отладки и операций над палитровыми пикселями операторы GET и PUT остаются полезными и в SCREEN, и в CANVAS.

Где работают операторы GET и PUT

Операторы GET и PUT работают, если программа уже вызвала оператор SCREEN с графическим режимом 1..10 или оператор CANVAS.

В графическом режиме SCREEN операторы GET и PUT используют тот же координатный договор, что и остальные screen-операторы: на них влияют VIEW и WINDOW.

В режиме CANVAS операторы GET и PUT принимают мировые координаты. Эти координаты проходят через CAMERA, а затем обрезаются активным VIEWPORT.

Синтаксис

GET (x1, y1)-(x2, y2), buffer
GET STEP (x1, y1)-STEP (x2, y2), buffer

PUT (x, y), buffer
PUT STEP (x, y), buffer
PUT (x, y), buffer, PSET
PUT (x, y), buffer, PRESET
PUT (x, y), buffer, AND
PUT (x, y), buffer, OR
PUT (x, y), buffer, XOR

Параметры и части синтаксиса

ЧастьОписание

Буфер у операторов GET и PUT должен быть уже выделенным двумерным числовым массивом. Допустимы типы элементов INTEGER, LONG, DOUBLE и DECIMAL.

PUT

GET и PUT — операторы языка Axiom, которые копируют прямоугольный блок пикселей между активной графической поверхностью и двумерным числовым массивом. Оператор GET читает блок в массив, а оператор PUT возвращает содержимое массива обратно на экран или на холст.

Полная статья: PUT

Что такое GET и PUT

GET — оператор языка Axiom, который считывает прямоугольный блок пикселей из активной графической поверхности в двумерный числовой массив.

PUT — оператор языка Axiom, который рисует такой буфер обратно на активной графической поверхности.

Когда использовать GET и PUT

Операторы GET и PUT нужны для старого блочного обмена: сохранить кусок изображения, временно убрать его, вернуть позже, перенести в другое место или наложить разными побитовыми действиями.

В новых полноцветных сценах чаще удобнее использовать IMAGE и SPRITE, но для небольших индексных блоков, отладки и операций над палитровыми пикселями операторы GET и PUT остаются полезными и в SCREEN, и в CANVAS.

Где работают операторы GET и PUT

Операторы GET и PUT работают, если программа уже вызвала оператор SCREEN с графическим режимом 1..10 или оператор CANVAS.

В графическом режиме SCREEN операторы GET и PUT используют тот же координатный договор, что и остальные screen-операторы: на них влияют VIEW и WINDOW.

Программа собирает рабочий кадр через CLS, прямоугольники, линии, круги, изображения, спрайты, тайлы и DRAWTEXT, при необходимости смещает мир камерой через CAMERA, ограничивает область рисования через VIEWPORT, при необходимости читает уже нарисованный пиксель через POINT(x, y) и выполняет индексные операции PSET, PRESET, PAINT, GET и PUT, а затем показывает готовый результат оператором PRESENT.

TEXTWIDTH(<текст>)

DRAWTILE <tileset>, <тайл>, <x>, <y>

Диагностика

  • MB3007: ширина или высота CANVAS не является положительным допустимым размером.
  • MB3007: компонент RGB находится вне диапазона 0..255.
  • MB3007: ширина или высота DRAWRECT / FILLRECT меньше либо равна нулю.
  • MB3007: радиус DRAWCIRCLE / FILLCIRCLE отрицателен.
  • MB3007: координаты CAMERA, VIEWPORT, DRAWLINE, DRAWTEXT и других современных примитивов выходят за поддерживаемый диапазон -1000000000..1000000000.
  • MB3007: прямоугольный viewport после обрезки по границам CANVAS становится пустым.
  • MB3010: BEGINFRAME, PRESENT, CLS color, CAMERA, RESETCAMERA, VIEWPORT, DRAWRECT, FILLRECT, DRAWLINE, DRAWCIRCLE, FILLCIRCLE, DRAWTEXT, TEXTWIDTH, TEXTHEIGHT, DRAWTILE, DRAWTILEMAP или DRAWTILELAYER вызваны без активного CANVAS.
  • MB3010: POINT(x, y) вызван без активного SCREEN или CANVAS.
  • MB3010: PSET, PRESET, PAINT, GET или PUT вызваны без активного SCREEN и без активного CANVAS.
  • MB3010: DRAWIMAGE или DRAWSPRITE вызваны без активного SCREEN или CANVAS.

DRAWIMAGE

Раздел изображений описывает тип данных IMAGE, встроенные функции LOADIMAGE, IMAGEWIDTH, IMAGEHEIGHT и оператор DRAWIMAGE. Тип IMAGE хранит загруженное полноцветное изображение. Оператор DRAWIMAGE выводит изображение на графический экран или холст CANVAS.

Полная статья: DRAWIMAGE

Оператор DRAWIMAGE

DRAWIMAGE — оператор языка Axiom, который выводит изображение на активную графическую поверхность.

DRAWIMAGE image, x, y
DRAWIMAGE image, x, y, width, height

Первая форма выводит изображение в его натуральном размере.

Вторая форма выводит изображение с масштабированием до размера width x height пикселей.

В режиме SCREEN координаты читаются по экранному договору SCREEN, VIEW и WINDOW. В режиме CANVAS координаты читаются по договору современного слоя и могут зависеть от оператора CAMERA.

Альфа-канал изображения учитывается при наложении на текущую поверхность.

Синтаксис

DIM name AS IMAGE
name = LOADIMAGE(path)

IMAGEWIDTH(image)
IMAGEHEIGHT(image)

DRAWIMAGE image, x, y
DRAWIMAGE image, x, y, width, height

Параметры и части синтаксиса

ЧастьОписание
nameПеременная типа IMAGE.
pathСтроковый путь к файлу изображения.
imageВыражение типа IMAGE.
x, yКоординаты левого верхнего угла вывода.
width, heightПоложительные размеры итогового вывода в пикселях.

Правила работы

Значение типа IMAGE копируется как ссылка на одно и то же загруженное изображение, а не как отдельная копия пикселей.

Оператор DRAWIMAGE в режиме SCREEN рисует на активную страницу графического экрана. Оператор DRAWIMAGE в режиме CANVAS рисует в рабочий кадр современного холста.

Если часть изображения выходит за границы доступной поверхности, результат обрезается по границе экрана или холста.

Диагностика

  • MB3007: путь в функции LOADIMAGE пустой.
  • MB3005: файл изображения отсутствует, недоступен, повреждён или не поддерживается текущим декодером.
  • MB3005: оператор DRAWIMAGE получил пустое значение IMAGE.
  • MB3007: ширина или высота в масштабированной форме DRAWIMAGE меньше либо равна нулю.
  • MB3010: оператор DRAWIMAGE вызван без активного графического режима SCREEN или CANVAS.

DRAWTILE

TILESET — встроенный тип данных языка Axiom, который хранит атлас одинаковых тайлов. На этой странице собраны разные сущности: тип TILESET, встроенные функции LOADTILESET, TILECOUNT, TILEWIDTH, TILEHEIGHT и оператор DRAWTILE. Синтаксис ниже относится не к одной общей конструкции, а к нескольким разным формам работы с тайлсетом.

Полная статья: DRAWTILE

Синтаксис

DIM name AS TILESET

name = LOADTILESET(path, tileWidth, tileHeight)
name = LOADTILESET(path, tileWidth, tileHeight, margin)
name = LOADTILESET(path, tileWidth, tileHeight, margin, spacing)

TILECOUNT(tileset)
TILEWIDTH(tileset)
TILEHEIGHT(tileset)

LOADTILESET поддерживает три формы. Если аргументы margin и spacing не указаны, они считаются равными 0.

Функции TILECOUNT, TILEWIDTH и TILEHEIGHT читают уже загруженное или пустое значение TILESET.

Оператор DRAWTILE выводит один тайл в его натуральном размере. Отдельной формы масштабирования или поворота у этого оператора в текущем срезе нет.

Параметры и части синтаксиса

АргументОписание
nameПеременная типа TILESET.
pathСтроковый путь к файлу изображения-атласа.
tileWidth, tileHeightПоложительные целые размеры одного тайла в пикселях.
marginНеотрицательный внешний отступ в пикселях между краем атласа и первой линией тайлов.
spacingНеотрицательный промежуток в пикселях между соседними тайлами внутри атласа.
tilesetВыражение типа TILESET.
tileIndexНомер тайла, начиная с 1.
x, yПиксельные координаты левого верхнего угла вывода тайла на CANVAS.

Правила работы

  • Тип TILESET допускает пустое значение переменной. Например, после DIM tiles AS TILESET переменная уже существует, но ещё не содержит загруженного атласа.
  • Для пустого значения TILESET функции TILECOUNT, TILEWIDTH и TILEHEIGHT возвращают 0.
  • Попытка вызвать оператор DRAWTILE для пустого значения TILESET считается ошибкой времени выполнения.
  • Сетка тайлов должна точно совпадать с размерами изображения с учётом margin и spacing. Частично заполненный последний ряд или последний столбец не допускается.
  • Отступ margin применяется с обеих сторон каждой оси. Если после его вычитания не помещается полный тайл, загрузка завершается ошибкой MB3005, даже для очень большого положительного отступа. Промежуток spacing применяется только между соседними тайлами: для атласа из одного тайла допустим большой неотрицательный промежуток, который не меняет число тайлов. После неудачной загрузки прежнее значение переменной тайлсета сохраняется. Проверить оба случая можно в примере числовых границ.
  • Тайлсеты в текущем срезе работают только как источник одинаковых тайлов. На этой странице не описываются TILEMAP, слои тайловой карты и загрузка карт Tiled.
  • Оператор DRAWTILE рисует тайл в натуральном размере tileWidth x tileHeight. Если нужна произвольная масштабируемая графика, для этого подходят DRAWIMAGE и DRAWSPRITE.

Диагностика

  • MB3007: путь path пустой.
  • MB3007: аргументы tileWidth или tileHeight не являются положительными целыми значениями.
  • MB3007: аргументы margin или spacing являются отрицательными.
  • MB3007: аргумент tileIndex не указывает существующий тайл тайлсета.
  • MB3005: файл тайлсета не удалось загрузить, изображение отсутствует или сетка тайлов не совпадает с размерами атласа.
  • MB3005: оператор DRAWTILE получил пустое значение TILESET.
  • MB3010: оператор DRAWTILE вызван без активного CANVAS.

Правила работы

  • Переменная типа TILEMAP после DIM может быть пустой.
  • Для пустого значения TILEMAP функции размеров и состава возвращают 0.
  • Функции MAPTILE, MAPTILESET и MAPTILEFLAGS при чтении за пределами карты возвращают 0, а не выдают ошибку.
  • Оператор SETMAPTILE при записи за пределами карты выдаёт ошибку времени выполнения.
  • Оператор SETMAPTILE может изменять только тайловые слои. Объектные слои нельзя изменять как сетку тайлов.
  • Оператор DRAWTILEMAP пропускает невидимые тайловые слои и не рисует объектные слои.
  • Оператор DRAWTILELAYER требует существующий тайловый слой. Попытка нарисовать объектный слой считается ошибкой времени выполнения.
  • Операторы DRAWTILEMAP и DRAWTILELAYER не меняют текущую графическую позицию Axiom.
  • Флаги отражения тайлов и tileoffset тайлсета применяются автоматически.

  • MB3007: путь path пустой.
  • MB3007: координаты x или y выходят за поддерживаемый диапазон графических координат.
  • MB3007: аргумент layerIndex не указывает существующий слой карты.
  • MB3007: оператор SETMAPTILE получил column или row за пределами тайлового слоя.
  • MB3007: оператор SETMAPTILE получил несуществующий tilesetIndex, несуществующий tileIndex или маску flags вне диапазона 0..7.
  • MB3005: файл карты, тайлсет или изображение тайлсета не удалось загрузить.
  • MB3005: оператор DRAWTILEMAP или DRAWTILELAYER получил пустое значение TILEMAP.
  • MB3005: оператор DRAWTILELAYER получил номер объектного слоя.
  • MB3005: оператор SETMAPTILE получил пустое значение TILEMAP или номер объектного слоя.
  • MB3010: оператор DRAWTILEMAP или DRAWTILELAYER вызван без активного CANVAS.

LOADTILEMAP поддерживает одну форму и возвращает значение TILEMAP.

MAPWIDTH, MAPHEIGHT, MAPPIXELWIDTH, MAPPIXELHEIGHT, MAPTILEWIDTH, MAPTILEHEIGHT и MAPLAYERCOUNT принимают одно значение TILEMAP.

MAPTILE, MAPTILESET и MAPTILEFLAGS читают одну клетку по 1-based номеру слоя, столбца и строки.

DRAWTILEMAP рисует карту целиком по её видимым тайловым слоям.

DRAWTILELAYER рисует один слой по 1-based номеру layerIndex.

SETMAPTILE записывает одну клетку тайлового слоя или очищает её формой SETMAPTILE tilemap, layerIndex, column, row, 0, 0.

Правила работы

  • Переменная типа TILEMAP после DIM может быть пустой.
  • Для пустого значения TILEMAP функции размеров и состава возвращают 0.
  • Функции MAPTILE, MAPTILESET и MAPTILEFLAGS при чтении за пределами карты возвращают 0, а не выдают ошибку.
  • Оператор SETMAPTILE при записи за пределами карты выдаёт ошибку времени выполнения.
  • Оператор SETMAPTILE может изменять только тайловые слои. Объектные слои нельзя изменять как сетку тайлов.
  • Оператор DRAWTILEMAP пропускает невидимые тайловые слои и не рисует объектные слои.
  • Оператор DRAWTILELAYER требует существующий тайловый слой. Попытка нарисовать объектный слой считается ошибкой времени выполнения.
  • Операторы DRAWTILEMAP и DRAWTILELAYER не меняют текущую графическую позицию Axiom.
  • Флаги отражения тайлов и tileoffset тайлсета применяются автоматически.

Диагностика

  • MB3007: путь path пустой.
  • MB3007: координаты x или y выходят за поддерживаемый диапазон графических координат.
  • MB3007: аргумент layerIndex не указывает существующий слой карты.
  • MB3007: оператор SETMAPTILE получил column или row за пределами тайлового слоя.
  • MB3007: оператор SETMAPTILE получил несуществующий tilesetIndex, несуществующий tileIndex или маску flags вне диапазона 0..7.
  • MB3005: файл карты, тайлсет или изображение тайлсета не удалось загрузить.
  • MB3005: оператор DRAWTILEMAP или DRAWTILELAYER получил пустое значение TILEMAP.
  • MB3005: оператор DRAWTILELAYER получил номер объектного слоя.
  • MB3005: оператор SETMAPTILE получил пустое значение TILEMAP или номер объектного слоя.
  • MB3010: оператор DRAWTILEMAP или DRAWTILELAYER вызван без активного CANVAS.

ON KEY

ON KEY — оператор языка Axiom, который включает простой событийный обработчик клавиатуры внутри выполняющейся программы. Оператор связывает строковое имя клавиши с процедурой SUB и позволяет перехватывать нажатие до обычного опроса через INKEY.

Полная статья: ON KEY

Когда использовать ON KEY

Оператор ON KEY подходит для узких интерактивных сценариев, где программе нужно реагировать на отдельную клавишу между обычными операторами. На этом шаге оператор ON KEY не строит общую систему сообщений и не отслеживает удержание клавиш: он включает или выключает обработчик для конкретного строкового имени либо запасной обработчик для любой клавиши.

Где работает оператор ON KEY

Оператор ON KEY работает в любой среде выполнения, где доступна клавиатурная очередь. Если программа работает без оператора SCREEN, события поступают из обычной поверхности ввода среды разработки. Если программа явно выбрала SCREEN 0 или графический режим SCREEN 1..10, события поступают из окна SCREEN.

Оператор ON KEY выполняется BytecodeVm после компиляции.

Синтаксис

ON KEY(keyText), HandlerName
ON KEY(keyText), ON
ON KEY(keyText), STOP
ON KEY(keyText), OFF

Процедура-обработчик может быть объявлена без параметров или с одним параметром STRING:

SUB HandlerName()
END SUB

SUB HandlerName(keyName AS STRING)
END SUB

Параметры и части синтаксиса

keyText и HandlerName в синтаксисе — метапеременные, то есть обозначения частей записи. В реальной программе вместо HandlerName пишут имя своей процедуры SUB, например HandleLeft. Слова ON, STOP и OFF в этих формах — режимы оператора ON KEY, а не отдельные операторы программы.

  • keyText — строковое выражение с именем клавиши, например "LEFT", "ESCAPE" или "A". Канонические имена и алиасы перечислены в общей таблице имён клавиш. Специальная строка "ANY" задаёт обработчик любой клавиши.
  • HandlerName — видимая в текущем месте процедура SUB без параметров или с одним параметром STRING.
  • ON — возобновление ранее зарегистрированного обработчика.
  • STOP — пауза ранее зарегистрированного обработчика без удаления регистрации.
  • OFF — полное отключение обработчика для той же клавиши.

Диагностика

  • MB2034: в обработчик оператора ON KEY передана не процедура SUB без параметров или с одним параметром STRING.

ON MOUSE

ON MOUSE — оператор языка Axiom, который связывает событие мыши с процедурой SUB. Обработчик вызывается при нажатии, отпускании или перемещении мыши между обычными инструкциями программы.

Полная статья: ON MOUSE

Когда использовать ON MOUSE

Оператор ON MOUSE подходит для интерактивных программ, где нужно реагировать на нажатие кнопки, отпускание кнопки, перемещение указателя или прокрутку колеса между обычными операторами. Оператор работает при активном графическом режиме SCREEN и при активном CANVAS.

Где работает оператор ON MOUSE

Оператор ON MOUSE работает при активном графическом режиме SCREEN 1..10 или при активном CANVAS. Без активной рисуемой поверхности выполнение сообщает диагностику MB3010.

При активном SCREEN координаты событий мыши измеряются в пикселях клиентской области активного окна и не пересчитываются через операторы VIEW и WINDOW. При активном CANVAS параметры x и y передаются уже в мировых координатах и учитывают текущие VIEWPORT и CAMERA.

Оператор ON MOUSE выполняется BytecodeVm после компиляции.

Синтаксис

ON MOUSE(buttonNumber), HandlerName
ON MOUSE(buttonNumber), ON
ON MOUSE(buttonNumber), STOP
ON MOUSE(buttonNumber), OFF

ON MOUSE(buttonNumber, "UP"), HandlerName
ON MOUSE(buttonNumber, "UP"), ON
ON MOUSE(buttonNumber, "UP"), STOP
ON MOUSE(buttonNumber, "UP"), OFF

ON MOUSE("MOVE"), HandlerName
ON MOUSE("MOVE"), ON
ON MOUSE("MOVE"), STOP
ON MOUSE("MOVE"), OFF

ON MOUSE("WHEEL"), HandlerName
ON MOUSE("WHEEL"), ON
ON MOUSE("WHEEL"), STOP
ON MOUSE("WHEEL"), OFF

Параметры и части синтаксиса

buttonNumber и HandlerName в синтаксисе — метапеременные. В реальном коде вместо buttonNumber пишут выражение с номером кнопки, а вместо HandlerName — имя своей процедуры SUB. Строки "UP", "MOVE" и "WHEEL" — имена событий мыши.

ЧастьОписание
buttonNumberНомер кнопки мыши: 1 — левая, 2 — правая, 3 — средняя. Без второго аргумента цель означает нажатие кнопки.
"UP"Строковое имя события отпускания кнопки. Допустимы также формы "RELEASE" и "RELEASED".
"MOVE"Строковое имя события перемещения указателя. Для него номер кнопки не указывается.
"WHEEL"Строковое имя события прокрутки колеса мыши. Допустимы также формы "MOUSEWHEEL", "SCROLL" и "SCROLLED".
HandlerNameИмя процедуры SUB, которая будет вызвана при подходящем событии.

Диагностика

  • MB2035: обработчик оператора ON MOUSE не является подходящей процедурой SUB. Для обработчика события допустимы только формы без параметров или с параметрами INTEGER, LONG, LONG.
  • MB2036: в операторе ON MOUSE указано недопустимое имя события мыши.
  • MB3010: оператор ON MOUSE вызван без активного графического режима SCREEN и без активного CANVAS.

Присваивание

Присваивание — инструкция языка Axiom, которая записывает вычисленное значение в переменную, элемент массива или поле записи.

Полная статья: Присваивание

Синтаксис

<цель> = <выражение>

Части синтаксиса

<цель> — объявленная изменяемая переменная, доступный элемент массива или поле записи. <выражение> — выражение совместимого типа.

Правила работы

Правая часть вычисляется, затем результат записывается в цель. Допустимые неявные преобразования определены правилами преобразования типов. Константе присвоить новое значение нельзя.

Знак = внутри выражения означает сравнение. Запись FieldName := expression применяется к именованным полям литерала записи TYPE; она не заменяет обычное присваивание.

Правила копирования записей и связи массивных представлений с исходным хранилищем определены на страницах TYPE и срезов массива.

Диагностика

  • MB2001 — имя цели или имя в выражении не объявлено.
  • MB2003 — тип значения несовместим с типом цели.
  • MB2010 — попытка присвоить значение константе.
  • MB3005 — хранилище индексируемого массива не выделено.
  • MB3007 — индекс элемента выходит за границы.

Вызов как инструкция

Вызов — форма языка Axiom, которая передаёт управление процедуре, функции или методу и связывает аргументы с параметрами. Функция возвращает результат; процедура выполняет действие.

Полная статья: Вызов как инструкция

Синтаксис

<имя>(<аргументы>)
<получатель>.<метод>(<аргументы>)

Для вызова без аргументов скобки сохраняются: Name(). Вызов функции может входить в выражение или записываться отдельной инструкцией; в последнем случае результат не используется.

Диагностика

  • MB2004 — число аргументов не соответствует форме вызова.
  • MB2003 — тип аргумента несовместим с типом параметра.
  • MB2020 — значение нельзя вызвать.
  • MB2029 — функция с параметром BYREF используется как функциональное значение.
  • MB2040 — отдельная инструкция содержит выражение без вызова, например одиночный литерал или имя.
