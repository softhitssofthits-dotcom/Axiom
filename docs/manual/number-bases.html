03 · Выражения и операции

Системы счисления и запись целых чисел

Раздел систем счисления описывает десятичные, шестнадцатеричные и двоичные целочисленные литералы Axiom, их типы, арифметику и текстовое представление.

Запись числа и его значение

Система счисления определяет, как записано число в исходнике. Десятичная запись 10, шестнадцатеричная &HA и двоичная &B1010 задают одну целую величину. После разбора числа участвуют в обычных операциях своего типа. Отдельных «шестнадцатеричного» и «двоичного» типов нет.

Шестнадцатеричная цифра задаёт четыре двоичных разряда. Например, F соответствует 1111, а &H2A и &B101010 равны 42.

Шестнадцатеричный литерал

&H<шестнадцатеричные цифры>

После префикса требуется хотя бы одна цифра 0–9 или буква A–F. Регистр префикса и букв не различается: &HFF и &hff задают 255. Ведущие нули разрешены, например &H000F задаёт 15. Они не фиксируют разрядность типа.

Двоичный литерал

&B<двоичные цифры>

После префикса требуется хотя бы одна цифра 0 или 1. Префикс не зависит от регистра: &B1010 и &b1010 задают 10. Ведущие нули разрешены: &B00001010 тоже задаёт 10. Цифры 2–9, буквы и подчёркивания внутри записи недопустимы. Например, &B102 отклоняется как один неверный литерал.

Выбор типа и диапазон

Литерал без минуса задаёт неотрицательную величину. Тип выбирается по её значению, а не по числу написанных цифр:

ЗначениеОбычный типПримеры
От 0 до 2147483647INTEGER&H7FFFFFFF; 31 двоичная единица.
От 2147483648 до 9223372036854775807LONG&H80000000, &H7FFFFFFFFFFFFFFF; до 63 значащих двоичных разрядов.
Больше 9223372036854775807Не допускается&H8000000000000000 и единица с 63 двоичными нулями вызывают MB0004.

Например, &HFFFFFFFF имеет значение 4294967295 и обычный тип LONG. Он не означает -1. Такой же результат даёт двоичный литерал из 32 единиц. Запись &H0000000000000001 остаётся INTEGER, несмотря на длину.

Явный числовой контекст может изменить тип литерала с проверкой диапазона: DIM wide AS LONG = &HFF, DIM exact AS DECIMAL = &B1010. Число не превращается в строку или BOOLEAN. Дробная часть, показатель степени, разделители разрядов и суффиксы типа для префиксных литералов не поддерживаются. Префиксы 0x, 0b и &O не являются формами числового литерала Axiom.

Отрицательное число

-&H<шестнадцатеричные цифры>
-&B<двоичные цифры>

Минус является отдельной унарной операцией. Сначала проверяется положительная величина литерала, затем меняется знак. Например, -&HFF равно -255, а -&B1010 равно -10.

Тип отдельно стоящего -&H80000000 — LONG: его положительная часть уже не помещается в INTEGER. При явном объявлении DIM n AS INTEGER = -&H80000000 конечное значение -2147483648 помещается в INTEGER и принимается.

Положительная величина 9223372036854775808 не допускается даже перед последующим минусом. Поэтому запись -&H8000000000000000 вызывает MB0004. Минимальное значение LONG можно получить целочисленным выражением, например CLNG(1) << 63. Префикс сам по себе не задаёт интерпретацию старшего бита как знака.

Арифметика и сравнения

Префиксы не меняют договор арифметики. Поддержаны обычные +, -, *, /, целочисленные \ и MOD, возведение в степень ^ и сравнения. Целочисленное переполнение вызывает MB3008, а не автоматическое расширение уже выбранного типа.

PRINT &H10 + &B11
PRINT &H10 \ &B11
PRINT &H10 MOD &B11
PRINT &HA = &B1010

Результат:

19
5
1
TRUE

&H7FFFFFFF + 1 переполняет INTEGER. Для расчёта в LONG задайте тип операнда до сложения: CLNG(&H7FFFFFFF) + 1. Обычное деление возвращает DOUBLE, а операция ^ — DOUBLE независимо от исходной записи чисел. Дополнительные правила числового продвижения описаны в разделе операций.

Десятичный, шестнадцатеричный и двоичный вывод

Обычный PRINT выводит число десятичным текстом. Исходный префикс не сохраняется в значении. В интерполяции формат X выбирает шестнадцатеричный текст, а B — двоичный. Они применяются к INTEGER и LONG:

DIM value AS INTEGER = &H2A
PRINT value
PRINT $"{value:X}"
PRINT $"{value:B}"
PRINT $"{value:X4}"
PRINT $"{value:B8}"

Результат:

42
2A
101010
002A
00101010

Число после буквы задаёт минимальное количество цифр с дополнением нулями слева. Длинный результат не обрезается. Префиксы &H и &B не добавляются автоматически. Для подписи добавьте их как обычный текст, например $"&B{value:B8}". Буквы формата приводятся к верхнему регистру, поэтому x4 тоже даёт заглавные шестнадцатеричные цифры.

Для отрицательных INTEGER и LONG форматы X/B выводят битовое представление дополнительного кода на 32 или 64 разрядах без минуса. Например, INTEGER -1 даёт FFFFFFFF и 32 единицы, а LONG -1 — FFFFFFFFFFFFFFFF и 64 единицы. Указание большей минимальной ширины дополняет текст нулями и не превращает INTEGER в LONG. Для изменения разрядности сначала используйте CLNG.

Форматы X/B для DOUBLE или DECIMAL и неверный числовой формат вызывают перехватываемую ошибку MB3007. Формат для нечислового значения игнорируется по общему договору интерполяции: BOOLEAN по-прежнему отображается TRUE/FALSE. Подробности: строковые литералы и интерполяция.

Чтение числового текста

Литерал в исходнике и строка с цифрами являются разными сущностями. Добавление префиксов &H/&B в язык не меняет разбор INPUT и VAL. Для INTEGER и LONG оператор INPUT принимает десятичную запись; ответы &HFF и &B1010 вызывают MB3003.

VAL("1010") возвращает десятичное 1010. Вызовы VAL("&HFF") и VAL("&B1010") возвращают 0; двоичный или шестнадцатеричный разбор строк этой функцией не поддерживается. Встроенных HEX и BIN в текущем реестре нет; для вывода используется интерполяция.

Диагностика

  • MB0003 — префикс без цифр, недопустимая цифра или примыкающий буквенный/цифровой суффикс.
  • MB0004 — величина литерала превышает максимум LONG.
  • MB2018 — числовой литерал не помещается в явно указанный целевой тип, например INTEGER = &H80000000.
  • MB3008 — переполнение арифметической операции.
  • MB3007 — числовой формат X/B не поддерживается типом значения или задан неверный числовой формат.
  • MB3003 — префиксный числовой текст передан INPUT.
