Процедура SUB

Процедура SUB нужна для именованного действия: вывести сообщение, изменить переданную переменную, выполнить несколько связанных инструкций или выделить повторяющийся фрагмент программы. В отличие от функции, SUB не возвращает значение и не используется внутри выражения.

Когда нужна процедура без результата

SUB ... END SUB объявляет процедуру. Вызов процедуры записывается отдельной инструкцией по её имени. Если процедуре нужно завершиться раньше конца блока, внутри неё можно использовать RETURN без значения.

Синтаксис

SUB <имя>([<список параметров>])
    <инструкции>
END SUB
<имя>([<список аргументов>])
[BYVAL | BYREF] <имя параметра> AS <тип параметра>
RETURN

Части записи

<имя> - имя объявляемой процедуры или имя процедуры при вызове.

<список параметров> - объявления параметров через запятую. У каждого параметра указывается тип через AS; модификатор BYVAL можно не писать, потому что он действует по умолчанию.

BYVAL и BYREF - модификаторы параметра. Они не выполняются как отдельная инструкция и не вызываются по имени; они только задают способ передачи аргумента в процедуру.

<список аргументов> - значения, передаваемые процедуре при вызове в том же порядке, в котором объявлены параметры.

<инструкции> - тело процедуры.

Вызов, параметры и локальные имена

  • SUB вызывается как инструкция и не может быть частью арифметического, строкового или логического выражения.
  • BYVAL передаёт в процедуру отдельное значение. Для записи TYPE это отдельная копия записи: изменения внутри SUB не меняют исходную переменную.
  • BYREF передаёт в процедуру саму переменную. Если процедура присвоит параметру новое значение или изменит поле записи, результат будет виден после возврата из SUB.
  • Если модификатор не указан, параметр считается BYVAL.
  • Внутри SUB допустим RETURN без значения.
  • Внутри процедуры можно объявлять локальные SUB и FUNCTION.

В QuickBASIC процедура SUB вызывалась как отдельный оператор и могла изменять значения через параметры. В Axiom сохраняется то же разделение между действием и значением, но вызов записывается напрямую по имени процедуры, без опоры на CALL и DECLARE из QuickBASIC.

BYVAL: процедура получает копию

BYVAL полезен, когда процедура должна работать с переданными данными, но не должна менять переменную вызывающего кода. Для обычных чисел это выглядит как работа с локальным значением, а для TYPE особенно заметно: процедура получает копию всей записи.

' Ожидаемый вывод: 10
SUB AddOne(BYVAL value AS INTEGER)
    value = value + 1
END SUB

DIM count AS INTEGER
count = 10

AddOne(count)
PRINT count

BYREF: процедура меняет исходную переменную

BYREF нужен, когда процедура должна вернуть результат через параметр или изменить переданную запись. В месте вызова сейчас допускается простая переменная: имя переменной без обращения к полю, без индекса массива и без выражения.

' Ожидаемый вывод: 11
SUB AddOne(BYREF value AS INTEGER)
    value = value + 1
END SUB

DIM count AS INTEGER
count = 10

AddOne(count)
PRINT count

Для BYREF допустим вызов AddOne(count). Недопустимы формы вроде AddOne(count + 1), AddOne(user.Age) и AddOne(items(1)), потому что это уже не простая переменная в текущем публичном договоре Axiom.

Пример вызова SUB

' Ожидаемый вывод: ==Axiom==
SUB ShowBanner(text AS STRING)
    PRINT "=="; text; "=="
END SUB

ShowBanner("Axiom")

Ручная проверка

  • SUB: базовый вызов
  • SUB: локальная вложенная процедура
  • SUB: захват внешней локальной переменной
  • SUB: простая переменная по BYREF
  • SUB: передача записи по BYREF
  • SUB: копия записи при BYVAL
  • RETURN: досрочный выход из SUB

Диагностика

Ошибка возникает, если SUB используется как выражение, если процедура вызывается с неверным числом или типами аргументов, если аргумент для BYREF не является простой переменной или если внутри SUB записан RETURN со значением.
