Раздел

Операции с файлами и папками

Раздел операций с файлами и папками описывает функции, которые изменяют файловую систему: создание и удаление объектов, копирование и перемещение, смена текущей рабочей папки и получение сведений о диске.

MAKEDIR

Функция MAKEDIR создаёт папку по указанному пути.

Синтаксис

result = MAKEDIR(path)

Аргументы

path задаёт путь к новой папке. Функция возвращает логическое значение.

Пример вызова MAKEDIR

' Создание папки output
PRINT MAKEDIR("output")

DELETEFILE

Функция DELETEFILE удаляет файл.

Синтаксис

result = DELETEFILE(path)

Аргументы

path задаёт путь к файлу. Если файла нет, функция возвращает FALSE.

Пример вызова DELETEFILE

' Удаление файла
PRINT DELETEFILE("notes.txt")

COPYFILE

COPYFILE — встроенная функция языка Axiom, которая копирует байты файла в другое место, сохраняя источник. Функция подходит для текстовых и двоичных файлов: содержимое не декодируется и кодировка не меняется.

Синтаксис

Без замены существующего файла

result = COPYFILE(sourcePath, targetPath)

С явным разрешением замены

result = COPYFILE(sourcePath, targetPath, overwrite)

Аргументы

sourcePath задаёт исходный файл. targetPath задаёт путь, куда нужно поместить копию. Необязательный overwrite задаёт логическое значение, разрешающее перезапись существующего файла назначения.

Правила и диагностика

Пути должны быть строками, overwrite должен быть логическим значением; по умолчанию overwrite равен FALSE. Относительные пути разрешаются от текущего каталога программы. Родитель назначения должен существовать: функция не создаёт отсутствующие папки. При успехе возвращается TRUE. Отсутствующий источник, конфликт существующего файла без разрешённой замены, отсутствующий родитель назначения и отказ файловой системы дают MB3007.

Символические ссылки в Windows

Если источник — символическая ссылка на файл, копируется содержимое её цели, а новая копия является обычным файлом. Если назначение — символическая ссылка, запись идёт в её цель, сама ссылка сохраняется. При существующей цели overwrite = FALSE даёт MB3007, а TRUE разрешает заменить её байты. При отсутствующей цели она создаётся даже при overwrite = FALSE: существующего целевого файла для перезаписи нет. Это поведение проверено на Windows; другие виды ссылок и файловые системы требуют отдельной проверки.

Копирование того же файла

В проверенной Windows совпадающие пути и разные жёсткие ссылки на один файл дают MB3007, даже при overwrite = TRUE. Исходные байты сохраняются. Разные текстовые пути не обязательно означают разные файлы.

Пример вызова COPYFILE

' Создание копии файла
PRINT COPYFILE("notes.txt", "notes-copy.txt")

MOVEFILE

MOVEFILE — встроенная функция языка Axiom, которая перемещает файл по новому пути. При переносе по другому пути прежнее имя источника исчезает; при совпадающем пути функция может успешно ничего не менять. Содержимое файла не декодируется.

Синтаксис

Без замены существующего файла

result = MOVEFILE(sourcePath, targetPath)

С явным разрешением замены

result = MOVEFILE(sourcePath, targetPath, overwrite)

Аргументы

sourcePath задаёт исходный файл. targetPath задаёт новое место расположения. Необязательный overwrite разрешает заменить существующий файл назначения.

Правила и диагностика

Пути должны быть строками, overwrite должен быть логическим значением; по умолчанию overwrite равен FALSE. Родитель назначения должен уже существовать. При успехе возвращается TRUE. Конфликт назначения без замены и отсутствующий родитель дают MB3007 и в проверенных случаях сохраняют источник. Функция не обещает откат любого отказа носителя или атомарность переноса между дисками.

Символические ссылки в Windows

Если источник — символическая ссылка на файл, перемещается сама ссылка, её цель не меняется. Если назначение является ссылкой, overwrite = FALSE даёт MB3007, в том числе при отсутствующей цели ссылки. При overwrite = TRUE ссылка назначения заменяется перемещаемым файлом, а её прежняя цель остаётся прежней. Это отличается от записи через ссылку функцией COPYFILE и проверено на Windows.

Одинаковый файл и разные имена

В проверенной Windows MOVEFILE(path, path, overwrite) возвращает TRUE без изменения файла при FALSE и TRUE. Если sourcePath и targetPath — два разных имени одного файла, созданные жёсткими ссылками, операция тоже успешна при обоих значениях overwrite: прежнее имя источника исчезает, байты остаются доступны под именем назначения. Это отличается от конфликта двух разных файлов.

DIM path AS STRING = MAKETEMPFILE("same_file_")
PRINT WRITEFILE(path, "Сохранить😀")
PRINT MOVEFILE(path, path, FALSE) ' TRUE; путь и текст не меняются.
PRINT READFILE(path) = "Сохранить😀"
PRINT DELETEFILE(path)

Полная запускаемая проверка: совпадающий путь файла.

Пример вызова MOVEFILE

' Перемещение файла в подпапку archive
PRINT MOVEFILE("notes.txt", "archive/notes.txt")

RENAMEFILE

Функция RENAMEFILE переименовывает файл в пределах его текущей папки.

Синтаксис

result = RENAMEFILE(path, newName)

Аргументы

path задаёт путь к существующему файлу. newName задаёт новое имя файла без изменения родительской папки.

Пример вызова RENAMEFILE

' Переименование файла
PRINT RENAMEFILE("notes.txt", "notes-old.txt")

DELETEDIR

Функция DELETEDIR удаляет пустую папку.

Синтаксис

result = DELETEDIR(path)

Аргументы

path задаёт путь к папке. Если папки нет, функция возвращает FALSE.

Пример вызова DELETEDIR

' Удаление пустой папки
PRINT DELETEDIR("output")

DELETEDIRRECURSIVE

Функция DELETEDIRRECURSIVE удаляет папку вместе со всем её содержимым.

Синтаксис

result = DELETEDIRRECURSIVE(path)

Аргументы

path задаёт путь к папке, которую нужно удалить рекурсивно.

Пример вызова DELETEDIRRECURSIVE

' Рекурсивное удаление папки
PRINT DELETEDIRRECURSIVE("output")

COPYDIR

COPYDIR — встроенная функция языка Axiom, которая копирует обычные файлы и вложенные папки в другой каталог. Отсутствующая папка назначения создаётся автоматически; содержимое существующей папки дополняется. Аргумент overwrite разрешает замену существующих файлов, а не удаление папки назначения целиком.

Пути должны быть строками; относительные пути разрешаются так же, как в остальных файловых функциях. Вложенные символические ссылки, соединения каталогов Windows и другие точки повторного разбора пропускаются: функция не копирует их и не переходит к их целям. Если в соответствующем месте назначения уже находится ссылка, операция выдаёт MB3007 вместо записи через эту ссылку. Явно указанная ссылка в исходном пути или пути назначения разрешается до конечного каталога. В проверенной Windows это относится и к явно указанному соединению с отсутствующей целью: если такое соединение задано как назначение, отсутствующая цель создаётся и получает копию; соединение сохраняется. Если оно задано как источник, возникает MB3007, но к этому моменту может быть создана пустая папка назначения. Этот случай отличается от вложенной ссылки назначения, которая отклоняется.

Нельзя копировать папку в саму себя или внутрь неё. Это проверяется до создания назначения и записи файлов, в том числе при пути через ссылку на исходную папку и при расширенной записи пути Windows с префиксом \\?\. Нарушение выдаёт MB3007. Отсутствующий источник, отказ доступа и конфликт существующего файла без overwrite = TRUE также дают MB3007. При прочих ошибках ввода-вывода уже скопированные файлы не откатываются. При успехе возвращается TRUE.

Синтаксис

result = COPYDIR(sourcePath, targetPath[, overwrite])

Аргументы

sourcePath задаёт исходную папку. targetPath задаёт папку назначения. Необязательный аргумент overwrite должен быть логическим значением и разрешает заменять существующие файлы; по умолчанию он равен FALSE.

Отказ от вложенной копии

DIM folder AS STRING = MAKETEMPDIR("axiom_copy_guard_")
TRY
    PRINT COPYDIR(folder, COMBINEPATH(folder, "copy"), TRUE)
CATCH err
    PRINT err.Code ' MB3007: назначение находится внутри источника.
END TRY
PRINT NOT DIREXISTS(COMBINEPATH(folder, "copy")) ' TRUE
PRINT DELETEDIRRECURSIVE(folder)

Запускаемый пример: проверка сохранности исходного файла.

Пример вызова COPYDIR

' Копирование папки docs
PRINT COPYDIR("docs", "docs-copy")

MOVEDIR

MOVEDIR — встроенная функция языка Axiom, которая перемещает папку по новому пути. Функция нужна для изменения расположения каталога вместе с его содержимым и работает с файловой системой в текущем каталоге программы.

Синтаксис

result = MOVEDIR(sourcePath, targetPath)

Аргументы

Аргументы sourcePath и targetPath должны быть строками. Исходная папка должна существовать, конечная папка назначения не должна существовать, а её родительский каталог уже должен быть создан. Относительные пути разрешаются от текущего каталога программы.

Результат и ограничения

При успехе функция возвращает TRUE. MOVEDIR не объединяет содержимое с существующим назначением и не создаёт отсутствующую цепочку родительских каталогов. Если исходный путь указывает на соединение каталогов Windows, переносится само соединение, а не его целевой каталог; это отличается от разрешения явно указанной ссылки функцией COPYDIR. Поведение других видов точек повторного анализа зависит от файловой системы.

Диагностика

Отсутствующий источник, существующее назначение, отсутствующий родитель назначения, совпадающие пути, попытка переноса внутрь исходной папки и отказ файловой системы дают MB3007. Проверенные отказы существующего назначения и отсутствующего родителя сохраняют источник и прежние файлы назначения; функция не обещает откат любого возможного отказа носителя.

Отказ при существующем назначении

' sourcePath и targetPath задают две уже существующие папки.
TRY
    PRINT MOVEDIR(sourcePath, targetPath)
CATCH err
    PRINT err.Code ' MB3007; содержимое папок сохраняется.
END TRY

Полная запускаемая проверка с собственными временными папками: конфликт существующего назначения.

Пример вызова MOVEDIR

' Перемещение папки в архив
PRINT MOVEDIR("docs-copy", "archive/docs-copy")

RENAMEDIR

Функция RENAMEDIR переименовывает папку в пределах её родительского каталога.

Синтаксис

result = RENAMEDIR(path, newName)

Аргументы

path задаёт путь к папке. newName задаёт её новое имя.

Пример вызова RENAMEDIR

' Переименование папки
PRINT RENAMEDIR("output", "output-old")

CURRENTDIR

CURRENTDIR — встроенная функция языка Axiom, которая возвращает полный путь текущей рабочей папки программы. От этой папки вычисляются относительные пути файловых операторов и функций.

При запуске сохранённой программы в WPF IDE начальной рабочей папкой становится папка её файла .axm. Для несохранённой программы используется текущая папка процесса в момент запуска. CLI сохраняет папку, из которой его вызвали; расположение переданного файла .axm само по себе её не меняет.

Каждый запуск через стандартный исполнитель хранит свою рабочую папку. Смена папки внутри программы не меняет рабочую папку процесса IDE и не переносится в следующий запуск; при продолжении остановленной программы её папка сохраняется.

Синтаксис

path = CURRENTDIR()

Аргументы

Функция не принимает аргументов. Результатом является строка с полным путём текущей папки.

Пример вызова CURRENTDIR

' Вывод текущей рабочей папки
PRINT CURRENTDIR()

CHANGEDIR

CHANGEDIR — встроенная функция языка Axiom, которая меняет текущую рабочую папку программы для последующих файловых операций. Функция нужна, чтобы последовательно работать с файлами внутри выбранной папки без повторения полного пути.

Синтаксис

result = CHANGEDIR(path)

Аргументы и результат

Аргумент path должен быть строкой с путём к существующей папке. Относительный путь вычисляется от текущей папки программы. После успешного перехода функция возвращает TRUE. Папки автоматически не создаются.

Правила и диагностика

При отсутствии папки или ошибке файловой системы функция сообщает MB3007, а текущая папка программы сохраняется. Уже открытый файл продолжает работать со своим прежним файлом. Базовая папка графических ресурсов остаётся папкой запуска; функция CHANGEDIR меняет базу файловых путей.

Пример вызова CHANGEDIR

' Переход в папку docs
PRINT CHANGEDIR("docs")
PRINT CURRENTDIR()

Пошаговая проверка файловых путей: рабочая папка текущего запуска.

MAKETEMPFILE

Функция MAKETEMPFILE создаёт новый временный файл и возвращает его полный путь.

Синтаксис

path = MAKETEMPFILE(prefix)

Аргументы

prefix задаёт начало имени временного файла. Результатом является строка с полным путём.

Пример вызова MAKETEMPFILE

' Создание временного файла
DIM path AS STRING

path = MAKETEMPFILE("demo_")
PRINT path

MAKETEMPDIR

Функция MAKETEMPDIR создаёт новую временную папку и возвращает её полный путь.

Синтаксис

path = MAKETEMPDIR(prefix)

Аргументы

prefix задаёт начало имени временной папки. Результатом является строка с полным путём.

Пример вызова MAKETEMPDIR

' Создание временной папки
DIM path AS STRING

path = MAKETEMPDIR("demo_")
PRINT path

Операции меняют файловую систему

  • DELETEFILE, DELETEDIR и DELETEDIRRECURSIVE возвращают FALSE, если удаляемого объекта нет.
  • COPYFILE, MOVEFILE и COPYDIR принимают необязательный параметр overwrite, если нужно явно разрешить замену существующего объекта назначения.
  • DELETEDIR удаляет только пустую папку. Если папка содержит файлы или подпапки, используйте DELETEDIRRECURSIVE.
  • CHANGEDIR влияет на все последующие относительные пути в программе.
  • MAKETEMPFILE и MAKETEMPDIR создают объекты в системной временной папке.

Диагностика

  • Недоступный исходный путь, невозможность создать целевой объект или ошибка доступа дают диагностику времени выполнения MB3007.
  • Попытка удалить непустую папку через DELETEDIR также завершается диагностикой MB3007.
  • Недопустимый префикс имени для MAKETEMPFILE и MAKETEMPDIR даёт MB3007.

Запускаемые примеры

  • MAKEDIR: создание папки
  • DELETEFILE: удаление файла
  • COPYFILE: копирование файла
  • MOVEFILE: перенос файла
  • RENAMEFILE: переименование файла
  • DELETEDIR: удаление пустой папки
  • DELETEDIRRECURSIVE: рекурсивное удаление
  • COPYDIR: копирование папки
  • MOVEDIR: перенос папки
  • RENAMEDIR: переименование папки
  • CURRENTDIR: текущая папка
  • CHANGEDIR: смена текущей папки
  • MAKETEMPFILE: временный файл
  • MAKETEMPDIR: временная папка
