Оператор

SCREEN

SCREEN выбирает экранный режим программы. Режимы 1..10 открывают графическую поверхность, а SCREEN 0 открывает отдельное текстовое окно программы, похожее на консоль. Пока экранный режим выбран явно, PRINT, PRINT USING, INPUT и клавиатурный ввод работают в окне SCREEN, а не во вкладке Output.

Синтаксис

SCREEN mode
SCREEN 0

Параметры

ПараметрОписание
modeЦелое значение от 0 до 10. Значение 0 выбирает текстовое окно, значения 1..10 выбирают логический размер графической поверхности.
0Текстовый режим окна SCREEN. Графические команды в нём недоступны, но обычный текстовый вывод и INPUT идут в это окно.

Режим, окно и ошибки

Значения режима меньше 0 или больше 10 дают ошибку времени выполнения. В SCREEN 0 функция SCREENISACTIVE() возвращает FALSE, потому что активной графической поверхности нет; SCREENMODE() возвращает 0, а SCREENWIDTH() и SCREENHEIGHT() отражают размер текстового окна.

В текущей IDE окно SCREEN создаётся как отдельное обычное Win32/DirectX-окно. Ввод клавиатуры, строковый INPUT и, для графических режимов, события мыши поступают из этого окна. Вкладка Output используется только программами, которые не выбирали SCREEN явно. При SCREEN 0 приглашение INPUT появляется в текущей текстовой позиции окна, начиная с первой строки, а нижняя консоль IDE не принимает параллельный ввод. Окно можно закрыть системной кнопкой закрытия; следующий запуск или сброс сеанса также закрывает старое окно.

Если пользователь закрывает окно SCREEN системной кнопкой закрытия во время выполнения программы, IDE считает это запросом на прерывание текущего запуска. Выполнение останавливается кооперативно между инструкциями, следующие операторы программы не выполняются, а команды IDE снова становятся доступными.

Пример выбора режима

SCREEN 5
PRINT "active="; SCREENISACTIVE()
PRINT "mode="; SCREENMODE()
PRINT "size="; SCREENWIDTH(); "x"; SCREENHEIGHT()

DO WHILE NOT KEYPRESS("ESC")
LOOP

SCREEN 0
PRINT "text mode screen"
