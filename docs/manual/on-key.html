Оператор ON KEY

ON KEY — оператор языка Axiom, который включает простой событийный обработчик клавиатуры внутри выполняющейся программы. Оператор связывает строковое имя клавиши с процедурой SUB и позволяет перехватывать нажатие до обычного опроса через INKEY.

Для чего нужен оператор ON KEY

Оператор ON KEY подходит для узких интерактивных сценариев, где программе нужно реагировать на отдельную клавишу между обычными операторами. На этом шаге оператор ON KEY не строит общую систему сообщений и не отслеживает удержание клавиш: он включает или выключает обработчик для конкретного строкового имени либо запасной обработчик для любой клавиши.

Где работает оператор ON KEY

Оператор ON KEY работает в любой среде выполнения, где доступна клавиатурная очередь. Если программа работает без оператора SCREEN, события поступают из обычной поверхности ввода среды разработки. Если программа явно выбрала SCREEN 0 или графический режим SCREEN 1..10, события поступают из окна SCREEN.

Оператор ON KEY поддерживается интерпретатором и BytecodeVm.

Синтаксис

ON KEY(keyText), HandlerName
ON KEY(keyText), ON
ON KEY(keyText), STOP
ON KEY(keyText), OFF

Процедура-обработчик может быть объявлена без параметров или с одним параметром STRING:

SUB HandlerName()
END SUB

SUB HandlerName(keyName AS STRING)
END SUB

Части оператора

keyText и HandlerName в синтаксисе — метапеременные, то есть обозначения частей записи. В реальной программе вместо HandlerName пишут имя своей процедуры SUB, например HandleLeft. Слова ON, STOP и OFF в этих формах — режимы оператора ON KEY, а не отдельные операторы программы.

  • keyText — строковое выражение с именем клавиши, например "LEFT", "ESCAPE" или "A". Канонические имена и алиасы перечислены в общей таблице имён клавиш. Специальная строка "ANY" задаёт обработчик любой клавиши.
  • HandlerName — видимая в текущем месте процедура SUB без параметров или с одним параметром STRING.
  • ON — возобновление ранее зарегистрированного обработчика.
  • STOP — пауза ранее зарегистрированного обработчика без удаления регистрации.
  • OFF — полное отключение обработчика для той же клавиши.

Порядок обработки клавиш

  • Обработчик вызывается между операторами, а не посреди вычисления выражения.
  • Совпавшая клавиша считается обработанной и не попадает в последующий INKEY.
  • Если клавиша не подошла ни под один зарегистрированный обработчик, она остаётся в очереди и может быть прочитана через INKEY.
  • Повторная регистрация для той же клавиши заменяет предыдущий обработчик.
  • Каноническое имя и алиас считаются одной клавишей: например, ON KEY("ESCAPE"), HandleEsc сработает на событие "ESC".
  • ON KEY("ANY"), HandlerName вызывается для доступных клавиш, у которых нет более точного обработчика.
  • Если для клавиши есть точный обработчик и одновременно зарегистрирован "ANY", сначала применяется точный обработчик.
  • Во время выполнения обработчика повторный вход в другой клавиатурный обработчик не делается.
  • STOP действует на события, которые приходят после паузы. Уже накопленная клавиша может быть обработана на ближайшей границе оператора до того, как программа выполнит строку ON KEY(...), STOP.
  • Если обработчик объявлен с одним параметром STRING, в него передаётся нормализованное имя фактической клавиши. Для ON KEY("ANY") это не строка "ANY", а имя сработавшей клавиши, например "LEFT" или "ESC".
  • Состояния модификаторов, удержание и мышь не входят в контракт оператора ON KEY.

Пример обработчика клавиши

ON KEY("LEFT"), HandleLeft

FOR i = 1 TO 200000
NEXT

ON KEY("LEFT"), OFF

SUB HandleLeft()
    PRINT "LEFT handler"
END SUB

Обработчик любой клавиши

ON KEY("ANY"), HandleAny

FOR i = 1 TO 200000
NEXT

ON KEY("ANY"), OFF

SUB HandleAny()
    PRINT "any key"
END SUB

Имя клавиши в обработчике

ON KEY("ANY"), HandleKey

FOR i = 1 TO 200000
NEXT

ON KEY("ANY"), OFF

SUB HandleKey(keyName AS STRING)
    PRINT keyName
END SUB

Аккорд клавиш

В строке keyText можно указать несколько клавиш через +. Последняя часть строки считается основной клавишей события, а все предыдущие части должны быть удержаны.

Проще говоря, ON KEY("CTRL+LEFT"), Handler сработает, когда CTRL уже удержан, а событием пришла последняя клавиша LEFT. Это тот же договор, что у KEYPRESS("CTRL+LEFT").

ON KEY("CTRL+LEFT"), HandleChord

FOR i = 1 TO 200000
NEXT

ON KEY("CTRL+LEFT"), OFF

SUB HandleChord(keyName AS STRING)
    PRINT keyName
END SUB

Если обработчик принимает параметр STRING, для аккорда он получает каноническую строку аккорда, например "CTRL+LEFT".

Отключение обработчика

ON KEY("ESC"), HandleEsc
' ...
ON KEY("ESC"), OFF

Пауза и возобновление

Оператор STOP временно выключает уже зарегистрированный обработчик, но не забывает его. Оператор ON снова разрешает вызов этого же обработчика.

ON KEY("LEFT"), HandleLeft
ON KEY("LEFT"), STOP

' Нажатие LEFT не вызовет HandleLeft,
' но останется обычной клавишей для INKEY() или KEYPRESS().

ON KEY("LEFT"), ON

' Следующее нажатие LEFT снова вызовет HandleLeft.

Ручная проверка

  • ON KEY: обработчик клавиши LEFT
  • ON KEY: обработчик любой клавиши
  • ON KEY: передача имени клавиши в обработчик
  • ON KEY: обработчик аккорда клавиш
  • ON KEY: пауза и возобновление обработчика

Диагностика

  • MB2034: в обработчик оператора ON KEY передана не процедура SUB без параметров или с одним параметром STRING.
