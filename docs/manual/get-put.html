Операторы

GET и PUT

GET и PUT переносят прямоугольный блок пикселей между текущим framebuffer и обычным двумерным числовым массивом. Эти операторы нужны, когда программе надо сохранить часть изображения, временно стереть её, а затем вернуть обратно или наложить в другом месте.

Синтаксис

GET [STEP] (<x1>, <y1>)-[STEP] (<x2>, <y2>), <buffer>
PUT [STEP] (<x>, <y>), <buffer>[, PSET|PRESET|AND|OR|XOR]

Для чего нужен двумерный буфер

В Axiom буфер для GET и PUT - это не скрытый packed-формат старых видеорежимов, а обычный двумерный числовой массив. Поэтому содержимое блока можно читать, менять обычными выражениями языка и передавать через уже существующие массивные формы.

Первая размерность буфера задаёт ширину блока по оси X, вторая - высоту по оси Y. Границы индексов могут быть любыми: важен не стартовый индекс, а видимый размер прямоугольника.

Части синтаксиса

ЧастьОписание
<x1>, <y1>Первая точка прямоугольника для GET. Если перед ней стоит STEP, координаты считаются смещением от текущей графической позиции.
<x2>, <y2>Вторая точка прямоугольника для GET. Если перед ней стоит STEP, смещение считается уже от фактически вычисленной первой точки.
<x>, <y>Левый верхний угол блока для PUT. Форма STEP считает координаты как смещение от текущей графической позиции.
<buffer>Обычный двумерный числовой массив или двумерное представление массива. Допустимы элементы типов INTEGER, LONG, DOUBLE и DECIMAL.
PSET, PRESET, AND, OR, XORСпособ наложения буфера при PUT. Если действие не указано, Axiom использует XOR.

Действия PUT

ДействиеРезультат
PSETПиксель назначения получает нормализованное значение из буфера без учёта старого цвета.
PRESETПиксель назначения получает значение 255 - source после нормализации буфера к диапазону 0..255.
ANDНовый цвет равен destination AND source.
ORНовый цвет равен destination OR source.
XORНовый цвет равен destination XOR source. Это действие используется по умолчанию.

Замечания

GET и PUT работают только в графических режимах SCREEN 1 ... SCREEN 10. Вне активного графического экрана оба оператора сообщают ошибку времени выполнения MB3010.

Координаты проходят через тот же договор, что и остальные графические операторы. После VIEW без слова SCREEN они считаются в локальной системе viewport, а при активном WINDOW - в логической системе окна.

GET можно вызывать с точками в любом порядке. Axiom сначала переводит обе пользовательские точки в физические координаты framebuffer, а затем сам определяет левую, правую, верхнюю и нижнюю границы блока.

Размер прямоугольника и видимая форма буфера должны совпадать. Если блок имеет ширину 2 и высоту 3, то у буфера тоже должна быть видимая форма 2 x 3, независимо от фактических нижних границ индексов.

PUT не меняет текущую графическую позицию, настройки VIEW и WINDOW и текстовый курсор. GET тоже не меняет текущую графическую позицию: оператор только считывает цвета из framebuffer в массив.

Перед наложением PUT приводит каждое значение буфера к 8-битному цвету по правилу ABS(TRUNC(value)) MOD 256. Для дробных значений сохраняется только целая часть, а нечисловые и бесконечные значения считаются ошибкой.

Примеры

SCREEN 1
DIM block(1 TO 2, 1 TO 2) AS INTEGER

PSET (10, 10), 1
PSET (11, 10), 2
PSET (10, 11), 3
PSET (11, 11), 4

GET (10, 10)-(11, 11), block
LINE (10, 10)-(11, 11), 0, BF
PUT (10, 10), block

Сначала четыре пикселя читаются в массив, затем область очищается и возвращается обратно через PUT. В такой форме буфер можно дополнительно изменить между двумя вызовами.

SCREEN 1
DIM buffer(1 TO 2, 1 TO 1) AS DOUBLE
buffer(1, 1) = 1.9
buffer(2, 1) = -2.2

PUT (10, 10), buffer
PUT (10, 12), buffer, PRESET

Здесь видно два важных правила: PUT принимает обычный числовой массив, а форма PRESET использует уже нормализованный цвет буфера и инвертирует его как 255 - source.

Диагностика

  • MB3010: графический режим SCREEN не активен.
  • MB3007: координаты вне поддержанного диапазона, буфер не является двумерным числовым массивом, форма буфера не совпадает с прямоугольником GET или значение буфера нельзя привести к допустимому 8-битному цвету.

Проверочные программы

Для ручной проверки чтения блока, наложения по умолчанию через XOR и режима PRESET используйте тематические runnable-примеры.

  • GET: чтение прямоугольника в двумерный массив
  • PUT: действие по умолчанию XOR и режим PRESET
