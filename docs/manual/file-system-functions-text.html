Раздел

Текстовые файлы

Раздел текстовых файлов описывает функции, которые принимают путь в виде строки и сами открывают файл, читают его или записывают результат — без ручного управления переменной FILE.

FILEEXISTS

Функция FILEEXISTS проверяет, существует ли файл по указанному пути.

Синтаксис

result = FILEEXISTS(path)

Аргументы

path задаёт путь к файлу. Функция возвращает TRUE, если файл найден, и FALSE, если файла нет.

Пример вызова FILEEXISTS

' Проверка существования файла
PRINT FILEEXISTS("notes.txt")

DIREXISTS

Функция DIREXISTS проверяет, существует ли папка по указанному пути.

Синтаксис

result = DIREXISTS(path)

Аргументы

path задаёт путь к папке. Функция возвращает TRUE, если папка найдена.

Пример вызова DIREXISTS

' Проверка существования папки
PRINT DIREXISTS(".")

PATHEXISTS

Функция PATHEXISTS проверяет, существует ли по пути файл или папка.

Синтаксис

result = PATHEXISTS(path)

Аргументы

path задаёт путь к объекту файловой системы. Результатом является логическое значение.

Пример вызова PATHEXISTS

' Проверка любого объекта по пути
PRINT PATHEXISTS("notes.txt")
PRINT PATHEXISTS("docs")

READFILE

READFILE — встроенная функция языка Axiom, которая читает весь текстовый файл целиком и возвращает одну строку.

Синтаксис

text = READFILE(path)

Форма с явной кодировкой

text = READFILE(path, encoding)

Аргументы

path задаёт путь к текстовому файлу. Результатом является строка с полным содержимым файла.

Пример вызова READFILE

' Чтение всего файла одной строкой
DIM text AS STRING

text = READFILE("notes.txt")
PRINT text

READALLLINES

READALLLINES — встроенная функция языка Axiom, которая читает текстовый файл построчно и возвращает массив строк.

Синтаксис

lines = READALLLINES(path)

Форма с явной кодировкой

lines = READALLLINES(path, encoding)

Аргументы

path задаёт путь к текстовому файлу. Результатом является массив STRING() с границами 1 TO N.

Пример вызова READALLLINES

' Чтение файла в массив строк
DIM lines() AS STRING

lines = READALLLINES("notes.txt")
PRINT ARRAYLENGTH(lines)
PRINT lines(1)

WRITEFILE

WRITEFILE — встроенная функция языка Axiom, которая записывает текст в файл с начала. Если файл уже существует, его содержимое заменяется.

Синтаксис

result = WRITEFILE(path, text)

Форма с явной кодировкой

result = WRITEFILE(path, text, encoding)

Аргументы

path задаёт путь к файлу. text задаёт строку для записи. Результат имеет тип BOOLEAN.

Пример вызова WRITEFILE

' Полная перезапись файла
PRINT WRITEFILE("notes.txt", "Первая строка")

APPENDFILE

APPENDFILE — встроенная функция языка Axiom, которая дописывает текст в конец файла. Если файла ещё нет, он создаётся.

Синтаксис

result = APPENDFILE(path, text)

Форма с явной кодировкой

result = APPENDFILE(path, text, encoding)

Аргументы

path задаёт путь к файлу. text задаёт строку, которую нужно добавить в конец файла. Результат имеет тип BOOLEAN.

Пример вызова APPENDFILE

' Добавление новой строки в конец файла
PRINT APPENDFILE("notes.txt", CHR(10) + "Вторая строка")

Выбор кодировки

Аргументы path, text и encoding должны быть строками. Явная кодировка нужна для обмена с программой, формат файлов которой известен заранее. Новые формы работают в обоих движках, в IDE и CLI. Относительные пути вычисляются от текущей папки программы; отсутствующие родительские папки автоматически не создаются.

Имя кодировкиЧтение и запись
UTF-8Строгое UTF-8. Запись без BOM; соответствующий BOM при чтении пропускается.
WINDOWS-1251Однобайтовая кириллическая кодировка, без BOM. Все входные байты читаются как WINDOWS-1251; похожие на Unicode BOM префиксы остаются обычным текстом. Непредставимые символы не заменяются знаком вопроса, а вызывают ошибку.
UTF-16LEСтрогое UTF-16 с младшим байтом первым. Новый файл получает BOM FF FE.
UTF-16BEСтрогое UTF-16 со старшим байтом первым. Новый файл получает BOM FE FF.

Регистр имени кодировки не важен, пробелы по краям игнорируются. Другие имена не поддерживаются. Явное чтение Unicode-кодировок допускает отсутствие BOM, но отвергает противоречащий выбранной кодировке распознанный BOM. Для WINDOWS-1251 BOM не распознаётся: байты FF FE могут означать обычный текст «яю», поэтому функция не угадывает Unicode вместо явно выбранной однобайтовой кодировки. Некорректные байты UTF-8/UTF-16 вызывают ошибку; функция не переключается на другую кодировку. Первая подпись EF BB BF в UTF-8 считается BOM, поэтому начальный символ U+FEFF при таком чтении не возвращается как текст. Пустой файл возвращает пустую строку или пустой массив строк.

Функция WRITEFILE проверяет возможность кодирования всего текста до создания или обнуления файла. При ошибке кодирования прежнее содержимое сохраняется. Функция APPENDFILE сначала проверяет весь существующий файл по выбранной кодировке, затем добавляет текст без повторного BOM. Для отсутствующего или пустого файла применяется правило создания из таблицы. Обе функции возвращают TRUE при успехе и сами не добавляют перевод строки.

Проверка декодирования не доказывает, какой формат задумал автор файла без BOM: одни байты могут быть корректны сразу в нескольких кодировках. Например, байты C3 A9 означают «é» в UTF-8 и «Г©» в WINDOWS-1251. Выбирайте кодировку по договору внешнего формата. Ошибки доступа и записи не делают операцию транзакционной: успешная проверка текста не исключает последующий сбой диска.

Диагностика явных форм

  • MB3007 при неизвестном имени кодировки: используйте одно из четырёх имён в таблице.
  • MB3007 при противоречащем BOM: выбранная кодировка не совпала с распознанной меткой файла.
  • MB3007 при некорректных байтах UTF-8/UTF-16: чтение или проверка перед дописыванием не заменяет повреждённый текст.
  • MB3007 при непредставимом символе: запись WINDOWS-1251 не заменяет эмодзи знаком вопроса; явные кодировки отвергают непарные суррогаты UTF-16.
  • MB3007 при отсутствии файла для чтения, недоступной папке или другой ошибке файловой системы.

Пример записи и дописывания WINDOWS-1251

PRINT MAKEDIR(".artifacts/encoding_examples")
PRINT WRITEFILE(".artifacts/encoding_examples/letters.txt", "А", "WINDOWS-1251")
PRINT APPENDFILE(".artifacts/encoding_examples/letters.txt", "я", "WINDOWS-1251")
PRINT READFILE(".artifacts/encoding_examples/letters.txt", "WINDOWS-1251")

Пример чтения UTF-16LE построчно

PRINT MAKEDIR(".artifacts/encoding_examples")
DIM lines() AS STRING
PRINT WRITEFILE(".artifacts/encoding_examples/lines.txt", "Первая" + CHR(10) + "Вторая", "UTF-16LE")
lines = READALLLINES(".artifacts/encoding_examples/lines.txt", "UTF-16LE")
PRINT ARRAYLENGTH(lines)

Полные запускаемые программы: выбор формата READFILE, строки UTF-16, отказ записи непредставимого символа, дописывание WINDOWS-1251.

Существующие формы без аргумента кодировки сохраняют прежние правила: чтение угадывает UTF-8/1251, запись использует UTF-8 без BOM. Оператор OPEN поддерживает тот же выбор через USING encoding.

Когда использовать чтение целиком и построчно

  • Формы READFILE и READALLLINES без аргумента кодировки сначала пытаются читать UTF-8, а при недопустимых байтах переходят к Windows-1251.
  • READALLLINES возвращает компактный массив строк. Для пустого файла это будет пустой массив с границами 1 TO 0.
  • Формы WRITEFILE и APPENDFILE без аргумента кодировки записывают UTF-8 без BOM; явные формы описаны выше.
  • Если нужно читать файл частями или управлять позицией вручную, используйте страницу Функции для открытого файла.

Диагностика

  • Отсутствие файла или недоступный путь для READFILE и READALLLINES дают диагностику времени выполнения MB3007.
  • Ошибки доступа к файловой системе при WRITEFILE и APPENDFILE также завершаются диагностикой MB3007.

Ручная проверка

  • FILEEXISTS: проверка файла
  • DIREXISTS: проверка папки
  • PATHEXISTS: проверка пути
  • READFILE: чтение целого файла
  • READALLLINES: чтение строк
  • WRITEFILE: запись текста
  • APPENDFILE: добавление текста

Однобайтовое чтение и повторная запись

Пример READFILE с явной WINDOWS-1251 читает ресурс со всеми значениями байта и записывает полученную строку той же кодировкой. Пример проверяет количество позиций и повторное чтение. Это обходной путь через текстовую кодировку, а не получение числового массива байтов. Операция держит весь файл в памяти. Для простого копирования файла используй COPYFILE.

В IDE ресурс ищется относительно каталога запускаемого исходника. При запуске этого примера через CLI перейди в его каталог, чтобы относительный путь byte_values.bin указывал на приложенный ресурс.
