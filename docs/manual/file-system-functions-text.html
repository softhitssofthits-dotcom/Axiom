Чтение и запись целого файла

Раздел содержит встроенные функции FILEEXISTS, DIREXISTS, PATHEXISTS, READFILE, READALLLINES, WRITEFILE, APPENDFILE, которые читают и записывают текст, а также проверяют наличие объектов.

Предел читаемого текста

READFILE возвращает не более 16 777 216 кодовых единиц UTF-16. Превышение вызывает MB3007 вместо возврата частичного текста. READALLLINES читает текст целиком перед разделением на строки и подчиняется тому же пределу для исходного прочитанного текста. Это предел текста после декодирования, а не число байтов файла; общие правила указаны в описании STRING.

Назначение и условия работы

Эта страница объединяет отдельные встроенные функции FILEEXISTS, DIREXISTS, PATHEXISTS, READFILE, READALLLINES, WRITEFILE, APPENDFILE. Каждый блок синтаксиса относится к указанной функции; общей конструкции для всей группы нет.

Файловые операции доступны в консольной программе и в IDE без оператора SCREEN. Относительные пути разрешаются от CURRENTDIR() текущего запуска. Перед разрешением пути раскрываются переменные окружения. Нулевой символ в пути недопустим. Создание файла не создаёт родительский каталог; сначала вызовите MAKEDIR, если он нужен.

FILEEXISTS

FILEEXISTS — встроенная функция языка Axiom, которая проверяет, существует ли обычный файл по заданному пути.

Операция работает с путём файловой системы либо со строковыми частями пути.

Синтаксис

FILEEXISTS(<путь>)

Аргументы

<путь> имеет тип STRING. Аргумент задаёт путь к файлу.

Результат и правила работы

Результат BOOLEAN равен TRUE, если по разрешённому пути существует файл; отсутствующий файл или каталог вместо файла дают FALSE.

Диагностика

MB2004 означает неверное число аргументов; MB2003 — несовместимые типы. MB3007 возникает, если путь нельзя разрешить, например он пуст или содержит нулевой символ. Отсутствующий файл даёт FALSE, а не ошибку.

Пример

DIM folder AS STRING = MAKETEMPDIR("axiom_manual_")
DIM path AS STRING = COMBINEPATH(folder, "notes.txt")
WRITEFILE(path, "AB")
PRINT FILEEXISTS(path)
DELETEDIRRECURSIVE(folder)

Ожидаемый вывод:

TRUE

PATHEXISTS

PATHEXISTS — встроенная функция языка Axiom, которая проверяет, существует ли файл или каталог по заданному пути.

Результат и правила работы

READFILE

READFILE — встроенная функция языка Axiom, которая читает весь текст файла в строку.

Операция работает с путём файловой системы либо со строковыми частями пути.

Синтаксис

READFILE(<путь>)
READFILE(<путь>, <кодировка>)

Аргументы

<путь> имеет тип STRING. Аргумент задаёт путь к файлу.

<кодировка> имеет тип STRING. Строка кодировки выбирает UTF-8, WINDOWS-1251, UTF-16LE или UTF-16BE; регистр и крайние пробелы игнорируются.

Результат и правила работы

Результат имеет тип STRING. Пустой файл даёт пустую строку. Переводы строк сохраняются. Файл должен существовать. Без явной кодировки чтение проверяет UTF-8 и при ошибке использует WINDOWS-1251; запись использует UTF-8 без BOM. Явная кодировка проверяется строго; UTF-16 при создании получает BOM. Совпадающий Unicode BOM пропускается при чтении, конфликтующий вызывает ошибку. APPENDFILE с явной кодировкой проверяет прежний текст перед добавлением.

Диагностика

MB2004 означает неверное число аргументов; MB2003 — несовместимые типы. MB3007 возникает, если файл не существует или недоступен, путь не разрешается, явная кодировка неизвестна, Unicode BOM конфликтует с ней либо байты не проходят строгое декодирование.

Пример

DIM folder AS STRING = MAKETEMPDIR("axiom_manual_")
DIM path AS STRING = COMBINEPATH(folder, "notes.txt")
WRITEFILE(path, "AB")
PRINT READFILE(path)
DELETEDIRRECURSIVE(folder)

Ожидаемый вывод:

AB

READALLLINES

READALLLINES — встроенная функция языка Axiom, которая читает строки файла в одномерный массив строк.

Операция работает с путём файловой системы либо со строковыми частями пути.

Синтаксис

READALLLINES(<путь>)
READALLLINES(<путь>, <кодировка>)

Аргументы

<путь> имеет тип STRING. Аргумент задаёт путь к файлу.

<кодировка> имеет тип STRING. Строка кодировки выбирает UTF-8, WINDOWS-1251, UTF-16LE или UTF-16BE; регистр и крайние пробелы игнорируются.

Результат и правила работы

Результат имеет тип массив STRING ранга 1. Разделители CR, LF и CRLF удаляются. Конечный разделитель не добавляет лишнюю строку; пустой файл даёт выделенный массив с границами 1 TO 0. Непустой результат имеет границы 1 TO N. Без явной кодировки чтение проверяет UTF-8 и при ошибке использует WINDOWS-1251; запись использует UTF-8 без BOM. Явная кодировка проверяется строго; UTF-16 при создании получает BOM. Совпадающий Unicode BOM пропускается при чтении, конфликтующий вызывает ошибку. APPENDFILE с явной кодировкой проверяет прежний текст перед добавлением.

Диагностика

MB2004 означает неверное число аргументов; MB2003 — несовместимые типы. MB3007 возникает, если файл не существует или недоступен, путь не разрешается, явная кодировка неизвестна, Unicode BOM конфликтует с ней либо байты не проходят строгое декодирование.

Пример

DIM folder AS STRING = MAKETEMPDIR("axiom_manual_")
DIM path AS STRING = COMBINEPATH(folder, "notes.txt")
WRITEFILE(path, "AB")
DIM lines() AS STRING
lines = READALLLINES(path)
PRINT ARRAYLENGTH(lines)
PRINT lines(1)
DELETEDIRRECURSIVE(folder)

Ожидаемый вывод:

1
AB

WRITEFILE

WRITEFILE — встроенная функция языка Axiom, которая записывает текст в файл, заменяя прежнее содержимое.

Операция работает с путём файловой системы либо со строковыми частями пути.

Синтаксис

WRITEFILE(<путь>, <текст>)
WRITEFILE(<путь>, <текст>, <кодировка>)

Аргументы

<путь> имеет тип STRING. Аргумент задаёт путь к файлу.

<текст> имеет тип STRING. Строка текста содержит символы, которые нужно записать.

<кодировка> имеет тип STRING. Строка кодировки выбирает UTF-8, WINDOWS-1251, UTF-16LE или UTF-16BE; регистр и крайние пробелы игнорируются.

Результат и правила работы

При успешном завершении функция возвращает TRUE; отказ сообщается диагностикой, а не значением FALSE.

Результат имеет тип BOOLEAN. Отсутствующий файл создаётся. Родительский каталог не создаётся. Разделитель строки автоматически не добавляется; пустой текст оставляет пустой файл. Без явной кодировки чтение проверяет UTF-8 и при ошибке использует WINDOWS-1251; запись использует UTF-8 без BOM. Явная кодировка проверяется строго; UTF-16 при создании получает BOM. Совпадающий Unicode BOM пропускается при чтении, конфликтующий вызывает ошибку. APPENDFILE с явной кодировкой проверяет прежний текст перед добавлением.

Диагностика

MB2004 означает неверное число аргументов; MB2003 — несовместимые типы. MB3007 возникает, если родительский каталог отсутствует, путь недоступен, кодировка неизвестна или текст нельзя строго закодировать в явно выбранную кодировку.

Пример

DIM folder AS STRING = MAKETEMPDIR("axiom_manual_")
DIM path AS STRING = COMBINEPATH(folder, "notes.txt")
WRITEFILE(path, "AB")
PRINT WRITEFILE(path, "CD")
PRINT READFILE(path)
DELETEDIRRECURSIVE(folder)

Ожидаемый вывод:

TRUE
CD

APPENDFILE

APPENDFILE — встроенная функция языка Axiom, которая дописывает текст в конец файла.

Операция работает с путём файловой системы либо со строковыми частями пути.

Синтаксис

APPENDFILE(<путь>, <текст>)
APPENDFILE(<путь>, <текст>, <кодировка>)

Аргументы

<путь> имеет тип STRING. Аргумент задаёт путь к файлу.

<текст> имеет тип STRING. Строка текста содержит символы, которые нужно записать.

<кодировка> имеет тип STRING. Строка кодировки выбирает UTF-8, WINDOWS-1251, UTF-16LE или UTF-16BE; регистр и крайние пробелы игнорируются.

Результат и правила работы

При успешном завершении функция возвращает TRUE; отказ сообщается диагностикой, а не значением FALSE.

Результат имеет тип BOOLEAN. Отсутствующий файл создаётся. Родительский каталог не создаётся. Разделитель строки автоматически не добавляется; пустой текст не увеличивает содержимое. Без явной кодировки чтение проверяет UTF-8 и при ошибке использует WINDOWS-1251; запись использует UTF-8 без BOM. Явная кодировка проверяется строго; UTF-16 при создании получает BOM. Совпадающий Unicode BOM пропускается при чтении, конфликтующий вызывает ошибку. APPENDFILE с явной кодировкой проверяет прежний текст перед добавлением.

При явной кодировке каждый вызов APPENDFILE проверяет всё существующее содержимое перед дописью. Для серии записей предпочтителен оператор OPEN ... FOR APPEND ... USING и вызовы WRITE: проверка исходного содержимого выполняется один раз при открытии. Строгая проверка кодировки сохраняется; несовместимые данные не дописываются. Во время проверки содержимого обрабатывается остановка программы.

MAKEDIR(".artifacts")
DIM path AS STRING = ".artifacts/append_series.txt"
WRITEFILE(path, "", "UTF-8")
DIM f AS FILE
OPEN path FOR APPEND AS f USING "UTF-8"
FOR i = 1 TO 3
    WRITE(f, "А😀")
NEXT
CLOSE f
PRINT READFILE(path, "UTF-8")
DELETEFILE(path)
' Результат: А😀А😀А😀.

Диагностика

MB2004 означает неверное число аргументов; MB2003 — несовместимые типы. MB3007 возникает, если родительский каталог отсутствует, путь недоступен, кодировка неизвестна, прежний текст или BOM несовместимы с явно выбранной кодировкой либо новый текст нельзя в ней представить.

Пример

DIM folder AS STRING = MAKETEMPDIR("axiom_manual_")
DIM path AS STRING = COMBINEPATH(folder, "notes.txt")
WRITEFILE(path, "AB")
PRINT APPENDFILE(path, "CD")
PRINT READFILE(path)
DELETEDIRRECURSIVE(folder)

Ожидаемый вывод:

TRUE
ABCD
