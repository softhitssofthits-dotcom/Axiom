Процедуры и функции

Раздел процедур и функций описывает именованные части программы: процедуры SUB и функции FUNCTION. Процедура выполняет действие, а функция вычисляет значение и может участвовать в выражении. На этой странице собраны разные сущности: операторы SUB, FUNCTION и RETURN, а также правила параметров и области видимости.

Что входит в раздел

Этот раздел не описывает одну общую команду. Синтаксис отдельных страниц относится к разным операторам языка Axiom.

  • оператор SUB объявляет процедуру без возвращаемого значения;
  • оператор FUNCTION объявляет функцию с возвращаемым значением;
  • оператор RETURN завершает выполнение процедуры или функции и возвращает значение из функции.

Зачем выносить код в процедуру

SUB вызывается как отдельная инструкция и не имеет возвращаемого значения. FUNCTION возвращает результат через RETURN и может использоваться там, где ожидается значение совместимого типа. Оба вида объявлений могут иметь параметры, локальные переменные и локальные вложенные процедуры или функции.

Выбор между SUB и FUNCTION

Выбор между процедурой и функцией лучше делать по смыслу результата. Если важен сам эффект выполнения — вывести текст, изменить переменную по BYREF, заполнить данные, выполнить проверку — обычно подходит SUB. Если нужен вычисленный результат для присваивания, условия, печати или передачи в другой вызов, используется FUNCTION.

SUB ShowBanner(text AS STRING)
    PRINT "=="; text; "=="
END SUB

FUNCTION Square(value AS INTEGER) AS INTEGER
    RETURN value * value
END FUNCTION

ShowBanner("Axiom")
PRINT Square(5)

Параметры и возврат

BYVAL и BYREF — это не операторы и не функции. Это модификаторы параметров: служебные слова, которые пишутся только в объявлении параметра SUB или FUNCTION перед именем параметра.

SUB Touch(BYREF value AS INTEGER)
    value = value + 1
END SUB

FUNCTION CopyOf(BYVAL value AS INTEGER) AS INTEGER
    RETURN value
END FUNCTION

Параметр без явного модификатора передаётся как BYVAL. Это значит: процедура или функция получает значение, а не саму переменную. Для TYPE это особенно важно, потому что передаётся отдельная копия записи.

Параметр BYREF связывается с простой переменной вызывающего кода и позволяет изменить её значение внутри процедуры или функции. Сейчас в BYREF можно передать именно простую переменную, например count. Выражение count + 1, поле user.Name и элемент массива items(1) для такого аргумента не подходят.

RETURN в FUNCTION должен возвращать значение. В SUB форма RETURN без значения используется для досрочного выхода.

Функции как значения

В Axiom функция может быть значением функционального типа, если её сигнатура совместима с ожидаемым типом. Это отличает FUNCTION от SUB: процедура не является значением и не подставляется в выражение.

Функции с параметрами BYREF сейчас нельзя передавать как функциональные значения или использовать как обратные вызовы. Такое ограничение нужно, потому что BYREF требует простой переменной в месте вызова.

Область видимости и вложенные объявления

В QuickBASIC функция возвращала значение и участвовала в выражениях, а процедура вызывалась как отдельный оператор. В Axiom это разделение сохранено, но нет текущей необходимости в DECLARE, а возврат значения из функции оформляется оператором RETURN, а не присваиванием имени функции.

  • И SUB, и FUNCTION могут быть объявлены на верхнем уровне программы.
  • Локальные SUB и FUNCTION можно объявлять внутри другой процедуры или функции.
  • Локальная функция может захватывать параметры и локальные переменные внешней функции, если эти имена объявлены раньше по тексту.
  • Для записей TYPE правила BYVAL и BYREF особенно важны: первое даёт копию, второе работает с исходной переменной.
