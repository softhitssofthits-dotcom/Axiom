Оператор

WINDOW

WINDOW задаёт логическую систему координат внутри текущего viewport. Это позволяет рисовать графики, оси и фигуры не по физическим пикселям экрана, а в собственной шкале программы, сохраняя один и тот же код для разных размеров области вывода.

Синтаксис

WINDOW
WINDOW SCREEN (<left>, <top>)-(<right>, <bottom>)
WINDOW (<left>, <top>)-(<right>, <bottom>)

Части синтаксиса

ЧастьОписание
WINDOW без аргументовСбрасывает логическое окно и возвращает графические координаты к текущей системе viewport.
SCREENОставляет направление оси Y экранным: вниз.
<left>, <top>, <right>, <bottom>Две противоположные вершины логического прямоугольника. Axiom сам нормализует порядок углов и принимает любые числовые выражения.

Замечания

WINDOW работает только в графических режимах SCREEN 1 ... SCREEN 10. Без активного графического режима оператор сообщает ошибку времени выполнения MB3010.

VIEW и WINDOW выполняют разные задачи. VIEW выбирает физическую область экрана, в которой разрешено рисование, а WINDOW задаёт логическую шкалу внутри этой области. Сначала программа обычно определяет viewport через VIEW, а затем, если нужно, включает поверх него логическое окно через WINDOW.

Форма WINDOW SCREEN создаёт логические координаты с экранным направлением оси Y: большее значение означает более низкую точку. Форма WINDOW без слова SCREEN создаёт декартову систему координат, где Y растёт вверх.

После WINDOW логические координаты используют PSET, PRESET, LINE, CIRCLE, PAINT, DRAW и форма POINT(x, y). Текущая графическая позиция остаётся общей для всех этих операторов.

Для явного перевода между логическими координатами окна и физическими координатами viewport используйте PMAP. Это полезно, когда программе нужно совместить логический рисунок с экранными измерениями.

Форма POINT(number) делится на две пары селекторов. POINT(0) и POINT(1) возвращают текущую физическую координату в системе viewport. POINT(2) и POINT(3) возвращают текущую логическую координату активного WINDOW. Если логическое окно не активно, все четыре селектора работают как координаты viewport.

Когда программа меняет VIEW или WINDOW, Axiom сохраняет физическую точку текущей графической позиции и заново вычисляет её логические координаты. Если при пересчёте получается нецелое значение, используется ближайшее целое.

WINDOW не влияет на LOCATE, текстовый курсор и текстовые координаты SCREEN. Для текста продолжает работать общий экранный режим.

Оператор сообщает MB3007, если логический прямоугольник вырождается, содержит нечисловые или слишком большие границы либо если текущий effective viewport после VIEW меньше 2 x 2 пикселей и потому не может задать масштаб окна.

Примеры

SCREEN 1
VIEW SCREEN (10, 10)-(20, 20)

WINDOW SCREEN (100, 200)-(110, 210)
PSET (104, 205), 6
DRAW "R1"
PRINT POINT(0), POINT(1)
PRINT POINT(2), POINT(3)

WINDOW (100, 210)-(110, 200)
PSET (104, 205), 7
PRINT POINT(104, 205)

В первой форме логические координаты ведут себя как экранные: точка (104, 205) попадает внутрь viewport и DRAW продолжает движение в той же логической системе. Во второй форме верхняя логическая граница больше нижней, поэтому координата Y начинает расти вверх, как на обычной декартовой плоскости.

Диагностика

  • MB3010: графический режим SCREEN не активен.
  • MB3007: логический прямоугольник WINDOW некорректен или текущий viewport слишком мал для его масштабирования.
