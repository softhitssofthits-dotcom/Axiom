Модули и исходные файлы

Модули — раздел языка Axiom, объединяющий импорт исходных файлов и доступность объявлений. Каждый файл образует отдельный модуль. Подпрограммы, типы, переменные и константы по умолчанию доступны только внутри своего файла.

Состав программы

Программа имеет явную точку входа — файл, выбранный для запуска. Оператор IMPORT подключает другой модуль. Модификаторы PUBLIC и PRIVATE определяют, какие объявления можно использовать из импортирующего файла. Лексическая вложенность подпрограмм и время жизни переменных не заменяются модульной доступностью.

Файлы и имена

Имя модуля совпадает с именем файла без расширения .axm. Сравнение имён не учитывает регистр. Импортируемые файлы разрешаются в папке точки входа, включая зависимости импортов. CLI читает их с диска. IDE использует текст открытой модели именованного файла, а закрытые зависимости читает с диска. Программа не создаёт отсутствующие исходники или каталоги. Для несохранённого документа нет папки поиска: такой импорт не разрешается. Несохранённые изменения открытых именованных зависимостей учитываются при проверке, подсказках и запуске без записи на диск. Точку входа перед запуском по-прежнему нужно сохранить.

При передаче исходников через API можно указать явный набор документов. Все переданные документы проходят проверку, однако инициализируются только достижимые от точки входа модули. В одном наборе имена модулей должны быть уникальны.

Снимок проекта в редакторе

Проверка и запуск фиксируют тексты открытых модулей из папки точки входа. В состав программы входят только явные импорты: посторонняя открытая вкладка не начинает исполняться автоматически. Если зависимость изменена, переименована или закрыта во время проверки, прежний ответ не применяется. Подсказка импортированного имени обновляется после правки зависимости даже без изменения основного файла.

Например, откройте оба файла примера ниже и измените в tools.axm выражение value * value на value * value * value. Не сохраняя tools.axm, запустите сохранённый main.axm: IDE напечатает 125. CLI продолжит использовать сохранённую версию файла до её записи на диск.

Уже работающая программа и продолжение отладки используют прежний снимок. Правка зависимости во время INPUT или остановки влияет только на следующий запуск. Ошибка запущенной версии сохраняет исходный текст; её диапазон и стрелка отладки не переносятся на изменённую модель. Это правило действует и для файла, открытого после начала запуска.

Инициализация и вызовы

Операторы верхнего уровня импортируемого модуля выполняются один раз за запуск, до операторов импортирующего модуля. Общая зависимость нескольких модулей не инициализируется повторно. При ошибке инициализации выполнение точки входа не начинается. Следующий запуск создаёт новое состояние программы. Порядок независимых зависимостей соответствует порядку IMPORT.

Циклы IMPORT, включая импорт самого себя, запрещены. Рекурсия подпрограмм внутри модуля поддерживается. Ссылка на закрытую функцию может возвращаться из открытой функции: PRIVATE ограничивает доступ к имени, а не возможность вызова уже полученного функционального значения.

Типы и данные

PUBLIC TYPE доступен для объявлений, параметров и конструктора записи. Открытые переменные и константы импортируются по имени; BYREF сохраняет обычные правила передачи изменяемой переменной. Открытая функция может принимать и возвращать закрытый TYPE, однако имя такого типа нельзя использовать снаружи. Поля уже полученной записи сохраняют обычный договор TYPE; PRIVATE не вводит отдельного режима закрытых полей.

Импорт не передаёт имена дальше автоматически: каждый файл явно импортирует те модули, к именам которых обращается. Квалифицированного доступа вида module.name и псевдонимов импортов пока нет.

Пример

Создайте два файла в одной папке. Файл tools.axm:

PUBLIC FUNCTION Square(value AS INTEGER) AS INTEGER
    RETURN value * value
END FUNCTION

Файл main.axm:

IMPORT tools
PRINT Square(5)

Запуск main.axm печатает 25. Готовые файлы: main.axm и tools.axm.
