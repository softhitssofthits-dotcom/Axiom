Типы данных

TYPE, массивы и групповые объявления

Помимо встроенных базовых типов Axiom поддерживает пользовательские записи через TYPE. Такая запись может содержать поля, массивные поля и пользовательские методы, а массивы в целом строятся поверх типа элемента.

Пользовательские записи TYPE

TYPE ... END TYPE объявляет новый тип записи с именованными полями. Переменная такого типа объявляется через DIM name AS TypeName, а поля читаются и записываются через точку: name.Field.

Если объяснять по-простому, TYPE нужен тогда, когда несколько значений должны жить вместе как одна сущность. Например, имя, возраст и город можно держать не в трёх отдельных переменных, а в одной записи Person.

Внутри TYPE можно объявлять не только поля, но и методы через SUB и FUNCTION. Метод — это действие самой записи, а текущая запись внутри него доступна как SELF.

Если у одного TYPE объявлено несколько методов с одним именем, они могут образовать набор перегрузок. В таком случае Axiom выбирает подходящий вариант по числу аргументов, совместимости сигнатуры и точности совпадения типов, а не по типу результата.

Запись можно создать через форму TypeName(...) в трёх режимах. Именованная форма Person(Name := "Ada", Age := 36) заполняет указанные поля, а остальные берёт из значений по умолчанию. Если внутри TYPE нет пользовательского конструктора, пустая форма Person() даёт запись со значениями по умолчанию, а позиционная форма Person("Ada", 36) сопоставляет аргументы полям по порядку объявления.

Если внутри TYPE объявлен SUB New(...), неименованная форма TypeName(...) становится вызовом конструктора. В текущем шаге такие конструкторы можно перегружать по полной сигнатуре пользовательских параметров, включая нулевую форму SUB New(). Именованная форма с := при этом остаётся литералом записи и конструктор не вызывает.

После выбранного SUB New(...) запись может пройти ещё одну пользовательскую проверку через специальную форму FUNCTION IsValid() AS BOOLEAN. Это инвариант: простая автоматическая проверка того, что запись после создания находится в допустимом состоянии. Если такая функция возвращает FALSE, конструкторный путь завершается runtime-ошибкой. Именованный литерал TypeName(Field := ...) этот шаг не выполняет.

Поле записи может быть не только скаляром или вложенным TYPE, но и массивом. Для массивных полей работает тот же договор ранга, что и для обычных переменных: допустимы динамические формы Scores(), Grid(,), Cube(,,) и фиксированные формы с диапазонами в каждом измерении.

TYPE Person
    Name AS STRING
    Age AS INTEGER
END TYPE

DIM user AS Person
user = Person(Name := "Ada", Age := 36)
DIM user AS Person
user = Person("Ada", 36)
TYPE Person
    Name AS STRING = "Unknown"
    Age AS INTEGER = 18

    SUB New()
        SELF.Name = "Zero"
    END SUB

    SUB New(name AS STRING)
        SELF.Name = name
        SELF.Age = SELF.Age + 1
    END SUB
END TYPE

DIM built AS Person
DIM literalOnly AS Person

built = Person()
literalOnly = Person(Name := "Grace")

Групповые объявления

  • AS <тип> относится ко всей ближайшей группе имён слева до начала оператора DIM или до предыдущего разделителя группы.
  • Форма DIM left, right AS BOOLEAN объявляет обе переменные как BOOLEAN.
  • Форма DIM total = 10 выводит тип как INTEGER, а DIM price = 1.5 выводит тип как DOUBLE.

Массивы как тип поверх элемента

Массивы используют тот же базовый набор типов, только через тип элемента, например DIM scores(1 TO 3) AS INTEGER. Отдельный базовый тип массива не вводится: в договоре участвуют тип элемента, ранг и видимые границы.

DIM scores(1 TO 3) AS INTEGER
DIM names(1 TO 2) AS STRING
DIM board(1 TO 3, 1 TO 3) AS BOOLEAN

Ручная проверка

  • TYPE: методы и SELF
  • TYPE: методы у поля записи и элемента массива
  • TYPE: методы у временного литерала и результата функции
  • TYPE: перегрузка обычных методов по сигнатуре
  • TYPE: пользовательский конструктор через SUB New
  • TYPE: инвариант после конструктора через FUNCTION IsValid
  • DIM: групповые объявления с общим типом
  • TYPE: именованные литералы через :=
  • TYPE: позиционная форма TypeName(...)
  • TYPE: строковые поля фиксированной длины
  • TYPE: подмассивы и диапазонные представления через поле
  • TYPE: многомерные динамические массивные поля
  • TYPE: многомерные фиксированные массивные поля
  • Многомерные массивы: двумерная сетка
