Типы данных

В текущей версии Axiom поддерживает семь базовых типов данных: INTEGER, LONG, DOUBLE, DECIMAL, STRING, BOOLEAN и FILE, а также пользовательские записи, объявленные через TYPE ... END TYPE. Эти типы определяют, какие литералы допустимы, как работает вывод типа в DIM, какие автоматические преобразования разрешены и в каких случаях появляется диагностика.

Сводка

Тип данных в Axiom задает форму допустимого значения, участвует в проверке выражений и определяет поведение операций, сравнений, INPUT, встроенных функций и вывода типа в DIM. В текущем публичном контракте подтверждены семь базовых типов, пользовательские записи через TYPE, а массивы строятся поверх типа элемента и не образуют отдельный дополнительный базовый тип.

Синтаксис

DIM <имя> AS <тип>
DIM <имя> AS <тип> = <выражение>
DIM <имя> = <выражение>
TYPE <имя типа>
    <имя поля> AS <тип поля>
END TYPE
CONST <имя> AS <тип> = <выражение>
DIM text AS STRING = "Привет"
DIM ready AS BOOLEAN = TRUE
DIM total = 10
DIM ratio = 1.5

Части синтаксиса

  • <имя> — имя переменной или константы.
  • <тип> — один из подтверждённых типов данных Axiom: встроенный тип, пользовательский TYPE, массив или функциональный тип в тех формах, где они разрешены.
  • <выражение> — выражение, которое даёт начальное значение и, в форме без AS, определяет выводимый тип.

Пользовательские записи TYPE

TYPE ... END TYPE объявляет новый тип записи с именованными полями. Переменная такого типа объявляется через DIM name AS TypeName, а поля читаются и записываются через точку: name.Field. Подробнее синтаксис и ограничения описаны на странице Оператор TYPE.

Тип STRING и фиксированная длина

Обычная форма STRING хранит строку переменной длины. Если нужен фиксированный размер, можно объявить строку как STRING * N, где N — целочисленная константа в диапазоне от 1 до 65535.

DIM code AS STRING * 4
TYPE Person
    Name AS STRING * 12
END TYPE

Фиксированная строка не вводит отдельного нового типа выражений: строковые функции, сравнения и присваивания работают с ней как со строкой. Отличие проявляется в хранении значения: пустое значение создаётся как строка из пробелов нужной длины, короткая строка дополняется пробелами справа, длинная строка обрезается справа до заданного размера.

Сейчас форма STRING * N поддержана только как непосредственный тип в DIM и в строковых полях TYPE. В CONST, параметрах и типе результата FUNCTION, а также внутри функциональных типов нужно использовать обычный STRING; неподдержанная форма даёт диагностику MB2026.

Тип FILE

FILE отличается от остальных базовых типов тем, что его значение не задают литералом и не получают обычным присваиванием. Переменная типа FILE получает открытый файл через OPEN, затем используется в ISOPEN, FILEPATH, FILEMODE, FILEPOS, FILELENGTH, LINENUMBER, EOF, READLINE, SKIPLINE, READTEXT, READTOEND, WRITE, WRITELINE, NEWLINE, FLUSH, SEEKFILE, REWIND и освобождается через CLOSE.

Литералы и вывод типа

Axiom выводит тип из литерала только в подтвержденных формах. Целый литерал в диапазоне INTEGER получает тип INTEGER; более крупный целый литерал в диапазоне LONG получает тип LONG; литерал с точкой получает тип DOUBLE. Строковые литералы остаются STRING, а TRUE и FALSE дают тип BOOLEAN.

Группы объявлений и массивы

  • AS <тип> относится ко всей ближайшей группе имен слева до начала оператора DIM или до предыдущего разделителя групп.
  • Форма DIM left, right AS BOOLEAN объявляет обе переменные как BOOLEAN.
  • Форма DIM total = 10 выводит тип как INTEGER, а DIM price = 1.5 выводит тип как DOUBLE.
  • Форма DIM price AS DECIMAL = 1.5 константно приводит инициализатор к DECIMAL.
  • Массивы используют тот же базовый набор типов, только через тип элемента, например DIM scores(1 TO 3) AS INTEGER.

Автоматические преобразования

  • Автоматически разрешены только INTEGER -> LONG, INTEGER -> DECIMAL, INTEGER -> DOUBLE, LONG -> DECIMAL и LONG -> DOUBLE.
  • STRING не превращается в число автоматически; для этого нужен явный вызов VAL(...).
  • Преобразование в строку тоже выполняется явно через STR(...).
  • DOUBLE и DECIMAL не смешиваются автоматически.
  • FILE не участвует в арифметике и не имеет автоматических преобразований к другим типам.
  • Оператор / возвращает DECIMAL, если в выражении участвует DECIMAL и не участвует DOUBLE; во всех остальных случаях результат имеет тип DOUBLE.

Ручная проверка

Для ручной проверки в IDE удобно использовать готовые запускаемые примеры по объявлениям, литералам и числовым крайним случаям.

  • DIM: базовое явное объявление
  • DIM: вывод типа из инициализатора
  • DIM: групповые объявления с общим типом
  • DIM: вывод LONG из большого целого литерала
  • DIM: явное объявление DECIMAL
  • DIM: фиксированная строка STRING * N
  • TYPE: фиксированные строковые поля
  • Литерал вне диапазона LONG
  • Константа не помещается в DECIMAL
  • Переполнение LONG во время выполнения
  • Неконечный результат DOUBLE
  • Переполнение DECIMAL во время выполнения
  • Автоматические числовые преобразования
  • STR: явное преобразование числа в строку
  • VAL: явное преобразование строки в число

Примеры

DIM COUNT AS INTEGER = 10
DIM NAME = "Алиса"
DIM READY = TRUE

PRINT COUNT
PRINT NAME
PRINT READY
DIM PRICE AS DECIMAL = 10.50
DIM TAX AS DECIMAL = 0.20
DIM TOTAL AS DECIMAL = PRICE + TAX

PRINT TOTAL
PRINT PRICE / 2
DIM CODE AS STRING * 4
CODE = "AB"
PRINT "[" + CODE + "]"

CODE = "Alpha"
PRINT "[" + CODE + "]"
DIM TEXT AS STRING = "123.5"
DIM NUMBER AS DOUBLE = VAL(TEXT)

IF NUMBER > 100 THEN
    PRINT STR(NUMBER)
END IF

Диагностика

  • MB0004 — числовой литерал выходит за допустимый диапазон своего типа, то есть не помещается в LONG или выходит за диапазон конечных значений DOUBLE.
  • MB2018 — константное числовое значение не помещается в явно указанный целевой тип, например при объявлении AS INTEGER, AS LONG или AS DECIMAL.
  • MB3008 — во время выполнения произошло числовое переполнение или получен недопустимый неконечный результат DOUBLE.
