## Первый кандидат: завершение нативного INPUT в Electron

Проблема существует в работающей возможности, не требует нового оператора и затрагивает согласованность программы и интерфейса. Она уже отмечена при приёмке SCREEN, теперь причина сверена с текущим кодом.

1. ProgramConsoleService передаёт изменение IsWaitingForInput в DesktopHost.
2. В DesktopHost.cs обработчик ожидания отправляет input.request. При окончании ожидания ветка else лишь очищает _inputRequestId, без сообщения Electron.
3. ExecutionController хранит inputRequestId/inputPrompt. Последующий output.append обновляет историю, но не закрывает запрос; renderOutput снова дописывает прежнее приглашение.
4. Если до следующего INPUT или окончания программы пользователь нажмёт Enter в консоли IDE, контроллер может отправить старый запрос. DesktopHost явно отвечает INVALID_INPUT: «Запрос ввода уже завершён». Отказ submitInput вызывает fault и локально завершает состояние исполнения интерфейса. Остановка самой VM этим путём не доказана.

Адресная проверка выполнена через Node vm с настоящим execution-controller.js и подставными терминалом/API: input.request №7, затем вывод после нативного ответа. Контроллер сохранил №7 и дописал «Ответ: » после строки «Программа продолжает работу». Последующий ввод отправил №7; при подставном отказе API контроллер перешёл в running=false. Реальный отказ INVALID_INPUT отдельно подтверждён веткой диспетчера DesktopHost. Это проверка контроллера и кода протокола, не новый сквозной запуск Electron с физической клавиатурой. Предыдущая оконная приёмка SCREEN подтверждала ответ программы и дальнейшее рисование, но не закрытие запроса интерфейса.

Приоритет выше измерений VM и расширения справочника: ошибка влияет на обычную рабочую операцию и может оставлять ложное приглашение или ложное сообщение о сбое. Аппаратную задачу второго монитора нельзя полноценно закрыть без соответствующего оборудования. Неподтверждённые строковые/числовые кандидаты сначала требуют отдельного воспроизведения.

## Границы предлагаемого исправления

Согласовать окончание запроса ввода между DesktopHost и Electron с идентификаторами сессии и запроса; не очищать более новый INPUT запоздалым событием. Учесть успешный ответ, отмену, повтор после неверного значения и смену запуска. Не менять синтаксис INPUT, графическое оформление и правила фокуса без отдельной причины.

Приёмка: реальный SCREEN принимает русский ответ, программа продолжает работу до своего завершения, старый запрос и приглашение в Electron отсутствуют; второй INPUT получает отдельный запрос; старый ответ не повреждает новый; закрытие окна и Stop освобождают ожидание; обычный консольный INPUT и история вывода сохраняются. Нужны адресные проверки протокола/контроллера и Electron. Для реализации затрагивается версия IDE; язык и компилятор повышать без изменения их договора не требуется.

Реализация в этой ревизии не изменялась. Версии остаются: язык 0.1.15, компилятор 0.1.15, IDE 0.6.0. Полные тесты решения и Electron не запускались.
