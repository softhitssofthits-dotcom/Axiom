# Исключительное сохранение и восстановление документов Electron IDE

## Session 1363 — 2026-10-11

По поручению автора закрыты межпроцессная защита сохранения и восстановление несохранённых документов после аварии основного процесса Electron или процесса интерфейса.

## Сохранение файла

Команда `file.save` в `Axiom.DesktopHost` открывает файл с `FileShare.None`. Проверка версии, запись текста, изменение длины и `Flush(true)` выполняются на одном исключительном дескрипторе. Пока он открыт, другой обычный процесс Windows не может открыть тот же файл для записи. Если чужой дескриптор уже открыт, сохранение завершается ошибкой, вкладка сохраняет текст и признак правки. Отдельная предварительная проверка средствами Node больше не является основанием для записи.

Исходная версия передаётся контрольной суммой SHA256 нормализованного текста без BOM, с одинаковыми окончаниями строк. При конфликте пользователь принимает решение после освобождения дескриптора. Повторная попытка сравнивает контрольную сумму точных байтов обнаруженной версии; новое изменение снова требует подтверждения. Отсутствующий файл создаётся через `CreateNew`. Наблюдатель приостанавливает обработку пути на время собственного сохранения.

Это исключительная условная запись, а не транзакционная замена файла при отказе питания. При обычной ошибке записи предпринимается восстановление прежних байтов под тем же дескриптором; авария Host во время записи или ошибка носителя может помешать этому. Договор относится к обычным файловым дескрипторам Windows. Основание выбора: [FileShare](https://learn.microsoft.com/dotnet/api/system.io.fileshare).

## Восстановление

В пользовательском каталоге Electron хранятся два чередующихся файла `documents-recovery-0.json` и `documents-recovery-1.json`. Каждый содержит номер последовательности, версию формата, документы и контрольную сумму всего снимка. Запись временного файла завершается `fsyncSync`, затем переименованием. Чтение выбирает последний целый снимок; частичный или изменённый снимок отвергается.

Изменение модели синхронно сохраняет текст всех вкладок, исходный сохранённый текст, признаки правки и отсутствия файла, выбранную вкладку. Повторный одинаковый снимок не записывается. Закрытие, завершённый отказ от правок и переход к сохранённому состоянию записываются в оба слота: повреждение последнего слота не должно возвращать уже отвергнутый текст. Ошибка журнала показывается в строке состояния; закрытие, зависящее от записи журнала, не подтверждается.

После аварии восстанавливаются именованные, безымянные и отсутствующие документы. Для изменённого документа сохраняется прежняя исходная версия, поэтому последующее сохранение обнаруживает внешнюю правку. Неизменённый доступный файл читается с диска заново. Если удалённый файл появился с новым содержимым, восстановленный буфер остаётся несохранённым и требует решения пользователя. Восстановление само не записывает исходники и не возобновляет выполнение программы.

Журнал сохраняет текст и выбранную вкладку, но не историю отмены или точки останова. Повреждение обоих слотов, отказ носителя и аппаратное отключение питания не покрываются гарантией восстановления. Синхронная запись выбрана для сохранности завершённых правок; отдельное измерение её стоимости на больших документах не проводилось.
