# Stop и Restart при отказе остановки

16 октября 2026 года. Язык и компилятор 0.1.15, IDE 0.6.10.

## Подтверждённая проблема

Неуспешный ответ Stop вызывал общий fault: IDE теряла идентификатор сессии, остановку и активный INPUT, хотя программа могла продолжать работать в DesktopHost. Restart не получал явного результата остановки и мог начать новый запуск после такого ложного завершения. Отклонённое ожидание ответа Stop не обрабатывалось. Команда оболочки преждевременно показывала «Остановлено», не дожидаясь подтверждения.

До исправления новый набор Node прошёл 2 проверки из 11; девять проверок отказали. Три оконных сценария также воспроизвели потерю INPUT/сессии, неправильное завершение Restart и необработанный поздний отказ. Новые проверки не меняют договор языка.

## Исправление

ExecutionController.stop сохраняет идентичность своей попытки, сессию и снимок запуска. Ответ с ошибкой и исключение доставки обрабатываются одинаково: действующая сессия, остановка и ввод сохраняются, причина остаётся видимой, ложный признак запрошенной остановки сбрасывается. Повторный Stop доступен. Более новая попытка, новый запуск и fault аннулируют прежнее владение ответом.

Внутренний результат Stop различает принятый/отложенный запрос и явный отказ. Принятие запроса само по себе не объявляет завершение VM. Если во время ожидания уже получено настоящее execution.finished исходного запуска, это событие подтверждает завершение даже при поздней ошибке доставки. Новая сессия или авария не считаются таким подтверждением.

TraceController прекращает попытку Restart при явном отказе Stop, сохраняя исходную программу. Повторный Restart может корректно остановить её и начать заново. AxiomIDE.stop возвращает ожидание контроллера; статус завершения теперь устанавливается по событию службы, а не непосредственно по нажатию кнопки. Протокол и .NET-исполнение не менялись.

## Проверки

Новые stop-failure.test.cjs — 11/11. Вместе с debug-command-failure, execution-session, trace-restart, execution-start, run-document, execution-input и execution-diagnostics итог Node — 52/52.

Новый оконный набор использует настоящий DesktopHost. Для ответа с ошибкой оболочка API отправляет Stop с неверной сессией и получает реальный отказ, оставляя исходную программу активной. Исключение доставки моделируется отдельно и не выдано за конкретный сбой ОС. После отказа проверены сохранность INPUT, принятие русского ответа, сохранность отладочной остановки и успешный повтор Restart. Для позднего исключения сначала выполняется настоящий Stop и подтверждается завершение; затем проверяются Restart, новая программа с INPUT и явная отмена перезапуска. Последующие программы действительно завершаются с ожидаемым выводом.

Итоговые доказательства stop-failure-{results,restart-results,debug-results,trace-results,preparation-results,session-results}.json находятся в ide/e2e/evidence/. Идентификаторы 15 сценариев не повторяются; отказов, падений и ошибок страницы нет. Общий results.json восстановлен. Снимок текущей неудачной попытки удалён. Каталог 444; весь каталог не запускался.

DesktopHost Debug после повышения IDE собран последовательно: 0 ошибок, 0 предупреждений. Оконные программы создавались в .artifacts, постоянные .axm и справочник не менялись.

## Границы и продолжение

Проверены управляемые отказы и перестановки доставки, а не частота естественных сетевых/системных сбоев. Отдельное падение процесса во время Restart проверено на уровне контроллеров; отдельный оконный аварийный сценарий этого состояния не заявлен. Новые материалы используют относительные пути репозитория и нейтральные проверочные данные. README, сайт и настройки GitHub в этот этап не входят.

Следующая связанная задача — отказ отправки консольного INPUT: ответ с ошибкой, исключение доставки и поздний ответ после следующего запроса/сессии. Сначала сверить уже действующие проверки и воспроизвести; не добавлять языковые формы и не объявлять дефекты заранее.
