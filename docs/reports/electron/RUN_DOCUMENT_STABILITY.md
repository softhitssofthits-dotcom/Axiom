# Принадлежность запуска исходному документу — 16 октября 2026 года

## Дефект

Команда Run запоминала путь до сохранения, но после await save() заново читала активную вкладку через runTarget(). Пока запись ожидалась, пользователь мог переключить вкладку. В результате запускалась другая программа; отказ сохранения исходного документа тоже не проверялся и мог привести к запуску соседнего чистого файла.

Пять проверок настоящего метода AxiomIDE.run, загруженного из app.js в Node vm без создания интерфейса, воспроизвели пять отказов до исправления. Проверены переключение вкладки, отказ сохранения, новый путь безымянного документа, закрытие с повторным открытием того же пути и завершение сохранения при уже работающей программе.

## Исправление

В ide/src/renderer/app.js команда Run сохраняет ссылку на исходную запись DocumentStore и явно передаёт её путь в save. Неудачное сохранение прекращает команду. После успешной записи используется текущий путь той же записи, включая Сохранить как. Перед исполнением повторно проверяются отсутствие другой работающей программы, идентичность записи в хранилище, доступность модели и сохранённость документа.

Закрытие и повторное открытие того же пути не подменяет первоначальную запись. Если исходный документ сохранился и пригоден к запуску, редактор возвращается к нему до передачи команды исполнения: это также согласует документ с точками останова и показом текущей строки отладки. Если запуск отменён, выбранная пользователем другая вкладка сохраняется.

Изменён только код Electron; формат байт-кода, язык, протокол и файловая запись не менялись. Ранее исправленная защита ожидания startExecution сохранена.

## Проверки

Node: **28/28** в run-document.test.cjs, document-save.test.cjs, execution-start.test.cjs, execution-session.test.cjs и execution-input.test.cjs.

Настоящий Electron:

- run-document.spec.js: **2/2, 25 утверждений**. Управляемо задерживается только отправка настоящей записи через исходный writeFile. Пока запись ожидается, выбирается другая вкладка. Проверены обычный Run, отладка и сохранение безымянного документа по новому пути; исполняется точный текст исходного документа, другая программа не перезаписывается. Отдельно проверены изменение текста после снятия сохраняемого снимка и закрытие документа: команда запуска не отправляется, поздние правки остаются несохранёнными, другая вкладка остаётся выбранной.
- execution-preparation.spec.js: **3/3, 16 утверждений** — ошибка компиляции после успеха, отмена сохранения, авария DesktopHost при ожидании старта.
- trace.spec.js: **4/4, 31 утверждение** — обычные точки и команды шагов, перезапуск и локализация.

Итого **9/9 сценариев, 72 утверждения**, без отказов и ошибок страниц в окончательных результатах. Сохранены ide/e2e/evidence/run-document-results.json, run-document-preparation-results.json и run-document-trace-results.json.

Первый вариант оконного сценария закрытия повторно подставлял уже сохранённый текст, поэтому запись не начиналась и ожидание задержки завершилось тайм-аутом. Проверочный текст разделён по случаям; окончательный повтор обоих сценариев прошёл. Это ошибка подготовки самого теста, не дополнительный продуктовый дефект. Общий results.json восстановлен; созданный этой неудачной попыткой снимок удалён, прежние посторонние снимки сохранены.

## Границы и продолжение

Задержка записи управляется проверкой; частота гонки при обычном диске не измерялась. Отказ сохранения, повторное открытие и запрет второго запуска имеют отдельные проверки метода; не все сочетания этих случаев прошли оконный сценарий. Полный каталог Electron и всё решение .NET не запускались. Каталог расширен с 425 до 427 сценариев.

Новых языковых форм нет; существующие запускаемые примеры не менялись. Новые проверочные .axm создаются в изолированной .artifacts. Пользовательские настройки не используются.

Версии: язык 0.1.15, компилятор 0.1.15, IDE 0.6.4. Исправление и проверки находятся в рабочей копии; коммит и push не выполнялись. Следующий независимый участок — точные диапазоны диагностики при CRLF и символах вне BMP (остатки IDE16–17), сначала сверка уже существующих проверок и воспроизведение конкретного расхождения.

DesktopHost Debug пересобран после повышения версии без ошибок и предупреждений. Перед завершением выполняются обе проверки версий и git diff --check.
