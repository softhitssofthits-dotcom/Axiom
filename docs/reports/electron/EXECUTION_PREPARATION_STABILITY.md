# Устойчивость подготовки запуска — 16 октября 2026 года

## Задача и подтверждённая причина

Проверен сценарий успешного запуска, последующего отказа подготовки и повторного исправленного запуска. ProgramRunService сравнивает SourceText при использовании кэша и очищает его при неуспешной компиляции. Запуск старого байт-кода в проверенном сценарии не воспроизведён; переработка кэша не выполнялась.

В ExecutionController.start найден отдельный дефект: fault сбрасывал running/sessionId, но оставлял starting и очередь ранних событий. Ответ команды startExecution после await не проверял принадлежность текущей попытке. Поэтому поздний успех мог установить старую сессию, поздний отказ — сбросить новую. Отклонённый Promise команды запуска выходил без восстановления состояния. Начальные четыре проверки настоящего контроллера через Node vm воспроизвели четыре соответствующих отказа до исправления.

## Исправление

Каждая попытка start получает собственный объект startRequest. Ответ и исключение применяются только к текущей попытке. fault аннулирует попытку, сбрасывает starting/pendingStop и удаляет ранние события. Неактуальный ответ не меняет состояние, очередь событий и фокус нового запуска. Отказ доступности терминала также освобождает попытку. Изменён только ide/src/renderer/execution-controller.js; компилятор, VM, протокол и семантика отмены сохранены.
