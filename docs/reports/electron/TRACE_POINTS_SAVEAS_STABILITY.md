# Точки останова и Save As выполняемого документа

16 октября 2026 года. Язык/компилятор 0.1.15, IDE 0.6.14.

## Подтверждённая проблема

При Save As во время отладочной паузы запись документа и модель сохранялись под новым путём, но AxiomIDE._runFile оставался прежним. TraceController и запрет закрытия искали выполняемую модель по уже освобождённому пути.

Оконное воспроизведение дало четыре нарушенных утверждения: старый путь владельца исполнения, снятая защита редактирования после смены вкладки, отсутствующий указатель следующего шага и разрешённое закрытие исполняемой вкладки. Первые два новых сценария обычных точек и Save As до запуска прошли без изменения реализации. Новые проверки переименования до исправления дали 2/4, подтвердив обе формы обновления записи: непосредственно через renameActive и после уже выполненного переименования DocumentSaver.

## Исправление

renameActive обновляет _runFile вместе с путём записи, если переименовывается выполняемый документ. Сохраняются идентификатор, модель и точки. Исходный execution.sourceSnapshot не переписывается: его файл и текст описывают прежний запуск; текущий путь записи используется для принадлежности интерфейса. Переименование другого документа не переносит владельца сессии.

Существующие пути TraceController, readOnly, запрета закрытия и Restart снова находят нужную модель. Отдельные обработчики этих симптомов не добавлены. Протокол, BytecodeVm, язык и договор точек в службе .NET не менялись.

Настоящие F9 устанавливают/снимают точки. Вставка строки переносит точку, Undo возвращает её. Две модели сохраняют независимые точки; Ctrl+Shift+F9 очищает активную и неактивную модели. Save As до запуска сохраняет модель и точку, настоящий запуск останавливается на нужной строке. После закрытия/повторного открытия новая модель не наследует точку, а закрытая модель удаляется из реестра.

Save As на настоящей паузе сохраняет исходный снимок; другая модель остаётся редактируемой. F9 и общая очистка во время исполнения не меняют набор точек. Возврат к переименованному документу сохраняет readOnly; реальный F10 устанавливает указатель на нужной модели. Restart создаёт новую сессию по новому пути с прежними точками. Закрытие выполняемой вкладки отвергается, Stop снимает указатель.

Доказательства: ide/e2e/evidence/trace-points-{results,trace-results,restart-results,run-results}.json. Идентификаторы 11 сценариев различны; отказов, падений и ошибок страницы нет. Общий results.json восстановлен; снимок собственной неудачной попытки удалён. Каталог 456 без полного прогона.

DesktopHost Debug собран последовательно после повышения IDE: 0 ошибок, 0 предупреждений. Обе проверки версий пройдены: check и check --base HEAD. Постоянные .axm и справочник не менялись; проверочные программы создаются в .artifacts. README и настройки GitHub сохранены.

## Границы и следующий этап

Это приёмка перечисленных условий, а не всех способов изменения файлов и всех перестановок доставки. Внешняя замена/удаление файла во время паузы отдельно не проверены. IDE37 остаётся частичной; новые средства точек останова и языка не вводились.

Следующий связанный участок — актуальность результатов и отказов форматирования после правки, смены/закрытия документа, а также защита исполняемой модели. Сначала сверить имеющиеся проверки и воспроизвести возможные нарушения.
