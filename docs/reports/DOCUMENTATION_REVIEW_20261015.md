## Исправление INPUT

В DesktopHost при запросе передаётся target=screen для активного SCREEN, включая SCREEN 0; остальные запросы остаются console. ExecutionController не вызывает term.focus для запроса screen, в том числе при завершении запуска с накопленными событиями. При прекращении ожидания после нативного Enter или отмены хост отправляет input.completed. Интерфейс сопоставляет сессию и идентификатор запроса и удаляет только завершённое приглашение. Позднее событие не закрывает новый запрос.

Синтаксис и преобразование значений INPUT не менялись. Неверное число вызывает прежнюю языковую ошибку; новый пример [screen_lifecycle.axm](../../samples/operators/input/screen_lifecycle.axm) организует повтор через TRY/CATCH. Между первым и вторым вводом SLEEP 4000 оставляет четыре секунды для наблюдения продолжения программы. CANVAS сохраняет консольный INPUT.

Проверки контроллера сначала дали два ожидаемых отказа на старом коде. После исправления вместе с backend-client пройдены 10/10, включая ранний запрос в очереди запуска. Сборка DesktopHost Debug — без ошибок и предупреждений. Настоящий Electron проверил SCREEN 1 и SCREEN 0: фокус, русский ответ, закрытие всех трёх запросов, повтор после обработанной ошибки и Stop во время ожидания — 28 утверждений. Дополнительно прошли пять сценариев консольного ввода / 37 утверждений, семь графического жизненного цикла / 53 и один активации окон / 3. Всего 14/14 сценариев, 121 утверждение, без отказов и ошибок страниц. Доказательства: ide/e2e/evidence/input-native-results.json, input-console-results.json, input-graphics-regression-results.json и input-foreground-results.json.

Первые варианты нового оконного примера исправлены: неучтённая ошибка числа должна перехватываться программой, а SLEEP измеряется миллисекундами. Старое окно SCREEN 0 после Stop может сохранять последний текст; это существующее поведение не изменялось. Приёмка проверяет прекращение сессии/запроса и отдельно закрывает такое окно. Ошибки самой автоматизации не выданы за отказы исправляемого протокола.

Редакционный ориентир абзаца manual/input.html — раздел INPUT книги Зельднера (извлечённый текст, строки 6101–6118); ближайший современный жанровый ориентир — [InputBox в Visual Basic](https://learn.microsoft.com/en-us/dotnet/api/microsoft.visualbasic.interaction.inputbox). Семантика чужого диалогового ввода в Axiom не переносилась.

Версии: язык 0.1.15, компилятор 0.1.15, IDE 0.6.1. Архивы, новые возможности языка, полный набор решения, все 419 сценариев и физическая аппаратная переаттестация в этот этап не входят.
