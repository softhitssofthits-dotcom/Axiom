## 1. Литералы массивов — компактная инициализация

### Проблема

Сейчас создание массива с заранее известными значениями требует много строк:

```axiom
DIM fruits(1 TO 3) AS STRING
fruits(1) = "яблоко"
fruits(2) = "банан"
fruits(3) = "вишня"
```

Для коротких списков это громоздко. Нужен компактный способ объявить и заполнить массив одной строкой.

### Предложение

Ввести синтаксис литерала массива через фигурные скобки. Ключевой принцип: `()` после имени остаётся маркером массива, а `{...}` задаёт значения.

```axiom
DIM fruits() = {"яблоко", "банан", "вишня"}
```

### Синтаксис

Фигурные скобки `{}` используются только для значений, а скобки `()` после имени — как и раньше показывают, что это массив:

```axiom
DIM fruits() = {"яблоко", "банан", "вишня"}           ' тип выводится: STRING()
DIM scores() = {10, 20, 30}                            ' тип выводится: INTEGER()
DIM flags() = {TRUE, FALSE, TRUE}                      ' тип выводится: BOOLEAN()

DIM fruits() AS STRING = {"яблоко", "банан", "вишня"}  ' явный тип
DIM fruits(1 TO 3) AS STRING = {"яблоко", "банан", "вишня"}  ' явные границы
```

Почему `()` обязательно:
- в Axiom (и в BASIC вообще) `()` после имени — это способ сказать «это массив»;
- запись `DIM fruits = {...}` выглядит так, будто `fruits` — обычная переменная, а не массив;
- все существующие формы массива используют `()`: `DIM values() AS INTEGER`, `DIM values(1 TO 3) AS INTEGER`;
- форма `DIM fruits() = {...}` естественно читается как «объявить динамический массив и сразу заполнить его».

Почему `{}` для значений:
- фигурные скобки `{}` уже используются в VB.NET и FreeBASIC для литералов массивов;
- визуально отличается от круглых скобок, которые используются для индексирования и вызовов;
- коротко и читаемо.

### Рекомендация

Форма `DIM name() = {values}` — основной синтаксис. Она согласуется с существующей логикой языка: `()` = массив, `{...}` = значения.

### Правила поведения

1. **Вывод типа:** тип элементов выводится из первого элемента литерала. Если все элементы совместимы, тип определяется автоматически.

```axiom
DIM fruits() = {"яблоко", "банан", "вишня"}   ' тип: STRING()
DIM scores() = {10, 20, 30}                    ' тип: INTEGER()
DIM values() = {1.5, 2.5, 3.5}                ' тип: DOUBLE()
```

2. **Явный тип:** можно указать тип явно через `AS`. Если элемент несовместим с указанным типом — ошибка семантики.

```axiom
DIM fruits(1 TO 3) AS STRING = {"яблоко", "банан", "вишня"}
```

3. **Пустой литерал:** `DIM items() = {}` — ошибка семантики, потому что тип элементов неопределён. Для пустого массива использовать `DIM items() AS STRING` + `REDIM`.

4. **Один элемент:** `DIM items() = {"яблоко"}` — допустимо, массив из одного элемента.

5. **Несовместимые типы:** `DIM mixed() = {1, "два", TRUE}` — ошибка семантики, все элементы должны быть совместимого типа.

6. **Границы:** литерал создаёт массив с границами `1 TO N`, где `N` — число элементов.

7. **Динамический массив:** литерал можно использовать с `REDIM`:

```axiom
DIM values() AS INTEGER
REDIM values() = {10, 20, 30}
```

### Что нужно реализовать

- лексер: добавить токены `{` и `}`;
- парсер: добавить разбор литерала массива в выражениях;
- семантика: проверить совместимость типов элементов;
- runtime: создать массив из литерала;
- bytecode: добавить инструкцию `CreateArray` или аналог;
- IDE: подсветка `{` и `}`;
- manual: страница «Литералы массивов»;
- тесты: позитивные и негативные сценарии;

## 2. FOR EACH — обход массива без индекса

### Проблема

Сейчас для обхода элементов массива нужен явный индекс:

```axiom
DIM fruits(1 TO 3) AS STRING
fruits(1) = "яблоко"
fruits(2) = "банан"
fruits(3) = "вишня"

FOR i = LBOUND(fruits) TO UBOUND(fruits)
    PRINT fruits(i)
NEXT
```

Для простого обхода всех элементов это избыточно.

### Предложение

Ввести оператор `FOR EACH`:

```axiom
DIM fruits() = {"яблоко", "банан", "вишня"}

FOR EACH f IN fruits
    PRINT f
NEXT
```

### Правила поведения

1. **Переменная цикла:** `f` получает значение каждого элемента массива по порядку. Тип переменной выводится из типа элементов массива.

2. **Обход:** элементы обходятся от `LBOUND` до `UBOUND` по каждому измерению в стабильном порядке.

3. **Изменение массива:** изменение переменной цикла не влияет на исходный массив. Для изменения элементов использовать индексацию.

4. **Многомерные массивы:** `FOR EACH` обходит все элементы многомерного массива в порядке линейного хранения.

5. **EXIT FOR:** допустим, как и в обычном `FOR`.

6. **CONTINUE FOR:** допустим, как и в обычном `FOR`.

7. **Тип переменной:** переменная цикла не может быть объявлена заранее с несовместимым типом.

### Что нужно реализовать

- лексер: добавить токены `EACH` и `IN`;
- парсер: добавить разбор `FOR EACH`;
- семантика: проверить тип переменной и массива;
- runtime: обход элементов массива;
- bytecode: добавить инструкцию или lowering в `FOR`;
- IDE: подсветка `EACH` и `IN`;
- manual: страница «FOR EACH»;
- тесты: позитивные и негативные сценарии;
- samples: runnable-примеры.

## 3. Строчные литералы — многострочные строки

### Проблема

Сейчас длинные строки приходится конкатенировать:

```axiom
DIM message AS STRING
message = "Длинное сообщение, " & "которое нужно " & "разбивать на части."
```

### Предложение

Ввести многострочные строковые литералы через тройные кавычки:

```axiom
DIM message = """
Длинное сообщение,
которое можно написать
на нескольких строках.
"""
```

### Правила поведения

1. **Начало и конец:** строка начинается и заканчивается тремя кавычками `"""`.

2. **Содержимое:** внутри допускаются любые символы, включая переводы строк.

3. **Экранирование:** обратная кавычка `"` внутри многострочной строки не требуется, если она не тройная.

4. **Пустые строки:** допускаются.

5. **Тип:** результат — `STRING`.

### Что нужно реализовать

- лексер: добавить разбор многострочных строк;
- парсер: нет изменений, литерал обрабатывается в лексере;
- семантика: нет изменений;
- runtime: нет изменений;
- bytecode: нет изменений;
- IDE: подсветка многострочных строк;

## 4. Словари (ассоциативные массивы)

### Проблема

Сейчас для хранения пар «ключ — значение» нужно использовать массивы пар или пользовательские типы. Нет встроенного способа создать словарь.

### Предложение

Ввести тип `DICTIONARY` или `MAP`:

```axiom
DIM ages() = {"Алиса": 25, "Боб": 30, "Вера": 28}
PRINT ages("Алиса")   ' 25
ages("Дима") = 35
```

### Правила поведения

1. **Создание:** словарь создаётся через литерал с парами `ключ: значение`.

2. **Ключи:** ключи должны быть строками или целыми числами.

3. **Значения:** значения могут быть любого типа, но все значения должны быть совместимого типа.

4. **Доступ:** доступ по ключу через круглые скобки `ages("Алиса")`.

5. **Добавление:** новая пара добавляется присваиванием `ages("Дима") = 35`.

6. **Удаление:** через функцию `DICTREMOVE(ages, "Боб")`.

7. **Проверка наличия:** через функцию `DICTCONTAINS(ages, "Алиса")`.

8. **Обход:** через `FOR EACH key IN ages` или `FOR EACH pair IN ages`.

### Что нужно реализовать

- лексер: добавить токен `:` внутри литерала;
- парсер: добавить разбор литерала словаря;
- семантика: проверить типы ключей и значений;
- runtime: реализовать хранение словаря;
- bytecode: добавить инструкции для работы со словарями;
- IDE: подсветка ключей и значений;
- manual: страница «Словари»;
- тесты: позитивные и негативные сценарии;
- samples: runnable-примеры.

## 5. Строковые шаблоны (интерполяция)

### Проблема

Сейчас для вставки значений в строки нужна конкатенация:

```axiom
DIM name AS STRING = "Алиса"
DIM age AS INTEGER = 25
PRINT "Привет, " & name & "! Тебе " & age & " лет."
```

### Предложение

Ввести интерполяцию строк через `${}`:

```axiom
DIM name AS STRING = "Алиса"
DIM age AS INTEGER = 25
PRINT "Привет, ${name}! Тебе ${age} лет."
```

### Правила поведения

1. **Синтаксис:** внутри обычных строк выражение `${...}` заменяется значением.

2. **Выражения:** внутри `${}` допускаются любые выражения: переменные, вызовы функций, арифметика.

3. **Экранирование:** символ `$` без `{` после него остаётся как есть. Для вставки литерального `${` использовать `$$`.

4. **Тип:** результат всегда `STRING`. Значения автоматически преобразуются в строку.

5. **Ошибки:** если выражение внутри `${}` не может быть вычислено — ошибка семантики или выполнения.

### Что нужно реализовать

- лексер: добавить разбор интерполяции внутри строк;
- парсер: нет изменений, интерполяция обрабатывается в лексере;
- семантика: проверить выражения внутри `${}`;
- runtime: вычисление выражений и преобразование в строку;
- bytecode: добавить инструкцию или lowering;
- IDE: подсветка выражений внутри строк;
- manual: обновить страницу строк;
- тесты: позитивные и негативные сценарии;
- samples: runnable-примеры.

## 6. Необязательные параметры в SUB и FUNCTION

### Проблема

Сейчас все параметры функций обязательны. Нет способа определить параметр со значением по умолчанию.

### Предложение

Ввести необязательные параметры с значениями по умолчанию:

```axiom
SUB Greet(name AS STRING, greeting AS STRING = "Привет")
    PRINT greeting & ", " & name & "!"
END SUB

Greet("Алиса")              ' Привет, Алиса!
Greet("Боб", "Здравствуй")  ' Здравствуй, Боб!
```

### Правила поведения

1. **Синтаксис:** параметр с значением по умолчанию записывается как `имя AS ТИП = значение`.

2. **Позиция:** необязательные параметры должны идти после обязательных.

3. **Вызов:** при вызове можно пропустить необязательные параметры, тогда используется значение по умолчанию.

4. **Тип:** значение по умолчанию должно быть совместимо с типом параметра.

5. **Константность:** значение по умолчанию должно быть константным выражением.

### Что нужно реализовать

- парсер: добавить разбор значений по умолчанию в параметрах;
- семантика: проверить типы и константность значений по умолчанию;
- runtime: подстановка значений по умолчанию при вызове;
- bytecode: добавить информацию о значениях по умолчанию в метаданные функции;
- IDE: подсветка значений по умолчанию;
- manual: обновить страницы SUB и FUNCTION;
- тесты: позитивные и негативные сценарии;

## 7. Лямбда-выражения

### Проблема

Сейчас для передачи функции как аргумента (например, в `ARRAYMAP` или `ARRAYFILTER`) нужно определять отдельную функцию через `FUNCTION`.

### Предложение

Ввести анонимные функции (лямбды):

```axiom
DIM scores() = {10, 20, 30, 40, 50}
DIM doubled() = ARRAYMAP(scores, FUNCTION(x) RETURN x * 2 END FUNCTION)
```

Или более компактная форма:

```axiom
DIM doubled() = ARRAYMAP(scores, x => x * 2)
```

### Правила поведения

1. **Синтаксис:** `FUNCTION(параметры) RETURN выражение END FUNCTION` или `параметр => выражение`.

2. **Тип:** тип параметров и результата выводится из контекста.

3. **Замыкание:** лямбда может захватывать переменные из окружающей области.

4. **Ограничения:** лямбда не может содержать операторы, только выражения.

### Что нужно реализовать

- парсер: добавить разбор лямбда-выражений;
- семантика: проверить типы и захват переменных;
- runtime: создание замыкания;
- bytecode: добавить инструкцию для создания лямбды;

## 8. Оператор SELECT для сопоставления с образцом

### Проблема

Сейчас `SELECT CASE` работает только с простыми значениями. Нет способа сопоставлять сложные структуры.

### Предложение

Расширить `SELECT CASE` для поддержки сопоставления с образцом:

```axiom
TYPE Point
    X AS INTEGER
    Y AS INTEGER
END TYPE

DIM p AS Point
p.X = 10
p.Y = 20

SELECT CASE p
    CASE Point(X := 0, Y := 0)
        PRINT "Начало координат"
    CASE Point(X := x, Y := 0)
        PRINT "На оси X: " & x
    CASE Point(X := 0, Y := y)
        PRINT "На оси Y: " & y
    CASE Point(X := x, Y := y)
        PRINT "Точка: " & x & ", " & y
END SELECT
```

### Правила поведения

1. **Синтаксис:** `CASE TypeName(поле := образец, ...)`.

2. **Образцы:** образцами могут быть литералы, переменные или `_` (любое значение).

3. **Захват:** переменные в образцах захватывают значения полей.

4. **Порядок:** проверка идёт сверху вниз, первый совпавший образец побеждает.

### Что нужно реализовать

- парсер: добавить разбор образцов в `CASE`;
- семантика: проверить типы и совместимость образцов;
- runtime: сопоставление с образцом;
- bytecode: добавить инструкции для сопоставления;
- IDE: подсветка образцов;
- manual: обновить страницу SELECT CASE;
- тесты: позитивные и негативные сценарии;

## 9. Модули и пространства имён

### Проблема

Сейчас все функции и переменные живут в одном пространстве имён. В больших программах это может приводить к конфликтам имён.

### Предложение

Ввести модули:

```axiom
MODULE Geometry
    FUNCTION Distance(x1 AS INTEGER, y1 AS INTEGER, x2 AS INTEGER, y2 AS INTEGER) AS DOUBLE
        ' ...
    END FUNCTION
END MODULE

' Использование:
PRINT Geometry.Distance(0, 0, 3, 4)
```

### Правила поведения

1. **Синтаксис:** `MODULE имя ... END MODULE`.

2. **Видимость:** функции и переменные внутри модуля видны только через имя модуля.

3. **Импорт:** `IMPORT Geometry` делает все функции модуля доступными без префикса.

4. **Вложенность:** модули не могут быть вложены друг в друга.

### Что нужно реализовать

- парсер: добавить разбор `MODULE` и `IMPORT`;
- семантика: проверить видимость и доступ к членам модуля;
- runtime: нет изменений;
- bytecode: добавить информацию о модулях в метаданные;
- IDE: навигация по модулям;
- manual: страница «Модули»;

## 10. Обработка событий

### Проблема

Сейчас программа выполняется последовательно. Нет способа реагировать на события (нажатия клавиш, мыши, таймеры) без явного опроса.

### Предложение

Ввести обработчики событий:

```axiom
ON KEY DOWN DO
    PRINT "Клавиша нажата!"
END DO

ON MOUSE CLICK DO
    PRINT "Клик мыши!"
END DO

ON TIMER 1000 DO
    PRINT "Прошла секунда!"
END DO
```

### Правила поведения

1. **Синтаксис:** `ON событие DO ... END DO`.

2. **События:** `KEY DOWN`, `KEY UP`, `MOUSE CLICK`, `MOUSE MOVE`, `TIMER`.

3. **Асинхронность:** обработчики выполняются асинхронно, не прерывая основной поток.

4. **Очередь:** события ставятся в очередь и обрабатываются по порядку.

### Что нужно реализовать

- парсер: добавить разбор `ON ... DO`;
- семантика: проверить типы обработчиков;
- runtime: очередь событий и вызов обработчиков;

## Порядок реализации

Рекомендуемый порядок:

1. **Литералы массивов** — самое востребованное улучшение, упрощает написание программ.
2. **FOR EACH** — естественное дополнение к литералам массивов.
3. **Строковые шаблоны** — упрощает работу со строками.
4. **Многострочные строки** — полезно для длинных текстов.
5. **Необязательные параметры** — упрощает API функций.
6. **Словари** — полезно для структурированных данных.
7. **Лямбда-выражения** — упрощает работу с ARRAY-функциями.
8. **Сопоставление с образцом** — расширяет SELECT CASE.
9. **Модули** — нужно для больших проектов.
10. **Обработка событий** — нужно для интерактивных программ.
