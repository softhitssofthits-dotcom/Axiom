# Гид по ведению документации Axiom

Короткий свод правил, чтобы хаос не вернулся. Подробные требования языка и manual — в `AGENTS.md`, `docs/manual/AUTHORING.md` и `docs/archive/meta-20260826/CLASSIFICATION.md`.

## 1. Одно правило сверху

**Не смешивать будущее, текущее и историческое в одном файле.**

- будущее → `docs/archive/root-documents-20261011/FUTURE.md` или соответствующий `docs/audit/*` (помечено как NOT_IMPLEMENTED);
- текущее → `docs/SPECIFICATION3.md`, `docs/ARCHITECTURE.md`, `docs/archive/root-documents-20261011/LANGUAGE_INVENTORY.md`;
- план → `docs/PLANS4.md`;
- журнал → `docs/WORKLOG5.md`;
- историческое → помечается статусом и уходит в архив, не редактируется.

## 2. Куда что писать

| Задача | Файл |
| --- | --- |
| Изменилось поведение оператора/функции | `docs/SPECIFICATION3.md` + manual-страница + `.axm`-пример + тест |
| Новое архитектурное решение | `docs/ARCHITECTURE.md` |
| Что сделано в сессии | `docs/WORKLOG5.md` (запись в конец, с номером и датой) |
| Что делать дальше | `docs/PLANS4.md` (запись в конец) |
| Новая идея на будущее | `docs/archive/root-documents-20261011/FUTURE.md` (с пометкой «не реализовано») |
| Состав языка изменился | `docs/archive/root-documents-20261011/LANGUAGE_INVENTORY.md` + `docs/BYTECODE_COVERAGE.md` при байткоде |
| Новая подсистема продумана глубоко | `docs/audit/<ПОДСИСТЕМА>.md` |

## 3. Проверка статуса перед использованием любого документа

1. Открыть `docs/archive/meta-20260826/DOC_REGISTRY.md` — найти файл, посмотреть статус.
2. Если «дублирующее» — перейти по ссылке «заменён на».
3. Если «историческое» — не брать оттуда факты о текущем состоянии.
4. Если «планируемое» — не считать реализованным, сверить с кодом.
5. Спорное — сверить с кодом (`src/Axiom.Lexing`, `BuiltinFunctionId`, тесты, samples).

## 4. Шаблоны

Шаблоны новых документов лежат в `docs/meta/templates/`:

- `feature-doc.md` — описание новой возможности языка (когда меняется поведение);
- `audit-subsystem.md` — глубокий аудит подсистемы;
- `plan-entry.md` — запись в `PLANS4.md`;
- `worklog-entry.md` — запись в `WORKLOG5.md`.

Перед созданием нового документа ответить: нельзя ли записать это в уже существующий файл нужной зоны?

## 5. Анти-паттерны (чего не делать)

- Не создавать `future2.md`, `spec4.md`, `plan5.md` вне схемы — сначала спросить, куда идёт запись.
- Не оставлять ранний отчёт аудита рядом с полным: заменённый файл уходит в архив.
- Не дублировать одну истину в двух файлах (пример: `LANGUAGE_INVENTORY.md` и `docs/archive/audits-legacy/LANGUAGE_FEATURE_INVENTORY.md`).
- Не удалять исторические файлы — только архивировать.
- Не писать статус по названию: сверять с кодом.

## 6. Кто и когда обновляет мета-слой

- Реестр `DOC_REGISTRY.md` — при появлении/удалении/переносе `.md`-файлов.
- Карту `FEATURE_LEDGER.md` — при изменении языка.
- План `MIGRATION_PLAN.md` — при переносе файлов.
