# Стоимость точного ARRAYAVERAGE

Session 1125, 2026-10-08. Измерена текущая реализация после исправления потери малого остатка LA26-015. Алгоритм языка в этой сессии не изменён.

## Методика

Использован `scripts/aggregate-perf/Axiom.AggregatePerf.csproj`, конфигурация Release, .NET 10.0.12, Windows 10.0.19045, X64, четыре логических процессора. Выполнены два отдельных последовательных запуска процесса, каждый с тремя прогревами и семью измерениями каждой строки. Все исходные времена и выделения сохранены в `.artifacts/aggregate-perf-1125/measurements.json` и `measurements-repeat.json`.

Общий обработчик вызывается через заранее созданный делегат: создание массива, заполнение и поиск метода исключены из интервала. Для каждого вызова проверяются биты результата: обычный ряд имеет среднее 2; повторяющаяся тройка `1e308`, `-1e308`, `1e-308` имеет среднее `1e-308 / 3`; минимальные субнормальные значения сохраняются; нулевой массив даёт 0. Размеры кратны трём.

Память — сумма выделений текущего потока по `GC.GetAllocatedBytesForCurrentThread`, а не пиковый объём процесса или удерживаемых объектов. Время включает расходы сборки мусора, если она произошла внутри вызова. Прогрев и изменение режима JIT заметно влияют на малые размеры и первый запуск; поэтому ниже приведены обе медианы, без обещания одинакового времени на другой машине.

## Вывод и следующий шаг

Основной источник выделений виден в текущем коде: каждый ненулевой обычный DOUBLE превращается в BigInteger с разрядностью до 2098 бит, затем сдвигается и прибавляется к сумме. Малые целые значения в единицах 2^-1074 тоже занимают большое целое. Для нулей и минимальных субнормальных значений этот расход почти отсутствует.

Следующая оптимизация должна сохранять точное накопление и прежнее однократное округление. Кандидат — группировать знаковые мантиссы по двоичному показателю в ограниченных целочисленных накопителях, затем собирать BigInteger один раз по группам. Перед изменением нужно доказать границы промежуточных сумм, проверить смешанные показатели, сокращение, перестановки, субнормальные и максимальные значения, после чего повторить эту же методику. Возврат к приближённой нормализованной сумме не является приемлемой оптимизацией: он снова потеряет подтверждённый малый остаток.

## Session 1126 — оптимизация с сохранением точности

Накопление заменено группами знаковых мантисс в Int128. Границы и устройство описаны в ARCHITECTURE, Session 1126. BigInteger создаётся после обхода для ненулевых групп. Прежняя формула окончательного округления не менялась. Маленькие массивы используют ленивый словарь вместо полного буфера показателей; нули и минимальные субнормальные числа обходятся без обоих хранилищ.

Новые ArrayAverageExactnessTests сравнивают результат с независимым эталоном: точная рациональная сумма, двоичный поиск соседних конечных DOUBLE и сравнение точных расстояний до них. Проверяются 500 воспроизводимых наборов и их перестановки, смешанные показатели, границы размеров 127/128/129, массивы из 1000 элементов, суммы одной группы шире UInt64, отрицательный ноль и субнормальные половинные случаи. Эталон до изменения прошёл на исходной реализации; после оптимизации проверки тоже проходят. Двоичный поиск и сравнение расстояний не повторяют производственную формулу округления.

Тот же профиль Release сохранён в optimized-1126.json (первый вариант) и optimized-final-1126.json (с отдельным хранилищем малых массивов), рядом с исходными отчётами в .artifacts/aggregate-perf-1125/.
