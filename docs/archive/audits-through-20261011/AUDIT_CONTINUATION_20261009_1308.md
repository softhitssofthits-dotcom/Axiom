# Завершение ограниченного прохода: POW и консольный PRINT

## POW: установленный статус кандидата

NUM26-CAND-001 классифицирован как KNOWN_PLATFORM_PRECISION_LIMIT. В текущей реализации оба движка вызывают Math.Pow. На Windows x64, .NET 10.0.12 значение POW(2,-1075) равно 5E-324, хотя математическое округление точной середины к чётному дало бы ноль. Совпадение движков не доказывает правильное округление. Требование правильно округлять каждую степень в действующей спецификации не найдено; нарушение такого требования не заявляется.

Это известное ограничение реализации, а не исправление численного результата. Более строгий договор точности и замена алгоритма требуют отдельной задачи. В руководстве теперь прямо указана приближённость и приведена граница; исходное расхождение сохранено в EXPONENTIAL_BOUNDARIES_20261009.md. Официальная документация [Math.Pow](https://learn.microsoft.com/en-us/dotnet/api/system.math.pow?view=net-10.0) предупреждает о зависимости результатов от системной библиотеки и архитектуры.

Пример samples/functions/pow/rounding_boundary.axm показывает минимальную степень, середину и уход к нулю. Его проверка не закрепляет 5E-324 как переносимую гарантию: для середины принимаются только ноль или минимальная положительная величина. Основной редакционный ориентир — раздел Зельднера «Возведение в степень», дополнительный жанровый — [оператор возведения в степень Visual Basic](https://learn.microsoft.com/ru-ru/dotnet/visual-basic/language-reference/operators/exponentiation-operator). Историческая подача не переносит неподтверждённую семантику в Axiom.

## CLI26-001: исчезновение границ строк

Реальный запуск нового примера выявил склеивание завершённых строк PRINT. Runtime передаёт в IOutputWriter уже завершённую логическую строку; ConsoleHost ошибочно использовал TextWriter.Write. Теперь используется WriteLine. Пустой PRINT сохраняет пустую строку, завершающий разделитель соединяет последующие части, подсказка INPUT остаётся без автоматического перевода строки. Поведение Runtime и новые языковые токены не добавлены.

До исправления обе новые проверки ConsoleLineBoundaryTests падали. После исправления полный CLI-набор прошёл 30/30. Пять прежних проверок RANDOMIZE ожидали прежнее склеивание; исправлена только граница каждой ожидаемой строки, независимые значения и сравнение двух повторений сохранены. Артефакты находятся в .artifacts/test-results/cli-lines-1308-before и cli-lines-1308-final.

Примеры samples/operators/print/console_line_boundaries.axm и samples/functions/pow/rounding_boundary.axm проверены через реальный axiom run и обоими движками: AuditContinuationSampleTests 4/4, без перехода на интерпретатор. Для PRINT основной редакционный ориентир — Зельднер, раздел «Вывод значений» с пустым PRINT и разделителями; запасной жанровый — [PrintLine Visual Basic](https://learn.microsoft.com/en-us/dotnet/api/microsoft.visualbasic.filesystem.printline?view=net-10.0). Обе страницы руководства синхронизированы.
