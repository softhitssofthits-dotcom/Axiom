# Оборванные ссылки при обходе каталогов

Session 1175 проверяет ссылки с отсутствующей целью. Это отдельные случаи: успешные проверки существующего соединения не доказывают поведение оборванной ссылки.

## Фактические проверки

DanglingDirectoryLinkEvidenceTests содержит шесть запусков в двух движках без перехода Bytecode на интерпретатор:

- Вложенное соединение каталогов в назначении COPYDIR создаётся с настоящей целью; пустая цель удаляется до вызова. COPYDIR выдаёт MB3007, прежняя цель не создаётся заново, ссылка и источник сохраняются.
- Оборванная символическая ссылка на файл в назначении COPYDIR с overwrite TRUE даёт MB3007. Отсутствующий целевой файл не создаётся, источник и сама ссылка сохраняются.
- Оборванная символическая ссылка на файл в источнике пропускается: DIRSIZE возвращает 0, COPYDIR успешен и создаёт пустую копию без ссылки и её цели.

На проверенной Windows File.GetAttributes видит ReparsePoint даже при отсутствующей цели. Дополнительная проба File.Exists для оборванной файловой ссылки вернула TRUE. Поэтому гипотеза о пропуске статической оборванной ссылки через проверку существования здесь не подтвердилась. Не переносить эти результаты автоматически на все файловые системы и виды точек повторного анализа.

Все шесть новых случаев прошли; вместе с DirectoryFailureEvidenceTests и DirectoryTraversalContractTests — 32/32, ошибок и пропусков 0. TRX: `.artifacts/test-results/dangling-1175/dangling-1175.trx`. Ссылки действительно созданы, тесты не заменены обычными папками. Всё размещено в собственных временных каталогах; перед рекурсивным удалением удаляются сами созданные ссылки.

## Граница доказательства: изменяемое дерево

Тесты используют неподвижное дерево во время самого COPYDIR. В BuiltinDirectoryHelpers.cs атрибуты источника проверяются перед помещением пути в стек или File.Copy, а ссылка назначения проверяется перед Directory.CreateDirectory/File.Copy. Между проверкой и использованием есть отдельные операции по строковому пути. Источник не показывает фиксацию всей структуры дерева или проверку каждого объекта через удерживаемый дескриптор.

Поэтому эти тесты не доказывают защиту от другого процесса, который меняет ссылку после проверки. Из чтения кода следует предел гарантий, но конкретный результат гонки в этой сессии не воспроизведён и не зарегистрирован как подтверждённый дефект. Полная изоляция файловой операции не является объявленным договором Axiom; вводить новый пользовательский API или обещать её по этим данным нельзя. Для отдельного исследования гонки нужен воспроизводимый контроль момента подмены и независимая проверка затронутых путей.

Runtime и семантика языка не менялись. Manual уже описывает пропуск вложенных ссылок источника, отказ от вложенных ссылок назначения и отсутствие отката частичного копирования. Новый runnable-пример не требуется: Axiom не имеет функции создания ссылки, а обычный пример без внешней подготовки не воспроизвёл бы этот случай. Реальная подготовка выполняется автоматизированными проверками.
