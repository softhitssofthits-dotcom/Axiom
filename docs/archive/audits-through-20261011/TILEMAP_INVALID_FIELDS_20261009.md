# Неверные поля Tiled и категория отказа — 2026-10-09

## TILE26-002 P2 — ошибочная InfrastructureFailure

До исправления обычные ошибки файла — отсутствующие width/height/layers, отрицательные размеры, нулевой tilewidth, дробный размер и число вне INTEGER — не перехватывались CATCH программы. ProgramRunService возвращал InfrastructureFailure, а не успешное продолжение программы послеMB3005. Это не доказательство падения самого приложения IDE: служба перехватывала исключение с неправильной для пользовательского файла категорией.

Исходный TilemapInvalidInputTests:12 файлов × два режима. Восемь вариантов × два режима дали InfrastructureFailure (16 случаев). Причина — прямые GetProperty/GetInt32/конструкторы моделей и отсутствие ArgumentException/KeyNotFoundException/FormatException в фильтре GraphicsHostService.LoadTilemap. Исходные наблюдения: .artifacts/test-results/tile-invalid-1208/tile-invalid-1208-before.trx и .artifacts/tile-invalid-1208-before.log.

ReadMapInteger теперь явно проверяет наличие поля, JSON-число, диапазон INTEGER и знак. width/height неотрицательны, tilewidth/tileheight положительны. ReadMapArray проверяет наличие и вид layers/tilesets. Причины написаны по-русски. Ожидаемые ошибки вложенных слоёв/тайлсетов дополнительно переводятся графическим загрузчиком в существующий InvalidDataException→MB3005 с сохранением сообщения. Не введён catch всех исключений.

## TILE26-003 P2 — неверный infinite молча принят

Два оставшихся отказа исходного набора относятся к infinite="да": файл успешно принимался и CATCH не исполнялся. ValidateMapRoot проверял только ValueKind.True, не проверяя тип заданного поля. Теперь infinite, если присутствует, обязан быть JSON true/false; неправильный вид даёт LOADTILEMAP: Поле infinite должно быть BOOLEAN. Настоящее infinite=true остаётся явно неподдержанным, отсутствие поля допускается как прежде.

Всего исходный набор6/24 passed,18 failed:16 InfrastructureFailure и2 принятия неверного Boolean. Шесть исходно правильных отказов сохранены при исправлении.
