Два режима счётчика

Неявный счётчик

Имя не объявлено заранее — цикл создаёт счётчик сам:

  • видим только внутри тела цикла;
  • после NEXT недоступен: обращение даёт MB2001;
  • подчиняется блочной области: внутри IF исчезает вместе с блоком;
  • повторное объявление того же имени в теле цикла — MB2002;
  • вложенный неявный FOR i в FOR i — MB2016.
FOR i = 1 TO 3
    PRINT i
NEXT
PRINT i   ' MB2001: имя 'i' не объявлено

Переиспользуемый счётчик

Переменная INTEGER/LONG/DOUBLE с тем же именем уже объявлена — цикл использует её:

  • после нормального завершения хранит значение «на шаг за концом»: FOR i = 1 TO 3 → i = 4;
  • после EXIT FOR хранит значение на момент выхода;
  • доступна и после цикла (паттерн «нужно итоговое значение»);
  • работает и с глобальной переменной из процедуры;
  • регистр имени не важен: FOR I и DIM i — одна переменная.
DIM i AS INTEGER = 0
FOR i = 1 TO 3
    PRINT i
NEXT
PRINT i   ' 4 — значение «на шаг за концом»

Главная ловушка: вложенные циклы с переиспользуемым счётчиком

Внутренний FOR i внутри внешнего FOR i, когда переменная объявлена заранее, молча ломает внешний цикл. Диагностики нет — цикл просто выполняется не так, как ожидалось:

DIM i AS INTEGER = 0
FOR i = 1 TO 3
    FOR i = 1 TO 2        ' переиспользует СЧЁТЧИК ВНЕШНЕГО цикла
        PRINT "in " + STR(i)
    NEXT                  ' после внутреннего цикла i = 3
    PRINT "out " + STR(i) ' печатает 3, а не 1
NEXT                      ' i = 4 — внешний цикл завершился за ОДНУ итерацию
PRINT i

Реальный вывод: in 1 | in 2 | out 3 | 4 — внешний цикл выполнился один раз вместо трёх, без единого предупреждения. Для новичка это самый опасный сценарий из всех.

Предложения по улучшению

ПриоритетУровеньПредложениеПочемуСтатус
P1 Диагностика Ошибка для вложенного переиспользования: внутренний FOR i, переиспользующий счётчик внешнего цикла, — новая диагностика MB2042: «Внутренний цикл FOR переиспользует счётчик внешнего цикла 'i' и сломает его; используйте другое имя». Сейчас поведение тихое и почти наверняка не то, что хотел автор. Это единственный сценарий, где я бы предложил ошибку, а не предупреждение: правильного использования у переиспользования во вложенном цикле нет. Заменено вариантом B (сессия 1115): переиспользование запрещено контрактом, ошибка MB2042 удалена.
P2 Диагностика Предупреждение при переиспользовании существующей переменной (в стиле MB2045/NIT-001): MB2043 «Цикл FOR переиспользует переменную 'i'; после NEXT она сохранит итоговое значение». Режим переиспользования — осознанная фича (паттерн «нужно значение после цикла»), поэтому не ошибка, но новичок часто не ожидает, что его i изменится. Семантика не меняется. Заменено вариантом B (сессия 1115): переиспользование — теперь ошибка MB2016, предупреждение MB2043 удалено.
P2 Документация В docs/manual/for.html — раздел «Значение счётчика после цикла»: итоговое значение «на шаг за концом» при нормальном завершении; значение на момент выхода при EXIT FOR; явный пример-ловушка вложенных циклов. Сейчас документированы два режима, но не сказано, какое именно значение остаётся в переменной и почему вложенные циклы с одним именем опасны. Переписано (сессия 1115): раздел описывает единую модель локального счётчика; строки MB2042/MB2043 удалены из diagnostics.html.
P2 UX Подсказки в существующих кодах: MB2009 — «объявите счётчик через DIM как INTEGER/LONG/DOUBLE»; MB2010 — «для изменяемого счётчика используйте DIM, а не CONST». Диагностики уже точные, не хватает только «что делать дальше». Переписано (сессия 1115): подсказки MB2009/MB2016 объясняют контракт «счётчик FOR всегда локальный».
P3 Дизайн языка Вариант A (рекомендуется): сохранить два режима как есть, добавить P1/P2. Паттерн QuickBASIC «счётчик нужен после цикла» продолжает работать. Ничего не ломает, закрывает главную ловушку. Заменён вариантом B (сессия 1115): два режима счётчика отменены, модель одна.
P3 Дизайн языка Вариант B (не рекомендуется): счётчики всегда локальны для цикла (стиль C#/Python), переиспользование запрещено. Ломает существующие программы и документацию («после цикла i = 4»), лишает паттерна «итоговое значение». Только если команда языка явно захочет современной строгости. Принят и реализован (сессия 1115): счётчик FOR всегда локальный, переиспользование — ошибка MB2016.

Итог

Ядро поведения корректное и предсказуемое: регистронезависимость, контроль типа, запрет констант. Единственный реальный дефект — тихая поломка вложенных циклов при переиспользовании счётчика. В сессии 1114 дефект закрыт диагностиками MB2042/MB2043 (вариант A). В сессии 1115 команда языка приняла вариант B: счётчик FOR всегда локальный, ловушка вложенных циклов исчезает на уровне контракта, а не диагностики. MB2042/MB2043 удалены; переиспользование имени — ошибка MB2016, неподходящий тип — MB2009; корпус сэмплов (617 файлов) и все тестовые проекты мигрированы; ментальная модель совпадает с C#/Python/JS.
