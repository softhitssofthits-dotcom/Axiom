# План переноса CANVAS на GPU

Выбранные автором решения: GPU-рисование только CANVAS; отдельное нативное окно DirectX; Electron остаётся IDE. Источник требований: `docs/superpowers/specs/2026-10-13-gpu-canvas-design.md`. Автор подтвердил начало реализации; работа и приёмка выполняются по этому плану.

## 1. Зафиксировать границы и исходные показатели

- [x] Составить реестр поддерживаемых CANVAS-команд, преобразований координат, читающих операций и правил кадра по `IGraphicsHost`, `GraphicsHostService`, VM, manual и тестам. Договор и передача GET/PUT проверены; сведения записаны в `docs/reports/graphics/CANVAS_GPU_MIGRATION.md`.
- [x] Проверить существующие графические сценарии и список Electron-тестов, завязанных на `canvas.html`; подготовить соответствующие нативные ожидания без потери покрытия.
- [x] Измерить текущий вывод одной сцены со спрайтами и одной сцены с тайловой картой, камерой и текстом. Использовать реальные окна; не заменять графический замер тестом VM без вывода. Исходные показатели и условия сохранены в отчёте.

## 2. Отделить игровой холст и выбор устройства

- [x] Выделить реализацию CANVAS за существующим `IGraphicsHost`; SCREEN и его старые примитивы не переводить.
- [x] Добавить создание аппаратного устройства, проверку возможностей и программный запасной путь. Закрепить тесты управляемого отказа и освобождения ресурсов.
- [x] Определить владельца графического контекста и очереди команд так, чтобы обработчики окна не выполняли тяжёлую работу.

## 3. Перевести нативное окно и границу кадра

- [x] Реализовать целевые GPU-поверхности, прежнюю очистку BEGINFRAME, запрет показа незавершённого кадра и публикацию PRESENT.
- [x] Включить нативный CANVAS в DesktopHost и исключить обычную пересылку полного пиксельного кадра в Electron для этого пути.
- [x] Сохранить ввод, фокус, координаты мыши, закрытие, остановку, отказ процесса и повторный запуск; перенести соответствующие E2E-проверки на нативное окно.

## 4. Перенести операции рисования

- [x] Добавить постоянные текстуры изображений/спрайтов, исходные области, масштабирование и прозрачность с независимыми цветовыми ожиданиями.
- [x] Перенести тайлы и тайловые слои, сохранив порядок, преобразования, камеру и область вывода; группировать только совместимые последовательные команды.
- [x] Перенести прямоугольники, линии, окружности и заливки; сравнить выходные пиксели с действующей реализацией и явно разобрать расхождения.
- [x] Перенести композицию текста с кешированием подготовленных глифов и сохранением подтверждённого договора шрифта/цветов.
- [x] Сохранить SMOOTH как фильтр готового кадра, проверив ON/OFF и отсутствие изменений логических пикселей.

## 5. Закрыть совместимость и особые операции

- [x] Реализовать необходимые чтения пикселей с упорядочиванием команд и ограниченными передачами GPU → CPU; обычный кадр не должен возвращаться в полный CPU-буфер.
- [x] Проверить допустимые для CANVAS особые формы и запасной путь, не расширяя молча договор языка.
- [x] Проверить большие координаты, границы, размеры ресурсов, прозрачность и ресурсы нескольких последовательных запусков.

## 6. Приёмка и завершение

- [x] Повторить исходные графические измерения и показать подтверждённые изменения без заранее обещанного FPS.
- [x] Выполнить существующие игры, включая Maze Chase, в Electron с нативным CANVAS; проверить реальный ввод и закрытие.

- [x] После реализации и проверок повысить только затронутые версии, выполнить versioning check/check --base HEAD и git diff --check, записать итог и точку продолжения в WORKLOG.

## Отдельно от этого переноса

Оптимизацию смены Classic/Modern для больших листингов автор отложил. Сейчас её не реализовывать. Будущий разбор должен измерить работу форматтера, нормализацию идентификаторов, передачу документа и применение изменений Monaco, сохраняя строки, комментарии и текущую защиту от устаревших ответов.

## Завершение переноса — 13 октября 2026 года

GPU-CANVAS реализован в DesktopHost: аппаратное устройство DirectX, резерв WARP, нативное окно и прямой показ опубликованной GPU-поверхности. SCREEN сохраняет прежнее CPU-рисование. Проверки: графический .NET-набор 41/41, Runtime 50/50, полный Electron-набор 121/121 с 773 утверждениями; после окончательной сборки повторены четыре GPU-сценария с 17 утверждениями. Итоговый отчёт — docs/reports/graphics/CANVAS_GPU_MIGRATION.md, ручной пример — samples/operators/canvas/native_game_frame.axm. Версии после приёмки: язык и компилятор 0.1.12, IDE 0.3.0. Оптимизация оформления больших листингов остаётся отложенной. Следующий шаг — авторская проверка примера и Maze Chase на обычном запуске IDE; независимый компьютер и физическое отключение GPU ещё не проверялись.
