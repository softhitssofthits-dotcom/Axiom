# Перенос рисования SCREEN на DirectX

Цель: после опубликованного f778e61 хранить страницы SCREEN и выполнять рисование/составление кадра на Direct3D 11, сохранив наблюдаемую семантику языка.

Архитектура: расширить существующие CanvasGpuSurface/CanvasRenderSession поддержкой экранных страниц в отдельных частях классов. Использовать один графический контекст и очередь команд; рабочие страницы содержат пары цвет/индекс, опубликованная текстура — видимую страницу с общим текстовым слоем. Смена палитры выполняет GPU-пересчёт индексных цветов без чтения кадров на CPU. Страницы создаются по необходимости.

Договор: SCREEN 0 остаётся текстовым режимом; SCREEN 1..10 автоматически публикуют изменения, не требуют PRESENT. Сохраняются страницы, PCOPY вместе с палитрой, независимый текст, STEP, VIEW/WINDOW/PMAP и индексный POINT. Явные POINT/GET/PUT читают необходимые данные; PAINT работает с временной копией области. Сложная геометрия дуг может готовиться на CPU и передаваться одним набором точек; обычные линии/заливки/окружности используют шейдеры. Обычная публикация не читает полный кадр обратно.

Работа выполняется последовательно в текущей рабочей копии. Автор разрешил реализацию; дополнительное согласование этого договора не требуется.

- [x] Подключить SCREEN к очереди команд и существующему нативному окну, исправить переходы между поверхностями и обработку ошибок.
- [x] Подключить точки, линии/B/BF, окружности/дуги, изображения/спрайты, VIEW, CLS, палитру и страницы в GraphicsHostService.
