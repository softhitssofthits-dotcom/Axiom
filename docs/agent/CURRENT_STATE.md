# Текущее состояние

## Проект

`Axiom IDE` — собственный BASIC-подобный язык, интерпретатор, `BytecodeVm`, WPF-IDE и крупный документный контур разработки.

## Стабильная база

- Ядро языка, интерпретатор, `BytecodeVm`, пайплайн выполнения и WPF-оболочка IDE уже работают.
- Активные источники правды проекта: `PROJECT.md`, `docs/SPECIFICATION3.md`, `docs/ARCHITECTURE.md`, `docs/PLANS3.md`, `docs/WORKLOG4.md`.
- Пользовательский manual живёт в `docs/manual/`.
- Для новых наблюдаемых изменений языка обязательны автотесты, runnable `.axm`-пример, обновление manual и запись в активные реестры.

## Где работа остановилась

Последний зафиксированный технический шаг:
- для второго современного графического среза закрыт runnable negative-parity;
- добавлены отдельные отрицательные sample для `CANVAS`-сценариев;
- в `docs/BYTECODE_COVERAGE.md` современная графика по этой линии доведена до `Негативный паритет: да`.

Последний зафиксированный процессный шаг:
- в `AGENTS.md` закреплён более строгий компактный агентный режим;
- локальный `docs/agent/`-слой признан основным вспомогательным контуром экономии токенов внутри репозитория;
- внешний инструмент не должен становиться вторым источником правды рядом с `docs/PLANS3.md` и `docs/WORKLOG4.md`.

## Следующий продуктовый шаг

Следующий официальный технический шаг из активного плана:
- взять следующую строку `Негативный паритет: частично`, где уже есть runtime/VM-покрытие, но ещё не хватает отдельного runnable negative sample;
- если короткий parity-хвост без новой семантики не найдётся, переключаться на новую benchmark-семью вне графики.

## Следующий процессный шаг

- использовать `scripts/ai-context.ps1` и `docs/agent/` как первый локальный слой повторного входа;
- держать `CURRENT_STATE.md`, `ARCHITECTURE_MAP.md` и `PLAYBOOKS.md` короткими и синхронными с активными документами;
- не переносить управление задачами во внешний task-manager как в основной журнал проекта.

## Что особенно важно не сломать

- Интерпретаторная архитектура остаётся базовой.
- Стек остаётся на C# / .NET.
- Слои lexer / syntax / parser / semantics / runtime / IDE не смешиваются.
- `docs/PLANS3.md` и `docs/WORKLOG4.md` остаются единственными активными проектными журналами плана и непрерывности.
- Вспомогательные агентные документы не должны расходиться с каноническими документами.

## Что читать первым делом

- `docs/PLANS3.md` — активный следующий шаг.
- `docs/WORKLOG4.md` — последняя завершённая работа.
- `docs/SPECIFICATION3.md` — точный договор поведения.
- `docs/ARCHITECTURE.md` — границы слоёв и технические решения.
- `docs/BYTECODE_COVERAGE.md` и `docs/BYTECODE_PERF_MATRIX.md` — если задача касается `BytecodeVm`, паритета или производительности.
- `scripts/ai-context.ps1` — если нужен короткий бриф или тематические фрагменты вместо повторного чтения всего массива документов.
