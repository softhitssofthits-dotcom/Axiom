# Спецификация Axiom

`docs/SPECIFICATION.md` закрыт как историческая первая часть спецификации. Активная спецификация ведётся в `docs/SPECIFICATION3.md`.


## Обновление IDE 2026-04-15: сохранение состояния окна и обновление поиска/замены

Дополнительно к разделу IDE для текущей оболочки зафиксированы правила:
- IDE сохраняет состояние окна между запусками: `WindowState` (`Normal` / `Maximized` / `Minimized`), видимость `View -> File Manager` и видимость `View -> Status Bar`.
- При следующем старте IDE восстанавливает сохранённые значения состояния окна вместо возврата к значениям по умолчанию.
- `View -> Status Bar` управляет показом нижней строки состояния; скрытие этой полосы влияет только на оформление оболочки и не отключает сами данные состояния (`Ready`, `Run succeeded`, `Ln / Col`, путь активного документа).
- Поиск больше не зависит от встроенной панели `AvalonEdit SearchPanel`: используется отдельное окно `Find/Replace` с сохранением текущих опций.
- Новое окно поддерживает уже используемые флаги поиска (`Match case`, `Whole words`, `Regex`, направление `Up/Down`) и операции `Find`, `Replace`, `Replace and Find`, `Replace All`.
- Поле слева от редактора должно быть визуально чистым: декоративные пунктирные вертикальные линии не отображаются.

## Обновление IDE 2026-04-15: файловая панель, редактируемые файлы и блокировка exe

Дополнительно к текущей оболочке зафиксированы правила:
- пункт меню `View -> File Manager` управляет левой файловой панелью (вместо старого `View -> Files Pane`);
- левая панель работает как мини файловый менеджер: корневые узлы — диски, папки раскрываются/сворачиваются через дерево, загрузка дочерних узлов выполняется лениво;
- дерево использует `+/-` индикатор раскрытия (вместо треугольника), иконку папки для каталогов и иконку файла для файлов;
- в заголовке `File Manager` есть отдельная кнопка закрытия (`X`), которая скрывает панель напрямую;
- кнопка `Refresh` в панели файлов отсутствует;
- файл из дерева открывается по клику;
- файлы, открываемые через `File Manager`, по умолчанию загружаются как редактируемые документы (включая `.axm`, `.txt`, `.md`, `.json`, `.css` и другие текстовые форматы);
- `.exe` не открываются в редакторе и блокируются в File Manager.

## Обновление IDE 2026-04-15: контекстное меню файловой панели, скрытые файлы и выделение

Дополнительно к текущей оболочке зафиксированы правила:
- у узлов `File Manager` есть контекстное меню по правой кнопке мыши;
- правый клик сначала выбирает узел в дереве, а уже потом открывает контекстное меню, без случайного открытия файла в редакторе;
- активный узел дерева подсвечивается контрастным инверсным цветом, чтобы выбранные файл/папка читались заметно;
- контекстное меню поддерживает рабочие действия: `Открыть в Axiom IDE` / `Перейти в`, `Открыть во внешнем приложении по умолчанию`, `Показать скрытые файлы`, `Свойства`;
- переключатель `Показать скрытые файлы` раскрывает скрытые файлы и скрытые папки в текущем дереве, но не снимает фильтрацию системных элементов;
- пункты `Новый файл...`, `Новый каталог...`, `Переименовать` открывают диалог ввода имени;
- `Вырезать` + `Вставить` выполняют перенос выбранного файла/каталога, а `Скопировать` + `Вставить` создают копию в выбранной папке или в родительской папке выбранного файла;
- пункт `Удалить` всегда просит подтверждение `Да / Нет` перед удалением и логически означает отправку выбранного файла/каталога в Корзину;
- при удалении файла или каталога, для которых уже открыты документы в редакторе, оболочка сначала закрывает затронутые вкладки через стандартный порядок `Save / Discard / Cancel`, а уже потом отправляет элементы в Корзину.
- любые действия создания, переименования, вырезания, копирования, вставки и удаления не должны схлопывать дерево `File Manager`: после обновления сохраняются раскрытые ветки и текущий рабочий контекст пользователя.

## Обновление IDE 2026-04-15: закрытие вкладок нижней панели и поведение разметки

Дополнительно к текущей оболочке зафиксированы правила:
- `View -> Output` и `View -> Diagnostics` работают как пункты с галочкой, напрямую управляющие видимостью соответствующих вкладок нижней панели;
- в заголовках вкладок `Output` и `Diagnostics` есть кнопки закрытия `X` для ручного скрытия панелей без захода в меню;
- при успешном `Run` вкладка `Output` должна автоматически открываться, даже если была скрыта вручную;
- при запуске с любой диагностикой вкладка `Diagnostics` должна автоматически открываться, даже если была скрыта вручную;
- если обе вкладки нижней панели скрыты, нижняя панель и её разделитель полностью схлопываются без пустой полосы в разметке;
- высота нижней панели регулируется вертикальным разделителем;
- в дереве `File Manager` вертикальная и горизонтальная прокрутка работают через режим `Auto`;
- во время активного `INPUT` панель `Output` не скрывается, чтобы не терять inline-ввод.

## 1. Назначение

Язык предназначен для:
- обучения;
- написания небольших программ;
- запуска из собственной IDE;
- постепенного развития в более крупный BASIC-подобный язык.

Текущий договор языка ориентирован на:
- простой синтаксис;
- понятные ошибки;
- интерпретируемое выполнение;
- лёгкую реализацию на C#.

## 2. Текущий договор языка

Текущая реализация поддерживает:
- переменные и константы;
- числа, строки, логические значения;
- арифметику и сравнения;
- `IF / ELSEIF / ELSE / END IF`;
- `FOR / NEXT / EXIT FOR`;
- `SELECT CASE / END SELECT`;
- `DO WHILE / LOOP`;
- `WHILE / END WHILE`;
- `PRINT`;
- `INPUT`;
- `SUB` и `FUNCTION`;
- `TYPE ... END TYPE`;
- одномерные массивы;
- базовые встроенные функции.

## 3. Неподдерживаемые или отдельно проектируемые возможности

Не поддерживается:
- указатели;
- графические команды;
- файловая система;
- модули из нескольких файлов;
- пользовательские классы/объекты;
- `BYREF`;
- перегрузка функций;
- неявное объявление переменных;
- однострочный `IF THEN PRINT ...`;
- несколько инструкций в одной строке через `:`;
- суффиксы типов вроде `A$`, `X%`, `N!`.

## 4. Общие правила

### 4.1 Регистр
Язык регистронезависимый.

### 4.2 Кодировка
Исходные файлы: UTF-8.

### 4.3 Расширение файла
Рекомендуемое расширение: `.axm`.

### 4.4 Разделитель инструкций
Одна строка = одна инструкция.

### 4.5 Комментарии
Поддерживаются:
- `' комментарий`
- `REM комментарий`

Только однострочные.

## 5. Лексика

### 5.1 Идентификаторы
Идентификатор:
- начинается с буквы или `_`;
- затем может содержать буквы, цифры и `_`.

Дополнительное правило базовой модели:
- Axiom не вводит собственного отдельного числового лимита на длину идентификатора сверх ограничений реализации на платформе .NET/C#;
- практический предел длины имени определяется возможностями underlying implementation, а не отдельным языковым cap внутри Axiom.

### 5.3 Литералы
Поддерживаются:
- целые числа;
- шестнадцатеричные целочисленные литералы в форме `&H...`;
- числа с плавающей точкой;
- строки в двойных кавычках;
- логические литералы `TRUE` и `FALSE`.

Числовые литералы не допускают ведущие нули в целой части, кроме самого литерала `0` и форм вида `0.xxx`.
Примеры допустимых форм:
- `0`
- `123`
- `&HFF`
- `&h80000000`
- `0.5`
- `10.25`

Примеры недопустимых форм:
- `00`
- `001`
- `00.5`
- `01.25`
- `&H`

Числовые диапазоны:
- целочисленный литерал, помещающийся в диапазон `INTEGER`, получает тип `INTEGER`;
- целочисленный литерал, выходящий за диапазон `INTEGER`, но помещающийся в диапазон `LONG`, получает тип `LONG`;
- шестнадцатеричный литерал `&H...` оценивается как неотрицательное целое число и получает тип `INTEGER` или `LONG` по тому же правилу;
- форма `&H` без хотя бы одной шестнадцатеричной цифры является syntax diagnostic `MB0003`;
- целочисленный литерал, выходящий за диапазон `LONG`, является syntax diagnostic `MB0004`;
- вещественный литерал, выходящий за диапазон конечных значений `DOUBLE`, является syntax diagnostic `MB0004`.

Кавычка внутри строки задаётся удвоением: `""`.

## 6. Типы данных

Поддерживаются 6 базовых скалярных типов:
- `INTEGER` — знаковое 32-битное целое;
- `LONG` — знаковое 64-битное целое;
- `DOUBLE` — 64-битное число с плавающей точкой;
- `DECIMAL` — точное десятичное число для денежных и других расчётов без бинарной погрешности `DOUBLE`;
- `STRING` — строка Unicode;
- `BOOLEAN` — логический тип.

Дополнительно поддерживаются:
- специальный тип `FILE` для открытых текстовых файлов;
- пользовательские типы записей, объявленные через `TYPE ... END TYPE`.

### 6.1 Дополнение по типу FILE

Наряду с числовыми, строковым и логическим типами в языке используется специальный тип `FILE`.

Правила для `FILE`:
- переменная `FILE` хранит состояние открытого текстового файла;
- значение этого типа создаётся оператором `OPEN` и освобождается оператором `CLOSE`;
- прямое присваивание значений типа `FILE` не допускается;
- работа с открытым файлом выполняется через `FILEPOS`, `FILELENGTH`, `LINENUMBER`, `EOF`, `READLINE`, `READLINES`, `SKIPLINE`, `READTEXT`, `READTOEND`, `WRITE`, `WRITELINE`, `NEWLINE`, `SEEKFILE`, `REWIND`.

### 6.2 Пользовательские типы записей TYPE

Форма:
- `TYPE Name`
- `    fieldName AS TYPE`
- `END TYPE`

Правила:
- `TYPE ... END TYPE` объявляется на верхнем уровне программы;
- внутри `TYPE` поддерживаются поля в форме `fieldName AS fieldType`, динамические массивные поля в форме `fieldName() AS fieldType` и фиксированные массивные поля в форме `fieldName(lower TO upper) AS fieldType`;
- имя пользовательского типа можно использовать после `AS` в `DIM`, параметрах `SUB`/`FUNCTION` и типе результата `FUNCTION`;
- пользовательский тип можно использовать как тип элемента одномерного массива, например `DIM people(1 TO 10) AS Person`;
- доступ к полю записывается через точку: `record.field`;
- доступ к полю элемента массива записывается после индексирования: `people(i).Name`;
- вложенные пользовательские типы разрешены, например `person.address.city`;
- значения полей по умолчанию совпадают со значениями по умолчанию их типов;
- присваивание записи целиком создаёт независимую копию значения;
- присваивание записи в элемент массива целиком тоже сохраняет копию значения, поэтому последующее изменение исходной переменной не меняет уже записанный элемент;
- фиксированное массивное поле получает выделенный диапазон сразу при создании записи и хранит значения по умолчанию для элементов;
- границы фиксированного массивного поля внутри `TYPE` должны быть целочисленными константами; специальная пустая форма `1 TO 0` допустима;
- `REDIM`, `REDIM PRESERVE` и `ERASE` применяются только к динамическому массивному полю внутри `TYPE`; для фиксированного поля диапазон остаётся частью объявления;
- присваивание записи целиком копирует и фиксированное массивное поле вместе с записью, тогда как динамическое массивное поле внутри записи сохраняет ссылочную семантику самого массива;
- `FILE`, функциональные типы, методы, константы, уровни доступа и инициализаторы полей внутри `TYPE` не поддерживаются;
- прямые и косвенные циклы вложенности пользовательских типов не поддерживаются.

Диагностика:
- неизвестный тип после `AS` даёт `MB2021`;
- неподдерживаемое поле или циклическая вложенность пользовательских типов даёт `MB2022`;
- обращение к отсутствующему полю даёт `MB2023`;
- доступ через точку к значению не пользовательского типа даёт `MB2024`.
- `REDIM` или `ERASE` для фиксированного массивного поля записи даёт `MB2025`.

## 7. Объявления

### 7.1 Переменные
Форма:
- `DIM name AS TYPE`
- `DIM name AS TYPE = expression`
- `DIM name = expression`
- `DIM name1 AS TYPE1, name2 AS TYPE2`
- `DIM name1, name2 AS TYPE`
- `DIM name1, name2 = expression`
- `DIM name1, name2 AS TYPE, name3 AS OTHER_TYPE`

Все переменные должны быть объявлены до использования.

Правила:
- `AS TYPE` относится ко всей ближайшей группе имён слева до начала оператора `DIM` или до предыдущего разделителя групп;
- в форме `DIM anotherVar, choice AS BOOLEAN` обе переменные `anotherVar` и `choice` имеют тип `BOOLEAN`;
- в форме `DIM anotherVar, choice AS BOOLEAN, birthDate AS STRING` переменные `anotherVar` и `choice` имеют тип `BOOLEAN`, а `birthDate` имеет тип `STRING`;
- тип может быть указан явно через `AS TYPE` или выведен из `= expression`;
- в форме `DIM count = 10` тип `count` выводится как `INTEGER`;
- в форме `DIM bigCount = 21474836479` тип `bigCount` выводится как `LONG`;
- в форме `DIM name = "Alice"` тип `name` выводится как `STRING`;
- в форме `DIM ready = TRUE` тип `ready` выводится как `BOOLEAN`;
- в форме `DIM price = 1.5` тип `price` выводится как `DOUBLE`;
- в форме `DIM price AS DECIMAL = 1.5` значение инициализатора константно приводится к `DECIMAL`, но без `AS DECIMAL` литерал с точкой по-прежнему считается `DOUBLE`;
- в форме `DIM left, right = 7` обе переменные получают тип `INTEGER`;
- в одном операторе `DIM` можно смешивать группы с явным типом и группы с выводом типа, например `DIM count = 10, name = "Alice", ready = TRUE, price = 1.5`;
- если у группы нет ни `AS TYPE`, ни `= expression`, это semantic error;
- если у группы после `AS TYPE` стоит `= expression`, это начальное значение применяется ко всем переменным этой группы;
- если у группы нет `AS TYPE`, но есть `= expression`, это начальное значение используется и для вывода типа, и как начальное значение всех переменных этой группы;
- группировать можно и массивы, например `DIM left(1 TO 3), right(1 TO 3) AS INTEGER`;
- для будущего динамического массива без немедленного выделения памяти допускается форма `DIM items() AS STRING`;
- форма `DIM items() AS STRING` объявляет одномерный массив без выделенного диапазона элементов;
- до отдельного этапа `REDIM` такой массив нельзя индексировать и использовать как уже выделенный набор значений.

### 7.2 Константы
Форма:
- `CONST name AS TYPE = expression`

После объявления константа не может быть изменена.

## 8. Присваивание

Форма:
- `name = expression`

Левая часть должна быть изменяемой переменной или элементом массива.

## 9. Выражения

### 9.1 Арифметика
Поддерживаются:
- `+`
- `-`
- `*`
- `^`
- `/`
- `\`
- `MOD`

Оператор `/` возвращает:
- `DECIMAL`, если хотя бы один операнд имеет тип `DECIMAL` и ни один операнд не имеет тип `DOUBLE`;
- `DOUBLE` во всех остальных случаях.

Оператор `^` возводит левый операнд в степень правого. Он принимает любые числовые операнды, всегда возвращает `DOUBLE` и связывается справа налево.

### 9.2 Сравнения
Поддерживаются:
- `=`
- `<>`
- `<`
- `<=`
- `>`
- `>=`

Результат — `BOOLEAN`.

Правила:
- числа поддерживают все операторы сравнения;
- строки поддерживают `=`, `<>`, `<`, `<=`, `>`, `>=`;
- строковые сравнения выполняются ordinal-способом, то есть по кодам символов без учёта локали;
- `BOOLEAN` поддерживает только `=` и `<>`;
- упорядоченные сравнения `BOOLEAN` через `<`, `<=`, `>`, `>=` недопустимы.

### 9.3 Логические и побитовые операторы
Поддерживаются:
- `NOT`
- `AND`
- `OR`
- `XOR`
- `EQV`
- `IMP`

Правила:
- `NOT`, `AND`, `OR`, `XOR`, `EQV`, `IMP` работают с `BOOLEAN`;
- `NOT`, `AND`, `OR`, `XOR`, `EQV`, `IMP` также работают как побитовые операторы для `INTEGER` и `LONG`;
- при побитовых `AND`, `OR`, `XOR`, `EQV`, `IMP` оба операнда должны быть целочисленными;
- если хотя бы один целочисленный операнд имеет тип `LONG`, результат побитовой операции тоже имеет тип `LONG`.
- `EQV` для `BOOLEAN` возвращает `TRUE`, если оба операнда одинаковы; для целых чисел вычисляет побитовое отрицание результата `XOR`.
- `IMP` для `BOOLEAN` возвращает `FALSE` только в случае `TRUE IMP FALSE`; для целых чисел вычисляется как побитовое `NOT` от левого операнда, затем побитовое `OR` с правым операндом.

### 9.4 Сдвиги
Поддерживаются:
- `<<`
- `>>`

Правила:
- сдвиги принимают только `INTEGER` и `LONG`;
- результат сдвига всегда имеет тип левого операнда;
- правый операнд задаёт количество битов для сдвига.

### 9.5 Конкатенация строк
Для объединения строк используется `+`.

## 11. Управляющие конструкции

### 11.1 IF
Формы:

```basic
IF condition THEN
    statements
END IF
```

```basic
IF condition THEN
    statements
ELSEIF otherCondition THEN
    statements
END IF
```

```basic
IF condition THEN
    statements
ELSEIF otherCondition THEN
    statements
ELSE
    statements
END IF
```

Правила:
- `ELSEIF` может повторяться несколько раз;
- `ELSEIF` является частью одного и того же блока `IF`, а не отдельным вложенным `IF`;
- вложенные `IF` при этом тоже разрешены обычным образом внутри любого блока `statements`;
- однострочный `IF` в v0.1 не поддерживается.

### 11.2 FOR
Формы:

```basic
FOR variable = startExpr TO endExpr
    statements
NEXT
```

```basic
FOR variable = startExpr TO endExpr STEP stepExpr
    statements
NEXT
```

```basic
FOR variable = startExpr TO endExpr
    IF condition THEN
        EXIT FOR
    END IF

    statements
NEXT
```

Правила:
- переменная цикла объявляется самой строкой `FOR` и принадлежит области видимости данного цикла;
- тип: `INTEGER`, `LONG` или `DOUBLE`;
- `DECIMAL` в управляющей переменной `FOR` в текущей базовой модели не поддерживается;
- `STEP`, если не указан, равен `1`;
- `STEP 0` — ошибка времени выполнения;
- `EXIT FOR` завершает ближайший окружающий блок `FOR ... NEXT`;
- `EXIT FOR` допустим только внутри `FOR ... NEXT`;
- циклы можно свободно вкладывать друг в друга, в том числе `FOR` в `FOR`, `FOR` в `WHILE` и `WHILE` в `FOR`;
- имя управляющей переменной доступно внутри заголовка и тела данного `FOR`, но недоступно после соответствующего `NEXT`;
- отдельный `DIM` для управляющей переменной не требуется;
- управляющая переменная не может повторно объявлять или затенять имя из окружающей области видимости уровня файла, области видимости процедуры или функции либо внешней области видимости блока.

### 11.3 WHILE
Форма:

```basic
WHILE condition
    statements
END WHILE
```

Вложенные циклы разрешены обычным образом. Если внутри `WHILE` находится вложенный `FOR`, то `EXIT FOR` относится именно к этому ближайшему `FOR`, а не к самому `WHILE`.

### 11.4 SELECT CASE
Поддерживается QuickBASIC-подобный блочный оператор:

```basic
SELECT CASE testExpression
    CASE 1
        PRINT "one"
    CASE 2, 3
        PRINT "small"
    CASE 10 TO 20
        PRINT "range"
    CASE IS > 100
        PRINT "big"
    CASE ELSE
        PRINT "other"
END SELECT
```

Правила:
- `testExpression` вычисляется один раз перед проверкой веток;
- ветки `CASE` проверяются сверху вниз;
- выполняется только первая подошедшая ветка;
- после выполнения выбранной ветки управление переходит сразу за `END SELECT`;
- `CASE value` задаёт точное совпадение значения;
- `CASE value1, value2, value3` задаёт список точных совпадений;
- `CASE low TO high` задаёт включительный диапазон;
- `CASE IS > expr`, `CASE IS >= expr`, `CASE IS < expr`, `CASE IS <= expr`, `CASE IS = expr`, `CASE IS <> expr` задают сравнение через `IS`;
- в одном `CASE` можно смешивать точные значения, диапазоны и `IS`-сравнения через запятую;
- `CASE ELSE` выполняется, если ни одна предыдущая ветка не подошла;
- внутри `SELECT CASE` разрешены вложенные `IF`, `FOR`, `WHILE`, `DO ... LOOP` и другой `SELECT CASE`.

Семантические ограничения текущей базовой модели:
- точные совпадения и `CASE IS =` / `CASE IS <>` поддерживаются для чисел, строк и `BOOLEAN` при совместимых типах;
- диапазоны `CASE ... TO ...` и упорядоченные сравнения `CASE IS <`, `<=`, `>`, `>=` допустимы для чисел и строк;
- для строк используется тот же ordinal-порядок, что и в обычных строковых сравнениях;
- `BOOLEAN` не поддерживает порядковые сравнения и не может использоваться в `CASE ... TO`.

### 11.5 DO ... LOOP
Базовая модель семейства `DO ... LOOP` в v0.1.12 поддерживает все основные формы:

```basic
DO WHILE condition
    statements
LOOP
```

```basic
DO UNTIL condition
    statements
LOOP
```

```basic
DO
    statements
LOOP WHILE condition
```

```basic
DO
    statements
LOOP UNTIL condition
```

```basic
DO
    statements
LOOP
```

Правила:
- `DO WHILE ... LOOP` проверяет условие перед каждой новой итерацией и не выполняет тело ни разу, если условие сразу ложно;
- `DO UNTIL ... LOOP` проверяет условие перед каждой новой итерацией и не выполняет тело ни разу, если условие сразу истинно;
- `DO ... LOOP WHILE condition` всегда выполняет тело хотя бы один раз и продолжает цикл, пока условие истинно;
- `DO ... LOOP UNTIL condition` всегда выполняет тело хотя бы один раз и продолжает цикл, пока условие ложно;
- `DO ... LOOP` без условия является бесконечным циклом и обычно завершается через `EXIT DO` или `RETURN`;
- любые формы `DO ... LOOP` можно свободно вкладывать в `FOR`, `WHILE` и другой `DO ... LOOP`;
- `EXIT DO` завершает ближайший окружающий блок `DO ... LOOP`;
- `EXIT DO` допустим только внутри `DO ... LOOP`;
- внутри `DO ... LOOP` команда `EXIT FOR` по-прежнему относится только к ближайшему окружающему `FOR`, если такой есть;
- в одной конструкции `DO ... LOOP` можно указать условие либо после `DO`, либо после `LOOP`, но не с двух сторон сразу.

## 12. Ввод и вывод

Текущая базовая модель уточняет поведение `PRINT` и `INPUT` в QuickBASIC-подобную сторону, включая форматированный вывод `PRINT USING`, но без построения полноценной консольной оболочки.

### 12.1 PRINT
Поддерживаются формы:
- `PRINT`
- `PRINT expression`
- `PRINT expression;`
- `PRINT expression,`
- `PRINT expression; expression`
- `PRINT expression, expression`
- `PRINT USING formatExpression; expression`
- `PRINT USING formatExpression; expression;`
- `PRINT USING formatExpression; expression,`
- смешанные списки вывода с `;` и `,`

Упрощённая грамматика:
- `PRINT [ printList | printUsingClause ]`
- `printList := expression { printSeparator expression } [ printSeparator ]`
- `printUsingClause := "USING" expression ";" [ printList ]`
- `printSeparator := ";" | ","`

Правила:
- пустой `PRINT` выводит перевод строки;
- если список вывода не заканчивается `;` или `,`, вывод завершается переводом строки;
- `;` конкатенирует соседние элементы без дополнительного разделителя и подавляет автоматический перевод строки, если стоит в конце;
- `,` задаёт мягкое поведение разделителя между соседними элементами списка вывода в текущей логической строке;
- в текущей реализации v0.1.5 поведение разделителя `,` фиксируется как один пробел;
- завершающая `,` использует то же поведение разделителя и подавляет автоматический перевод строки;
- `PRINT USING` требует строковое `formatExpression`; нестроковый формат отвергается на этапе семантического анализа;
- после `USING` обязателен разделитель `;`, который отделяет строку формата от списка значений;
- строка формата управляет внешним видом вывода и поддерживает строковые поля `!`, `&`, `\   \`, числовые маски на базе `#`, `0`, `.`, `+`, `-`, `,`, `$`, `*`, `^`, а также экранирование литерала через `_X`;
- внутри `PRINT USING` разделители между значениями используются как синтаксис списка аргументов, а фактическое выравнивание и вставка литералов определяются строкой формата;
- только завершающий `;` или `,` после последнего аргумента влияет на перевод строки так же, как в обычном `PRINT`;
- если для числового поля не хватило значения или тип значения не совпал с типом поля, возникает диагностика времени выполнения;
- v0.1.5 сознательно не эмулирует исторические зоны вывода DOS/QuickBASIC, ширину консоли и перенос строк по 80 колонкам.

### 12.2 INPUT
Поддерживаются формы:
- `INPUT variable`
- `INPUT variable1, variable2`
- `INPUT "Prompt"; variable`
- `INPUT "Prompt", variable`

Упрощённая грамматика:
- `INPUT [ stringLiteral inputPromptSeparator ] identifier { "," identifier }`
- `inputPromptSeparator := ";" | ","`

Правила:
- один оператор `INPUT` читает одну логическую строку ввода из строки ввода среды;
- `INPUT var1, var2` разбирает введённую строку как минимальный список значений, разделённых запятыми;
- количество значений должно совпадать с количеством целевых переменных;
- для `INTEGER`, `LONG`, `DOUBLE`, `DECIMAL` и `BOOLEAN` значение преобразуется из текстового поля после минимальной нормализации пробелов;
- для `STRING` при вводе нескольких значений используется текст соответствующего поля без полноценного CSV-разбора и без отдельного консольного анализатора;
- если число значений не совпадает или преобразование невозможно, возникает предсказуемая диагностика времени выполнения;
- если приглашение не указано, IDE использует консольное приглашение `? `;
- `INPUT "Prompt"; var` и `INPUT "Prompt", var` обе формы передают текст приглашения в строку ввода среды;
- в v0.1.5 различие между `;` и `,` в части приглашения `INPUT` синтаксически поддерживается, но в оболочке IDE намеренно не разрастается в отдельную консольную модель форматирования.

Значение читается из строки ввода IDE и приводится к типу целевых переменных. Если преобразование невозможно или число введённых значений не совпадает с числом целевых переменных, возникает диагностика времени выполнения `MB3003`.

На этапе v0.1.5 для `Axiom.Ide` действует минимальное поведение ввода внутри оболочки:
- `INPUT` больше не открывает отдельное модальное окно и не показывает отдельную панель или карточку ввода с кнопкой подтверждения;
- панель `Output` работает как консольная запись сеанса: приглашение попадает в тот же поток вывода, а активный ввод идёт через одну встроенную строку ввода внутри основной оболочки IDE;
- подтверждение ввода происходит по `Enter`, без отдельной кнопки `Submit`;
- путь выполнения по-прежнему получает ввод через существующую границу среды;
- ввод остаётся построчным и не превращается в терминальную эмуляцию;
- ошибка преобразования по-прежнему идёт через обычный путь диагностики времени выполнения с указанием места в исходном тексте.

## 14. Массивы

Поддерживаются только одномерные массивы.

### 14.1 Объявление
Поддерживаются две формы объявления:
- `DIM arr(start TO finish) AS TYPE`
- `DIM arr() AS TYPE`

Смысл форм:
- `DIM arr(start TO finish) AS TYPE` сразу создаёт массив с включительными границами `start .. finish`;
- `DIM arr() AS TYPE` объявляет динамический одномерный массив без выделенных элементов;
- `TYPE` после `AS` может быть встроенным типом или пользовательским типом записи;
- динамический массив уже существует как имя массива, но диапазон элементов ещё не задан.

### 14.2 Доступ
Форма:
- `arr(index)`

### 14.3 Правила
- границы у выделенного массива включительные;
- индекс должен быть числом;
- выход за границы выделенного массива даёт ошибку времени выполнения `MB3002`;
- обращение к динамическому массиву, который объявлен через `DIM arr() AS TYPE`, но ещё не выделен, даёт ошибку времени выполнения `MB3005`;
- если элемент массива имеет пользовательский тип, его поля доступны через точку после индексирования: `arr(index).field`;
- присваивание записи в элемент массива хранит копию записи по тем же правилам, что и присваивание записи обычной переменной;
- многомерные массивы не поддерживаются;
- `REDIM` и `ERASE` управляют выделенным диапазоном динамического массива и описаны в пользовательском справочнике по массивам.

- `MID(text AS STRING, start AS INTEGER, count AS INTEGER) AS STRING`
- `TRIM(text AS STRING) AS STRING`
- `TRIM(text AS STRING, chars AS STRING) AS STRING`
- `LTRIM(text AS STRING) AS STRING`

- `INSTR(text AS STRING, fragment AS STRING) AS INTEGER`
- `INSTR(start AS INTEGER, text AS STRING, fragment AS STRING) AS INTEGER`
- `INSTRREV(text AS STRING, fragment AS STRING) AS INTEGER`
- `INSTRREV(start AS INTEGER, text AS STRING, fragment AS STRING) AS INTEGER`

- `LCASE(text AS STRING) AS STRING`

Общее правило проверки:
- проверка числа аргументов выполняется в связывателе по сигнатуре встроенной функции;
- проверка типов выполняется в связывателе по типам параметров встроенной функции и существующим правилам преобразования;
- проверка области допустимых значений выполняется во время выполнения, если корректность зависит от фактических значений;
- ошибки области допустимых значений у встроенных функций оформляются как предсказуемая диагностика времени выполнения, а не как общее исключение реализации;
- одна встроенная функция может иметь несколько допустимых форм вызова с одним и тем же публичным именем, например `TRIM(text)` и `TRIM(text, chars)`;
- выбор между такими формами делает только каталог встроенных функций; это не означает поддержку перегрузки пользовательских `SUB` и `FUNCTION`;
- если недопустимое на первый взгляд значение не считается ошибкой, это поведение должно быть явно зафиксировано в спецификации.

### 15.1 LEN
- Сигнатура: `LEN(text AS STRING) AS INTEGER`
- Число аргументов: ровно 1
- Типы: `text` должен быть `STRING`
- Поведение: возвращает длину строки в символах
- Пограничные случаи:
  - пустая строка даёт `0`
- Недопустимый ввод:
  - неверное число аргументов -> диагностика семантического анализа;
  - неверный тип аргумента -> диагностика семантического анализа.

### 15.2 LEFT
- Сигнатура: `LEFT(text AS STRING, count AS INTEGER) AS STRING`
- Число аргументов: ровно 2
- Типы: `text` = `STRING`, `count` = `INTEGER`
- Правила значений:
  - `count <= 0` -> диагностика времени выполнения;
  - `count > LEN(text)` -> возвращается вся строка
- Недопустимый ввод:
  - неверное число аргументов -> диагностика семантического анализа;
  - неверный тип аргумента -> диагностика семантического анализа;
  - `count <= 0` -> диагностика времени выполнения `MB3007`.

### 15.3 RIGHT
- Сигнатура: `RIGHT(text AS STRING, count AS INTEGER) AS STRING`
- Число аргументов: ровно 2
- Типы: `text` = `STRING`, `count` = `INTEGER`
- Правила значений:
  - `count <= 0` -> диагностика времени выполнения;
  - `count > LEN(text)` -> возвращается вся строка
- Недопустимый ввод:
  - неверное число аргументов -> диагностика семантического анализа;
  - неверный тип аргумента -> диагностика семантического анализа;
  - `count <= 0` -> диагностика времени выполнения `MB3007`.

### 15.4 MID
- Сигнатура: `MID(text AS STRING, start AS INTEGER, count AS INTEGER) AS STRING`
- Число аргументов: ровно 3
- Типы: `text` = `STRING`, `start` = `INTEGER`, `count` = `INTEGER`
- Индексация: начальная позиция считается с единицы
- Правила значений:
  - `start < 1` -> диагностика времени выполнения;
  - `count <= 0` -> диагностика времени выполнения;
  - `start > LEN(text)` -> пустая строка;
  - если `start` попадает в строку, но `count` выходит за хвост строки, возвращается доступный суффикс без ошибки
- Недопустимый ввод:
  - неверное число аргументов -> диагностика семантического анализа;
  - неверный тип аргумента -> диагностика семантического анализа;
  - `start < 1` или `count <= 0` -> диагностика времени выполнения `MB3007`.

### 15.5 INT
- Сигнатура: `INT(value AS DOUBLE) AS INTEGER`
- Число аргументов: ровно 1
- Типы: принимает числовое скалярное значение; `DECIMAL` также допускается как точный числовой аргумент, а `INTEGER` и `LONG` по-прежнему работают как числовые аргументы
- Поведение: возвращает значение после округления вниз (`floor`) и приводит его к `INTEGER`
- Пограничные случаи:
  - отрицательные дробные значения округляются вниз, а не к нулю;

  - `text = ""` -> диагностика времени выполнения `MB3007`.

### 15.29 CHR
- Сигнатура: `CHR(code AS INTEGER) AS STRING`
- Число аргументов: ровно 1
- Типы:
  - `code` = `INTEGER`
- Поведение:
  - возвращает строку из одного символа Unicode с кодом `code`;
  - функция принимает допустимые коды символов Unicode и не использует отдельные исторические таблицы основных или расширенных кодов;
  - `CHR(65)` возвращает `"A"`;
  - `ASC(CHR(1071))` возвращает `1071`;
  - `ASC(CHR(128512))` возвращает `128512`.
- Недопустимый ввод:
  - неверное число аргументов -> диагностика семантического анализа;
  - неверный тип аргумента -> диагностика семантического анализа;
  - код меньше `0`, больше `1114111` или попадающий в суррогатный диапазон `55296..57343` -> диагностика времени выполнения `MB3007`.

### 15.30 CENTER
- Сигнатуры:
  - `CENTER(text AS STRING, width AS INTEGER) AS STRING`
  - `CENTER(text AS STRING, width AS INTEGER, fill AS STRING) AS STRING`
- Число аргументов:
  - допускается 2 или 3 аргумента;
  - если третий аргумент не передан, используется пробел.
- Типы:
  - `text` = `STRING`
  - `width` = `INTEGER`
  - `fill` = `STRING`
- Поведение:
  - центрирует строку `text` в поле ширины `width`;
  - если `width <= LEN(text)`, возвращается исходная строка без изменений;
  - в форме с `fill` используется только первый символ строки заполнителя;
  - при нечётной разнице между шириной поля и длиной текста лишний символ заполнения добавляется справа;
  - `CENTER("A", 3)` возвращает `" A "`;
  - `CENTER("A", 4, ".")` возвращает `".A.."`;
  - `CENTER("AB", 5, ".")` возвращает `".AB.."`.
- Недопустимый ввод:
  - неверное число аргументов -> диагностика семантического анализа;
  - неверный тип аргумента -> диагностика семантического анализа;
  - `width < 0` -> диагностика времени выполнения `MB3007`;
  - `fill = ""` в форме с тремя аргументами -> диагностика времени выполнения `MB3007`.

### 15.31 SPLIT
- Формы вызова:
  - `SPLIT(text AS STRING) AS STRING()`
  - `SPLIT(text AS STRING, separator AS STRING) AS STRING()`
- Назначение:
  - разделяет строку `text` на части и возвращает новый одномерный массив строк;
  - если `separator` не передан, используется запятая.
- Поведение:
  - непустой результат получает компактные границы `1 TO N`;
  - пустые части между соседними разделителями сохраняются;
  - если `text = ""`, результатом является пустой выделенный массив `1 TO 0`;
  - если разделитель не найден, результат содержит один элемент с исходной строкой;
  - `separator = ""` даёт диагностику времени выполнения `MB3007`.
- Ошибки:
  - неверное число аргументов диагностируется на этапе семантического анализа;
  - неверный тип аргумента диагностируется на этапе семантического анализа.

### 15.32 JOIN
- Формы вызова:
  - `JOIN(items AS STRING()) AS STRING`
  - `JOIN(items AS STRING(), separator AS STRING) AS STRING`
- Назначение:
  - собирает элементы строкового одномерного массива в одну строку;
  - если `separator` не передан, используется запятая.
- Поведение:
  - элементы берутся в порядке логических индексов от нижней границы к верхней;
  - невыделенный массив возвращает пустую строку;
  - пустой выделенный массив `1 TO 0` возвращает пустую строку;
  - пустой разделитель допустим и соединяет элементы без промежутка между ними.
- Ошибки:
  - неверное число аргументов диагностируется на этапе семантического анализа;
  - первый аргумент должен иметь тип `STRING()`;
  - второй аргумент, если он есть, должен иметь тип `STRING`.

## 16. Области видимости

Axiom принимает строгую C#-подобную модель видимости для локальных имён.

Поддерживаются следующие уровни областей видимости:
- область видимости уровня файла для кода верхнего уровня;
- область видимости процедуры или функции внутри `SUB`/`FUNCTION`;
- область видимости блока внутри:
  - `THEN`-тела `IF`;
  - каждого `ELSEIF`-тела;
  - `ELSE`-тела;
  - тела `FOR`, включая управляющую переменную цикла;
  - тела `WHILE`;
  - тела `DO ... LOOP`;
  - тела каждой ветви `CASE`;
  - тела ветви `CASE ELSE`.

Правила:
- имя, объявленное через `DIM` или `CONST` внутри блока, доступно только внутри этого блока и его вложенных дочерних блоков;
- после выхода из блока такое имя становится недоступным;
- соседние блоки не делят между собой локальные объявления;
- поэтому два разных соседних блока могут объявлять одинаковое имя, если ни один из них не является внешней областью видимости для другого;
- `IF`, `ELSEIF` и `ELSE` считаются разными соседними областями видимости блоков;
- каждая ветвь `CASE` и ветвь `CASE ELSE` считаются разными соседними областями видимости блоков;
- повторное объявление имени в той же самой области видимости запрещено;
- затенение локального имени, параметра, константы или управляющей переменной из внешней области видимости запрещено;
- при таком запрещённом затенении диагностика семантического анализа должна быть человекопонятной:
  - явно говорить, что имя уже объявлено во внешней области видимости;
  - явно называть текущий контекст, например `в блоке IF`, `в ветви ELSE`, `в цикле FOR`, `в ветви CASE`;
- это правило не привязано к текущему набору конструкций:
  - любая будущая блочная конструкция, которая вводит новую область видимости, обязана получить такое же контекстное имя для диагностических сообщений;
  - при добавлении будущих областей видимости блоков запрещено возвращаться к абстрактным формулировкам без указания текущей конструкции;
- область видимости уровня файла и область видимости процедуры или функции по-прежнему существуют, но больше не являются единственными областями видимости в языке.

Иллюстративные примеры:

```mbas
IF flag THEN
    DIM x AS INTEGER = 1
    PRINT x
END IF

PRINT x
```

`PRINT x` после `END IF` должен давать диагностику семантического анализа: имя `x` недоступно вне блока.

```mbas
IF a = 1 THEN
    DIM message AS STRING = "one"
    PRINT message
ELSE
    DIM message AS STRING = "other"
    PRINT message
END IF
```

Такой код допустим, потому что ветви `THEN` и `ELSE` — разные соседние области видимости блоков.

```mbas
FOR i = 1 TO 3
    DIM localSum AS INTEGER = i * 10
    PRINT localSum
NEXT

PRINT i
PRINT localSum
```

`i` и `localSum` после `NEXT` должны быть недоступны вне цикла.

### 16.1 Явность объявлений

Axiom работает в строгом режиме, аналогичном `Option Explicit On`.

Правила:
- локальные и глобальные переменные должны объявляться явно через `DIM`;
- константы должны объявляться явно через `CONST`;
- неявное появление имени по первому присваиванию не поддерживается;
- Python-подобная модель `name = expression` без предварительного объявления не входит в текущую спецификацию;
- директивы `Option Explicit On` / `Option Explicit Off` не поддерживаются в текущем договоре: язык всегда ведет себя так, как будто строгий режим явного объявления уже включен.

## 17. Топ-уровневый код

В файле допускаются:
- `DIM`;
- `CONST`;
- `SUB`;
- `FUNCTION`;
- исполняемые инструкции.

При запуске:
1. сначала регистрируются все `SUB` и `FUNCTION`;
2. затем исполняется топ-уровневый код сверху вниз.

## 18. Преобразования типов

Разрешается:
- `INTEGER` в†’ `LONG`
- `INTEGER` в†’ `DECIMAL`
- `INTEGER` в†’ `DOUBLE`
- `LONG` в†’ `DECIMAL`
- `LONG` в†’ `DOUBLE`

Не допускаются автоматически:
- `STRING` в†’ `INTEGER`
- `STRING` в†’ `LONG`
- `STRING` в†’ `DOUBLE`
- `STRING` в†’ `DECIMAL`
- `LONG` в†’ `INTEGER`
- `DOUBLE` в†’ `INTEGER`
- `DOUBLE` в†’ `LONG`
- `DOUBLE` в†’ `DECIMAL`
- `DECIMAL` в†’ `INTEGER`
- `DECIMAL` в†’ `LONG`
- `DECIMAL` в†’ `DOUBLE`
- `BOOLEAN` в†’ число
- число в†’ `BOOLEAN`

Преобразование в строку должно быть явным через `STR(...)`, а из строки в число — через `VAL(...)`.

## 19. Ошибки

### 19.1 Ошибки лексера
Примеры:
- недопустимый символ;
- незакрытая строка.

### 19.2 Ошибки парсера
Примеры:
- ожидался `THEN`;
- ожидался `END IF`;
- ожидался идентификатор;
- ожидалось выражение.

### 19.3 Семантические ошибки
Примеры:
- переменная не объявлена;
- повторное объявление;
- несовместимые типы;
- вызов неизвестной функции;
- неправильное число аргументов;
- `EXIT FOR` вне `FOR ... NEXT`;
- `EXIT DO` вне `DO ... LOOP`;
- диапазон `CASE ... TO` с недопустимым типом проверяемого значения;
- присваивание или инициализация, требующие сужения значения вне диапазона целевого типа.

### 19.4 Ошибки времени выполнения
Примеры:
- деление на ноль;
- выход за границы массива;
- ошибка преобразования `INPUT`;
- отсутствует `RETURN` в `FUNCTION`;
- `STEP 0`;
- переполнение арифметики `INTEGER` / `LONG` / `DECIMAL`;
- получение не-конечного результата `DOUBLE` (`Infinity`, `-Infinity`, `NaN`);
- константный числовой литерал, который не помещается в явно указанный целевой тип вроде `INTEGER`, `LONG` или `DECIMAL`.

## 20. Формат диагностики

Дополнительно для числовой базовой модели:
- `MB0004` — числовой литерал выходит за допустимый диапазон типа литерала (`LONG` или конечного `DOUBLE`);
- `MB2018` — константное числовое значение не помещается в явно указанный целевой числовой тип;
- `MB3008` — во время выполнения произошло числовое переполнение или получен недопустимый не-конечный числовой результат.

Каждая ошибка должна содержать:
- код ошибки;
- сообщение;
- строку;
- столбец;
- длину проблемного участка.

Рекомендуемая схема кодов:
- `MB0xxx` — лексер;
- `MB1xxx` — парсер;
- `MB2xxx` — семантика;
- `MB3xxx` — время выполнения.

## 21. Сводная грамматика

Упрощённо:

```text
program         := { topLevel }

topLevel        := dimDecl
                 | constDecl
                 | subDecl
                 | functionDecl
                 | statement

dimDecl         := "DIM" dimGroup { "," dimGroup }
dimGroup        := dimDeclarator { "," dimDeclarator } ( "AS" typeName [ "=" expression ] | "=" expression )
dimDeclarator   := identifier arrayBounds?
constDecl       := "CONST" identifier "AS" typeName "=" expression

arrayBounds     := "(" expression "TO" expression ")"

subDecl         := "SUB" identifier "(" parameterList? ")"
                   { statement }
                   "END" "SUB"

functionDecl    := "FUNCTION" identifier "(" parameterList? ")" "AS" typeName
                   { statement }
                   "END" "FUNCTION"

parameterList   := parameter { "," parameter }
parameter       := identifier "AS" typeName

statement       := assignmentStmt
                 | ifStmt
                 | forStmt
                 | doLoopStmt
                 | whileStmt
                 | exitForStmt
                 | exitDoStmt
                 | printStmt
                 | inputStmt
                 | returnStmt
                 | callStmt
                 | dimDecl
                 | constDecl

assignmentStmt  := target "=" expression
target          := identifier | arrayAccess
arrayAccess     := identifier "(" expression ")"

ifStmt          := "IF" expression "THEN"
                   { statement }
                   { elseifClause }
                   [ "ELSE" { statement } ]
                   "END" "IF"

elseifClause    := "ELSEIF" expression "THEN"
                   { statement }

forStmt         := "FOR" identifier "=" expression "TO" expression [ "STEP" expression ]
                   { statement }
                   "NEXT"

exitForStmt     := "EXIT" "FOR"
exitDoStmt      := "EXIT" "DO"

doLoopStmt      := "DO" [ doLoopConditionClause ]
                   { statement }
                   "LOOP" [ doLoopConditionClause ]

doLoopConditionClause := ( "WHILE" | "UNTIL" ) expression

whileStmt       := "WHILE" expression
                   { statement }
                   "END" "WHILE"

printStmt       := "PRINT" [ printList | printUsingClause ]
printUsingClause := "USING" expression ";" [ printList ]
printList       := expression { printSeparator expression } [ printSeparator ]
printSeparator  := ";" | ","

inputStmt       := "INPUT" [ stringLiteral inputPromptSeparator ] identifier { "," identifier }
inputPromptSeparator := ";" | ","
returnStmt      := "RETURN" [ expression ]
callStmt        := identifier "(" argumentList? ")"

argumentList    := expression { "," expression }

typeName        := "INTEGER" | "LONG" | "DOUBLE" | "DECIMAL" | "STRING" | "BOOLEAN" | "FILE"
```

## 22. Пример корректной программы

```basic

DIM globalCount AS INTEGER = 0

    RETURN a + b
END FUNCTION

END SUB

```

## 24. Требования к IDE

IDE должна иметь:
- редактор текста;
- вкладки открытых документов с кнопкой закрытия (`X`) в заголовке;
- открыть/сохранить файл;
- кнопку `Run`;
- панель вывода `PRINT`;
- панель ошибок;
- подсветку ключевых слов, строк, чисел, комментариев;
- переход к позиции ошибки по клику на diagnostic entry.

Для вкладок документов действует стандартное правило оболочки:
- если документ не изменён после последнего сохранения, вкладка закрывается сразу;
- если документ изменён после последнего сохранения, IDE перед закрытием показывает стандартный запрос `Save / Discard / Cancel`.

Для разметки оболочки действует правило пользовательского интерфейса:
- пункт `View -> File Manager` должен полностью убирать левую область панели;
- при снятой галочке редактор кода занимает освободившееся место, без пустого поля между левым краем окна и областью редактора.
- при включённых `Output`/`Diagnostics` высота `File Manager` ограничена верхней областью редактора: вертикальная прокрутка дерева, включая нижнюю кнопку полосы прокрутки, не должна уходить под нижнюю панель.
- вертикальная граница-разделитель между `File Manager` и областью редактора заканчивается на горизонтальной границе нижней панели и не рисуется внутри `Output`/`Diagnostics`.
- выбранный узел `File Manager` подсвечивается инверсным цветом как для текста, так и для иконки файла/папки.

Для нижней панели и строки состояния действует правило оболочки:
- `Output` и `Diagnostics` живут в одной нижней панели с вкладками и могут выбираться как автоматически, так и вручную через `View -> Output` / `View -> Diagnostics`;
- при успешном `Run` оболочка переключается на `Output`;
- при любой ошибке запуска оболочка переключается на `Diagnostics` и передаёт фокус панели диагностик, чтобы ошибка была визуально заметна сразу;
- при выборе конкретной строки диагностики IDE переводит курсор активного редактора на соответствующие `Line / Column` и прокручивает документ к этой позиции;
- после перехода текущая строка должна быть визуально различима мягкой подсветкой, чтобы место ошибки было видно без ручного поиска;
- при `INPUT` фокус автоматически возвращается в строку ввода внутри `Output`;
- строка состояния `Ln / Col` должна в реальном времени показывать координаты курсора активного редактора, а не оставаться статической меткой.

Отдельно проектируемые возможности:
- отладчик;
- breakpoint;
- autocomplete;
- refactoring;
- IntelliSense;
- проектная система.

## 26. Режимы форматирования IDE

Для оболочки редактора действует отдельное правило визуального форматирования вводимой строки.

### 26.1 Classic

- в меню `Format` есть пункт `Classic` с галочкой;
- при включённом `Classic` IDE автоматически преобразует строку, когда пользователь уходит с неё на другую строку или когда редактор теряет фокус клавиатуры;
- форматирование применяется только к одной строке, без полного переформатирования всего документа;
- распознанные ключевые слова и имена типов переводятся в верхний регистр;
- встроенные функции переводятся в верхний регистр только в синтаксисе вызова, когда дальше идёт `(`, чтобы идентификаторы-переменные с тем же именем не искажались;
- форматирование нормализует пробелы вокруг бинарных арифметических и сравнительных операторов, а также после `,` и `;`;
- префиксные `+`/`-` должны оставаться без лишнего пробела между знаком и числом или выражением;
- комментарии не должны ломать форматирование части кода: для `REM` сохраняется хвост комментария, но сам маркер `REM` нормализуется к виду `REM`;
- если строка содержит ошибку разбиения на токены, например незакрытую строку, IDE оставляет её без изменений;
- форматирование не должно срабатывать в документе только для чтения, при активном выделении или при перетаскивании мышью, чтобы не мешать ручному редактированию.

### 26.2 Источник словаря форматирования

- форматирование IDE не должно дублировать отдельный жёстко заданный список ключевых слов и встроенных функций;
- источником ключевых слов для `Classic` является словарь подсветки синтаксиса IDE, чтобы добавление новых ключевых слов и функций в подсветку автоматически расширяло покрытие форматирования;
- `Modern` остаётся следующим отдельным этапом и до его реализации не должен менять строку.

### 26.3 Журнал диагностического сеанса IDE

- `Axiom.Ide` автоматически открывает файловый журнал трассировки при старте приложения;
- логи пишутся в каталог `Logs` рядом с исполняемым файлом IDE, один файл на один запуск приложения;
- в трассировку обязательно попадают:
  - завершение старта IDE;
  - параметры `Run` для активного документа;
  - итог выполнения (`status`, число диагностик, длина и предварительный просмотр вывода);
  - срабатывание запасного показа `Output`, если панель записи сеанса осталась пустой;
  - события консольной записи сеанса: начало консольной сессии, печать строк, запрос `INPUT`, подтверждение ввода;
  - необработанные исключения IDE;
- журнал трассировки предназначен для расследования проблем отображения и ошибок пути запуска на уровне IDE и не меняет поведение языка или выполнения.

### 26.4 Запуск только из сохранённого файла

- запуск программы из IDE разрешён только для документа, который сохранён на диск;
- при попытке `Run` для `Untitled`-документа или документа с несохранёнными изменениями IDE не должна молча игнорировать команду;
- перед запуском IDE обязана показать пользователю явное сообщение/подтверждение с предложением сохранить документ;
- если пользователь подтверждает сохранение и операция `Save`/`Save As` завершается успешно, IDE запускает именно содержимое файла по `FilePath`, перечитанное с диска;
- если пользователь отказывается от сохранения или сохранение не завершилось, запуск отменяется без выполнения программы.

### 26.5 Стиль форматирования Modern

- `Modern` использует тот же путь построчного форматирования, что и `Classic`;
- различие только в правиле регистра для ключевых слов, имён типов, `REM` и вызовов встроенных функций: первая буква заглавная, остальные строчные;
- примеры: `dim a as integer=1` -> `Dim a As Integer = 1`, `print len("x")+1` -> `Print Len("x") + 1`;
- правила пробелов у `Modern` совпадают с `Classic`: бинарные операторы, запятые и `;` нормализуются до одного аккуратного пробела, лишние пробелы вырезаются, строка с ошибочным синтаксисом не меняется.

### 26.6 Переключение стиля переписывает активный `.axm`-документ

- при переключении `Format -> Classic` или `Format -> Modern` IDE сразу переписывает текст активной вкладки в выбранный стиль;
- преобразование выполняется построчно по всему документу, используя тот же путь форматирования, что и для автоформатирования строки;
- правило действует только для внутренних Axiom-документов с расширением `.axm`;
- `.txt`, `.md` и другие открытые текстовые файлы не преобразуются при смене стиля форматирования;
- при активации другой уже открытой `.axm`-вкладки IDE автоматически приводит её к текущему выбранному стилю;
- если после преобразования текст изменился, вкладка помечается как изменённая и требует обычного сохранения пользователем.

### 26.7 Выделяемый путь в строке состояния

- полный путь текущего документа в нижней строке состояния должен быть доступен для выделения мышью и копирования;
- область пути отображается как поле только для чтения с поддержкой выделения, а не как обычная невыделяемая текстовая метка;
- поле не предназначено для редактирования пути и не меняет модель документа;
- всплывающая подсказка области пути совпадает с полным `StatusBar.PathText`, чтобы длинные пути можно было быстро просмотреть целиком.

### 26.8 Автозавершение блоков и структурный отступ в IDE

- `Axiom.Ide` получает отдельное правило автозавершения блочных конструкций на уровне оболочки; это поведение редактора и оно не меняет синтаксический анализатор, семантический анализ или выполнение;
- автозавершение блоков срабатывает только для редактируемых `.axm` документов;
- базовый триггер: пользователь завершил строку заголовка блока и уходит с нее через `Enter`;
- дополнительный запуск допустим при уходе курсора на другую строку мышью или стрелками, но только если текущая строка была изменена в рамках текущего редактирования;
- автозавершение не должно срабатывать повторно для уже закрытого блока и не должно дублировать уже существующую закрывающую строку ниже;
- если строка не образует корректный заголовок поддерживаемой конструкции, IDE ничего не вставляет;
- если курсор стоит в середине строки, а не в конце заголовка, IDE ничего не вставляет;
- если документ доступен только для чтения, автозавершение не применяется.

Поддерживаемые автозавершаемые заголовки v1:
- `IF <expression> THEN` -> вставляется `End If`;
- `FOR ...` -> вставляется `Next`;
- `WHILE <expression>` -> вставляется `End While`;
- `SELECT CASE <expression>` -> вставляется `End Select`;
- `DO` -> вставляется `Loop`;
- `DO WHILE <expression>` -> вставляется `Loop`;
- `DO UNTIL <expression>` -> вставляется `Loop`;
- `SUB Name(...)` -> вставляется `End Sub`;
- `FUNCTION Name(...) AS TYPE` -> вставляется `End Function`.

Ограничение v1 для семейства `DO ... LOOP`:
- постусловные формы `DO ... LOOP WHILE <expression>` и `DO ... LOOP UNTIL <expression>` не угадываются заранее;
- для них IDE не пытается автоматически создавать закрывающую строку с условием;
- если пользователь начал блок с `DO` без условия, IDE вставляет только базовый `Loop`, а уточнение `WHILE`/`UNTIL` на закрывающей строке остается ручным действием пользователя.

Правила вставки блока:
- после успешного автозавершения IDE создает пустую строку тела между открывающей и закрывающей строками;
- закрывающая строка выравнивается строго под открывающей строкой, в ту же колонку;
- строка тела блока получает один дополнительный уровень отступа относительно открывающей строки;
- стандартный шаг одного уровня отступа для этого поведения фиксируется как `4` пробела;
- если открывающая строка начата не с первого столбца, закрывающая строка и внутренний отступ считаются от фактической колонки этой строки, а не от нулевого уровня документа.

Пример для `IF`:

```mbas
          If a = 0 Then
              |
          End If
```

Структурный автоотступ при `Enter`:
- когда пользователь нажимает `Enter` внутри тела уже открытого блока, новая строка получает тот же рабочий уровень отступа, что и текущая строка тела;
- курсор не должен самопроизвольно переходить в первый столбец, пока пользователь логически остается внутри текущего блока;
- если пользователь завершил внутренний вложенный блок и продолжает писать уже внутри родительского блока, следующий `Enter` должен давать отступ родительского блока;
- если пользователь вышел из всех окружающих блоков, следующий `Enter` должен возвращать строку в нулевой уровень программы;
- таким образом, IDE должна ориентироваться не только на предыдущую строку, а на текущий структурный контекст вложенности.

Требование для вложенных блоков:
- каждый новый вложенный блок считает свой закрывающий отступ от собственной открывающей строки;
- внутренний `End If` выравнивается под внутренний `If`, а не под внешний;
- те же правила действуют для `For/Next`, `While/End While`, `Select Case/End Select`, `Do/Loop`, `Sub/End Sub` и `Function/End Function`;
- последовательные `Enter` внутри самого глубокого текущего блока должны сохранять именно уровень этого блока до тех пор, пока пользователь не перейдет на уровень выше.

Специальные правила для промежуточных ветвей:
- `ELSEIF <expression> THEN` и `ELSE` не создают новый `End If`;
- если пользователь начал строку `ELSEIF <expression> THEN` или `ELSE` из текущего тела `IF`, IDE должна автоматически выровнять саму эту строку на уровень соответствующего `IF`, а не оставлять ее на уровне вложенного отступа тела;
- после `ELSEIF <expression> THEN` и `ELSE` следующая строка тела должна получать один внутренний уровень отступа относительно строки ветви;
- если строка после `ELSEIF <expression> THEN` или `ELSE` уже занята существующим `End If`, другой ветвью или любой другой строкой, IDE при уходе со строки ветви должна вставить пустую строку тела перед этой уже существующей строкой, а не считать ветвь завершённой;
- `CASE ...` и `CASE ELSE` не создают новый `End Select`;
- если пользователь начал строку `CASE ...` или `CASE ELSE` из текущего тела предыдущей ветви `SELECT CASE`, IDE должна автоматически выровнять саму эту строку на один уровень внутрь относительно `SELECT CASE`, а не на тот же самый уровень, что и строка `SELECT CASE`;
- после `CASE ...` и `CASE ELSE` следующая строка тела ветви должна получать еще один внутренний уровень отступа относительно строки `CASE`;
- если строка после `CASE ...` или `CASE ELSE` уже занята существующим `End Select`, другой ветвью или любой другой строкой, IDE при уходе со строки `CASE` должна вставить пустую строку тела перед этой уже существующей строкой.

Ограничения поведения редактора:
- вся автозавершенная вставка одного блока должна откатываться одним `Undo`;
- после автозавершения по `Enter` курсор должен оказываться на пустой строке тела блока;
- автозавершение по уходу мышью или стрелками не должно неожиданно переносить курсор в несвязанные части документа;
- поведение должно быть предсказуемым и не мешать ручному редактированию уже существующих закрывающих строк.

Правило расширяемости:
- если в будущих версиях языка появляется новая парная блочная конструкция с явным открывающим и закрывающим синтаксисом, IDE должна рассматривать ее как кандидата на такое же поведение автозавершения;
- это правило относится, например, к возможным будущим конструкциям вида `TYPE ... END TYPE` или любым другим аналогичным парам блоков, которые будут официально добавлены в языковую спецификацию;
- при добавлении новой такой конструкции разработка IDE должна в том же наборе правок обновить правила автозавершения блоков, правила структурного отступа и соответствующие автоматические тесты;
- появление новой парной блочной конструкции без синхронного обновления автозавершения IDE считается незавершенной интеграцией на уровне редактора.
## 27. Математический пакет встроенных функций

### 27.1 Общие правила

- Нового синтаксиса для математических возможностей не вводится. Используются только встроенные функции.
- Имена функций остаются английскими, короткими, записываются в верхнем регистре и не зависят от регистра при распознавании.
- Тригонометрические функции работают в радианах.
- Язык не вводит кортежи и выходные параметры, поэтому аналоги `DivRem` и `SinCos` в базовом наборе отсутствуют.
- `INT` сохраняется как классическая BASIC-функция: округление вниз с возвратом именно `INTEGER` и с проверкой диапазона.
- Для поведения "отбросить дробную часть к нулю" используется отдельная функция `FIX`.

## 28. Локальные SUB и FUNCTION

Начиная с текущей реализации язык поддерживает локальные подпрограммы и функции внутри другой процедуры или функции.

Правила:
- локальные `SUB` и `FUNCTION` разрешены только непосредственно в теле внешней `SUB` или `FUNCTION`;
- размещать локальные объявления внутри `IF`, `FOR`, `WHILE`, `DO ... LOOP` или `SELECT CASE` на этом этапе нельзя;
- внутри одной внешней процедуры или функции все локальные объявления процедур и функций сначала регистрируются, а затем тело связывается в текстовом порядке;
- поэтому вызов локальной подпрограммы или функции разрешён до её текстового объявления в теле внешней процедуры или функции;
- локальная подпрограмма или функция видна только внутри своей внешней процедуры или функции и внутри вложенных в неё локальных процедур или функций;
- снаружи внешней процедуры или функции локальное имя недоступно;
- локальная процедура или функция может вызывать саму себя и другие локальные процедуры или функции, которые видимы по цепочке внешних процедур или функций;
- локальная процедура или функция может захватывать параметры и локальные переменные внешней процедуры или функции, если эти имена уже объявлены раньше по тексту к моменту её собственного объявления;
- локальная `SUB` может изменять захваченные внешние переменные;
- локальная `FUNCTION` может использовать захваченные внешние параметры и переменные в выражениях и `RETURN`.

Ограничение текущего этапа:
- захват работает только для имён, объявленных раньше текста локальной `SUB` или `FUNCTION`;
- локальная процедура или функция не получает доступ к внешним локальным именам, объявленным ниже по тексту после её собственного объявления;
- локальные процедуры и функции по-прежнему не являются значениями первого класса: их нельзя сохранить в переменную, вернуть или передать как аргумент;
- внутри локальной процедуры или функции доступны только:
    - её собственные параметры;
    - её собственные локальные переменные и константы;
    - захваченные параметры и локальные переменные внешних процедур и функций по лексической цепочке;
    - глобальные переменные и константы;
    - глобальные и лексически видимые имена локальных процедур и функций.

Это означает, что реализован лексический захват внешних локальных данных без полноценной модели замыканий как значений языка: вложенная процедура или функция вызывается только по имени и опирается на активный внешний вызов своей объявляющей процедуры или функции.
- `ROUND(x)` в первой версии означает округление до целого по правилу half away from zero без параметра `digits`.

### 27.2 Каталог математических встроенных функций v1

  - `FLOOR(x)`
  - `CEIL(x)`
  - `ROUND(x)`
  - `FIX(x)`
- С фиксированным результатом `INTEGER`:
  - `SGN(x)`
- С фиксированным результатом `DOUBLE`:
  - `RND()`
  - `SIN(x)`
  - `COS(x)`
  - `TAN(x)`
  - `ATN(x)`
  - `ATN2(y, x)`
  - `ASIN(x)`
  - `ACOS(x)`
  - `ASINH(x)`
  - `ACOSH(x)`
  - `ATANH(x)`
  - `SINH(x)`
  - `COSH(x)`
  - `TANH(x)`
  - `SQR(x)`
  - `CBRT(x)`
  - `EXP(x)`
  - `LOG(x)` — натуральный логарифм
  - `LOG10(x)`
  - `LOG2(x)`
  - `POW(x, y)`

### 27.3 Типовые правила и ограничения

- `ABS`, `MIN`, `MAX`, `CLAMP`, `SETSIGN` используют текущую модель числового продвижения Axiom.
- Автоматическое смешивание `DECIMAL` и `DOUBLE` для этих встроенных функций не разрешается.
- `RND()` не принимает аргументов и возвращает псевдослучайное `DOUBLE` в диапазоне `0 <= x < 1`.
- `SIN`, `COS`, `TAN`, `ATN`, `ATN2`, `ASIN`, `ACOS`, `ASINH`, `ACOSH`, `ATANH`, `SINH`, `COSH`, `TANH`, `SQR`, `CBRT`, `EXP`, `LOG`, `LOG10`, `LOG2`, `POW` приводят числовые аргументы к `DOUBLE` внутри контракта встроенной функции.
- `ASIN(x)` и `ACOS(x)` требуют `-1 <= x <= 1`.
- `ACOSH(x)` требует `x >= 1`.
- `ATANH(x)` требует `-1 < x < 1`.
- `SQR(x)` требует `x >= 0`.
- `LOG(x)`, `LOG10(x)`, `LOG2(x)` требуют `x > 0`.
- `CLAMP(x, low, high)` требует `high >= low`.
- `POW(x, y)` завершает выполнение ошибкой, если комбинация аргументов даёт недопустимую область определения.
- `SETSIGN(value, signFrom)` переносит знак второго аргумента на первый аргумент и возвращает значение в числовом семействе первого аргумента.
- Переполнение и не-конечные результаты (`NaN`, `Infinity`) не считаются допустимыми пользовательскими значениями Axiom v1.

### 27.4 Диагностика

- Ошибки области определения математических встроенных функций диагностируются как диагностика времени выполнения `MB3007`.
- Переполнение и не-конечные результаты диагностируются как диагностика времени выполнения `MB3008`.
- Это правило относится и к крайним случаям вроде `ABS` от минимального `INTEGER`/`LONG`, если модуль не помещается в то же числовое семейство.

### 27.5 Отличие INT, FIX и ROUND

- `INT(-3.9)` даёт `-4`, потому что это округление вниз к `INTEGER`.
- `FIX(-3.9)` даёт `-3`, потому что дробная часть просто отбрасывается к нулю.
- `ROUND(-3.9)` даёт `-4`, потому что число округляется к ближайшему целому.

## 29. Диагностика вложенных вызовов процедур и функций

Для вложенных `SUB` и `FUNCTION` дополнительно зафиксированы правила диагностики времени выполнения.

Правила:
- если ошибка возникает внутри локальной процедуры или функции, координаты ошибки по-прежнему указывают на реальную проблемную строку и столбец;
- текст сообщения дополняется блоком `Цепочка вызовов`;
- в цепочке перечисляются активные вызовы от текущей локальной процедуры или функции к внешним вызовам;
- для каждого кадра в цепочке показывается место вызова в виде номера строки и столбца;
- для локальной процедуры или функции в цепочке отдельно указывается внешняя процедура или функция, внутри которой она объявлена.

Ограничения:
- цепочка вызовов пока остаётся только текстовой частью сообщения и не оформлена как отдельная структурированная модель в интерфейсе диагностики;
- это изменение не делает процедуры и функции значениями языка и не добавляет полноценные замыкания как объекты.

## 30. Функции как значения и полноценные замыкания

На текущем этапе Axiom поддерживает не только вызов функции по имени, но и саму функцию как значение языка.

Правила:
- функциональный тип записывается как `FUNCTION(TYPE, TYPE) AS TYPE`;
- такой тип можно указывать в `DIM`, в параметрах и в типе результата другой функции;
- имя обычной или локальной `FUNCTION`, использованное в выражении без немедленного вызова, означает значение этой функции;
- функцию можно присвоить переменной функционального типа, передать в параметр другой функции или вернуть из функции;
- вызвать можно любое выражение функционального типа, включая переменную с функцией и немедленный вызов возвращаемой функции вроде `MakeAdder()(5)`;
- `SUB` не является значением языка: попытка использовать его как значение даёт семантическую ошибку `MB2019`;
- вызов значения, которое не имеет функциональный тип, даёт семантическую ошибку `MB2020`;
- переменная функционального типа без присвоенной функции считается пустым значением; её вызов даёт ошибку времени выполнения `MB3009`;
- типы функций равны только при точном совпадении списка типов параметров и типа результата.

Полноценные замыкания:
- если внутренняя локальная функция возвращается или сохраняется в переменную, она сохраняет ссылку на захваченную лексическую область видимости;
- благодаря этому возвращённая локальная функция может продолжать читать и изменять захваченные внешние параметры и локальные переменные даже после завершения внешней функции;
- ограничение по текстовому порядку сохраняется: захватываются только те внешние имена, которые объявлены раньше по тексту момента объявления внутренней функции.

Ограничения текущего этапа:
- анонимных функций и литералов функции пока нет;
- операций сравнения и особой модели печати для заполненных значений функции пока не добавлено;
- `SUB` по-прежнему остаётся только вызываемой подпрограммой, а не значением.

### 27.7 Арифметика v0.1.13

- операторы `\` и `MOD` введены как часть базовой арифметики;
- `\` выполняет целочисленное деление с отбрасыванием дробной части к нулю;
- `MOD` возвращает остаток от деления по правилу C#: знак результата совпадает со знаком левого операнда;
- `\` и `MOD` принимают только `INTEGER` и `LONG`;
- результат `\` и `MOD` имеет тип `LONG`, если хотя бы один операнд имеет тип `LONG`, иначе `INTEGER`;
- для `+`, `-` и `*` числовой результат продвигается по правилу `DOUBLE` > `DECIMAL` > `LONG` > `INTEGER`;
- смешивание `DECIMAL` и `DOUBLE` в одном арифметическом выражении не допускается;
- `+` также используется для конкатенации двух строк.

## 31. Функции регулярных выражений

Axiom поддерживает отдельный набор встроенных функций для поиска по регулярному выражению. Эти функции работают со строками и возвращают скалярные значения или новые массивы строк.

### 31.1 Доступные функции

- `REGEXISMATCH(<текст> AS STRING, <образец> AS STRING) AS BOOLEAN`
- `REGEXISMATCH(<текст> AS STRING, <образец> AS STRING, <режимы> AS STRING) AS BOOLEAN`
- `REGEXMATCH(<текст> AS STRING, <образец> AS STRING) AS STRING`
- `REGEXMATCH(<текст> AS STRING, <образец> AS STRING, <режимы> AS STRING) AS STRING`
- `REGEXEXTRACT(<текст> AS STRING, <образец> AS STRING, <номер группы> AS INTEGER) AS STRING`
- `REGEXEXTRACT(<текст> AS STRING, <образец> AS STRING, <номер группы> AS INTEGER, <режимы> AS STRING) AS STRING`
- `REGEXMATCHES(<текст> AS STRING, <образец> AS STRING) AS STRING()`
- `REGEXMATCHES(<текст> AS STRING, <образец> AS STRING, <режимы> AS STRING) AS STRING()`
- `REGEXEXTRACTALL(<текст> AS STRING, <образец> AS STRING, <номер группы> AS INTEGER) AS STRING()`
- `REGEXEXTRACTALL(<текст> AS STRING, <образец> AS STRING, <номер группы> AS INTEGER, <режимы> AS STRING) AS STRING()`
- `REGEXSPLIT(<текст> AS STRING, <образец> AS STRING) AS STRING()`
- `REGEXSPLIT(<текст> AS STRING, <образец> AS STRING, <режимы> AS STRING) AS STRING()`
- `REGEXREPLACE(<текст> AS STRING, <образец> AS STRING, <замена> AS STRING) AS STRING`
- `REGEXREPLACE(<текст> AS STRING, <образец> AS STRING, <замена> AS STRING, <режимы> AS STRING) AS STRING`
- `REGEXREPLACE(<текст> AS STRING, <образец> AS STRING, <замена> AS STRING, <количество> AS INTEGER) AS STRING`
- `REGEXREPLACE(<текст> AS STRING, <образец> AS STRING, <замена> AS STRING, <режимы> AS STRING, <количество> AS INTEGER) AS STRING`
- `REGEXCOUNT(<текст> AS STRING, <образец> AS STRING) AS INTEGER`
- `REGEXCOUNT(<текст> AS STRING, <образец> AS STRING, <режимы> AS STRING) AS INTEGER`

### 31.2 Поведение

- `<текст>` содержит исходную строку.
- `<образец>` содержит регулярное выражение.
- `REGEXISMATCH` возвращает `TRUE`, если найдено хотя бы одно совпадение, иначе `FALSE`.
- `REGEXMATCH` возвращает первое совпадение целиком; если совпадение не найдено, возвращается пустая строка.
- `REGEXEXTRACT` возвращает указанную группу из первого совпадения; группа `0` означает совпадение целиком.
- Если `REGEXEXTRACT` не находит совпадение или указанная группа отсутствует, возвращается пустая строка.
- `REGEXMATCHES` возвращает все найденные совпадения целиком как новый массив `STRING()`.
- `REGEXEXTRACTALL` возвращает значения указанной группы из всех найденных совпадений как новый массив `STRING()`; группа `0` означает совпадение целиком.
- Если для отдельного совпадения указанная группа в `REGEXEXTRACTALL` отсутствует, соответствующий элемент результата получает пустую строку.
- `REGEXSPLIT` разделяет строку по регулярному выражению и возвращает части как новый массив `STRING()`.
- Массивные функции регулярных выражений возвращают компактный выделенный массив `1 TO N`; если результат пуст, возвращается выделенный пустой массив `1 TO 0`.
- `REGEXSPLIT` сохраняет пустые части, которые возникают при совпадении в начале, в конце или рядом с другим совпадением. Для пустого исходного текста возвращается пустой массив `1 TO 0`.
- `REGEXREPLACE` без `count` заменяет все совпадения.
- `REGEXREPLACE` с `count` заменяет не больше указанного количества первых совпадений.
- `REGEXREPLACE` с `count = 0` возвращает исходный текст без изменений.
- В строке замены `REGEXREPLACE` можно ссылаться на группы через `$1`, `$2` и последующие номера.
- `REGEXCOUNT` возвращает количество найденных совпадений.

### 31.3 Режимы

Необязательный аргумент `<режимы>` является строкой из символов режимов. Допустимые символы:

- `i` — не различать строчные и прописные буквы;
- `m` — считать начало и конец каждой строки отдельными границами для `^` и `$`;
- `s` — позволить точке `.` совпадать с переводом строки;
- `x` — игнорировать незначащие пробелы в регулярном выражении, если они не экранированы и не входят в набор символов.

Режимы можно объединять, например `"im"`.

### 31.4 Диагностика

- неверное число аргументов диагностируется на этапе семантического анализа;
- неверный тип аргумента диагностируется на этапе семантического анализа;
- недопустимое регулярное выражение даёт диагностику времени выполнения `MB3007`;
- неизвестный символ режима даёт диагностику времени выполнения `MB3007`;
- отрицательный номер группы в `REGEXEXTRACT` и `REGEXEXTRACTALL` даёт диагностику времени выполнения `MB3007`;
- отрицательное количество замен в `REGEXREPLACE` даёт диагностику времени выполнения `MB3007`;
- каждая операция по регулярному выражению ограничена пятью секундами, превышение ограничения даёт диагностику времени выполнения `MB3007`.

### 31.5 Решение по именам

В классическом QuickBASIC полноценного встроенного слоя регулярных выражений нет. Visual Basic даёт оператор `Like` для более простого сопоставления с образцом, а современная линия Visual Basic через .NET использует семейство `System.Text.RegularExpressions.Regex`, где есть операции `Match`, `Matches` и `Split`. Поэтому для Axiom оставлены уже зарезервированные имена `REGEXMATCH`, `REGEXMATCHES` и `REGEXSPLIT`; `REGEXEXTRACTALL` является парой к уже существующей функции `REGEXEXTRACT`.

## 32. Файловая система и текстовые файлы

Axiom поддерживает функции файловой системы, а также минимальную операторную модель для текстовых файлов. Исторические файловые номера в духе старого BASIC не используются: вместо них введён специальный тип `FILE`.

### 32.1 Тип FILE и операторы работы с открытым файлом

Поддерживаются формы:

- `DIM f AS FILE`
- `OPEN <путь> FOR INPUT AS f`
- `OPEN <путь> FOR OUTPUT AS f`
- `OPEN <путь> FOR APPEND AS f`
- `CLOSE f`

Правила:

- переменная типа `FILE` хранит состояние открытого текстового файла;
- значение типа `FILE` нельзя присваивать напрямую через обычное присваивание;
- `OPEN` открывает файл и записывает результат в указанную переменную типа `FILE`;
- `CLOSE` закрывает ранее открытый файл;
- для чтения используется режим `INPUT`;
- для записи с очисткой файла используется режим `OUTPUT`;
- для дописывания в конец используется режим `APPEND`.

### 32.3 Поведение

- Все функции файловой системы принимают путь как `STRING`.
- Перед обращением к файлу или папке путь приводится к полному виду.
- `OPEN` использует тот же путь и ту же кодировку UTF-8, что и функции `READFILE`, `READALLLINES`, `WRITEFILE` и `APPENDFILE`.
- `OPEN ... FOR INPUT AS f` требует существующий текстовый файл и открывает его для чтения.
- `OPEN ... FOR OUTPUT AS f` создаёт новый текстовый файл или полностью перезаписывает существующий.
- `OPEN ... FOR APPEND AS f` открывает файл для дописывания в конец и создаёт его при отсутствии.
- `CLOSE f` закрывает файл и переводит переменную `FILE` обратно в закрытое состояние.
- `ISOPEN` возвращает `TRUE`, если переменная `FILE` сейчас содержит открытый файл, и `FALSE` для ещё не открытого или уже закрытого файла.
- `FILEPATH` возвращает полный путь открытого файла.
- `FILEMODE` возвращает строку `INPUT`, `OUTPUT` или `APPEND` по текущему режиму открытого файла.
- `FILEPOS` возвращает текущую позицию внутри уже открытого файла в байтах от начала файла.
- `FILELENGTH` возвращает текущую длину уже открытого файла в байтах.
- `LINENUMBER` разрешена только для файла, открытого в режиме чтения, и возвращает номер текущей строки для следующего чтения.
- `EOF` разрешена только для файла, открытого в режиме чтения.
- `READTOEND` разрешена только для файла, открытого в режиме чтения, и возвращает весь оставшийся текст от текущей позиции до конца файла.
- `READTEXT` разрешена только для файла, открытого в режиме чтения, и возвращает следующий фрагмент текста длиной до `count` символов.
- `READLINE` разрешена только для файла, открытого в режиме чтения, и читает одну строку без символов перевода строки.
- `READLINES` разрешена только для файла, открытого в режиме чтения, и читает до `count` следующих строк без символов перевода строки.
- `READLINES` возвращает одномерный массив `STRING()`.
- Непустой результат `READLINES` получает границы массива `1 TO N`.
- Если `count = 0`, `READLINES` возвращает выделенный пустой массив `1 TO 0` и не меняет позицию чтения.
- Если файл уже находится в конце, `READLINES` возвращает выделенный пустой массив `1 TO 0`.
- Если до конца файла осталось меньше строк, чем указано в `count`, `READLINES` возвращает только доступные строки.
- `SKIPLINE` разрешена только для файла, открытого в режиме чтения, пропускает одну строку и возвращает `TRUE`.
- `WRITE` разрешена только для файла, открытого в режиме записи или дописывания, и помещает текст в буфер записи без перевода строки.
- `WRITELINE` разрешена только для файла, открытого в режиме записи или дописывания, помещает текст в буфер записи и завершает строку переводом строки.
- `NEWLINE` разрешена только для файла, открытого в режиме записи или дописывания, записывает только перевод строки и возвращает `TRUE`.
- `FLUSH` разрешена только для файла, открытого в режиме записи или дописывания, и принудительно сбрасывает буфер записи на диск.
- `CLOSE` завершает работу с файлом и тоже гарантированно сбрасывает накопленный буфер записи.
- `SEEKFILE` переводит уже открытый файл на указанную позицию в байтах от начала файла и возвращает `TRUE`.
- `REWIND` переводит уже открытый файл в начало и возвращает `TRUE`.
- Для `SEEKFILE` первая позиция равна `0`.
- `SEEKFILE` разрешён только для файлов, открытых в режимах `INPUT` и `OUTPUT`.
- `REWIND` разрешён только для файлов, открытых в режимах `INPUT` и `OUTPUT`.
- `SEEKFILE` не разрешает выходить за пределы диапазона от `0` до текущей длины файла включительно.
- В режиме `OUTPUT` функции `FILEPOS` и `FILELENGTH` учитывают уже накопленные, но ещё не сброшенные буфером данные.
- Низкоуровневая позиция файла в `FILEPOS`, `FILELENGTH`, `SEEKFILE` и `REWIND` всегда считается в байтах.
- Текстовое чтение в `READLINE`, `READLINES`, `READTEXT` и `READTOEND` всегда работает с символами текста.
- `LINENUMBER` тоже относится к текстовой модели чтения и возвращает номер строки, в которой находится текущая позиция для чтения.
- После успешного `READLINE` или `SKIPLINE` номер строки увеличивается на единицу.
- После успешного `READLINES` номер строки увеличивается на число фактически прочитанных строк.
- Если `SEEKFILE` или `REWIND` меняют позицию чтения, `LINENUMBER` затем вычисляется уже по новой текущей позиции.
- Эти две модели можно смешивать, но позиция перед текстовым чтением должна попадать на корректную границу символа UTF-8.
- Если позиция указывает внутрь многобайтного символа UTF-8, `READLINE`, `READLINES`, `READTEXT` и `READTOEND` дают диагностику времени выполнения.
- `READTEXT` с `count = 0` возвращает пустую строку.
- `READTEXT` с `count < 0` даёт диагностику времени выполнения.
- `READTEXT` может вернуть меньше символов, чем запрошено, если до конца файла осталось меньше текста.
- `READLINES` с `count < 0` даёт диагностику времени выполнения.
- `READTOEND` в конце файла возвращает пустую строку.
- Первая строка текстового файла имеет номер `1`.
- `FILEEXISTS` возвращает `TRUE`, если существует файл.
- `DIREXISTS` возвращает `TRUE`, если существует папка.
- `PATHEXISTS` возвращает `TRUE`, если существует файл или папка.
- `READFILE` читает текстовый файл целиком и возвращает его содержимое.
- `READALLLINES` читает текстовый файл целиком по строкам и возвращает одномерный массив `STRING()`.
- Строки в результате `READALLLINES` не содержат символов перевода строки.
- Непустой результат `READALLLINES` получает границы массива `1 TO N`.
- Пустой файл в `READALLLINES` возвращает выделенный пустой массив `1 TO 0`.
- `WRITEFILE` создаёт новый текстовый файл или перезаписывает существующий и возвращает `TRUE` при успешном завершении.
- `APPENDFILE` добавляет текст в конец файла, создаёт файл при его отсутствии и возвращает `TRUE` при успешном завершении.
- `FILESIZE` возвращает размер существующего файла в байтах.
- `FILEDATE` возвращает дату последнего изменения файла в форме `yyyy-MM-dd HH:mm:ss`.
- `FILECREATEDATE` возвращает дату создания существующего файла в форме `yyyy-MM-dd HH:mm:ss`.
- `FILEACCESSEDDATE` возвращает дату последнего доступа к существующему файлу в форме `yyyy-MM-dd HH:mm:ss`.
- `DIRDATE` возвращает дату последнего изменения существующей папки в форме `yyyy-MM-dd HH:mm:ss`.
- `GETFILES` возвращает одномерный массив строк с полными путями файлов ближайшего уровня указанной папки.
- `GETFILES` без второго аргумента использует маску `*`.
- `GETFILES` со вторым аргументом использует указанную файловую маску, например `*.txt`.
- `GETDIRS` возвращает одномерный массив строк с полными путями папок ближайшего уровня указанной папки.
- `GETDIRS` без второго аргумента использует маску `*`.
- `GETDIRS` со вторым аргументом использует указанную файловую маску, например `data*`.
- `GETFILES` и `GETDIRS` не выполняют рекурсивный обход вложенных папок.
- Результат `GETFILES` и `GETDIRS` сортируется без учёта регистра.
- Непустой результат `GETFILES` и `GETDIRS` получает границы массива `1 TO N`.
- Пустой результат `GETFILES` и `GETDIRS` возвращается как выделенный пустой массив `1 TO 0`.
- `COMBINEPATH` соединяет две части пути.
- `FILENAME` возвращает имя файла из пути.
- `DIRNAME` возвращает имя папки из полного пути.
- `EXTNAME` возвращает расширение файла вместе с точкой или пустую строку, если расширения нет.
- `FULLPATH` возвращает полный путь.
- `PATHROOT` возвращает корневую часть полного пути, например `C:\`.
- `ISABSOLUTEPATH` возвращает `TRUE`, если путь уже задан как абсолютный.
- `MAKEDIR` создаёт папку и возвращает `TRUE`; если папка уже существует, результат также равен `TRUE`.
- `DELETEFILE` удаляет файл и возвращает `TRUE`; если файла нет, возвращает `FALSE`.
- `COPYFILE` копирует файл. Без третьего аргумента существующий целевой файл не перезаписывается.
- `COPYFILE` с третьим аргументом `TRUE` может перезаписать существующий целевой файл.
- `MOVEFILE` переносит файл. Без третьего аргумента существующий целевой файл не перезаписывается.
- `MOVEFILE` с третьим аргументом `TRUE` может перезаписать существующий целевой файл.
- `RENAMEFILE` переименовывает файл в той же папке.
- `DELETEDIR` удаляет пустую папку и возвращает `TRUE`; если папки нет, возвращает `FALSE`.
- `DELETEDIRRECURSIVE` удаляет папку вместе со всем содержимым и возвращает `TRUE`; если папки нет, возвращает `FALSE`.
- `COPYDIR` копирует папку вместе с содержимым. Без третьего аргумента существующие целевые файлы не перезаписываются.
- `COPYDIR` с третьим аргументом `TRUE` может перезаписать существующие целевые файлы.
- `MOVEDIR` переносит папку.
- `RENAMEDIR` переименовывает папку в той же родительской папке.
- `CURRENTDIR` возвращает текущую папку программы в полном виде.
- `CHANGEDIR` меняет текущую папку программы и возвращает `TRUE` при успешном завершении.
- После `CHANGEDIR` все последующие относительные пути вычисляются уже относительно новой текущей папки программы.
- `DIRSIZE` возвращает суммарный размер файлов в папке и её вложенных папках в байтах.
- `DIRSIZE` не заходит в папки-ссылки и другие точки повторного анализа, чтобы не образовывать циклы обхода.
- `FREESPACE` возвращает доступное свободное место на диске, к которому относится указанный путь.
- `TOTALFREESPACE` возвращает общее свободное место на диске, к которому относится указанный путь.
- `TOTALSPACE` возвращает полный размер диска, к которому относится указанный путь.
- `ISREADONLY` возвращает `TRUE`, если файл или папка имеют атрибут только для чтения.
- `ISHIDDEN` возвращает `TRUE`, если файл или папка имеют скрытый атрибут.
- `DRIVENAME` возвращает имя диска, к которому относится указанный путь, например `C:\`.
- `DRIVEFORMAT` возвращает строковое имя файловой системы, например `NTFS`.
- `DRIVETYPE` возвращает строковое имя типа диска, например `Fixed`, `Network` или `Removable`.
- `MAKETEMPFILE` создаёт новый пустой временный файл в системной временной папке и возвращает полный путь к нему.
- `MAKETEMPDIR` создаёт новую временную папку в системной временной папке и возвращает полный путь к ней.
- В `MAKETEMPFILE` и `MAKETEMPDIR` аргумент `<префикс>` задаёт только начало имени; путь в нём недопустим.

### 32.4 Диагностика

- неверное число аргументов диагностируется на этапе семантического анализа;
- неверный тип аргумента диагностируется на этапе семантического анализа;
- попытка присвоить значение типа `FILE` напрямую диагностируется на этапе семантического анализа;
- недопустимый путь, отказ доступа или ошибка файловой системы дают диагностику времени выполнения `MB3007`;
- попытка открыть файл в переменную `FILE`, которая уже содержит открытый файл, даёт диагностику времени выполнения `MB3007`;
- попытка закрыть уже закрытый `FILE` даёт диагностику времени выполнения `MB3007`;
- вызов `FILEPATH`, `FILEMODE`, `FILEPOS`, `FILELENGTH`, `LINENUMBER`, `EOF`, `READTOEND`, `READTEXT`, `READLINE`, `READLINES`, `SKIPLINE`, `WRITE`, `WRITELINE`, `NEWLINE`, `FLUSH`, `SEEKFILE` или `REWIND` для закрытого `FILE` даёт диагностику времени выполнения `MB3007`;
- вызов `LINENUMBER`, `EOF`, `READTOEND`, `READTEXT`, `READLINE`, `READLINES` или `SKIPLINE` для файла, открытого не в режиме `INPUT`, даёт диагностику времени выполнения `MB3007`;
- вызов `WRITE`, `WRITELINE`, `NEWLINE` или `FLUSH` для файла, открытого не в режиме `OUTPUT` или `APPEND`, даёт диагностику времени выполнения `MB3007`;
- вызов `SEEKFILE` для файла, открытого в режиме `APPEND`, даёт диагностику времени выполнения `MB3007`;
- вызов `REWIND` для файла, открытого в режиме `APPEND`, даёт диагностику времени выполнения `MB3007`;
- отрицательная позиция или попытка выйти за пределы файла в `SEEKFILE` даёт диагностику времени выполнения `MB3007`;
- отрицательный `count` в `READTEXT` и `READLINES` даёт диагностику времени выполнения `MB3007`;
- позиция, не совпадающая с корректной границей символа UTF-8, в `READLINE`, `READLINES`, `READTEXT` и `READTOEND` даёт диагностику времени выполнения `MB3007`;
- вызов `READLINE` после достижения конца файла даёт диагностику времени выполнения `MB3007`;
- вызов `SKIPLINE` после достижения конца файла даёт диагностику времени выполнения `MB3007`;
- отсутствие файла для `READFILE`, `READALLLINES`, `FILESIZE`, `FILEDATE`, `FILECREATEDATE` и `FILEACCESSEDDATE` даёт диагностику времени выполнения `MB3007`.
- отсутствие исходного файла для `COPYFILE`, `MOVEFILE` и `RENAMEFILE` даёт диагностику времени выполнения `MB3007`.
- отсутствие исходной папки для `GETFILES`, `GETDIRS`, `COPYDIR`, `MOVEDIR`, `RENAMEDIR`, `CHANGEDIR`, `DIRSIZE` и `DIRDATE` даёт диагностику времени выполнения `MB3007`.
- отсутствие файла или папки для `ISREADONLY` и `ISHIDDEN` даёт диагностику времени выполнения `MB3007`.
- попытка удалить непустую папку через `DELETEDIR` даёт диагностику времени выполнения `MB3007`.
- пустая маска для `GETFILES` и `GETDIRS` даёт диагностику времени выполнения `MB3007`.
- недопустимый префикс имени для `MAKETEMPFILE` и `MAKETEMPDIR` даёт диагностику времени выполнения `MB3007`.
- переполнение суммарного размера в `DIRSIZE` даёт диагностику времени выполнения `MB3008`.

### 32.5 Отложенные возможности

Следующие возможности пока остаются отложенными. Это предварительный перечень развития, а не уже действующий контракт языка:

- двоичная модель файлов как отдельный будущий слой вокруг `FILE`, включая форму `OPEN ... FOR BINARY AS <file>`;
- побайтовое чтение и запись как отдельный будущий слой, например `READBYTE` и `WRITEBYTE`;
- чтение и запись блоков байтов и наборов числовых значений после завершения нужного этапа развития массивов;
- символьные ссылки;
- наблюдение за изменениями файлов;
- историческая модель `OPEN`/`CLOSE` с файловыми номерами.

## Update 2026-04-20 - Arrays As First-Class Values

This update completes the second foundation slice for one-dimensional arrays.

- Arrays now have an explicit semantic type: `ArrayTypeSymbol(ElementType)`.
- A declared array variable is no longer modeled only by `VariableSymbol.IsArray`; the variable type itself is the source of truth.
- In variable declarations, the existing syntax `DIM name(...) AS TYPE` still declares arrays.
- In type positions, an array type is written as `TYPE()`, for example:
  - parameter: `items AS INTEGER()`
  - function result: `AS STRING()`
  - nested function type result: `FUNCTION(INTEGER) AS INTEGER()`
- Whole-array assignment is now valid when source and target have the same array type.
- Arrays can now be passed to `SUB` / `FUNCTION` parameters and returned from `FUNCTION`.
- The current assignment and parameter-passing model is shared-reference semantics:
  - assigning an array variable copies the array reference, not the elements;
  - passing an array parameter copies the reference value into the callee;
  - mutating array elements through that reference is observable by every alias.
- Indexing syntax is intentionally unchanged in this stage: element access still uses the array name form `arr(index)`.
- `DIM arr() AS TYPE` still means an unallocated dynamic array and indexing it before future allocation still reports runtime diagnostic `MB3005`.
- `REDIM`, `REDIM PRESERVE`, `ERASE`, explicit cloning, and generalized postfix indexing remain deferred to the next stages.

## Update 2026-04-20 - REDIM For Dynamic One-Dimensional Arrays

This update completes the first lifecycle operation for one-dimensional arrays.

- The language now supports `REDIM name(<lower> TO <upper>)` as a statement.
- `REDIM` works with existing one-dimensional array variables and array parameters.
- The current stage supports only the basic form:
  - no `REDIM PRESERVE`;
  - no empty form `REDIM name()`;
  - no multidimensional shape changes.
- A successful `REDIM` allocates the array if it was still unallocated after `DIM name() AS TYPE`.
- A successful `REDIM` also reallocates an already allocated array and resets all elements to their default values.
- Because array assignment and parameter passing already use shared-reference semantics, `REDIM` mutates the shared array storage:
  - if two variables refer to the same array, `REDIM` through either alias changes the visible bounds for both;
  - the old element values are discarded in the non-`PRESERVE` form.
- Bounds are inclusive and continue to use the existing array range contract `lower TO upper`.
- Lower and upper bounds must be numeric expressions convertible to runtime array bounds.
- If the resulting upper bound is smaller than the lower bound, runtime reports `MB3005`.
- Using `REDIM` on a non-array name is rejected during semantic analysis through the existing array-target diagnostic path.
- `REDIM PRESERVE`, `ERASE`, and informational array built-ins remain the next follow-up steps.

## Update 2026-04-20 - REDIM PRESERVE For Dynamic One-Dimensional Arrays

This update completes the second lifecycle slice for one-dimensional arrays.

- The language now supports `REDIM PRESERVE name(<lower> TO <upper>)` as a statement.
- `REDIM PRESERVE` uses the same explicit bound syntax as the base `REDIM` form.
- If the target array is still unallocated, `REDIM PRESERVE` allocates it just like `REDIM`.
- If the target array is already allocated, `REDIM PRESERVE` keeps the overlapping portion of the old and new ranges:
  - an index is preserved only if it exists in both the previous and the new bounds;
  - preserved elements keep their previous runtime values;
  - indices that are new in the resulting range are initialized with the default value of the array element type.
- Preservation is defined by logical index, not by physical offset:
  - resizing `1 TO 3` into `2 TO 4` keeps old elements `2` and `3`;
  - old element `1` is discarded;
  - new element `4` is initialized to the default value.
- The shared-reference array model is unchanged:
  - `REDIM PRESERVE` mutates the same `RuntimeArrayValue` object;
  - if two variables or parameters alias the same array, preserving through either alias changes the visible bounds and preserved contents for both.
- The current lifecycle surface still remains intentionally narrow:
  - no empty form `REDIM name()`;
  - no multidimensional shape changes;
  - no `ERASE` yet.
- `ERASE` and informational built-ins such as `LBOUND`, `UBOUND`, `ARRAYLENGTH`, and `ARRAYISALLOCATED` remain the next follow-up steps.

## Update 2026-04-20 - ERASE For Dynamic One-Dimensional Arrays

This update completes the third lifecycle slice for one-dimensional arrays.

- The language now supports `ERASE name` as a statement.
- In the current stage, `ERASE` accepts exactly one array name.
- `ERASE` works with existing one-dimensional array variables and array parameters.
- A successful `ERASE` returns the target array to the unallocated state:
  - after `ERASE`, indexing the array again reports runtime diagnostic `MB3005` until a later successful `REDIM` or `REDIM PRESERVE`;
  - old bounds and old element values are discarded.
- The shared-reference array model is unchanged:
  - `ERASE` mutates the same `RuntimeArrayValue` object;
  - if two variables or parameters alias the same array, erasing through either alias makes the array unallocated for both.
- Using `ERASE` on a non-array name is rejected during semantic analysis through the existing array-target diagnostic path.
- Informational built-ins such as `LBOUND`, `UBOUND`, `ARRAYLENGTH`, and `ARRAYISALLOCATED` remain the next follow-up steps.

## Обновление 2026-04-20 - Информационные встроенные функции одномерных массивов

Этот шаг завершает первый набор функций, которые позволяют программе узнать текущее состояние одномерного массива без изменения его содержимого.

- Язык теперь поддерживает функции `LBOUND`, `UBOUND`, `ARRAYLENGTH` и `ARRAYISALLOCATED`.
- Все четыре функции принимают ровно один аргумент, и этот аргумент должен иметь тип одномерного массива.
- `LBOUND(array)` возвращает нижнюю границу выделенного массива.
- `UBOUND(array)` возвращает верхнюю границу выделенного массива.
- `ARRAYLENGTH(array)` возвращает текущее число элементов массива.
- `ARRAYISALLOCATED(array)` возвращает `TRUE`, если массив уже выделен, и `FALSE`, если он всё ещё находится в невыделенном состоянии после `DIM name() AS TYPE` или после `ERASE`.
- Поведение для невыделенного массива намеренно различается:
  - `LBOUND` и `UBOUND` недопустимы и во время выполнения сообщают `MB3005`;
  - `ARRAYLENGTH` безопасно возвращает `0`;
  - `ARRAYISALLOCATED` безопасно возвращает `FALSE`.
- Эти функции не меняют содержимое массива и не меняют его границы.
- Текущий контракт по-прежнему относится только к одномерным массивам.

Следующий ожидаемый шаг после этого среза — зафиксировать в модели времени выполнения нормальную форму пустого, но уже выделенного массива, чтобы будущие функции, возвращающие массивы, могли безопасно возвращать пустой результат без перехода в невыделенное состояние.

## Обновление 2026-04-20 - Пустой выделенный одномерный массив

Этот шаг отделяет пустой выделенный массив от полностью невыделенного состояния.

- Нормальная форма пустого выделенного одномерного массива — диапазон `1 TO 0`.
- Такой массив считается выделенным:
  - `ARRAYISALLOCATED(array)` возвращает `TRUE`;
  - `ARRAYLENGTH(array)` возвращает `0`;
  - `LBOUND(array)` возвращает `1`;
  - `UBOUND(array)` возвращает `0`.
- Индексация пустого выделенного массива всегда выходит за границы, потому что допустимых индексов в нём нет.
- Обычный `REDIM name(1 TO 0)` выделяет пустой массив и сбрасывает старые элементы.
- `REDIM PRESERVE name(1 TO 0)` тоже создаёт пустой выделенный массив; пересечение диапазонов при этом пустое, поэтому старые элементы не сохраняются.
- Объявление `DIM name(1 TO 0) AS TYPE` также создаёт пустой выделенный массив.
- `ERASE name` по-прежнему переводит массив именно в невыделенное состояние, а не в пустой выделенный диапазон.
- Любой другой диапазон, где верхняя граница меньше нижней, остаётся недопустимым и даёт диагностику времени выполнения `MB3005`.

Этот контракт нужен как основа для будущих функций, возвращающих массивы: пустой результат должен возвращаться как выделенный массив `1 TO 0`, а не как невыделенное значение.

## Обновление 2026-04-20 - GETFILES и GETDIRS

Этот шаг переносит договор результата `STRING()` на первые файловые функции перечисления.

- Язык теперь поддерживает `GETFILES` и `GETDIRS`.
- `GETFILES(path)` и `GETFILES(path, pattern)` возвращают массив полных путей файлов ближайшего уровня указанной папки.

## Проектный договор 2026-04-20 - ARRAYCLONE и ARRAYSLICE

Этот раздел фиксирует ближайший договор для первых чистых операций над одномерными массивами. Эти функции ещё не являются реализованным поведением языка до отдельного шага реализации.

### ARRAYCLONE

- Форма вызова: `ARRAYCLONE(array) AS T()`, где `T()` — фактический тип переданного одномерного массива.
- Функция создаёт новый массив того же типа элемента.
- Исходный массив не изменяется.
- Результат не должен ссылаться на то же хранилище элементов, что и исходный массив.
- Если исходный массив не выделен, результатом становится новый невыделенный массив того же типа.
- Если исходный массив выделен и содержит элементы, результат сохраняет те же нижнюю и верхнюю границы.
- Если исходный массив выделен как пустой `1 TO 0`, результат тоже выделяется как пустой `1 TO 0`.
- Значения элементов копируются по тем же правилам значения, которые уже действуют для элементов массива. Отдельное глубокое копирование вложенных объектов этим договором не вводится.

### ARRAYSLICE

- Форма вызова: `ARRAYSLICE(array, start AS INTEGER, count AS INTEGER) AS T()`, где `T()` — фактический тип переданного одномерного массива.
- Функция создаёт новый массив из части исходного массива.
- `start` — логический индекс исходного массива, а не смещение от нуля.
- `count` — число элементов, которое нужно взять.
- Исходный массив не изменяется.
- Результат не должен ссылаться на то же хранилище элементов, что и исходный массив.
- Для непустого результата всегда используется компактный диапазон `1 TO count`.
- Если `count = 0`, результатом становится выделенный пустой массив `1 TO 0`.
- Если исходный массив не выделен, вызов считается ошибкой состояния массива и должен давать диагностику времени выполнения `MB3005`.
- Если `count < 0`, вызов должен давать диагностику времени выполнения `MB3007`.
- Если `count > 0`, весь диапазон от `start` до `start + count - 1` должен попадать в текущие границы исходного массива. Нарушение этого правила должно давать диагностику времени выполнения `MB3007`.

## Проектный договор 2026-04-20 - Поисковые и счётные функции одномерного массива

Следующий пакет одномерных массивов должен вводиться как согласованная группа:

- `ARRAYCONTAINS(array, value) AS BOOLEAN`
- `ARRAYINDEXOF(array, value) AS INTEGER`
- `ARRAYLASTINDEXOF(array, value) AS INTEGER`
- `ARRAYCOUNT(array, value) AS INTEGER`

Базовый договор пакета:

- Все четыре функции работают только с уже выделенным одномерным массивом.
- Невыделенный массив не считается случаем "совпадения нет" и должен сообщать `MB3005`.
- Сравнение элементов массива со значением поиска должно использовать то же правило равенства, которое уже применяется во время выполнения языка.
- Поиск должен работать в логических индексах текущего массива, а не в смещениях от нуля.
- Если массив выделен, но пуст, это допустимый случай поиска без совпадений.

Договор результата при отсутствии совпадения:

- `ARRAYCONTAINS` возвращает `FALSE`.
- `ARRAYCOUNT` возвращает `0`.
- `ARRAYINDEXOF` возвращает значение строго левее текущего диапазона массива.
- `ARRAYLASTINDEXOF` возвращает значение строго левее текущего диапазона массива.

Выбранная форма специального индекса для отсутствия совпадения:

- Если совпадение отсутствует, `ARRAYINDEXOF` и `ARRAYLASTINDEXOF` должны возвращать `LBOUND(array) - 1`.
- Фиксированные специальные значения вроде `0` или `-1` для этого пакета запрещены, потому что в Axiom массив уже может иметь произвольную нижнюю границу.
- Для пустого выделенного массива `1 TO 0` значение "не найдено" по тому же правилу равно `0`.

Связанный защитный договор перед реализацией:

- До выпуска поискового пакета нужно явно закрыть вопрос переполнения для случая, когда нижняя граница массива равна минимальному значению `INTEGER`.
- Допустимы два пути:
  - либо заранее запретить такую нижнюю границу при `DIM` и `REDIM`;
  - либо в самой реализации поискового пакета ввести эквивалентную защиту и отдельную диагностику времени выполнения.
- Реализация пакета не должна выходить в рабочее состояние, пока этот крайний случай не закреплён явно в коде и тестах.

- Язык теперь поддерживает `ARRAYTOSORTED(array)`.
- Функция работает только с уже выделенным одномерным массивом.
- Невыделенный массив сообщает `MB3005`.
- Функция принимает только массивы с числовыми или строковыми элементами.
- Исходный массив не изменяется.
- Результат имеет тот же тип элемента, что и исходный массив.
- Результат сохраняет текущие логические границы исходного массива, а не переводит его в компактный диапазон `1 TO N`.
- Сортировка использует то же упорядоченное сравнение, что язык уже применяет для чисел и строк.
- Дубликаты не удаляются.
- Для пустого выделенного массива `1 TO 0` функция возвращает такой же пустой выделенный массив `1 TO 0`.

## Обновление 2026-04-20 - ARRAYFILL, ARRAYREVERSE и ARRAYSORT

Этот шаг открывает mutating-подпакет одномерных массивов.

- Язык теперь поддерживает процедуры `ARRAYFILL(array, value)`, `ARRAYREVERSE(array)` и `ARRAYSORT(array)`.
- Все три операции меняют уже выделенный массив на месте.
- Эти операции вызываются как отдельные инструкции и не возвращают пользовательского значения.
- Невыделенный массив сообщает `MB3005`.
- Пустой выделенный массив `1 TO 0` допустим и обрабатывается без ошибки.
- `ARRAYFILL` привязывает аргумент `value` к типу элемента массива и записывает это значение во все логические индексы текущего диапазона.
- `ARRAYREVERSE` меняет порядок элементов на обратный и сохраняет текущие границы массива.
- `ARRAYSORT` поддерживает только массивы с числовыми или строковыми элементами.
- `ARRAYSORT` сортирует элементы по неубыванию, используя то же упорядоченное сравнение, что уже действует в языке для чисел и строк.
- Ни одна из этих процедур не меняет сами границы массива.

## Обновление 2026-04-20 - ARRAYPUSH и ARRAYPOP

Этот шаг закрывает следующий mutating-блок одномерных массивов.

- Язык теперь поддерживает процедуру `ARRAYPUSH(array, value)`.
- Язык теперь поддерживает функцию `ARRAYPOP(array)`.
- Обе операции работают только с уже выделенным одномерным массивом.
- Невыделенный массив сообщает `MB3005`.
- `ARRAYPUSH` привязывает аргумент `value` к типу элемента массива.
- `ARRAYPUSH` расширяет массив вправо на один логический индекс и записывает новое значение в новый верхний элемент.
- Для непустого массива `ARRAYPUSH` сохраняет текущую нижнюю границу и увеличивает верхнюю границу на `1`.
- Для пустого выделенного массива `1 TO 0` вызов `ARRAYPUSH` создаёт первый элемент и переводит массив в форму `1 TO 1`.
- `ARRAYPOP` возвращает последний элемент массива как обычное значение типа элемента массива.
- Если после `ARRAYPOP` массив остаётся непустым, его нижняя граница сохраняется, а верхняя уменьшается на `1`.
- Если `ARRAYPOP` снимает единственный элемент массива, массив переходит в каноническую пустую форму `1 TO 0`.
- `ARRAYPOP` не поддерживает пустой выделенный массив `1 TO 0`; этот случай сообщает `MB3007`.
- Из-за канонической пустой формы информация о прежней нижней границе после полного опустошения массива не сохраняется.

## Обновление 2026-04-20 - ARRAYINSERT и ARRAYREMOVE

Этот шаг закрывает indexed mutating-блок одномерных массивов.

- Язык теперь поддерживает процедуру `ARRAYINSERT(array, index, value)`.
- Язык теперь поддерживает функцию `ARRAYREMOVE(array, index)`.
- Обе операции работают только с уже выделенным одномерным массивом.
- Невыделенный массив сообщает `MB3005`.
- Обе операции используют логические индексы текущего массива, а не смещения от нуля.
- `ARRAYINSERT` привязывает аргумент `value` к типу элемента массива.
- Для непустого массива `ARRAYINSERT` допускает индекс от `LBOUND(array)` до `UBOUND(array) + 1`.
- `ARRAYINSERT` сдвигает все элементы начиная с позиции `index` вправо на один логический индекс, записывает новое значение в `index`, сохраняет текущую нижнюю границу массива и увеличивает верхнюю границу на `1`.
- Вставка по `UBOUND(array) + 1` эквивалентна добавлению нового последнего элемента.
- Для пустого выделенного массива `1 TO 0` `ARRAYINSERT` допускает только индекс `1`, после чего массив переходит в форму `1 TO 1`.
- Если индекс вставки недопустим или расширение правой границы переполняет диапазон `INTEGER`, `ARRAYINSERT` сообщает `MB3007`.
- `ARRAYREMOVE` возвращает удалённый элемент массива как обычное значение типа элемента массива.
- Для непустого массива `ARRAYREMOVE` допускает индекс только внутри текущего диапазона от `LBOUND(array)` до `UBOUND(array)`.
- `ARRAYREMOVE` сдвигает все элементы правее удаляемой позиции влево на один логический индекс, сохраняет текущую нижнюю границу и уменьшает верхнюю границу на `1`.
- Если `ARRAYREMOVE` снимает единственный элемент массива, массив переходит в каноническую пустую форму `1 TO 0`.
- `ARRAYREMOVE` не поддерживает пустой выделенный массив `1 TO 0`; этот случай сообщает `MB3007`.

## Обновление 2026-04-20 - ARRAYSOME и ARRAYEVERY

Этот шаг открывает минимальный стартовый подпакет higher-order-операций над одномерными массивами.

- Язык теперь поддерживает `ARRAYEVERY(array, predicate)`.
- Язык теперь поддерживает `ARRAYSOME(array, predicate)`.
- Обе функции работают только с уже выделенным одномерным массивом.
- Невыделенный массив сообщает `MB3005`.
- Аргумент `predicate` должен иметь тип `FUNCTION(T) AS BOOLEAN`, где `T` — тип элемента массива.
- В роли `predicate` разрешены обычные именованные функции и возвращённые замыкания Axiom.
- Callback получает только текущее значение элемента массива; дополнительный индекс и сам массив в этот минимальный срез не входят.
- `ARRAYEVERY` возвращает `TRUE`, если `predicate` возвращает `TRUE` для каждого элемента массива.
- `ARRAYSOME` возвращает `TRUE`, если `predicate` возвращает `TRUE` хотя бы для одного элемента массива.
- Для пустого выделенного массива `1 TO 0`:
  - `ARRAYEVERY` возвращает `TRUE`;
  - `ARRAYSOME` возвращает `FALSE`.
- Обе функции не меняют исходный массив.
- Если `predicate` содержит пустое значение функционального типа, выполнение сообщает `MB3009`.

## Обновление 2026-04-20 - ARRAYFILTER

Следующий producer higher-order-шаг поверх уже введённого predicate-механизма — `ARRAYFILTER(array, predicate)`.

- Язык теперь поддерживает `ARRAYFILTER(array, predicate)`.
- `ARRAYFILTER` работает только с уже выделенным одномерным массивом.
- Невыделенный массив сообщает `MB3005`.
- Аргумент `predicate` должен иметь тип `FUNCTION(T) AS BOOLEAN`, где `T` — тип элемента массива.
- В роли `predicate` разрешены обычные именованные функции и возвращённые замыкания Axiom.
- Callback получает только текущее значение элемента массива; индекс и сам массив в этот шаг не входят.
- `ARRAYFILTER` не меняет исходный массив.
- Результат имеет тот же тип элементов `T`, что и исходный массив.
- Результат всегда нормализуется к компактным границам:
  - если найдено `N > 0` элементов, результат имеет границы `1 TO N`;
  - если совпадений нет, результатом становится выделенный пустой массив `1 TO 0`.
- Порядок элементов в результате совпадает с порядком их обхода в исходном массиве.
- Пустой выделенный массив `1 TO 0` даёт пустой выделенный результат `1 TO 0`.
- Если `predicate` содержит пустое значение функционального типа, выполнение сообщает `MB3009`.

Этот договор намеренно остаётся минимальным:

- `ARRAYFILTER` становится первым producer higher-order built-in без расширения callback-контракта до `(value, index)` или `(value, index, array)`.
- Реализация должна использовать уже существующий в языке механизм function values и closures.
- Этот шаг не вводит новые синтаксические формы и не размораживает пока ещё не начатые `ARRAYMAP` и `ARRAYREDUCE`.

## Обновление 2026-04-20 - договор ARRAYMAP

- Callback получает только текущее значение элемента массива; индекс и сам массив в этот шаг не входят.
- `ARRAYMAP` не меняет исходный массив.
- Результат имеет тот же тип элементов `T`, что и исходный массив.
- Результат всегда нормализуется к компактным границам:
  - если исходный массив содержит `N > 0` элементов, результат имеет границы `1 TO N`;
  - если исходный массив пустой и выделен как `1 TO 0`, результатом становится выделенный пустой массив `1 TO 0`.
- Порядок элементов в результате совпадает с порядком их обхода в исходном массиве.

Этот договор намеренно остаётся минимальным:

- шаг не вводит новый механизм вывода типа результата built-in по возвращаемому типу callback-а;

## Обновление 2026-04-20 - договор ARRAYREDUCE

Следующий higher-order-шаг после `ARRAYMAP` — `ARRAYREDUCE(array, seed, reducer)`.

- Язык должен поддерживать `ARRAYREDUCE(array, seed, reducer)`.
- Первый зафиксированный вариант `ARRAYREDUCE` ограничен same-type accumulator-контрактом `T -> T`.
- `ARRAYREDUCE` работает только с уже выделенным одномерным массивом.
- Невыделенный массив сообщает `MB3005`.
- Аргумент `seed` должен иметь тот же тип `T`, что и элемент массива.
- Аргумент `reducer` должен иметь тип `FUNCTION(T, T) AS T`, где первый аргумент reducer-а — текущее значение аккумулятора, а второй — текущее значение элемента массива.
- В роли `reducer` разрешены обычные именованные функции и возвращённые замыкания Axiom.
- Callback получает только `(accumulator, value)`; индекс и сам массив в этот шаг не входят.
- `ARRAYREDUCE` не меняет исходный массив.
- Выполнение идёт по текущим логическим индексам массива слева направо, от `LBOUND(array)` до `UBOUND(array)`.
- Стартовое значение аккумулятора равно `seed`.
- Для каждого элемента массива выполняется шаг `acc = reducer(acc, element)`.
- Результатом функции становится финальное значение аккумулятора.
- Для пустого выделенного массива `1 TO 0` результатом становится исходное значение `seed`.
- Если `reducer` содержит пустое значение функционального типа, выполнение сообщает `MB3009`.

Этот договор намеренно остаётся минимальным:

- первый вариант `ARRAYREDUCE` не поддерживает polymorphic accumulator-контракт `FUNCTION(A, T) AS A`;
- шаг не вводит новый механизм вывода типа результата built-in по reducer-у;
- расширенный вариант с отдельным типом аккумулятора, если понадобится, должен рассматриваться отдельно;
- этот шаг не расширяет `ARRAYMAP` до `T -> U`.

## Обновление 2026-04-20 - договор пакета даты и времени

- Историческая опора для Microsoft BASIC-family зафиксирована так:
  - в классической линии GW-BASIC / QuickBASIC базовый пакет состоял из `DATE$`, `TIME$`, `TIMER`, а также statement-форм `DATE$ = ...` и `TIME$ = ...`;

  - имена с историческим суффиксом `$` не подходят текущей модели идентификаторов Axiom;

  - без нового scalar-типа `DATE`, `TIME` или `DATETIME` на первом этапе;

- Все публичные строковые представления даты и времени должны быть каноническими и locale-independent:
  - дата: `yyyy-MM-dd`;
  - время: `HH:mm:ss`;
  - дата и время: `yyyy-MM-dd HH:mm:ss`.
- Этот договор согласован с уже существующими file-system built-ins `FILEDATE`, `FILECREATEDATE`, `FILEACCESSEDDATE` и `DIRDATE`, которые уже возвращают `yyyy-MM-dd HH:mm:ss`.
- Locale-sensitive parsing в стиле VBA `DateValue` / `TimeValue`, зависящий от host Short Date и региональных настроек ОС, не должен копироваться в Axiom; разбор даты и времени должен быть явно определён спецификацией и одинаков на всех машинах.

### Этап 1 - минимальный classic clock surface

- Язык должен поддерживать `DATE() AS STRING`.
- `DATE()` возвращает текущую локальную дату в форме `yyyy-MM-dd`.
- Язык должен поддерживать `TIME() AS STRING`.
- `TIME()` возвращает текущее локальное время в форме `HH:mm:ss`.
- Язык должен поддерживать `NOW() AS STRING`.
- `NOW()` возвращает текущие локальные дату и время в форме `yyyy-MM-dd HH:mm:ss`.
- Язык должен поддерживать `TIMER() AS DOUBLE`.
- `TIMER()` возвращает число секунд, прошедших с локальной полуночи текущего дня.
- Для `TIMER()` допускается дробная часть секунд.

### Этап 2 - конструирование и извлечение частей

- Следующий минимальный дата-временной слой должен поддерживать:
  - `DATESERIAL(year, month, day) AS STRING`;
  - `TIMESERIAL(hour, minute, second) AS STRING`;
  - `YEAR(value) AS INTEGER`;
  - `MONTH(value) AS INTEGER`;
  - `DAY(value) AS INTEGER`;
  - `HOUR(value) AS INTEGER`;
  - `MINUTE(value) AS INTEGER`;
  - `SECOND(value) AS INTEGER`;
  - `WEEKDAY(value) AS INTEGER`.
- `DATESERIAL` должен принимать только целочисленные аргументы `year`, `month`, `day`, проверять календарную корректность даты и возвращать каноническую строку `yyyy-MM-dd`.
- `TIMESERIAL` должен принимать только целочисленные аргументы `hour`, `minute`, `second`, проверять корректность времени и возвращать каноническую строку `HH:mm:ss`.
- `DATESERIAL` и `TIMESERIAL` должны нормализовать результат только к каноническому строковому формату Axiom, а не к локально-зависимому отображаемому тексту.
- На этом этапе `DATESERIAL` и `TIMESERIAL` не должны выполнять арифметическую нормализацию переполненных компонентов:
  - `DATESERIAL(2026, 13, 1)` должен считаться ошибкой, а не автоматически превращаться в январь следующего года;
  - `TIMESERIAL(25, 0, 0)` должен считаться ошибкой, а не автоматически переноситься на следующие сутки.
- `YEAR`, `MONTH`, `DAY` должны работать как минимум с каноническими значениями даты `yyyy-MM-dd` и даты-времени `yyyy-MM-dd HH:mm:ss`.
- `HOUR`, `MINUTE`, `SECOND` должны работать как минимум с каноническими значениями времени `HH:mm:ss` и даты-времени `yyyy-MM-dd HH:mm:ss`.
- `YEAR`, `MONTH`, `DAY`, `WEEKDAY` не должны принимать локально-зависимые текстовые формы даты.
- `HOUR`, `MINUTE`, `SECOND` не должны принимать локально-зависимые текстовые формы времени.
- `WEEKDAY(value)` на этом этапе должен:
  - принимать только каноническую дату `yyyy-MM-dd` или каноническую дату-время `yyyy-MM-dd HH:mm:ss`;
  - возвращать целое число от `1` до `7`;
  - использовать Monday-first нумерацию: `1 = Monday`, `7 = Sunday`;
  - игнорировать time-часть, если передана дата-время;
  - не иметь второго параметра настройки первого дня недели.
- Для всех функций Этапа 2 некорректный текстовый формат или недопустимые компоненты даты/времени должны завершаться обычной runtime-диагностикой ошибки аргумента встроенной функции.

### Следующий отдельный этап поверх базового пакета

- Арифметика и нормализация даты и времени должны вводиться отдельным договором после стабилизации Этапа 1 и Этапа 2.
- В этот следующий этап должны войти как минимум кандидаты:
  - `DATEADD`;
  - `DATEDIFF`;
  - `DATEPART`;
  - `DATEVALUE`;
  - `TIMEVALUE`;
  - `ISDATE`;
  - modern helper built-ins вроде `ISLEAPYEAR` и `DAYSINMONTH`, если они действительно понадобятся после базового classic-compatible слоя.
- Этот следующий этап не должен смешиваться с первым вводом текущего пакета времени источника (`DATE`, `TIME`, `NOW`, `TIMER`) и пакетами конструирования/извлечения частей (`DATESERIAL`, `TIMESERIAL`, `YEAR` и т.д.).


## Обновление 2026-04-21 - Арифметический слой даты и времени

Следующий слой поверх уже реализованных DATE, TIME, NOW, TIMER, DATESERIAL, TIMESERIAL, YEAR, MONTH, DAY, HOUR, MINUTE, SECOND, WEEKDAY сохраняет договор string-first и locale-independent.

- Этот слой добавляет:
  - DATEADD(interval, number, value) AS STRING;
  - DATEDIFF(interval, fromValue, toValue) AS LONG;
  - DATEPART(part, value) AS INTEGER;
  - DATEVALUE(value) AS STRING;
  - TIMEVALUE(value) AS STRING;
  - ISDATE(value) AS BOOLEAN.
- DATEVALUE, TIMEVALUE и ISDATE не должны включать VBA-style locale-sensitive parsing.
- Все built-ins должны распознавать только канонические форматы Axiom:
  - дата yyyy-MM-dd;
  - время HH:mm:ss;
  - дата-время yyyy-MM-dd HH:mm:ss.

### DATEADD

- DATEADD(interval, number, value) принимает:
  - interval — строковый token для единицы интервала;
  - number — целочисленное количество шагов;
  - value — нативное значение DATE, TIME или DATETIME, соответствующее интервалу.
- Строковые формы не поддерживаются: для преобразования строк в нативные значения используйте DATEVALUE, TIMEVALUE, DATESERIAL или TIMESERIAL.
- Поддерживаются следующие interval tokens:
  - date-based: yyyy, q, m, d;
  - time-based: h, n, s.
- Для date-based interval значение value должно быть нативным DATE или DATETIME.
- Для time-based interval значение value должно быть нативным TIME или DATETIME.
- Сохраняется вид результата:
  - date -> date;
  - time -> time;
  - date-time -> date-time.
- Для time-only значений с интервалами h / n / s результат заворачивается через полночь и не выходит за пределы 24 часов.
- Для date и date-time значений month/quarter/year arithmetic результат соответствует поведению .NET AddMonths / AddYears:
  - DATEADD("m", 1, DATEVALUE("2026-01-31")) -> 2026-02-28;
  - leap-day поведение соответствует поведению .NET для високосного года.
- Если результат date/date-time arithmetic выходит за допустимый диапазон годов 1..9999, возникает runtime-диагностика ошибки встроенной built-in функции.

### DATEDIFF

- DATEDIFF(interval, fromValue, toValue) возвращает результат LONG.
- Поддерживаются следующие interval tokens:
  - yyyy, q, m, d, h, n, s.
- Для date-based interval оба аргумента должны быть нативными значениями DATE или DATETIME.
- Для time-based interval оба аргумента должны быть нативными значениями TIME или DATETIME одного вида; смешение TIME и DATETIME не проходит проверку типов (ошибка компиляции MB2003).
- Строковые аргументы не принимаются: для преобразования строк в нативные значения используйте DATEVALUE, TIMEVALUE, DATESERIAL или TIMESERIAL.
- Результат DATEDIFF — это количество целых границ интервалов:
  - yyyy - количество целых границ лет;
  - q - количество целых границ кварталов;
  - m - количество целых границ месяцев;
  - d - количество целых границ дней;
  - h - количество целых границ часов;
  - n - количество целых границ минут;
  - s - количество целых границ секунд.
- Для time-only интервалов h / n / s значения TIME сравниваются по времени суток; значения DATETIME — по полной разнице с учётом календарных дней.

### DATEPART

- DATEPART(part, value) возвращает INTEGER.
- Поддерживаются следующие part tokens:
  - date-based: yyyy, q, m, d, y, w;
  - time-based: h, n, s.
- yyyy, q, m, d, y, w принимают нативное значение DATE или DATETIME.
- h, n, s принимают нативное значение TIME или DATETIME.
- Строковые формы не поддерживаются: для преобразования строк в нативные значения используйте DATEVALUE, TIMEVALUE, DATESERIAL или TIMESERIAL.
- q возвращает quarter number 1..4.
- y возвращает день года 1..366.
- w возвращает day-of-week по шкале Monday-first: 1 = Monday, 7 = Sunday.

### DATEVALUE, TIMEVALUE, ISDATE

- DATEVALUE(value) принимает каноническую дату или каноническую дату-время и возвращает каноническую дату yyyy-MM-dd.
- TIMEVALUE(value) принимает каноническое время или каноническую дату-время и возвращает каноническое время HH:mm:ss.
- ISDATE(value) возвращает TRUE, если строка распознана как одна из канонических форм Axiom (yyyy-MM-dd, HH:mm:ss, yyyy-MM-dd HH:mm:ss), и FALSE в остальных случаях.
- ISDATE не должен считать допустимыми locale-specific строки вроде 20.04.2026, 04/20/2026, 2:24PM и их варианты.

### Границы этапа

- На этом этапе не добавляем optional arguments в духе VBA firstdayofweek / firstweekofyear.
- На этом этапе не добавляем interval tokens w, ww и y для DATEADD / DATEDIFF.
- На этом этапе не добавляем WEEKDAYNAME.
- На этом этапе не добавляем locale-sensitive short-date и 12-hour clock forms.

- Добавлен минимальный слой календарных функций поверх string-first договора даты и времени:

  - `ENDOFMONTH(value) AS STRING`;
  - `STARTOFYEAR(value) AS STRING`;
  - `ENDOFYEAR(value) AS STRING`.
- Функции `ISLEAPYEAR` и `DAYSINMONTH` работают с числовыми аргументами и дают календарные свойства года и месяца.
- Функции `STARTOFMONTH`, `ENDOFMONTH`, `STARTOFYEAR`, `ENDOFYEAR` принимают каноническую дату или дату-время и возвращают каноническую дату соответствующей границы месяца или года.

### ISLEAPYEAR

- `ISLEAPYEAR(year)` принимает номер календарного года `year` в диапазоне `1..9999`.
- Возвращает `TRUE`, если год високосный по обычным правилам Gregorian calendar.
- Возвращает `FALSE`, если год не является високосным.
- Функция не принимает строковую дату и не извлекает год из текста.

### DAYSINMONTH

- `DAYSINMONTH(year, month)` принимает:
  - `year` как целый год в диапазоне `1..9999`;
  - `month` как целый месяц в диапазоне `1..12`.
- Возвращает количество дней календарного месяца в указанном календарном году.
- Функция не принимает строковую дату и не извлекает месяц из текста.

### STARTOFMONTH, ENDOFMONTH, STARTOFYEAR, ENDOFYEAR

- Все четыре функции принимают `value` как:
  - каноническую дату `yyyy-MM-dd`;
  - или каноническую дату-время `yyyy-MM-dd HH:mm:ss`.
- Time-only значение, если оно передано, отклоняется.
- Возвращаемое значение всегда является канонической датой `yyyy-MM-dd`.
- `STARTOFMONTH(value)` возвращает первый день месяца переданной даты.
- `ENDOFMONTH(value)` возвращает последний день месяца переданной даты.
- `STARTOFYEAR(value)` возвращает первый день года переданной даты.
- `ENDOFYEAR(value)` возвращает последний день года переданной даты.
- Эти функции не сохраняют форму `date-time`; они возвращают именно дату, потому что описывают календарную границу, а не момент времени.

- Если преобразование выводит значение за поддерживаемый канонический диапазон, выполнение завершается диагностикой времени выполнения об ошибке аргумента встроенной функции.

## Обновление 2026-04-21 - Смещение по конкретной дате и времени

- Пакет UTC и локального времени расширен формой для расчёта смещения на конкретный момент.
- `UTCOFFSET` поддерживает формы:
  - `UTCOFFSET() AS INTEGER`;
  - `UTCOFFSET(value AS STRING) AS INTEGER`.
- Форма `UTCOFFSET(value)` принимает только каноническую локальную дату-время `yyyy-MM-dd HH:mm:ss` и возвращает локальное смещение от UTC в минутах для этой даты-времени.
- `TOUTC(value)` также использует локальное смещение именно для переданной даты-времени, а не текущее смещение «на сейчас».
- `FROMUTC(value)` принимает каноническую дату-время UTC и возвращает локальную дату-время по правилам локального часового пояса для соответствующего момента.
- Если локальная дата-время попадает в пропущенный или повторённый диапазон перевода часов, `UTCOFFSET(value)` и `TOUTC(value)` завершаются диагностикой ошибки аргумента встроенной функции.
- Отдельная форма `UTCOFFSET(timeZone)` не вводится: строковый аргумент уже занят формой `UTCOFFSET(value)`, а перегрузка по смыслу строки сделала бы договор неоднозначным.
## Обновление 2026-04-21 - именованные часовые пояса и явный выбор пояса

- Пакет даты и времени расширен формами с явным часовым поясом без ввода нового публичного типа:
  - `DATE(timeZone) AS STRING`;
  - `TIME(timeZone) AS STRING`;
  - `NOW(timeZone) AS STRING`;
  - `UTCOFFSET(value, timeZone) AS INTEGER`;
  - `TOUTC(value, timeZone) AS STRING`;
  - `FROMUTC(value, timeZone) AS STRING`.
- Аргумент `timeZone` задаётся строкой и принимает:
  - переносимый псевдоним `UTC`;
  - переносимый псевдоним `LOCAL`;
  - известный хосту идентификатор часового пояса.
- Для Windows-first окружения проектно допускается использование идентификаторов `TimeZoneInfo.Id` вроде `Russian Standard Time`.
- `DATE(timeZone)`, `TIME(timeZone)` и `NOW(timeZone)` берут текущий момент хоста и форматируют его в указанном часовом поясе.
- `UTCOFFSET(value, timeZone)` трактует `value` как каноническую локальную дату-время указанного пояса и возвращает смещение этого пояса в минутах для данного момента.
- `TOUTC(value, timeZone)` трактует `value` как каноническую локальную дату-время указанного пояса и переводит её в каноническую дату-время UTC.
- `FROMUTC(value, timeZone)` трактует `value` как каноническую дату-время UTC и переводит её в каноническую дату-время указанного пояса.
- Для `UTCOFFSET(value, timeZone)` и `TOUTC(value, timeZone)` пропущенные и неоднозначные локальные моменты из-за перевода часов по-прежнему завершаются диагностикой ошибки аргумента встроенной функции.
- Одноаргументная форма `UTCOFFSET(timeZone)` намеренно не вводится, потому что строковый аргумент уже занят формой `UTCOFFSET(value)` для канонической даты-времени и такая перегрузка делала бы договор неоднозначным.
- Именованные часовые пояса введены через перегрузку уже существующих имён `DATE`, `TIME`, `NOW`, `UTCOFFSET`, `TOUTC`, `FROMUTC`; это зафиксировано как проектное решение Axiom, поскольку у исторической линии BASIC нет одного готового стандартного семейства имён для такого пакета.

- Если UTF-8-файл начинается с BOM, эта служебная метка не включается в строковый результат `READFILE` и не становится первым символом первой строки `READALLLINES`.

## Обновление 2026-04-22 - полиморфные ARRAYMAP и ARRAYREDUCE реализованы

- Язык теперь поддерживает `ARRAYMAP(array, selector)` в полиморфной форме `FUNCTION(T) AS U`.
- Тип `T` по-прежнему определяется типом элемента исходного массива.
- Тип `U` определяется возвращаемым типом `selector`, а результат вызова получает тип `U()`.
- `ARRAYMAP` по-прежнему:
  - работает только с уже выделенным одномерным массивом;
  - не меняет исходный массив;
  - возвращает компактный результат `1 TO N` или канонический пустой массив `1 TO 0`.
- Поскольку вложенные массивы в текущем поколении языка не поддерживаются, `selector` не может возвращать массивный тип.

- Язык теперь поддерживает `ARRAYREDUCE(array, seed, reducer)` в полиморфной форме `FUNCTION(A, T) AS A`.
- Тип `T` задаётся типом элемента массива.
- Тип аккумулятора `A` задаётся значением `seed` и сигнатурой `reducer`; при необходимости к `seed` применяются обычные допустимые числовые расширения binder-а.
- Результат `ARRAYREDUCE` имеет тип `A`.
- `ARRAYREDUCE` по-прежнему:
  - работает только с уже выделенным одномерным массивом;
  - не меняет исходный массив;
  - обходит элементы слева направо;
  - для пустого выделенного массива возвращает исходный `seed`.

- Тем самым higher-order слой одномерных массивов больше не ограничен same-type-контрактом:
  - `ARRAYFILTER` остаётся producer-операцией `T -> T` по условию;
  - `ARRAYMAP` поддерживает `T -> U`;
  - `ARRAYREDUCE` поддерживает `A + T -> A`.

## Обновление 2026-04-22 - фиксированные строки STRING * N

- Язык теперь поддерживает форму фиксированной строки `STRING * N`:
  - в объявлениях переменных через `DIM`;
  - в полях пользовательских записей `TYPE`.
- Семантически такая сущность остаётся строкой, а не новым отдельным типом выражений:
  - строковые функции, сравнения и обычные строковые присваивания продолжают работать по общим правилам `STRING`;
  - специальное поведение проявляется именно при хранении значения.
- Требования к длине `N`:
  - длина должна сводиться к целочисленной константе;
  - допустимый диапазон: от `1` до `65535`;
  - при недопустимой длине выдаётся диагностика `MB2026`.
- Правила хранения фиксированной строки:
  - значение по умолчанию создаётся как строка из пробелов указанной длины;
  - если присваиваемая строка короче длины поля или переменной, она дополняется пробелами справа;
  - если строка длиннее, она обрезается справа до фиксированного размера.
- Для `DIM` действует тот же общий путь объявления, что и для остальных переменных:
  - на верхнем уровне длина может использовать верхнеуровневые целочисленные `CONST`, в том числе объявленные ниже по файлу;
  - в локальной области длина может использовать уже вычисленные ранее по потоку локальные целочисленные `CONST`.
- Для `TYPE` фиксированная строка продолжает историческую линию QuickBasic / Visual Basic:
  - строковое поле объявляется как `FieldName AS STRING * N`;
  - при создании новой записи поле сразу получает пробельное значение нужной длины;
  - при копировании записи фиксированное строковое поле копируется как часть значения записи.
- Во всех остальных контекстах форма `STRING * N` сейчас считается неподдержанной и должна завершаться диагностикой `MB2026`:
  - `CONST`;
  - параметры и тип результата `FUNCTION`/`SUB`;
  - вложенные функциональные типы вида `FUNCTION(STRING * N) AS ...`;
  - любые другие типовые позиции, где фиксированная длина синтаксически читается, но для неё нет отдельной метаинформации хранения.
