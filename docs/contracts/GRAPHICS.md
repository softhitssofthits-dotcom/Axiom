# Действующие графические поверхности

SCREEN и CANVAS — две поддержанные поверхности языка Axiom. DesktopHost создаёт нативные окна обеих поверхностей; CANVAS и SCREEN 1..10 рисуют и показывают кадры через DirectX. SCREEN 0 сохраняет текстовый путь. Electron управляет запуском и состоянием, обычные кадры GPU не пересылаются в интерфейс. Координатные договоры сохраняются; сложная геометрия и читающие операции имеют явно описанные пути совместимости.

CANVAS поддерживает BEGINFRAME/PRESENT, DRAW*/FILL*, изображения, спрайты, CAMERA/RESETCAMERA/VIEWPORT и тайловые карты. Поддержанные формы PSET/PRESET, POINT, PAINT и GET/PUT следует применять по их справочным страницам. Индекс палитры POINT и RGB-код не являются взаимозаменяемыми результатами.

Точные формы, единицы, ограничения и границы: [графика](../manual/graphics.html), [примитивы](../manual/graphics-primitives.html), [современная графика](../manual/modern-graphics.html), [тайловый договор](TILEMAP.md).

Клавиатура и мышь используют разные договоры состояния и очереди событий. При потере фокуса удержанные состояния освобождаются. Отмена INPUT и закрытие поверхности принадлежат текущей сессии. Автор подтвердил физическую мышь SCREEN и доступные системные DPI 100/125/150/175%; второй монитор остаётся непроверенным. Это прежняя аппаратная приёмка, а не новое доказательство всех условий GPU-пути. Подробности — в ELECTRON_HARDWARE_ACCEPTANCE.md и отчётах миграций.

Планы удобной анимации, столкновений и перевода Maze Chase на TILEMAP не объявляются реализованными только по наличию DRAWSPRITE. См. [UNFINISHED_WORK.md](../plans/UNFINISHED_WORK.md).
