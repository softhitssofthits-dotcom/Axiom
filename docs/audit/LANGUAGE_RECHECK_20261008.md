# Независимая перепроверка после исправлений исходного аудита

Дата: 2026-10-08. Исходные JSON/CSV от 2026-10-07 сохранены как снимок до исправлений. Этот документ дополняет реестр новыми подтверждёнными находками; он не означает аттестацию всех перегрузок стандартной библиотеки.

## LA26-015 — потеря малого остатка среднего массива

- Severity: P1. Category: DEFECT. Subsystem: числовые агрегаты.
- Affected files: `src/Axiom.Runtime/Builtins/BuiltinArrayAggregateHelpers.cs`; `tests/Axiom.Execution.Tests/AuditRemainingBehaviorTests.cs`.
- Function/operator: `ARRAYAVERAGE`.
- Reproducer: массив DOUBLE со значениями `VAL("1e308")`, `-VAL("1e308")`, `VAL("1e-308")`; сравнить среднее с `VAL("1e-308") / 3`.
- Expected: примерно `3.33333333333333E-309`, сравнение TRUE. Actual: 0, сравнение FALSE.
- Interpreter result: FALSE. BytecodeVm result: FALSE. Подтверждено корректной программой после замены неподдержанных экспоненциальных литералов на VAL.
- Root cause: нормализация по максимальному модулю превращала малое слагаемое в ноль ещё до сложения.
- User impact: неправильное среднее при взаимном сокращении сильно различающихся по модулю чисел.
- Regression risk: цена точного накопления на крупных массивах пока не измерена; элементы других числовых типов по-прежнему сначала преобразуются в DOUBLE.
- Recommended fix: точная целочисленная сумма представленных DOUBLE в единицах 2^-1074 и однократное округление среднего к ближайшему чётному.
- Tests required: сокращение, перестановка элементов, субнормальные значения, максимальные конечные значения обоих знаков, оба движка.
- Documentation impact: `arrays-and-builtins.html`, SPECIFICATION3, ARCHITECTURE, BYTECODE_COVERAGE. Пример `samples/functions/arrayaverage/tiny_cancellation.axm`.
- IDE impact: новых имён и синтаксических токенов нет.
- Confidence: CONFIRMED. Статус: исправлено в Session 1122. Полные Execution.Tests 1054/1054; доказательства `.artifacts/average-recheck-1122/`.

## LA26-016 — содержимое WRITE зависит от FLUSH и дополняется нулевыми байтами

- Severity: P1. Category: DEFECT. Subsystem: текстовые файловые дескрипторы и Unicode.
- Affected files: `src/Axiom.Runtime/Values/RuntimeTextFile.cs`; `tests/Axiom.Runtime.Tests/TextFileUnicodeBoundaryTests.cs`; `tests/Axiom.Execution.Tests/FileWriteUnicodeContractTests.cs`.
- Function/operator: `WRITE`, буферизированная запись FILE в OUTPUT/APPEND.
- Reproducer: передать `LEFT("😀", 1)` и `RIGHT("😀", 1)` двумя вызовами WRITE; повторить с FLUSH между вызовами; закрыть файл и сравнить байты.
- Expected: независимое кодирование каждого вызова; два U+FFFD, `EF BF BD EF BF BD`, позиция и длина 6; результат не зависит от FLUSH. Целый эмодзи в одном вызове сохраняется четырьмя байтами.
- Actual: без FLUSH строковый буфер объединял половины в эмодзи, `F0 9F 98 80 00 00`; с FLUSH записывались две замены. Размер 6 не соответствовал кодированному содержимому до SetLength.
- Interpreter result: подтверждена общая реализация RuntimeTextFile; после исправления языковой сценарий проверен через Interpreter. BytecodeVm result: та же общая реализация; после исправления выполнена отдельная проверка BytecodeVm без перехода на интерпретатор.
- Root cause: GetByteCount выполнялся для каждого фрагмента, а GetBytes — для их объединения. Эти операции неаддитивны на границе изолированных суррогатов.
- User impact: подмена текста и лишние нулевые байты в файле, нестабильность результата при FLUSH.
- Regression risk: кодирование перенесено на момент WRITE; действующая замена изолированных единиц UTF-16 сохранена, отказ по ним не введён.
- Recommended fix: буферизовать уже закодированные байты и использовать их длину для позиций.
- Tests required: OUTPUT/APPEND, с FLUSH и без него, реальное содержимое после CLOSE, FILEPOS/FILELENGTH, оба движка.
- Documentation impact: `file-system-functions-open-files.html`, SPECIFICATION3, ARCHITECTURE, BYTECODE_COVERAGE. Пример `samples/functions/write/utf16_fragment_bytes.axm`.
- IDE impact: новых имён и токенов нет.
- Confidence: CONFIRMED. Исправление внесено в Session 1123. До правки два прямых сценария без FLUSH воспроизвели разные байты; варианты с FLUSH проходили. Первоначальная попытка читать открытый на запись файл через File.ReadAllBytes получила конфликт совместного доступа и исключена из доказательств. Текущие адресные проверки: 5/5 Runtime и 4/4 Execution. Доказательства `.artifacts/unicode-files-1123/`.

## LA26-017 — DIRSIZE и COPYDIR переходят по вложенным ссылкам

- Severity: P1 для неограниченного повторного обхода, P2 для подтверждённого неправильного размера. Category: DEFECT / SEMANTIC DEFECT. Subsystem: обход файловой системы.
- Affected files: `src/Axiom.Runtime/Builtins/BuiltinFileSystemHelpers.cs`, новый `BuiltinDirectoryHelpers.cs`; `tests/Axiom.Execution.Tests/DirectoryTraversalContractTests.cs`.
- Function/operator: `DIRSIZE`, `COPYDIR`.
- Reproducer: обычный файл 3 байта в источнике, соединение каталогов Windows на внешний каталог с файлом 11 байт. Выполнить DIRSIZE и COPYDIR.
- Expected: размер 3; обычный файл скопирован, вложенная ссылка и её цель пропущены. Это восстанавливает уже записанный в manual договор DIRSIZE; для COPYDIR правило пропуска ссылок закреплено явно в этой сессии.
- Actual: размер 14; COPYDIR создавал обычную папку с содержимым внешней цели.
- Interpreter result: `14, TRUE, TRUE, TRUE`. BytecodeVm result: тот же результат. После исправления размер 3 и отсутствие копии ссылки подтверждены отдельно в обоих движках.
- Root cause: рекурсивный GetDirectories не проверял FileAttributes.ReparsePoint.
- User impact: подсчёт и копирование объектов за границами обычного дерева; исходный алгоритм не имел защиты от цикла. Зависание исходного алгоритма на цикле намеренно не запускалось; исправленный алгоритм проверен на реальной циклической ссылке.
- Regression risk: вложенные точки повторного разбора теперь пропускаются; они не сохраняются как ссылки. Явно выбранный корневой каталог допускается через ссылку. Обход не является снимком файловой системы и не гарантирует атомарность при её внешнем изменении.
- Recommended fix: общий итеративный обход обычных файлов и каталогов, пропуск вложенных ReparsePoint.
- Tests required: обычные вложенные файлы, внешний каталог, цикл, сохранность внешнего файла, паритет обоих движков.
- Documentation impact: `file-system-functions-paths.html`, `file-system-functions-management.html`, SPECIFICATION3, ARCHITECTURE, BYTECODE_COVERAGE. Примеры `samples/functions/dirsize/ordinary_nested_bytes.axm`, `samples/smoke/directory_link_boundaries.axm`; подготовка реальных ссылок — `scripts/language-audit/Prepare-DirectoryLinkSample.ps1`.
- IDE impact: новых имён и токенов нет; создание ссылок не добавляется в язык, поскольку оно нужно проверочной среде, а не подтверждённому пользовательскому сценарию Axiom.
- Confidence: CONFIRMED. Исправление внесено в Session 1123. Исходное воспроизведение `.artifacts/unicode-files-1123/directories-red.log`.

## LA26-018 — COPYDIR начинает изменять источник при вложенном назначении

- Severity: P1. Category: DEFECT. Subsystem: копирование каталогов.
- Affected files: `BuiltinFileSystemHelpers.cs`, `BuiltinDirectoryHelpers.cs`, `DirectoryTraversalContractTests.cs`.
- Function/operator: `COPYDIR`.
- Reproducer: источник с a.dat и b.dat; существующее назначение source/child уже содержит b.dat. Вызвать COPYDIR без overwrite. Этот конфликт безопасно останавливает прежний алгоритм до повторной рекурсии.
- Expected: MB3007 с объяснением вложенного назначения, отсутствие source/child/a.dat, сохранность прежнего b.dat.
- Actual: a.dat уже скопирован внутрь источника до ошибки о существующем b.dat; специальной проверки назначения нет.
- Interpreter result: `MB3007, FALSE, TRUE`. BytecodeVm result: тот же результат. После исправления `MB3007, TRUE, FALSE`.
- Root cause: создание назначения и запись файлов начинались до проверки совпадения или вложенности путей; без конфликтующего файла назначение включалось бы в следующий обход источника.
- User impact: изменение входного дерева, разрастание вложенных копий и непонятная поздняя ошибка.
- Regression risk: самокопирование теперь отвергается даже с overwrite=TRUE. Обычная копия в соседний каталог сохраняется. Ошибки прав доступа или файловые конфликты в допустимом назначении не получают полного отката.
- Recommended fix: до записи разрешить существующие ссылки в компонентах путей и проверить совпадение/вложенность источника и назначения. Вложенные ссылки в назначении не использовать для записи.
- Tests required: вложенный путь, сохранность файлов, путь через соединение каталогов, соседнее имя с общим префиксом, оба движка.
- Documentation impact: `file-system-functions-management.html`, SPECIFICATION3, ARCHITECTURE, BYTECODE_COVERAGE. Пример `samples/functions/copydir/reject_nested_destination.axm`.
- IDE impact: новых имён и токенов нет.
- Confidence: CONFIRMED. Исправление внесено в Session 1123. Доказательства `copy-descendant-red.log` и `parity-final.log` в `.artifacts/unicode-files-1123/`.

## Session 1124 — рабочая папка, POINT и границы остановки отладчика

LA26-019, DEFECT, файловая система: ProgramRunService определял папку sourceFilePath, но ExecutionRequest не передавал её адаптеру исполнения. Относительный WRITEFILE попадал в папку процесса, CURRENTDIR показывал её же. Исправлено: начальная папка передаётся явно, адаптер хранит изменяемую CurrentDirectory отдельно на каждый запуск; CHANGEDIR не меняет папку процесса. Оба движка, включая быстрые ветви VM, используют одну базу для файловых операций и OPEN. Проверены новый запуск, повторное использование скомпилированной программы и продолжение остановленного VM после другого запуска. Доказательства red-final.log, directory-contracts.log; 5/5 WorkingDirectoryContractTests. CLI сохраняет папку вызова; графические ресурсы сохраняют исходную базу запуска. Нового языкового API не требуется.

LA26-020, DEFECT, графика: POINT(x, y) в CANVAS должен читать физический пиксель. Настоящий GraphicsHostService применял CAMERA/VIEWPORT в GetPixel, тогда как прежний подставной хост тестов читал физически. Поэтому тест PUT после восстановления блока видел нули. Валидное воспроизведение в обоих движках: PSET (100, 50), 6 при CAMERA 100, 50 и VIEWPORT (10, 6)-(15, 11); POINT(10, 6), POINT(100, 50) давали 0, 6 вместо 6, 0. Исправлено чтение через GetAbsolutePixel только для CANVAS; SCREEN сохраняет логическую систему координат. PUT сам по себе исправления не требовал. Доказательство point-red.log; новые проверки настоящего сервиса IDE проходят в обоих движках. Пример samples/functions/point/physical_canvas_coordinates.axm, также проверен samples/operators/put/canvas_block_restore.axm.

LA26-021, DEFECT, IDE: BytecodeVmDebuggerAdapter сохранял строку и столбец, но терял TextLocation.Span. MainWindow передавал отрисовщику пустой диапазон, который тот закономерно отвергал. DebuggerStopInfo теперь передаёт необязательный полный TextLocation; редактор использует непустой исходный диапазон. Проверка DebuggerAdapterPreservesSourceSpanForStoppedInstruction подтверждает диапазон второй строки исходника. Фактическое изображение окна отладчика в этой сессии не проверялось.

TEST GAP: два графических теста ожидали screen.output при CANVAS, хотя PRINT в этом режиме пишет console.output; ожидания исправлены. GET работает без изменения его реализации. Текстовые маркеры форматирования исчезли после прежнего выделения кода; проверка обновлена по текущим вызовам и дополнена поведенческой проверкой нормализации идентификатора активного изменённого документа. Прежняя проверка SourceLocation.Span при этом выявила реальную потерю диапазона, а не была просто удалена.

Полный последовательный прогон решения: 3596/3596, без падений и пропусков; Runtime 1031/1031, Execution 1075/1075, IDE 592/592, CLI 23/23.
