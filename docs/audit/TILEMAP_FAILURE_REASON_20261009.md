# Причина отказа LOADTILEMAP — 2026-10-09

## Воспроизведение и изменение

Реальный IDE-загрузчик принимал исключение об ellipse, но возвращал null. Interpreter и BytecodeVm сообщали только «не удалось загрузить тайловую карту». Новые два случая до изменения0/2, .artifacts/tile-reason-1207-before.log. После изменения сообщение LOADTILEMAP: Объекты ellipse пока не поддерживаются. доходит до err.Message, кодMB3005 сохраняется.

GraphicsHostService.LoadTilemap оборачивает ожидаемые исключения загрузки в InvalidDataException, сохраняя сообщение и InnerException. Это узкий договор IGraphicsHost.LoadTilemap, не смена поведения всех графических загрузчиков. Interpreter.Graphics и BytecodeVm.Graphics переводят этот отказ в диагностику языка/RuntimeFailureException, которую перехватывает TRY/CATCH. Null по-прежнему даёт прежний общий отказ.

Быстрый LOADTILEMAP в BytecodeVm теперь вызывает общий обработчик с местоположением текущей инструкции. Первоначальный промежуточный вариант возвращал false после исключения и повторял чтение; он заменён до итоговой проверки. TilemapLoadFailureTests использует хост с первым отказом и последующим успехом: ожидаемые MB3005/причина/ширина2, ровно два обращения для двух явно записанных вызовов. Оба движка2/2; .artifacts/test-results/tile-load-once-1207/tile-load-once-1207.trx. Это проверка количества вызовов и восстановления после CATCH, не настоящий отказ диска.

Реальный IDE-набор TilemapMetadataAccessTests/TilePropertyAcceptanceSampleTests232/232, включая ресурсный ellipse и прежние данные/границы/примеры, .artifacts/test-results/tile-reason-1207/tile-reason-1207.trx. После этого обновлён русский metadata_validation.axm для печати причины и начат полный прогон решения; окончательные результаты ниже после завершения.
