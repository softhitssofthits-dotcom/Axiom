Важное следствие NIT-004

Порядок объявлений перестал влиять на видимость в обе стороны: локальная переменная или параметр, повторяющие имя более поздней глобальной, теперь дают MB2016 (раньше такое проходило из-за порядка). Это единообразно и соответствует действующему запрету перекрытия имён. Обновлены сэмплы и тесты, полагавшиеся на старую порядковую зависимость (переименованы параметры age→inputAge, user→person; ожидаемый вывод не менялся):

  • samples/acceptance/smoke_v0_1.axm
  • samples/operators/sub/byval_record_copy.axm, byref_record_argument.axm
  • tests/Axiom.Runtime.Tests/InterpreterTests.Type.cs, BytecodeVmTests.cs

Технические детали

  • Diagnostic получил Severity (Error/Warning; конструктор обратно совместим). Новые коды: MB2040, MB2041.
  • Пайплайн: предупреждения не блокируют компиляцию, но доставляются в ExecutionResult и в успешном пути — раньше фронтенд-диагностики терялись (CompileCore передавал пустой список, Run не сливал их с результатом).
  • Позитивный acceptance-набор сэмплов ослаблен с «нет диагностик» до «нет ошибок» — предупреждения больше не валят сэмплы.
  • Контекст текущего метода TYPE (_currentMethodOwner) задаётся в BindTypeMethods и используется для MB2040; локальная переменная с именем поля остаётся в приоритете.
