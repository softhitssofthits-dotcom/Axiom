## DT26-001 — VM отвергает DIM временного типа без инициализатора

- Классификация: сломана существующая форма языка; новый API не нужен.
- Приоритет: P1. Уверенность: высокая, воспроизведено в обоих движках.
- Воспроизводитель: `DIM moment AS DATETIME`, далее присваивание канонического текста и вызов UTCOFFSET.
- Ожидание: создание переменной с начальным значением, как в RuntimeValue.CreateDefault и интерпретаторе.
- Факт до исправления: Interpreter проходит; Bytecode выдаёт BC3001 при понижении объявления. Исходный набор 7/8, журнал .artifacts/datetime-1133-zone.log и TRX сохранены. Первые шесть календарных проверок прошли до изменения кода.
- Причина: LowerVariableDeclaration не поддерживал начальные значения DATE/TIME/DATETIME; список допустимых неявных значений также их не содержал.
- Исправление: понижение явно загружает каноническую строку, преобразует её существующей инструкцией Convert и сохраняет переменную. Новые инструкции/типы/имена не добавлены. Простое пропускание объявления не выбрано: оно не сбрасывало бы изменённое значение при повторном выполнении DIM.
- Регрессия: два прохода цикла с присваиваниями доказывают повторное создание всех трёх типов. Риск изменения ограничен объявлениями этих типов без инициализатора.
- Проверка после исправления: 10/10; .artifacts/datetime-1133-fixed.log и одноимённый каталог TRX. Результаты UTC и DST в обоих движках совпали.
- IDE: новых токенов нет; DATE/TIME/DATETIME и DIM уже существуют в подсветке. Живая визуальная приёмка не заявляется.

## DT26-003 — переполнение промежуточных тиков DATEADD для TIME

Session 1135, P2, сломана существующая функция. Применение 2147483647 часов к 23:59:59 должно дать 06:59:59 по существующей циклической модели TIME, однако обе реализации дают MB3007. Причина — умножение количества часов на тики до приведения по модулю суток; дополнительный случай 256204778 часов переполняет сложение с временем суток. Новый API не нужен, значение INTEGER допустимо, дата в TIME отсутствует. Исходный реальный прогон 0/2 в .artifacts/datetime-1135-large-hours-runtime.log/TRX сохранён до исправления. Первоначальная запись -2147483648 была LONG из-за положительного литерала перед унарным минусом; исправлено на (-2147483647 - 1). Первый отказ связывания не считается доказательством ошибки DATEADD.
