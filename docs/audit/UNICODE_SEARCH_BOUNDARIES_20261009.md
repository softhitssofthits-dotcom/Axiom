# Поиск на границах UTF-16

Session 1219, 2026-10-09. Проверен следующий участок из Session 1218: четыре вызываемые формы INSTR/INSTRREV на границах суррогатных пар и повреждённых строках.

## Договор и независимые ожидания

Руководство `docs/manual/string-functions-search-and-replace.html` определяет позиции в единицах UTF-16, точное сравнение без нормализации и ограничение INSTRREV: весь фрагмент должен помещаться до start включительно. Пустой фрагмент имеет отдельный договор, который уже описан в руководстве.

`UnicodeSearchBoundaryEvidenceTests` содержит 24 буквальных пары вызов/результат, каждый вызов выполняется обоими движками. Ожидания не вычисляются через IndexOf, LastIndexOf или другие функции поиска. Непарные суррогаты создаются внутри теста, параметры xUnit содержат только номер и режим исполнения.

| Участок | Проверенные результаты |
| --- | --- |
| Полный emoji в `А😀Б😀` | INSTR со start=2/3/6 возвращает 2/5/0; INSTRREV со start=2/3/5/6 возвращает 0/2/2/5 |
| Половины пары | Старший и младший суррогаты находятся отдельно; обратный поиск старшего до позиции 5 возвращает 5, младшего — 3 |
| Повреждённые строки | Находятся непарные суррогаты в начале и конце; обратный порядок младший/старший не совпадает с корректной парой |
| Пустой фрагмент | Старт внутри пары сохраняется у INSTR; INSTRREV возвращает start+1 в пределах строки; проверены позиция после строки, выход за неё и INTEGER.MaxValue |
| Нормализация | Предварительно составленное é не совпадает с e и отдельным знаком ударения в обеих функциях |

Проверены статус успеха, отсутствие диагностик, точный числовой вывод, фактический движок и отсутствие запасного интерпретатора.
