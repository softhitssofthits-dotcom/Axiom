Проверка читабельности страниц по переменным

Доказательство критерия «Текст понятен читателю без опыта программирования» · 2026-08-26

Методика

  1. Контрольная перечитка обеих новых страниц «глазами новичка»: каждый термин проверялся на предмет объяснения при первом появлении.
  2. Автоматический скан на жаргон: поиск по списку из 19 технических терминов (binder, lowerer, runtime, bytecode, байткод, VM, стек, литерал, токен, парсер, AST, shadowing, scope, интерпретатор, компилятор, инициализатор, препроцессор, семантика, синтаксис) по страницам variables-scope.html и variables-glossary.html.
  3. Проверка покрытия словарика: каждый термин, используемый на странице-справочнике, имеет статью-объяснение в словарике.
  4. Проверка стиля: наличие таблиц «можно/нельзя», примеров с ожидаемым выводом, разделов «Совет новичку», пояснений для каждой диагностики MB…

Жаргон внутренних подсистем (binder, lowerer, VM) на страницах справочника не используется вовсе — он встречается только в аудит-документах для мейнтейнеров.

Словарик содержит 20 статей-терминов (плюс раздел «См. также»). Каждый термин, используемый на странице «Имена, регистр и область видимости переменных», имеет статью-объяснение:

Правки, внесённые по итогам перечитки

  1. В словарик добавлена статья «Компилятор»; статья «Диагностика» ссылается на неё.
  2. На variables-scope.html первое упоминание «диагностика» пояснено: «компилятор выдаёт диагностику (сообщение об ошибке)».
  3. На variables-scope.html слово «компилятор» в разделе про SELF пояснено в скобках.
  4. Англицизм «reuse-семантика» заменён на «повторное использование» в отчётах и журнале.
