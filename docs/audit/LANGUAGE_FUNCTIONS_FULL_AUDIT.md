# Полный аудит языка Axiom: встроенные функции, стандартная библиотека и паритет движков

Дата: 2026-10-06. Аудит режима «только чтение» (без правок кода). Аудиторский harness и все воспроизводимые кейсы сохранены в `.artifacts/audit/` (не входят в постоянные файлы репозитория).

## 1. Executive Summary

Проведён доказательный аудит всего языка Axiom: построена полная инвентаризация встроенных функций из исходников (295 дескрипторов, 241 пользовательское имя, 282 из 285 ID enum), выполнен дифференциальный прогон Interpreter ↔ BytecodeVm по ~700 кейсам (значения, границы, ошибки домена, локации и тексты диагностик) и по всем runnable-примерам `samples/`, проверены подсистемы: математика, RND, строки, Unicode, regex, массивы, дата/время, преобразования, файловые дескрипторы, файловая система, кодировки, консольный I/O, процедуры, BYREF, замыкания, TYPE, операторы, управление, обработка ошибок.

Главные выводы:

1. **Ядро языка зрелое.** Все проверенные значения функций корректны; проверенная арифметика checked; все ошибки домена и границ дают чистые Axiom-диагностики без утечек CLR-исключений; stdout-паритет Interpreter/VM на валидных программах — 100 % в проведённых батареях.
2. **Найден 1 подтверждённый P1-дефект исполнения:** повторный выброс ошибки из `CATCH` пропускает `FINALLY` в Interpreter (VM исполняет FINALLY; спецификация требует FINALLY всегда).
3. **Найден 1 подтверждённый P1-дефект удобства, ведущий к потере данных:** вызовы встроенных функций в позиции оператора без скобок (`FLUSH f`, `WRITELINE f "текст"`) — молчаливый no-op: выражения-операторы выбрасываются без диагностики.
4. **Систематические P2-расхождения двух движков** в текстах и локализациях диагностик (6+ подтверждённых пар разных формулировок; Interpreter указывает на аргумент, VM — на вызов; цепочки вызовов в ошибках расходятся по глубине в обе стороны). Корневая причина — дублирование текстов валидации per-engine.
5. **7 диагностик Interpreter содержат mojibake** (двойная кодировка русских строк в `Interpreter.Builtins.FileSystem.cs`).
6. **Кодировочный контракт файлов внутренне противоречив:** `READFILE` и `OPEN FOR INPUT` по-разному трактуют BOM и Windows-1251.
7. Стандартная библиотека покрыта тестами, примерами и manual исчерпывающе (принудительная синхронизация реестр↔VM↔manual↔samples через `Axiom.ManualChecks`), но подсветка IDE ведётся в трёх ручных копиях без синхронизации с реестром, автодополнения нет.

Итоговый вердект: **стандартную библиотеку можно считать зрелой для текущего этапа продукта; расширение языка можно продолжать на её основе после закрытия Wave 0–1** (см. дорожную карту в разделе 40).

## 7. Numeric/Math

Прогоны: `cases/math_values.txt` (86 кейсов), `cases/math_domains.txt` (33), `cases/typed.prog` (36). Все значения и коды ошибок — паритет SAME.

Подтверждённая корректность:
- Домены: `SQR(-1)`, `LOG(0/-1)`, `LOG10/LOG2(≤0)`, `ASIN/ACOS(|x|>1)`, `ACOSH(<1)`, `ATANH(±1 и >1)`, `POW(-2,0.5)`, `POW(0,-1)`, `EXP(1000)`, `POW(10,400)` — все дают MB3007/MB3008 с точными сообщениями; CLR-исключения наружу не протекают.
- `CBRT(-27)=-3` (нечётный корень из отрицательного — корректно), `CBRT(-8)=-2`.
- `POW(0,0)=1` (конвенция .NET/VB).
- Целочисленная арифметика checked: `2147483647+1` → MB3008, константы переполнения ловятся на компиляции (MB2018).
- DECIMAL: `0.1@ + 0.2` (переменные DECIMAL) = ровно `0.3`; `1/3` = 28 знаков.
- `ROUND` — «половины от нуля» (`ROUND(2.5)=3`, `ROUND(-0.5)=-1`) — **задокументировано в manual** (`numeric-functions-roots-rounding.html`: «В Axiom половины округляются от нуля»), отличие от banker's-округления VB является осознанным.
- `INT` — floor; `FIX` — усечение к нулю; `SGN` → INTEGER.
- `/0` для DOUBLE — runtime «Деление на ноль» (MB3001), т.е. Infinity как значение недостижим по конструкции.

Найденные дефекты/нестыковки:
- **AXD-008 (P2):** `(-8) ^ (1/3)` даёт MB3008 «Результат операции '^' выходит за диапазон DOUBLE» — вводящая в заблуждение диагностика (это ошибка домена, не диапазона); встроенная `POW` для того же случая даёт корректный MB3007 «аргумент 'value' cannot be used with the specified exponent». Оператор и функция не согласованы.
- **AXD-009 (P3):** `^` правоассоциативен: `2 ^ 3 ^ 2 = 512` (= 2^(3²)), тогда как QuickBASIC/VB вычисляют левоассоциативно (`(2^3)^2 = 64`). Ассоциативность `^` не зафиксирована ни в SPECIFICATION3, ни в manual (для `&` левоассоциативность зафиксирована).
- **AXD-005 (частично, P2):** `CLAMP(5,10,1)` — разные тексты ошибки у движков (см. раздел 26); `ABS(-2147483648)`-переполнение — Interpreter печатает смешанный англ. текст «Result of ABS(value) выходит за диапазон INTEGER».
- P3-наблюдение: сообщения numeric-helpers на английском («must be greater than or equal to 0»), string/file — на русском; единый стиль отсутствует (AXD-010).

Суффиксы/литералы (P3, AXD-018): нет суффиксов типов (`%&!#@` — «недопустимый символ»), нет экспоненциальной записи (`1e3` → «Имя 'e3' не объявлено»), из `&H/-префиксов есть только `&H` (нет `&O`, `&B`). Литерал `9223372036854775808` корректно отвергается (MB0004).

## 8. Random (RND)

- Диапазон подтверждён `[0,1)`: 1000 выборок, min≈0.00065 ≥ 0, max < 1; последовательные вызовы дают разные значения.
- Детерминизм: при фиксированном host-seed Interpreter и VM дают побитово одинаковые последовательности (harness: seed 42 и seed 7). Источник — `_host.NextRandomDouble()` (общий `BuiltinNumericHelpers`), т.е. паритет абсолютный.
- **RANDOMIZE отсутствует** (MB2001 «Имя 'RANDOMIZE' не объявлено») — пользователь не может ни засеять, ни зафиксировать последовательность из языка (P3, кандидат SHOULD в gap-анализе).
- Воспроизводимые тесты возможны только инъекцией IRuntimeRandom (как в тестах/harness) — из языка нельзя.

## 9. Strings

Прогон: `cases/strings.txt` (139 кейсов). Паритет SAME 139/139. Значения корректны (включая все границы: пустые строки, start=0/-1, count=0/-1/за-границей, перекрытия REPLACE, INSTR/INSTRREV семантика 1-базированная и совпадающая с VB).

Зафиксированные контракты (значения верны, здесь фиксируются решения):
- `LEFT/RIGHT/MID` с `count=0` → ошибка MB3007 «должен быть больше 0» (в QB — пустая строка). Осознанное сужение, в manual отражено частично (см. раздел 31).
- `REPLACE("aaa","aa","b")="ba"` — слева направо без перекрытия; `SUBSTRCOUNT("aaaa","aa")=2` — без перекрытия.
- `STRING(3,"xy")="xxx"` — первый символ заполнителя (как QB `STRING$`).
- Сравнение строк — ординальное (`"a" < "B"` = FALSE), culture-независимое.
- Esc-последовательностей в литералах нет (`"\n"` — два символа, код 92; кавычка удвоением `""` — работает, QB-совместимо).
- **AXD-012 (P3):** `VAL("1,5") = 15` — запятая трактуется как разделитель тысяч и выбрасывается (парсер .NET AllowThousands); для ru-локали, где запятая — десятичный разделитель, это сюрприз. `VAL("&HFF")=0` (QB даёт 255). `VAL("1e2")=100` — VAL понимает экспоненту, хотя литералы языка её не поддерживают. Контракт VAL в spec/manual явно не описан.
- P4: `STR` неотличим от `PRINT`-форматирования (полная точность DOUBLE, `0.30000000000000004`) — задокументировать как отображаемый формат.

## 10. Unicode

Прогон: `cases/unicode.txt` (48 кейсов) + точечные пробы. Паритет SAME 48/48. Найдена **смешанная модель единиц строки** (AXD-011, P3):

| Функция | Единица | Поведение на non-BMP |
|---|---|---|
| `LEN` | UTF-16 code unit | `LEN("😀")=2` |
| `LEFT/RIGHT/MID/REMOVE/INSERT/PAD*` | UTF-16 code unit | `LEFT("a😀b",2)` возвращает половину суррогатной пары (невалидная строка) |
| `REVERSE` | суррогатные пары сохраняются | `REVERSE("😀😎")="😎😀"` корректно |
| `ASC/ASCW` | Unicode scalar | `ASC("😀")=128512` (не половина пары!) |
| `CHR/CHRW` | Unicode scalar, границы U+0000..U+10FFFF, суррогатные половины U+D800..U+DFFF и >U+10FFFF отвергаются | `CHR(128512)="😀"`, `CHR(55296)`/`CHR(1114112)` — MB3007 |

Итог: три разные семантики в одной подсистеме. Кириллица, комбинируемые диакритики (`LEN("ё́")=2` — е+U+0308 считается двумя) и `UCASE("ǆ")="Ǆ"` (специальные правила регистра .NET работают). Модель нигде не задокументирована — DOCUMENTATION GAP. Рекомендация: зафиксировать в spec/manual договор «LEN/индексация — UTF-16 code units» и добавить явную пометку о последствиях для эмодзи.

## 11. Regex

Прогон: `cases/regex.txt` (62 кейса). Паритет SAME 62/62.

- Все 8 семейств функций и их перегрузки (modes/count/group) работают: i/m/s/x подтверждены поведением (m: `^b` на "a\nb" TRUE только с "m"; s: `a.b` матчит "a\nb" только с "s"; x игнорирует пробелы).
- Повторяющиеся режимы (`"ii"`) и пустая строка режимов допустимы; неизвестный режим (`"z"`) — точная MB3007 со списком допустимых.

- Группы: 0/1/2 — корректно; отсутствующая группа → пустая строка; отрицательная группа → MB3007; count=0 → нет замен; count>совпадений → все; отрицательный count → MB3007.
- Zero-width: `REGEXMATCHES("abc","b*")` → 4 элемента, `REGEXSPLIT("abc","")` → 5, `REGEXCOUNT("aaa","a*")=2` — семантика .NET, паритет полный.
- Защиты от катастрофического бэктрекинга (timeout) нет — .NET Regex без MatchTimeout; зафиксировано как осознанное отсутствие (риск зависания на патологических паттернах — P3, рекомендация рассмотреть таймаут).
- Подстановки `$&`, `$1` работают (VB-совместимо).

## 12. Arrays

Прогон: `cases/arrays.prog` (56 блоков после исправления синтаксиса тестов). Паритет значений и кодов полный; 3 текстовых расхождения диагностик (см. раздел 26).

- Границы: `DIM a(l TO u)` — явная нижняя граница обязательна; отрицательные нижние работают; перевёрнутые границы — MB3005 (кроме канонической пустой `1 TO 0`); `LBOUND/UBOUND` по измерениям; rank до 3 проверен (`ARRAYRANK`).
- Индексы вне границ — MB3002 с указанием границ; чтение неинициализированного элемента — 0 (не ошибка).
- `REDIM` сбрасывает значения; `REDIM PRESERVE` сохраняет пересечение (задокументировано в spec, раздел REDIM).
- `ARRAYCLONE` — независимая копия; мутация оригинала не видна; присваивание массивов (`b = ARRAYCLONE(a)`) — значение; **передача массива в SUB без BYREF мутирует оригинал** (ссылочная передача) — контракт «копия при присваивании, ссылка при передаче» задокументирован в spec (BYVAL для массивов делит тело) — но это стоит подсветить в manual.
- Higher-order: `ARRAYEVERY/SOME/FILTER/MAP/REDUCE` с пользовательскими функциями — полный паритет, включая захват состояния; builtin как колбэк — только при точном совпадении FUNCTION-типа: `ARRAYMAP(целочисленный_массив, ABS)` — MB2003 (ABS типизирован DOUBLE→DOUBLE), на DOUBLE-массиве `ARRAYMAP(a, SQR)` работает (P3, AXD-014-смежное: нет ко/контравариантности function-values).
- `ARRAYBINARYSEARCH` на несортированном массиве молча даёт произвольный результат — предусловие «отсортирован» в диагностике не проверяется (документировано как предусловие? — в manual отражено, проверить; классифицировано как приемлемое предусловие с пометкой).
- Сортировка строк — ординальная (`apple < Яблоко < банан`); `ARRAYSORT(a, 0)` — убывание.

## 13. Date/Time

Прогон: `cases/datetime.txt` (110 кейсов) на фиксированных часах 2026-06-15 12:34:56+03:00 (Russian Standard Time). Паритет SAME 110/110.

## 14. Conversions

- Явных функций преобразования почти нет: `INT` (floor→INTEGER), `STR` (число→строка PRINT-формата), `VAL` (строка→DOUBLE). Семейства CINT/CLNG/CDBL/CDEC/CBOOL (VB) отсутствуют — P3 gap (SHOULD-кандидат: хотя бы потому что `i = l` при LONG→INTEGER запрещён, а обходной путь — `INT(l)`, семантически floor, не «преобразование»).
- Неявные расширения: INTEGER→LONG→DOUBLE/DECIMAL работают; **все сужения запрещены на компиляции** (`DIM i AS INTEGER : i = 4.0-литерал/DOUBLE-переменная/LONG-переменная` — MB2003/MB2018). Строже QB/VB — задокументировать как принцип «явных сужений нет».
- `INTEGER↔BOOLEAN`, `STRING→число` — запрещены (MB2003).
- `&` — универсальная склейка в строку (`"a" & 5.5 & TRUE`); `+` для строк строгий STRING+STRING (`"a" + 5` — MB2003, задокументировано в spec 2026-05-11).
- Локале-зависимость: парсер чисел invariant (`.` — десятичный, запятая — тысячи, см. AXD-012); PRINT/STR — invariant. Влияния ОС-локали на язык не обнаружено (положительный результат).

## 15. File handles (OPEN/CLOSE/потоковые)

Прогоны: `cases/fileio.axm`, `cases/seek.axm`, `cases/rewind2.axm`, `cases/callforms.axm` в песочнице `.artifacts/audit/sandbox`.

- Полный lifecycle CREATE→WRITE→FLUSH→FILEPOS→CLOSE→OPEN INPUT→READ→EOF→CLOSE работает; `ISOPEN/FILEPATH/FILEMODE/FILEPOS/FILELENGTH/LINENUMBER/EOF/READTOEND/READTEXT/READLINE/READLINES/SKIPLINE/WRITE/WRITELINE/NEWLINE/FLUSH/SEEKFILE/REWIND` — все исполнимы; операции после CLOSE — чистая MB3007 «нужен открытый файл».
- `SEEKFILE` в границы файла проверяется (за пределы — MB3007; отрицательные — вне диапазона).
- **NEWLINE пишет LF (1 байт), не CRLF** — Windows-файлы, созданные Axiom, имеют unix-концы строк (FILELENGTH подтверждает 13 байт для «first\nsecond»). Контракт нигде явно не зафиксирован — DOCUMENTATION GAP (P4), для Basic-продукта на Windows ожидаем CRLF или переключатель.
- **AXD-002 (P1):** вызов файловых функций в позиции оператора без скобок — молчаливый no-op: `FLUSH f`, `REWIND f`, `NEWLINE f`, `WRITELINE f "текст"` парсятся как expression-стейтменты и выбрасываются без диагностики; `WRITELINE f "текст"` **не записывает данные и не сообщает об ошибке** (проверено: READFILE после такого вызова возвращает пустой файл). Со скобками всё работает. Корень: язык допускает произвольные выражения-операторы (`5`, `x`, `ABS(-5)` — тоже молчаливые no-op). Требуется либо запрет безскобочных вызовов с диагностикой, либо предупреждение.
- Два открытых файла одновременно, FILEPOS после FLUSH — работают.

## 16. File system

Прогон: `cases/fs.axm` (обёрнут в TRY/CATCH). ## 17. Encoding/BOM

**AXD-004 (P2), подтверждено эмпирически** (`cases/enc.axm`, файлы bom.txt/nobom.txt/cp1251.txt/invalid.txt):

| Файл | READFILE / READALLLINES | OPEN FOR INPUT + READTOEND |
|---|---|---|
| UTF-8 + BOM | «тест» (BOM вырезан) | LEN=5 — **BOM остаётся символом U+FEFF** в начале потока |
| UTF-8 без BOM | «тест» | «тест» |
| Windows-1251 | «тест» (fallback 1251) | **runtime-ошибка** «не удалось прочитать текст как UTF-8» |
| Невалидные байты | молча декодирует как 1251 (3 кривых символа) | — |

Корень: `BuiltinFileSystemHelpers.ReadTextFileWithFallback` (strict UTF-8 → catch → 1251) против `RuntimeTextFile` (lenient UTF-8, без fallback, без strip BOM). Один и тот же файл читается двумя API по-разному; файл, записанный в русской Windows-кодировке сторонним ПО, READFILE читает, а OPEN INPUT — не может открыть вовсе. Рекомендация: единый детектор BOM + единый fallback-контракт, зафиксированный в spec.

## 18. Binary file I/O — gap analysis

Реестр режимов `RuntimeTextFileMode`: Input/Output/Append — **только текстовый I/O**. Отсутствуют: binary OPEN, байтовые读写, GET/PUT, random-access записи, выбор кодировки при OPEN, PRINT #/INPUT #/LINE INPUT # (QB-формы).

Классификация:
- **DESIGN LIMITATION** (текстовая модель файлов — архитектурный выбор текущего этапа);
- **MISSING ESSENTIAL FEATURE**: выбор кодировки при OPEN (без него нельзя прочитать 1251-файл потоково — см. AXD-004) и побайтовое чтение хотя бы через отдельные built-ins;
- **OPTIONAL FUTURE FEATURE**: GET/PUT/random-records, PRINT #/INPUT # (исторические QB-формы; современная модель WRITELINE(f, …) уже закрывает основной сценарий).
Рекомендация: спроектировать `OPEN FOR BINARY` + `READBYTE/READBYTES/WRITEBYTES` и параметр кодировки — до этого зафиксировать ограничение в manual.

## 19. Console I/O (PRINT/INPUT/PRINT USING)

- `PRINT` с несколькими аргументами, пустой PRINT, `;`/`,`-разделители — работают; формат чисел — shortest-round-trip DOUBLE (0.30000000000000004), E-нотация для малых чисел — одинаково в обоих движках.
- `PRINT USING` — QB-маски `#`, `.`, `\\ \\`, `!`, `&`; переполнение ширины — префикс `%` (QB-совместимо); нечисловое значение в числовом поле — MB3007. Паритет полный.
- `INPUT`: разделитель значений — запятая (QB-семантика: «3 4» в `INPUT a, b` — ошибка «Ожидалось 2 значений, получено 1»; «3,4» — ок); конверсия неудачного типа — MB3003 с указанием значения; подсказка `INPUT "текст";` — ок.
- DATA/READ/RESTORE и LINE INPUT — запланированы (`docs/meta/FEATURE_LEDGER.md`), не регрессия. Отсутствие LINE INPUT смягчено тем, что одиночный `INPUT s` (STRING) читает строку целиком.
- P4: STRING-переменные через INPUT читают всю строку до конца — фактически покрывает LINE INPUT для одного аргумента (документировать).

## 20. Procedures / Functions

- `SUB`/`FUNCTION` с явными типами параметров; `RETURN value` — единственная форма возврата; QB-идиома `FuncName = value` **не поддерживается** (присваивание имени функции = MB2001 «Имя не объявлено») — осознанное решение, но для QB-аудитории стоит задокументировать крупно.
- Определения могут следовать после вызывающего кода (module-level видимость) — проверено образцами.
- Вызов SUB: `Name(args)`; безскобочный `Name arg` — **MB2019 «Процедуру нельзя использовать как значение»** для SUB и молчаливый no-op для builtin (см. AXD-002) — непоследовательность реакций на одну и ту же форму вызова (P3).
- `EXIT SUB`/`RETURN` — корректны; рекурсия (factorial, взаимная, 5000 глубины) — ок в обоих движках; переполнение стека не достигнуто (глубже не проверялось).
- Аргументы-массивы, `BYREF`/`BYVAL` для скаляров/TYPE/массивов — см. раздел 20.1.
- Функция без RETURN со значением — Interpreter: MB3006 с цепочкой вызовов; VM: **BC4054 «Инструкция Return ожидает высоту стека 1, получили 0»** — разные коды (MB3006 vs BC4054), тексты, и Interpreter успевает напечатать побочный вывод тела до ошибки, VM — нет. P2 (важное расхождение диагностики одного и того же дефекта).

### 20.1 BYVAL/BYREF

- По умолчанию BYVAL (спецификация 2026-05-04; подтверждено: скаляры и TYPE не мутируют вызывающего).
- `BYREF` мутирует; `BYREF` с несовместимым типом — MB2003 на вызове.
- Массивы: тело разделяется даже без BYREF (мутация видна вызывающему) — контракт spec, отразить в manual поярче.
- Передача BYREF через несколько уровней — работает.

## 23. Operators

Прогон: `cases/operators.txt` (48 кейсов). Паритет SAME 48/48.

- Приоритет арифметика>сравнения>NOT>AND>OR подтверждён выражениями-ловушками (`NOT a AND b`, `a + b * c`, сравнения+булевы).
- `-2 ^ 2 = -4` (унарный минус слабее `^`) — QB/VB-совместимо.
- **`^` правоассоциативен** — AXD-009 (P3), отличие от QB/VB, не задокументировано.
- AND/OR/NOT/XOR на INTEGER — битовые (`5 AND 3=1`, `NOT 5=-6`); на BOOLEAN — логические; смешение BOOLEAN/INTEGER — MB2003; короткого замыкания нет (нет AndAlso/OrElse — gap P3).
- `\` и `MOD` требуют целые типы: `10 \ 2.0`, `7.5 MOD 2`, `8 \ 2 ^ 2` — MB2003 (результат `^` — всегда DOUBLE; пользователь обязан писать `INT()`). P3 usability: неявное приведение целозначного DOUBLE отсутствует.
- Цепочки сравнений (`1 < 2 < 3`) — MB2003 (строго, хорошо).
- Shift-операторов (SHL/SHR) нет при наличии битовых AND/OR/NOT — непоследовательность битовой подсистемы (SHOULD-кандидат).

## 32. Performance

Быстрые пробы (20k конкатенаций, сортировка 20k, сумма 20k): оба движка укладываются < 1 с на операцию (процесс целиком < 2 с). O(n²)-катастроф в базовых операциях не наблюдается; профильные сценарии поддерживаются собственной инфраструктурой `samples/smoke/engine-compare/` + `docs/BYTECODE_PERF_MATRIX.md` (аудит матрицы не входил в объём — она актуальна). Regex без таймаута — см. раздел 11.

## 33. Resource safety

- Файловые дескрипторы: CLOSE освобождает; ошибки после CLOSE — чистые; утечки в проверенных сценариях не найдены. Cleanup после runtime-ошибки: файл, открытый OPEN, закрывается по завершении запуска (pipeline dispose) — проверено транзакционно (после MB3003 при чтении следующий запуск работал).
- REWIND/SEEKFILE не допускают выхода за пределы; буфер записи сбрасывается при Seek в Output.
- Рекурсия: 5000 глубины — ок; преднамеренный stack overflow не тестировался (риск фиксированный, не дефект).
- Regex runaway — защиты нет (см. раздел 11).

## 34. Platform assumptions

Windows-first подтверждён: пути через System.IO.Path, разделители `\`, DRIVETYPE/ISHIDDEN — Windows-семантика, Windows-1251 fallback — Windows-ориентирован. ACCIDENTAL-зависимостей (жёстко зашитых `\` в логике) не найдено — Path-API везде. Классификация: LANGUAGE CONTRACT — Windows-пути в DRIVETYPE/ISHIDDEN; WINDOWS-ONLY DESIGN — 1251-fallback, DRIVETYPE; переносимость текста на LF (NEWLINE) наоборот облегчает кроссплатформенность.

## 39. Recommended additions (standard library)

Формат: ИМЯ | категория | вердикт | обоснование.

**MUST** — нет (библиотека функционально полна для базовых программ).

**SHOULD:**
1. `RANDOMIZE [seed]` (random) — воспроизводимость/управляемость RND; QB-наследие; сейчас невозможно из языка. ADD.
2. Явные преобразования `CINT/CLNG/CDBL/CDEC/CSTR` (conversion) — сужения запрещены, `INT()` — floor, а не преобразование; без этого LONG→INTEGER невозможен идиоматично. ADD (имена из VB-линейки, соответствуют правилу 9.2).
3. `SHL/SHR` (bitwise) — AND/OR/NOT битовые уже есть; отсутствие сдвигов — неполнота битовой подсистемы. ADD.
4. `ANDALSO/ORELSE` (boolean) — VB-наследие; без них-guard-выражения вроде `i <= n AND a(i) <> 0` опасны (оценка обоих операндов). ADD.
5. `ARRAYSUM/ARRAYMIN/ARRAYMAX/ARRAYAVERAGE` (array aggregates) — самый частый пользовательский цикл. ADD (проверить QB-прецедент имен: SUM в Basic-линейке нет — имена по проектному прецеденту ARRAY*).
6. Параметр кодировки для файловых операций / `OPEN … ENCODING "utf-8|1251"` (file) — закрывает AXD-004. ADD (после фиксации единого контракта кодировок).
7. `ISDATE`-подобные предикаты чисел? — REJECT (значения NaN/Inf недостижимы by design).

**NICE:**
8. `PI`, `E` константы — QB/VB их не имели; пользователь пишет `4 * ATN(1)`. CONSIDER (низкий приоритет).
9. `GCD/LCM` — легко вручную (цикл); QB не имел. CONSIDER.
10. `HYPOT` — редкий сценарий. CONSIDER.
11. `FRAC(x)` = `x - FIX(x)`; `TRUNC` = FIX (дубль — REJECT TRUNC, CONSIDER FRAC).
12. `DEGREES/RADIANS` — тривиально вручную. CONSIDER (низкий).
13. `LOG(x, base)` — есть `LOG(x)/LOG(base)`. CONSIDER.
14. Case-insensitive варианты поиска (`INSTR`-режим) — `UCASE`-обход есть. CONSIDER.
15. `RANDOMINTEGER(min,max)` — `INT(RND()*(max-min+1))+min`. CONSIDER.
16. Форматирование чисел в строку (`FORMAT`) — PRINT USING есть, строкового варианта нет. CONSIDER.
17. Base-conversion (`HEX/DEC/OCT/BIN` функции) — QB имел HEX$/OCT$; полезно для отладки. CONSIDER.

**REJECT:**
18. `ISNAN/ISFINITE/ISINFINITY` — NaN/Inf недостижимы (ошибки вместо значений — осознанный контракт).
19. `COPYSIGN` — уже есть `SETSIGN` (проектный прецедент).
20. Статистические функции (median/stddev) — преждевременно для продукта.

## Финальный вердикт (вопросы раздела 48 задания)

1. Функции с неверным результатом: **нет** (все проверенные значения корректны); есть неверное *поведение* — AXD-001 FINALLY.
2. Расхождения Interpreter↔VM: **да** — семантика FINALLY (P1), MB3006/BC4054, тексты/локализации/цепочки диагностик (P2), побочные эффекты до ошибки.
3. Зарегистрированные built-ins без реализации: **нет** (282/282 исполняются обоими движками; 3 orphan-ID — сознательные плейсхолдеры).
4. Реализованные функции вне реестра: **не найдены**.
5. Неправильные перегрузки: **не найдены** (конфликтов/неоднозначностей нет).
6. Numeric promotion: расхождений нет; P3 — `\`/`MOD` не принимают целозначный DOUBLE (`8 \ 2 ^ 2` — ошибка).
7. Unicode-дефекты: **да** — смешанные единицы (AXD-011), ломание суррогатных пар в LEFT/MID/INSERT/REMOVE/PAD.
8. File I/O с риском потери данных: **да** — молчаливый no-op `WRITELINE f "..."` (AXD-002); далее — кодировочная асимметрия (чтение), mojibake-диагностики.
9. Протекающие CLR-исключения: **не обнаружены** (0 случаев в ~700 кейсах).
10. Функции, требующие изменения семантики: без изменения результатов; требуется согласование `^`-ассоциативности с BASIC-семейством (или документирование), VAL-запятой, ROUND уже задокументирован.
11. Реально не хватает: RANDOMIZE, Cxxx-преобразования, ANDALSO/ORELSE, SHL/SHR, ARRAY-агрегаты, ENCODING-параметр файлов, binary I/O.
12. Добавлять НЕ следует: ISNAN/ISINF-семейство, TRUNC (есть FIX), COPYSIGN (есть SETSIGN), статистические хелперы, GOTO.
13. Пять исправлений с максимальным эффектом: (1) FINALLY-rethrow; (2) no-op-диагностика безскобочных вызовов; (3) единые тексты/локализации диагностик через общий helper; (4) единый кодировочный контракт файлов; (5) генерация подсветки из реестра.
