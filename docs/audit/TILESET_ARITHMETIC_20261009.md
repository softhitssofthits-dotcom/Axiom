# Переполнение арифметики регулярного атласа

## Доказательство до исправления

Реальный PNG samples/graphics/sprites/assets/walk_sheet.png имеет32×32 пикселя. Через ProgramRunService в обоих движках проверены две формы LOADTILESET. При tileWidth=tileHeight=17 и margin=2147483647 загрузчик возвращал4 тайла вместо отказа. При tileWidth=tileHeight=32, margin=0 и spacing=2147483647 загрузчик выдавал MB3005 вместо корректного одного тайла. Исходный результат0/4 успешно,4/4 ошибочно; TRX .artifacts/test-results/tileset-arithmetic-1212/tileset-arithmetic-1212-before.trx.

TILE26-010 P2:margin*2 переполняет INTEGER; полезная длина32-(margin*2) ошибочно становится34 и образует ложную сетку. TILE26-011 P2:usableLength+spacing и tileLength+spacing переполняют INTEGER, поэтому корректная сетка из одного тайла отклоняется. Это ошибки существующей геометрии, а не отсутствующие функции языка. Фактические пиксели после ошибочного рисования здесь не исследовались.

## Исправление

RuntimeTilesetValue вычисляет удвоенный отступ и длины осей с промежуточным long, шаг сетки также long. Количество тайлов возвращается в int через checked после проверки геометрии. GetTileLeft/GetTileTop вычисляют координаты с long и проверенным приведением. Внешние типы параметров и пользовательский синтаксис не изменены. Невозможный отступ отклоняется, а spacing не создаёт ложного ограничения для одного тайла.

Общая модель используется ручной загрузкой и Tiled-картой. Итоговый IDE-набор8 случаев проверяет два значения × два движка × LOADTILESET/LOADTILEMAP с настоящим PNG. Для карт добавлены large_margin.tmj и large_spacing.tmj. Эти дополнительные проверки не выдаются за исходное воспроизведение.

Пять прямых Runtime-проверок подтверждают отказ для огромного margin, один тайл с максимальным spacing и точные координаты последнего тайла обычной сетки, сетки с margin=2 и сетки со spacing=2. Полный Runtime1075/1075 успешно. Полный IDE выполняется последовательно; итог будет записан ниже.

## Руководство и пример

samples/functions/loadtileset/arithmetic_boundaries.axm показывает допустимый большой промежуток, отказ для невозможного отступа и сохранение прежнего тайлсета. Включён в TilePropertyAcceptanceSampleTests обоих движков. docs/manual/tilesets.html объясняет геометрию и ссылается на пример. Уточнение применяется также к загрузке регулярного тайлсета внутри Tiled.

Редакционный мотив — проверка загрузки и обработка ошибки из раздела OPEN книги Зельднера; конкретной модели Tiled в книге нет. Запасной справочный ориентир загрузки файла: https://learn.microsoft.com/en-us/dotnet/api/microsoft.visualbasic.filesystem.fileopen?view=net-10.0. Описание полей Tiled: https://doc.mapeditor.org/en/stable/reference/json-map-format/. Факты Axiom проверены по общей модели и реальному загрузчику, внешняя семантика не переносится.

Следующий шаг — экстремальные tileoffset и границы видимого диапазона при рисовании, включая большие конечные координаты и произведение камеры на параллакс. Возможные переполнения в других графических моделях требуют отдельного доказательства. Общий аудит остаётся активным.
