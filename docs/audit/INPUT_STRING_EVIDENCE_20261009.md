Ожидаемые значения заданы вне языка; для одиночной цели результат побуквенно равен строке IInputProvider. ## Вывод для пробела API

Синтаксис LINE INPUT отсутствует, но основная пользовательская возможность уже доступна: INPUT одной переменной STRING сохраняет всю логическую строку без деления по запятым, удаления пробелов или специальной обработки кавычек. Для проверенного сценария отдельный новый оператор не необходим. Он мог бы служить привычной BASIC-формой или частью будущего иного договора, но не должен вводиться на основании ложного утверждения о невозможности полного строкового ввода.

INPUT с несколькими целями имеет другой договор. Его нельзя рекомендовать для CSV с запятыми внутри кавычек. Не заявлены проверка живого графического окна, обработка всех физических клавиш/вставки, EOF/отмена, ввод многострочного текста или максимальная длина: новые автоматические случаи работают через IInputProvider.

## Код и справочник

Interpreter.Helpers.TryParseInputValues выбирает [text] для одной цели и text.Split(',') для нескольких. BytecodeVm.Input.TryParseAndStoreInputValues передаёт одиночную строку напрямую; ветви2/3 и общий путь разбирают запятые. BuiltinIOHelpers.TryParseInputField для STRING сохраняет строку; NormalizeInputField удаляет пробелы только по флагу. docs/manual/input.html уже явно описывает различие одной и нескольких переменных; публичный договор не менялся.
