# Повреждённые UTF-16 строки в GRAPHEME

Session 1218, 2026-10-09. Следующий участок после завершённой тайловой части выбран из Unicode: прежние доказательства покрывали одиночные суррогаты в CODEPOINT, но не выделяли границы GRAPHEME на повреждённых строках.

## Независимые ожидания

`UnicodeMalformedGraphemeEvidenceTests` содержит восемь наборов частей, заданных буквально: одиночный старший/младший суррогат, два старших, два младших, обратный порядок, непарные суррогаты рядом с целым emoji, чередование с кириллицей и соседство с составным символом и флагом. Ожидания не вычисляются через StringInfo или проверяемые функции. Повреждённые строки создаются внутри теста: xUnit получает только номер набора и движок.

В каждом движке проверены LEN и каждый отдельный MID, все префиксы LEFT и суффиксы RIGHT. Сравнение выполняется внутри языка, поэтому замена суррогата при выводе терминала не может скрыть повреждение. Дополнительно проверены count=2147483647 и start=2147483647. Фактический движок проверен явно, запасной интерпретатор не использован.

Три дополнительных случая проверяют четыре неверные границы среза для каждой единицы UTF16/CODEPOINT/GRAPHEME на строке с одиночным старшим суррогатом: LEFT с нулём, RIGHT с отрицательным количеством, MID с нулевым началом и нулевым количеством. Оба движка дают MB3007 с одинаковыми координатами диагностики.

Следующий адресный участок — INSTR/INSTRREV с началом внутри суррогатной пары, непарным суррогатом в искомом фрагменте и пустым фрагментом. Ожидания следует сверить с существующим договором позиций UTF-16; поиск не становится поиском по графемам из-за появления GRAPHEME у срезов.
