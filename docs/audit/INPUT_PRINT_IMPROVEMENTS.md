### Задача 5: Общий OutputBuffer

**Проблема:** Логика буферизации вывода дублируется между Interpreter и VM (~100 строк).
**Решение:** Создать `BuiltinOutputBuffer` в `Axiom.Runtime.Builtins`.
**Зависимости:** Задачи 1-4 (стабильные тесты).

### Задача 6: Кэш формата PRINT USING в Interpreter

**Проблема:** VM кэширует распарсенные токены формата (`_printUsingFormatCache`), Interpreter — нет.
**Решение:** Добавить аналогичный кэш в Interpreter.
**Зависимости:** Задача 5.

### Задача 7: Оптимизация AppendPendingOutput

**Проблема:** Interpreter использует `ToDisplayString()` для чисел (аллокация строки). VM использует `stackalloc` + `TryFormat()`.
**Решение:** Добавить `ISpanFormattable` путь в Interpreter.
**Зависимости:** Задача 5.

# ПРЕДЛОЖЕНИЕ: Интерполяция строк в Axiom

На основе `docs/FUTURE.md` §5 и аудита INPUT/PRINT.

## Текущее состояние

Сейчас для вставки значений в строки нужна конкатенация:
```axiom
DIM name AS STRING = "Алиса"
DIM age AS INTEGER = 25
PRINT "Привет, " & name & "! Тебе " & age & " лет."
```

## Вариант 1: `${expr}` — как в shell/JavaScript (рекомендуется)

**Синтаксис:**
```axiom
DIM name AS STRING = "Алиса"
DIM age AS INTEGER = 25
PRINT "Привет, ${name}! Тебе ${age} лет."
```

**Плюсы:**
- Не конфликтует с существующим синтаксисом (`$` не используется в языке)
- Привычный для пользователей shell, JavaScript, Python (f-strings), C#
- Легко экранировать: `$$` для литерального `$`
- Поддерживает произвольные выражения: `${a + b}`, `${LEN(s)}`
- Не требует изменения парсера — обрабатывается в лексере

**Минусы:**
- Лексер становится сложнее (рекурсивный разбор внутри строк)
- Нужно обрабатывать вложенные `${}` и многострочные выражения

**Реализация:**
- Лексер: при встрече `$` + `{` внутри строкового литерала — переключение в режим интерполяции
- Лексер: рекурсивный вызов `ReadExpression()` внутри `${}`
- Парсер: без изменений (интерполяция — часть строкового литерала)
- Lowering: `"текст ${expr} текст"` → конкатенация `"текст " & ToStr(expr) & " текст"`
- Runtime: `ToStr()` — существующая функция или автоматический `ToDisplayString()`
- IDE: подсветка выражений внутри строк (отдельный цвет для `${}`)
- Тесты: позитивные, негативные, вложенные, экранирование

## Вариант 2: `$"expr"` — как в C# 6+

**Синтаксис:**
```axiom
DIM name AS STRING = "Алиса"
PRINT $"Привет, {name}! Тебе {age} лет."
```

**Плюсы:**
- Привычно для C# разработчиков
- Чистый синтаксис без `$` перед каждой переменной

**Минусы:**
- `$` перед кавычкой — новый префикс строкового литерала
- Конфликт с `$` суффиксом (если будет добавлен)
- Требует изменения парсера (новый тип строкового литерала)

## Вариант 3: `f"expr"` — как в Python

**Синтаксис:**
```axiom
DIM name AS STRING = "Алиса"
PRINT f"Привет, {name}! Тебе {age} лет."
```

**Плюсы:**
- Привычно для Python разработчиков
- Чистый синтаксис

**Минусы:**
- `f` — может конфликтовать с идентификаторами
- Требует изменения парсера
- Необычно для BASIC-подобного языка

## Вариант 4: `PRINT USING` расширение — без нового синтаксиса

**Синтаксис:**
```axiom
DIM name AS STRING = "Алиса"
DIM age AS INTEGER = 25
PRINT USING "Привет, &! Тебе # лет."; name; age
```

**Плюсы:**
- Уже реализовано!
- Не требует изменений в языке

**Минусы:**
- Менее читаемо, чем интерполяция
- `&` и `#` — неочевидные обозначения
- Нужно считать позиции значений

## Рекомендация

**Вариант 2 (`$"expr"`)** — лучший выбор для Axiom:
1. Один `$` в начале строки — не нужно писать `${}` перед каждой вставкой
2. Чистый и читаемый синтаксис при множественных вставках
3. Привычен для C# разработчиков
4. Поддерживает произвольные выражения: `{a + b}`, `{LEN(s)}`
5. Легко экранировать: `{{` и `}}` для литеральных скобок
6. Соответствует BASIC-стилю (простой и понятный)

## Этапы реализации (Вариант 2)

1. **Lexer:** добавить `ReadInterpolatedString()` при встрече `$"` — разбор `{expr}` внутри строк
2. **Syntax:** новый `InterpolatedStringExpressionSyntax` с частями (текст + выражения)
3. **Binder:** проверка выражений внутри `{}`
4. **Lowering:** `$"текст {expr}"` → `"текст " & ToStr(expr)`
5. **Runtime:** `ToStr()` или автоматическое `ToDisplayString()`
6. **IDE:** подсветка выражений внутри интерполированных строк
7. **Tests:** позитивные, негативные, вложенные, экранирование `{{`/`}}`
8. **Samples:** runnable-примеры
9. **Manual:** обновление `data-types-strings-and-files.html`
