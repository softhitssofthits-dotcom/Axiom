## RX26-001 — неверная проверка номера группы — P2

Минимальная программа: PRINT REGEXEXTRACT("a", "(?<10>a)", 10). Ожидается a, фактически пустая строка в Interpreter и BytecodeVm. Та же ошибка у REGEXEXTRACTALL и вариантов с modes. BuiltinRegexHelpers сравнивает group с Groups.Count, хотя номер явно заданной группы не обязан быть плотным порядковым индексом. GroupCollection[int] в .NET 10 сопоставляет такой номер через captureMap и возвращает пустую группу для отсутствующего номера. Подтверждение: .artifacts/regex-1131-baseline-corrected.log, 78/80, два падения с шестью неверными результатами каждое. Исходник библиотеки: https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Text.RegularExpressions/src/System/Text/RegularExpressions/GroupCollection.cs .

## RX26-002 — поиск после достижения count вызывает лишний отказ — P1

Текст x + 12000 букв a + !a; шаблон x|(?:a|aa)+$; замена y; count=1. Ожидается только замена первого x на y с неизменным остатком. Фактически MB3007 «pattern выполняется слишком долго» в обоих движках, с modes и без. .artifacts/regex-1131-suffix-probe.log: 0/4, около 20 секунд суммарно. BuiltinRegexHelpers.ReplaceRegexMatches вызывает Matches.Count и ищет все совпадения до проверки количества замен. Предыдущие кандидатные шаблоны .NET обрабатывал быстро; они не являются доказательством этого отказа. Стандартная перегрузка Regex.Replace(input, replacement, count) поддерживает требуемое ограничение без предварительного сбора всех совпадений: https://learn.microsoft.com/en-us/dotnet/api/system.text.regularexpressions.regex.replace?view=net-10.0 .

## Исправление и итог Session 1131

Ограниченная замена использует regex.Replace(text, replacement, count), удалён дублирующий сборщик всех совпадений. После исправления первоначальный набор 80/80, расширенный — 118/118. ## RX26-003 — лишнее экранирование в примерах manual — P4, DOCUMENTATION-ONLY

Subsystem: REGEX/manual. Affected files: regex-functions-match-and-extract.html (два вызова), regex-functions-arrays-and-split.html и regex-functions-replace-and-count.html. Function: REGEXEXTRACT/REGEXEXTRACTALL/REGEXREPLACE. В примерах класс цифр был записан двумя обратными косыми чертами. Строки Axiom не имеют C#-экранирования: двойная черта меняет шаблон на поиск буквальной косой черты и буквы d, вместо класса цифр. Минимальный воспроизводитель .artifacts/regex-1132-manual-escape.axm сравнивает оба варианта с ожидаемым 12; CLI даёт FALSE/TRUE. Независимый PatternBackslashesAreWrittenOnceInAxiomStrings в обоих движках подтверждает 12/пустую группу и A-12 B-34.

Expected: примеры дают заявленные в manual результаты. Actual/Interpreter/VM: вариант с лишней чертой не извлекает цифры; правильный одиночный вариант работает. Root cause: перенесено экранирование другого языка. User impact: скопированный пример даёт неверный результат. Regression risk: минимальный, исправлены только ошибочные сочетания перед d; правильное удвоение для буквальной обратной косой черты в общей таблице сохранено. Recommended fix/Status: четыре примера исправлены, FIXED. Tests required: оба вида записи и шаблон замены, оба движка. Documentation impact: уточнение синтаксиса строк и новый runnable sample samples/functions/regexextract/pattern_backslash.axm. IDE impact: новых токенов нет. Confidence: CONFIRMED.

Сам проверочный текст дважды содержал неверное число обратных черт при переносе через несколько строковых уровней. Перед окончательной проверкой число черт проверено явно (1/2/1); промежуточные падения не являются дефектом языка. Исправленный быстрый набор 163/163 и дополнительная проверка Span 1/1 проходят.
